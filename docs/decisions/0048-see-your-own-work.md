# 0048. Lucia는 자기가 만든 것을 직접 확인한다

- 날짜: 2026-11-19
- 상태: 확정. 한도(그림 3 MB, 글 한 번에 2만 자, 스크립트 결과의 그림 3장)는 [제안].
- 결정 방식: 사용자 지시를 따랐다.
  - "지금 모델이 자신이 작업한 것을 직접 확인할 수 없는 상황이야. 이미지 등. 이 부분 개선해. 비서 에이전트이긴 하나 Claude Code나 Cowork같이 여러 작업을 수행할 수 있는 다기능 에이전트로서의 기능은 기본적으로 있어야 해."
- 관련 결정: 0005(파일), 0045(이모지·스티커), 0046(이미지 생성), 0047(스크립트 패키지·파일)

## 원칙

- **Lucia가 만들 수 있는 것은 Lucia가 볼 수 있어야 한다.** 만든 결과를 보지 못한 채 사용자에게 설명하거나 보내지 않게 한다.
- 새 기능을 더할 때 "결과를 Lucia가 어떻게 확인하나"를 함께 정한다. 확인하는 길이 없으면 그 기능은 덜 된 것이다.
- Lucia는 비서지만, 여러 일을 하는 에이전트의 기본기(만들고, 돌려 보고, 결과를 열어 확인하기)는 갖춘다.

## 무엇이 안 보였나(이 결정 전)

- 스크립트가 만든 파일: `code_run`은 글만 돌려주었다. 개발 설정에서 사진을 640×640 스티커로 바꿨을 때 Lucia는 결과를 보지 못한 채 "흰 배경 가운데에 넣었다"고 설명했다.
- 파일 ID로 다시 열기: 길이 없었다. 자기가 만든 파일도, 대화가 정리된 뒤의 사용자 첨부도 열 수 없었다.
- 등록된 이모지·스티커의 그림: 이름과 설명만 보였다.
- 파일 ID 찾기: 목록이 없었다.

## 결정

### `file_view`: 파일을 직접 연다(늘 바로 보이는 도구)

- 파일 ID(`f_…`)를 주면 그 파일을 보여 준다. 스크립트가 남긴 파일, 만들거나 고친 그림, `file_create`로 만든 파일, 스크린샷, 사용자가 붙인 파일 모두.
  - 그림: 그림으로 보인다(PNG·JPEG·WebP·GIF, 움직이는 PNG는 PNG로). 3 MB(3 MiB)까지.
  - 글: 글로, 외부 데이터로 싸서. 한 번에 2만 자, `offset`으로 이어 읽는다. SVG·HTML은 그려진 모습이 아니라 원문이라고 알린다.
  - Office 문서(docx·pptx·xlsx): 글만 뽑아 보인다.
  - PDF, 그 밖의 형식, 한도를 넘는 그림: 무엇인지와 볼 수 있게 만드는 길(스크립트에서 줄이기, pypdf로 글 뽑기)을 알려 준다. 보지 못한 것은 단정하지 말라고 적는다.
- 이모지·스티커 ID(`e_…`, `s_…`)를 주면 등록된 그림을 보여 준다. 목록을 턴마다 그림으로 싣지는 않는다(필요할 때만 본다).
- ID를 비우면 최근 파일 20개의 목록을 준다(받은 것·만든 것, 종류, 크기, 때).
- 새 문턱을 두지 않았다. 파일을 만들 수 있는 실행은 볼 수도 있다. 어떤 파일 ID든 이미 답에 붙일 수 있으므로, 보는 것이 새로 나가는 길을 만들지 않는다.
- 도구 하나로 묶었다(보기와 목록). 찾기 뒤에 둔 도구는 실제 모델이 못 찾았고(결정 0046), 바로 보이는 도구는 캐시되는 앞부분을 차지한다.

### 스크립트가 만든 그림은 결과와 함께 보인다

- `code_run`과 `skill_run`의 결과에, 스크립트가 `lucia.save_file`로 남긴 그림을 붙인다. 따로 열어 보는 단계는 건너뛰기 쉽기 때문이다.
- 3장까지, 합계 3 MB까지. 넘는 것은 "file_view로 하나씩 본다"고 알린다. 그림은 세션이 압축될 때까지 맥락에 남으므로 수를 작게 잡았다.

### 크기 규칙은 한 곳에

- 그림을 모델에게 보여 주는 규칙(형식, 3 MB)을 `fileview.rs`에 모았다. 이미지 생성의 결과 보여 주기도 이것을 쓴다.

## 아직 직접 확인하지 못하는 것

- 그려진 SVG·HTML(원문만 본다). 그려 보려면 변환기가 필요하다.
- PDF(스크립트에서 글을 뽑아 본다).
- 3 MB를 넘는 그림(스크립트에서 줄인 사본을 만들어 본다).
- 사용자 화면에 실제로 어떻게 보이는지(Discord·앱의 말풍선, 앱이 그린 이모지).

## 확인(2026-11-19)

- **시험**: 종류별 보여 주기(그림, 큰 그림, 긴 글 이어 읽기, SVG 원문, PDF, 모르는 형식, APNG), 스크립트 결과의 미리보기 한도, `file_view`의 보기·목록·없는 파일·이모지 그림·실행 종류별 허락.
- **실제 모델**(개발 설정):
  - 내용을 미리 알 수 없는 그림(네 구역이 보라·주황·청록·분홍)을 저장소에 넣고 "직접 열어 보고 네 구역의 색을 말해 줘"라고 했다. 넷을 모두 맞혔다. 그 실행의 도구 기록은 `file_view`와 보고뿐이다(스크립트로 픽셀을 읽은 것이 아니다).
  - "두 구역을 잘라 줄여 저장하고, file_view 없이 code_run 결과에 보이는 그림만 보고 말해 줘"라고 했다. 도구 기록은 `code_run`과 보고뿐이고, 결과에 붙은 두 장을 "색 점 노이즈"라고 맞게 말했다. 두 장짜리 결과가 지나가는 것은 보았다. 다만 두 장이 똑같은 노이즈라, 두 그림을 서로 구별하는지는 이것으로 알 수 없다.
  - 4.1 MB 그림을 열라고 하자 "한도를 넘어 보이지 않는다, 전체는 단정하지 못한다"고 하고 줄인 사본을 제안했다.
- **세션 크기**: 본 그림은 세션이 정리될 때까지 남는다. 개발 세션 기록을 재 보니 Claude Code가 큰 그림을 줄여서 둔다(2.2 MB PNG → 약 0.17 MB, 3.1 MB PNG → 약 0.47 MB의 JPEG). 그래서 큰 그림을 여러 번 봐도 요청이 그 크기만큼 불어나지 않는다.
