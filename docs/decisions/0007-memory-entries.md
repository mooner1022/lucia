# 0007. 기억을 나·주제·영역의 항목으로 나누고, 평소에는 색인만 붙인다

- 날짜: 2026-11-17
- 상태: 확정
- 결정 방식: 사용자 요청과 결정이다.
  - 사용자는 지금 방식이 크기에 한계가 있고, 그 한계가 크지 않다고 했다.
  - Claude 서비스처럼 기억을 카테고리로 나누고, 평소 대화에는 목록만 붙이고, 필요한 기억은 그때그때 도구로 받아 보는 방식을 적용하라고 했다. 설정 화면 사진 두 장을 참고로 주었다.
  - 사진의 모양: 갈래 "나·주제·영역", 항목마다 제목·요약·업데이트 날짜, 항목 화면에는 요약·세부 정보·삭제, 그리고 "기억해 둘 것" 입력창.

## 배경

- 지금까지: 핵심 기억은 8 KB 상한의 마크다운 한 덩어리였고, 매 실행 요청 앞에 통째로 붙었다.
  - 명세 §기억과 연속성의 "핵심 기억은 매 실행 전체를 붙인다"를 그대로 따른 것이다(PLAN §6 측정과 결정).
  - 바꿀 때는 모델이 완성본 전체를 다시 썼다.
- 문제: 상한이 작다. 늘리면 그만큼 매 실행 맥락(과 비용)이 커진다.

## 결정

**명세의 "매 실행 전체를 붙인다"를 사용자 결정으로 바꾼다.**

### 갈래와 항목

- **갈래**:
  - 나(`me`): 사용자 자신과 바라는 방식(프로필, 선호, 말투, 규칙).
  - 주제(`topic`): 생활의 주제별 사실(기기, 건강, 취미, 장소, 사람 등).
  - 영역(`area`): 진행 중인 일, 프로젝트, 활동 영역.
- **항목**: 이름(kebab-case, `[[이름]]`으로 서로 가리킨다), 갈래, 제목, 요약, 세부 정보(마크다운 목록), 만든 날·고친 날, 개정 번호.
- **크기 상한**:
  - 제목은 한 줄 40자, 요약은 한 줄 120자다. 둘 다 매 실행 색인에 들어가므로 줄바꿈을 받지 않는다.
  - 세부 정보는 항목마다 8 KB, 항목은 200개까지다.
  - 전체로는 1.6 MB까지 담을 수 있다. 예전 8 KB 한 덩어리의 200배다.
- **변경 기록**: 모든 쓰기·지우기를 개정으로 남긴다. 지우기는 지우기 전 내용을 남긴다.
  - 예전 핵심 기억 기록(`core_memory_revisions`)은 그대로 둔다.

### 맥락에는 색인만

- 매 실행(채팅, 브리핑, 기억해 줘) 앞에 `<memory_index>`를 붙인다. 갈래별로 `- [[이름]] 제목 — 요약 (고친 날)`이고, 세부 정보는 넣지 않는다.
- 색인 예산은 16 KB다.
  - 넘으면 남은 항목은 이름과 제목만 적는다.
  - 그래도 넘으면 "항목 N개 더 있다"만 적는다.
  - 항목 순서(갈래 → 제목)가 정해져 있어 결과가 늘 같다.
- 지침:
  - 답에 필요한 항목은 `memory_read`로 읽는다.
  - 메일을 보내기 전에는 규칙이 든 항목을 읽는다.
  - 기억은 색인과 `memory_read`가 기준이다. 상주 세션 앞쪽에 남은 예전 `<core_memory>` 블록은 낡았다.

### 도구

| 도구 | 하는 일 | 쓸 수 있는 실행 |
|---|---|---|
| `memory_read(names)` | 항목 세부 정보(5개까지)와 지금 개정 번호, 연결된 항목(`[[이름]]`)의 제목·요약 | 채팅, 브리핑, 기억해 줘 |
| `memory_write(name, section, title, summary, body, revision, reason)` | 항목 전체를 만들거나 고친다 | 채팅, 브리핑, 기억해 줘 |
| `memory_delete(name, reason)` | 항목을 지운다 | 채팅, 기억해 줘(사람이 시작한 실행만) |
| `memory_search(query)` | 항목과 지난 기록(에피소드)을 함께 찾는다(항목 먼저) | 모두 |

- **읽지 않은 내용을 덮어쓰지 않는다.** 세부 정보가 맥락에 없으므로, 이미 있는 항목은 `memory_read`가 준 개정 번호를 함께 내야 고칠 수 있다.
  - 번호가 없거나 낡았으면 거부하고 "읽고 다시 쓰라"고 돌려준다.
  - 새 항목은 0을 낸다.
  - 칸이 모두 필수다. 예전 모양(`body`·`reason`만)으로 부르면 실패한다.
- **지우기**는 사람이 시작한 실행에만 준다(실행별 허락 `memory_delete`). 외부 글을 읽는 브리핑이 기억을 지우지 못하게 하려는 것이다.
  - 도구 알림과 활동 기록에 항목 이름을 남긴다.
- `memory_write` 설명에 "지침의 '핵심 기억'은 이 기억 항목을 말한다"를 적어 캐릭터 파일(보호 영역)의 낱말과 잇는다. (2026-11-17 결정 0009에서 캐릭터 19행을 고치면서 지웠다.)

### 관리 페이지

- 새 화면 **기억**(`/memory`):
  - 갈래별 목록(제목, 요약, 고친 때)과 "기억해 둘 것 말하기" 입력창.
  - 입력하면 작업 큐에 넣는다(루틴 동작 `remember`, 대화와 겹치지 않게).
  - Lucia가 기억 도구만 쓰는 실행(`RunProfile::Remember`)으로 알맞은 항목에 넣거나 고치거나 지운다. 결과는 화면의 마지막 결과와 활동 기록에 남는다.
- **항목 화면**(`/memory/<이름>`):
  - 요약과 세부 정보를 보인다. 목록, 소제목, 문단을 그리고, `[[이름]]`은 그 항목으로 잇는다.
  - 변경 기록(누가, 왜, 언제)과 두 번 눌러 지우기가 있다.
  - 사진의 Claude 화면처럼 직접 고치는 칸은 두지 않는다. 고칠 때는 Lucia에게 말한다.
- 시스템 화면의 핵심 기억 게이지는 "기억 항목 N개 · 크기 · 기억 보기"로 바꿨다.

### 옮기기와 호환

- 마이그레이션 0006이 예전 핵심 기억(마지막 개정)을 항목 하나(`core-notes`, 나, "예전 핵심 기억")로 손실 없이 옮긴다.
  - 운영 저장소는 2026-11-17 00:55(한국 시간)에 옮겼다(539바이트). 옮기기 전 백업은 `lucia.sqlite.pre-0006.bak`(스키마 5)이다.
  - 주제별로 나누는 일은 데이터를 손으로 고치지 않고 Lucia에게 맡긴다(저장소 검증과 변경 기록을 거치게).
- 설정의 `[memory] core_max_bytes`는 받기만 한다. 기존 설정 파일이 그대로 뜨게 하려는 것이다.

## 실측(2026-11-17, 개발 저장소, sonnet, 실제 VM)

- 시험 항목 둘(나 "선호와 규칙": 메일 주소 규칙은 세부 정보에만, 주제 "기기")을 넣고 대화 네 번을 했다.
  1. "내 휴대폰 케이스가 어떤 거였지?": `memory_read(devices)` 뒤 세부 정보에만 있던 "자석 케이스"로 답했다.
  2. "에어팟 프로 2도 같이 써, 기억해 둬": 읽고 고쳐 썼고 기존 줄이 모두 남았다.
     - 다만 두 번 실패한 뒤 성공했다. `memory_read` 결과의 "제목:/요약:" 줄을 본문에 넣었고, 갈래에 화면 이름 "주제"를 넣었다.
     - **고침**: 읽기 결과의 칸 이름을 쓰기 칸과 같게(`section="topic"`, `title`, `summary`, `body`) 맞추고 쓰는 법을 한 줄 붙였다. 갈래는 한국어 이름(나·주제·영역)도 받는다.
  3. "기억 시험이라는 제목으로 테스트 메일 보내 줘": `memory_read(preferences)` → `mail_aliases` → 보내는 주소 `me@example.com`(세부 정보의 규칙)로 발송 요청을 만들었다.
     - 이 시험 항목의 요약에는 "메일 보내기 전 세부 정보 확인"이라는 힌트가 있었다. 요약에 아무 힌트가 없는 항목을 스스로 찾아 읽는지는 확인하지 않았다. 그래서 "나" 항목 요약에 규칙 자체를 쓰게 한다.
  4. 고친 뒤 "서피스는 이제 안 써, 고쳐 줘": 읽기 한 번, 쓰기 한 번으로 끝났다.

## 남는 한계와 [제안]

- **[제안] 나 갈래 늘 붙이기**: 말투와 메일 규칙 같은 "나" 항목은 예전처럼 늘 맥락에 있지 않다.
  - 지금은 요약에 규칙 자체를 쓰게 하고, 메일 전에 읽게 지침을 두었다.
  - 놓치는 일이 보이면 나 갈래의 세부 정보를 늘 붙이는 것을 검토한다.
- 검색은 여전히 낱말 일치다(항목은 LIKE, 지난 기록은 trigram). 의미 검색은 하지 않는다.
- **[제안] compact 전 기억 정리**: 세션을 줄이기 전에 오래 갈 사실을 항목으로 옮기는 단계는 아직 없다.
- 외부 글이 기억을 바꿀 수 있는 틈(PLAN §6 "알려진 틈")은 그대로다. 지우기만 사람이 시작한 실행으로 좁혔다.
- **색인이 세션에 쌓인다.** 색인은 상주 세션의 매 요청 앞에 붙으므로, 같은 색인이 턴마다 세션에 남는다.
  - 지금은 작다(항목 몇 개, 1 KB 남짓).
  - 예산 16 KB까지 차면 턴마다 수천 토큰이 늘고 compact가 그만큼 일찍 온다.
  - **[제안]**: 새 세션의 첫 요청이나 색인이 바뀌었을 때만 색인 전체를 붙이고, 그 밖에는 바뀐 항목만 알린다.
- 캐릭터 파일 19행("핵심 기억에 취향으로 남긴다")은 보호 영역이라 고치지 않았다. → 사용자 요청으로 고쳤다(결정 0009: "기억의 ‘나’ 갈래 항목에 말투 취향으로 남긴다").
