# 0002. 관리 웹 페이지(설정과 연결 상태)

- 날짜: 2026-11-16
- 상태: 확정
- 결정 방식: 사용자가 제안하고, 범위와 노출 범위를 골랐다.

## 결정

- **D8**: MVP에 관리 웹 페이지를 넣는다. 범위는 **설정과 연결 상태**뿐이다.
  - 설정: Discord 봇 토큰 입력, Google OAuth 클라이언트 등록과 동의(연결), 연결 해제.
  - 상태: Discord 연결, Google 토큰 유효성과 마지막 확인, sbx 데몬(kvm GID, 인증), Claude 로그인 만료 예정일과 사용량 창, 오늘·이번 주 비용, 다음 루틴 시각, 최근 알림.
  - 넣지 않는 것: 기억 편집, 작업 관리, 차트, 대화 기록 열람.
- 명세 변경: 명세의 초기 비목표 "대시보드"를 위 범위로 좁혀 앞당긴다. 명세에 원래 있던 "비밀 입력용 내부 웹 폼"(4단계)과 "로그인 폼·관리 API(axum)"를 MVP로 당겨 온 것에 가깝다.
- **노출 범위**: 집 LAN 안에서만 연다. 서버의 LAN 주소와 localhost에만 바인드한다. 밖에서는 사용자가 이미 구성한 WireGuard로 집 LAN에 들어와 접속한다(이 서버에는 WireGuard 인터페이스가 없고, VPN은 다른 장비가 맡는다). 인터넷에 노출하지 않고, Traefik에도 올리지 않는다.
- **Google OAuth**: 클라이언트 종류는 Desktop app, 리디렉션은 루프백(`http://127.0.0.1:<포트>`). 페이지를 LAN 주소로 열면 동의 뒤 브라우저가 사용자 기기의 127.0.0.1로 가서 "연결할 수 없음"이 뜬다. 그 주소창의 URL을 관리 페이지에 붙여 넣으면 데몬이 코드를 꺼내 토큰으로 바꾼다(PKCE 사용). 서버에서 SSH 터널로 열면 붙여넣기 없이 바로 끝난다.

## 지켜야 할 것

- 비밀 값은 넣기만 하고 다시 보여 주지 않는다. 받는 즉시 `systemd-creds --user`로 암호화해 저장하고 메모리에서 버린다. 화면에는 "설정됨, 마지막 갱신 시각"만 보인다.
- 비밀 값은 로그, 원장, 메신저, 모델 맥락 어디에도 남기지 않는다(마스킹 필터 통과).
- 로그인이 있어야 열린다. 세션 쿠키는 `HttpOnly`, `SameSite=Strict`. 상태를 바꾸는 폼에는 CSRF 토큰을 쓴다.
- 처음 로그인할 자격 증명을 만드는 방법(초기 설정)은 구현할 때 정해 이 기록에 덧붙인다.
- LAN 바인드 주소는 설정 파일 값으로 둔다(예: `192.168.0.10`).

## 구현하며 정한 것 (2026-11-16)

- **소유자 한 명**: 허용 사용자는 목록이 아니라 소유자 Discord ID 하나다(명세가 1인용이고, 구독 인증의 전제이기도 하다). 관리 페이지에서 넣으면 DM을 열어 그 대화를 브리핑·알림 대상으로 저장하고 확인 메시지를 보낸다. 값은 저장소(`settings`)에 두고 매 메시지마다 읽으므로 바꾸면 곧바로 반영된다. 비어 있으면 아무도 허용하지 않는다. 사용자 요청: 사용자 ID도 하드코딩하지 않고 관리 페이지에서 넣는다.
- **초기 비밀번호**: 서버 터미널에서 `luciad admin-setup`을 실행하면 일회용 설정 링크가 **그 터미널에만** 찍힌다(로그·저널에 남기지 않는다). 비밀번호가 없을 때만 동작하고 30분 뒤 만료되며, 토큰은 해시로만 저장한다. 비밀번호(12자 이상)는 argon2id 해시로 저장한다. 잊었으면 서버에서 `luciad admin-setup --reset`(서버에 들어올 수 있는 사람만 할 수 있다).
- **로그인 보호**: 같은 주소에서 5번 틀리면 5분 잠근다. 틀릴 때마다 1초 늦게 답한다. 세션은 메모리에만 두고 12시간 뒤 끝난다(데몬을 다시 시작하면 다시 로그인).
- **포트 분리**: 관리 페이지(기본 8780)는 MCP(47810)와 다른 포트이고, 설정 검증이 같은 포트를 거부한다. `luciad check`가 VM에서 관리 페이지 주소로 갈 수 없는지 확인한다.
- **바인드 제한**: 설정 검증이 loopback과 사설 LAN 주소만 허용한다(0.0.0.0, 공인 주소 거부).
- **받아들인 절충**: LAN 안에서는 평문 HTTP다. 집 LAN(밖에서는 WireGuard 터널)을 믿는다는 전제이고, 봇 토큰과 관리 비밀번호가 LAN 위를 평문으로 지나간다. 쿠키에 `Secure`를 붙이지 않는 것도 같은 이유다. 이 전제가 바뀌면(예: 공용 와이파이를 LAN에 붙임) HTTPS를 붙인다.
- **Google 콜백**: Google에서 `http://127.0.0.1:<포트>/`로 넘어오는 이동에는 `SameSite=Strict` 세션 쿠키가 실리지 않는다. 그래서 콜백은 로그인 세션 없이 처리하고, 로그인한 관리자가 시작한 동의의 일회용 state(약 244비트, 10분, 한 번만)가 맞을 때만 코드를 교환한다. LAN 주소로 열었을 때는 브라우저가 사용자 기기의 127.0.0.1로 가므로 주소창의 주소를 붙여 넣는다. CSP `form-action`에 `https://accounts.google.com`을 더했다(폼 제출 뒤 동의 화면으로의 리디렉션도 form-action 검사를 받는다).
- **Google 기준선은 연결할 때 잡는다**(2026-11-16 실사용에서 고침): 처음에는 첫 사전 체크가 기준선이었는데, 연결한 뒤 첫 확인 전에 온 메일이 기준선에 묻혀 감지되지 않았다. 이제 동의를 마치는 순간 두 소스의 기준선을 새로 잡는다(전 기준점은 다른 계정 것일 수 있어 버린다). 상태 카드에 기준선 시각을 보인다.
- **소유자를 바꾸면**: 핵심 기억, 에피소드, 상주 세션은 그대로 남는다(1인용이라 사람이 바뀌는 경우를 상정하지 않는다). 다른 사람에게 넘길 일이 생기면 저장소를 새로 시작한다.
- **알림 기록**: 메신저가 없거나 전송에 실패한 알림도 저장소에 남아 상태 화면에 보인다. 브리핑은 보낼 곳이 없으면 모델을 부르기 전에 멈춘다.

## 화면 정비(2026-11-16, MVP 뒤 첫 완성도 작업, 사용자 요청: "디자인과 사용성 모두를 개선해")

- **화면 넷**: 개요(`/`: 상태 타일, 확인할 것, 사용량, 지금 실행, 최근 활동), 연결(`/connections`: Discord·Google을 상태에 맞는 단계로), 활동(`/activity`: 승인 대기, 활동 기록과 종류 거르개, 메일 발송 기록, 알림), 시스템(`/system`: 점검, 세션·기억 게이지, 백업, 루틴, 사용량). 머리글에 전체 상태(정상·주의·확인 필요)와 승인 대기 수.
- **상태에 맞는 단계**: 처음에는 해야 할 일(토큰, 소유자, 클라이언트 JSON → 동의 → 주소 붙여 넣기)만 보이고, 연결된 뒤에는 상태와 바꾸기(펼침)가 보인다. 어느 상태에서든 고칠 수단에 닿는다(멈춘 Discord에 새 토큰, 연결된 Google의 클라이언트 바꾸기, 동의 중 주소 붙여 넣기).
- **"지금 실행"에 둘을 더했다**: 세션 정리(compact, 결정 0004)와 세션 기록 백업. 넷 모두 옆에 마지막 결과(시각, 성공 여부, 한 줄)를 보인다(설정 `last_run.<동작>`, 정해진 루틴이 돌 때도 남는다). 세션 정리는 실패하면 새 세션으로 넘어간다는 것을 확인 단계에서 알린다.
- **되돌리기 어려운 동작은 두 번 누른다**: 연결 끊기, 토큰 지우기, 소유자 지우기, 세션 정리. 첫 버튼은 펼치기만 하고 펼친 안의 버튼이 보낸다. 펼친 안의 "취소"는 같은 화면을 다시 열어 닫는다(스크립트 없음).
- **처리 결과 안내**: 성공·실패·대기가 색과 아이콘으로 구분되고, 처리한 화면으로 돌아간다. 돌아갈 화면은 정해진 네 곳만 받는다(`back` 값을 그대로 쓰지 않는다).
- **CSP를 좁혔다**: `default-src 'none'; style-src 'self'; img-src 'self'; form-action 'self' https://accounts.google.com; frame-ancestors 'none'; base-uri 'none'`. 스크립트를 쓰지 않고, 인라인 스타일을 없앴다(`style-src 'unsafe-inline'` 삭제). 스타일시트와 아이콘은 `/static/`에서 로그인 없이 준다(비밀 없음). 스타일시트 주소에 내용 해시를 붙여(`?v=`) 바뀌면 캐시를 건너뛴다.
- **그리기와 데이터 분리**: 데이터를 모으는 부분(`admin::gather` → `Snapshot`)과 그리는 부분(`admin::view`, maud)을 나눴다. 상태별 가짜 데이터로 화면을 시험한다(처음 설치, 소유자 없음, Discord 멈춤, 동의 중, 발송 권한 없음, 점검 실패, 승인 대기, 못 보낸 알림).
- **넣지 않은 것([제안])**: 핵심 기억 내용 보기·고치기, 웹에서 메일 발송 승인. 둘 다 이 결정(설정과 상태만)과 결정 0003(승인은 Discord 카드) 밖이다.

## 결과

- 사용자 준비 절차가 줄어든다: Discord 토큰과 Google 클라이언트 JSON을 터미널 명령 대신 관리 페이지에 넣는다. 터미널 절차(`docs/PLAN.md` §4)는 페이지가 동작하지 않을 때의 대안으로 남긴다.
- MVP 3번 조각(Discord, Google)에 관리 페이지를 함께 만든다.

## 후속(2026-11-18)

화면 짜임, 마크업, 스타일, 접근성은 결정 0041에서 전면 개편했다(위 "화면 넷"은 홈·할 일·자동화·활동·기억·스킬·캐릭터·연결·브라우저·설정·시스템으로 나뉘었다). 이 문서의 보안 결정(로그인, CSRF, 바인드, 비밀 값 처리)은 그대로다. **CSP는 결정 0042에서 해제했다**("CSP를 좁혔다" 항목과 `form-action` 예외는 더 이상 적용되지 않는다).

## 후속(2026-11-19)

**노출 범위는 결정 0043에서 넓혔다.** 설정 `[public] admin_url`과 믿는 프록시를 정하면 리버스 프록시(Traefik) 뒤에서 밖에서도 열 수 있다. 그때 외부 로그인에는 2단계 인증(TOTP)이 필요하고, 외부 쿠키에는 `Secure`, 응답에는 HSTS가 붙는다. 설정이 비어 있으면 위 "노출 범위" 그대로다.
