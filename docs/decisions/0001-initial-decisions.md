## 결과

- D7에 따라 3단계에서 외부 쓰기 MCP 도구를 설계한다. PoC P2·P6에서 bypass 상태의 훅과 permission-prompt-tool 동작을 확인한 결과가 D7의 전제와 다르면 이 기록을 다시 연다.

## P2 이후 재검토 (2026-11-16)

- 전제 하나가 바뀌었다: bypass는 피할 수 없는 것이 아니었다. 데몬이 `sbx exec`로 실행 조합을 정하면 bypass를 켜지 않을 수 있고(`--restricted`는 아예 거부한다), bypass 상태에서도 PreToolUse 훅의 거부는 지켜졌다.
- 그래도 **D7은 유지한다. 이유는 더 강해졌다.** VM 사용자는 비밀번호 없는 sudo가 있고 Claude Code 설정과 실행 파일을 소유하므로, 훅·권한 모드 같은 VM 안 통제는 그 실행 하나에만 보장된다. 실행이 바뀌어도 유지되는 경계는 호스트 쪽(네트워크 정책, 프록시, 읽기 전용 마운트, 데몬 MCP의 승인 확인)뿐이다. 외부 쓰기는 호스트 경계에서 막아야 한다. 근거: `poc/RESULTS.md` P2.
- permission-prompt-tool은 VM 안 행동의 승인 경로로 유지하되, 강제 수단이 아니라 사용자 경험(무엇을 하려는지 묻기)으로 본다. 동작은 P6에서 확인한다.
