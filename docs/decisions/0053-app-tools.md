# 0053. 앱이 내준 기능을 Lucia가 부른다

- 날짜: 2026-11-20
- 상태: 확정. 한도(기능 32개, 설명 200자, 인자 설명 2 KB, 답 40초, 결과 8 KB)는 [제안].
- 결정 방식: 사용자 지시("앱 개선 중 앱 기능 호출 도구 … 개선해").
- 관련 결정: 0043(앱 연동: `invoke` 통로와 `hello.features`를 만들어 두었다), 0013(도구 선언과 허락)
- 앱 쪽 설명: `docs/app-api.md` 3.4, 5.2, 5.3, 7장

## 배경

- 결정 0043은 데몬이 앱에 일을 부탁하는 통로(`invoke`)만 만들고, 부르는 쪽은 만들지 않았다. 앱은 기능의 첫 마디(`location`)만 알렸기 때문에 Lucia는 메서드 이름도 인자도 알 수 없었다.

## 결정

- **앱이 정한다.** 앱이 `hello.tools`로 내줄 기능을 알린다: 이름(`기능.동작`), 설명, 인자 설명, 읽기인지 쓰기인지. 데몬에는 미리 정해 둔 기능 목록이 없다. 새 기능은 앱만 고치면 된다(전용 앱에서만 가능한 연동을 넓히는 자리).
- **Lucia의 도구 둘**(찾기 뒤에 있고, 대화 지침이 이름을 말한다):
  - `app_tools`: 지금 쓸 수 있는 기능 목록(이름, 설명, 인자, 어느 앱).
  - `app_call`: 기능 하나를 부른다. 그 기능을 내준 연결된 앱에 `invoke`로 부탁하고 답을 기다린다(40초).
- **사용자 허락은 범위로**: 앱 토큰에 범위 `app_tools`가 있어야 그 앱의 기능이 Lucia에게 보이고 불린다. 관리 페이지 "연결"에서 켠다(발급할 때와 그 뒤 모두). 기본은 꺼져 있다. 휴대폰의 위치나 알림을 읽는 일이라 사용자가 한 번은 켜야 한다고 보았다.
- **읽기와 쓰기**: 읽기 기능은 앱 기능 갈래가 열린 실행(대화, 작업, 브리핑·후속 조치)에서 부른다. `effect: "write"`인 기능은 사람이 대화 중인 실행에서만 부른다. 스크립트 다리로는 부르지 못한다.
  - 쓰기 표시는 앱이 한다. 앱은 사용자가 토큰을 준 자기 앱이고, 휴대폰 권한과 사용자 확인도 앱이 맡는다. 데몬은 그 위에 범위와 "사람이 있는가"를 더 본다.
- **연결돼 있을 때만**: 앱이 끊겨 있으면 부르지 못하고 그렇게 답한다. 푸시로 깨워 부르지는 않는다.
- 앱 기능의 결과(위치, 알림 등)는 사용자의 비공개 자료로 친다: 사람 없는 실행이 바깥으로 내보내려 할 때의 대조 자료(결정 0029)에 넣는다.
- 이름·설명과 결과는 앱이 준 글이다. Lucia에게는 외부 데이터로 싸서 준다. 부른 일은 활동 기록에 남는다(`app_call`).
- 새 갈래 `App`을 두었다. 기능 보존 기준 목록은 범위 체크 상자 둘이 더해졌다(추가 2줄, 삭제 없음).

## 하지 않은 것

- 푸시로 앱을 깨워서 부르기.
- 쓰기 기능의 승인 카드(지금은 "사람이 대화 중일 때만"으로 본다).
- 내준 기능을 대화 요청에 미리 싣기. Lucia가 필요할 때 `app_tools`로 본다.
- 외부 기기(`device` 역할)의 명령. 같은 모양(선언 → 등급 → 부르기)으로 뒤에 붙일 수 있다.

## 확인(2026-11-20)

- **시험**(실제 WebSocket): `hello.tools` 정리(잘못된 이름·겹친 이름 버리기, 설명 한 줄, 큰 인자 설명 버리기), `welcome.tools`와 `features`, 범위가 없으면 보이지도 불리지도 않기, 부르기 왕복(`invoke` → `result`), 쓰기 기능은 사람 없으면 거절, 앱이 거절한 까닭 전달, 다른 앱 짚기, 끊기면 사라지기. 도구의 허락과 안내, 활동 기록.
- 실제 앱으로는 아직 보지 않았다. 앱이 `hello.tools`를 보내고 사용자가 범위를 켜야 한다.
