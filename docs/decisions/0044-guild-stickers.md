# 0044. 서버 스티커: 대화 중인 Discord 서버의 스티커를 어울릴 때만 쓰기

- 날짜: 2026-11-19
- 상태: 확정. 간격·지침 문구는 [제안].
- 결정 방식: 사용자 질문과 지시를 따랐다.
  - 질문: "대화중인 서버에 등록되어 있는 스티커를 상황에 따라 유연하게 쓸 수 있도록 설계할 수 있나? 캐싱을 유지하면서."
  - 지시: "이대로 설계하고 구현 진행해. 그림 기반 설명은 빼고. 스티커를 너무 자주 사용하지 않도록 적절히 프롬프트를 조정하는 게 중요해."

## 사실 확인(Discord 공식 문서)

- Create Message의 `sticker_ids`: "IDs of up to 3 stickers in the server to send in the message". 스티커만 있는 메시지도 된다.
- 스티커 종류는 공식 팩(`STANDARD`)과 서버(`GUILD`)뿐이다. 앱 소유 스티커는 없다. 앱 소유 이모지는 있다(2000개).
- 문서에 없는 것: DM에서 서버 스티커를 쓸 수 있는지, 다른 서버의 스티커를 쓸 수 있는지, 보낼 때 필요한 권한. 그래서 **부른 그 서버의 스티커만, 그 서버 채널에서만** 쓴다.

## 결정

### 캐시를 깨지 않는 자리

- 상주 세션은 DM·서버·앱이 함께 쓴다. 캐시되는 앞부분(시스템 프롬프트, 도구 목록, 앞선 턴)에는 서버마다 다른 것을 넣지 않는다.
- 스티커 목록은 **서버에서 부른 그 턴의 요청**(`<place>` 뒤의 `<stickers>`)에만 싣는다. 서버를 오가도 앞부분은 그대로다.
- 같은 상주 세션에 같은 서버의 같은 목록을 이미 실었으면 다시 싣지 않는다. 대신 "앞에서 준 그대로"라는 한 줄과 지침만 싣는다.
  - 턴 요청은 세션 기록에 남아 맥락 창을 차지하기 때문이다.
  - 목록이 바뀌었거나(지문 비교), 세션이 바뀌었거나, 압축됐으면 다시 싣는다.
- 목록은 `GET /guilds/{id}/stickers`로 읽어 서버별로 10분 둔다. 읽지 못하면 빈 목록으로 2분 쉰다.
  - `available: false`(부스트가 빠져 잠긴 것)는 뺀다. 이 필드는 선택이라, 없으면 쓸 수 있는 것으로 본다.
- 모델은 그림을 보지 않는다. 이름·설명·태그만 준다(그림 기반 설명은 하지 않는다).
  - 이 글은 서버 사람이 쓴 외부 데이터다. 이스케이프하고, 이름 40자·설명 100자·태그 60자로 자른다.

### 아껴 쓰기(사용자 지시: 너무 자주 쓰지 않게)

- **지침**(매 서버 턴에 짧게 싣는다):
  - 대부분의 답에는 붙이지 않는다.
  - 가벼운 대화에서 감정 표현(축하, 고마움, 맞장구, 농담 받아치기)이 말보다 잘 어울리고, 이름·설명이 그 순간에 분명히 맞을 때만 쓴다.
  - 정보·설명·일 처리·진지한 이야기·사과·나쁜 소식·질문에 답할 때는 쓰지 않는다.
  - 최근 답에서 썼거나 조금이라도 망설여지면 쓰지 않는다. 목록에 없는 이름은 쓰지 않는다.
- **데몬의 막기**:
  - 답 하나에 하나까지만 보낸다(첫 표기만).
  - 한 채널에서 스티커 사이는 30분을 둔다 [제안]. 간격 안이면 목록 대신 "N분 전에 스티커를 보냈다. 이번 답에는 쓰지 않는다"만 싣는다. 그래도 표기를 쓰면 글에서 지우고 보내지 않는다.
- 기록(에피소드)에는 표기가 남는다. 다음 턴의 Lucia가 최근에 쓴 것을 알게 하려는 것이다.
- 말투에 맞춰 더 줄이거나 늘리는 것은 사용자가 캐릭터 파일에서 정한다.

### 표기와 보내기

- 모델은 답의 끝 줄에 `[스티커:이름]`을 쓴다.
- 데몬(`Engine::send`)은 보내는 모든 글에서 표기를 지운다. 표기만 있던 조각은 보내지 않는다.
- 글을 다 보낸 뒤, 그 서버 목록에서 이름을 찾아(대소문자·앞뒤 공백 무시) 스티커 메시지를 따로 보낸다.
  - 채널 인터페이스에 `send_sticker`를 더했다. Discord는 `sticker_ids`로 보낸다.
  - 앱과 메모리 채널 말고 다른 채널은 지원하지 않는다고 답한다.
  - 실패해도 답에는 영향이 없고 로그만 남긴다.
- DM과 앱 대화에는 목록을 싣지 않는다. 표기를 써도 지우기만 한다.

## 하지 않은 것

- 그림을 보고 설명 만들기(사용자 지시로 뺐다).
- 앱 전용 이모지·스티커, Discord 앱 이모지. 앱에서 쓸 커스텀 이모지·스티커는 따로 설계한다.

## 확인(2026-11-19)

- **시험**:
  - 목록 읽기: 잠긴 것은 빼고, `available`이 없으면 쓸 수 있다고 본다.
  - 캐시, 실패 쉬기, 세션마다 한 번 싣기, 압축 뒤 다시 싣기, 채널 간격, 이름 찾기, 이스케이프, 표기 고르기·지우기.
  - 엔진:
    - 서버 턴에 목록과 지침이 실린다. 글에서는 표기가 빠지고 스티커가 따로 간다. 기록에는 표기가 남는다.
    - 간격 안이면 "쓰지 않는다"가 실리고, 표기를 써도 보내지 않는다.
    - 같은 세션의 다음 턴은 가리키기만 한다.
    - DM에는 목록이 없고, 표기는 지운다.
- **실제로 아직 안 본 것**: 실제 서버에서 스티커 보내기(권한), 실제 모델이 얼마나 자주 쓰는지.

## 후속(2026-11-19, 결정 0045)

- 앱 대화에는 이제 앱 목록의 이모지·스티커를 싣는다(결정 0045). 위의 "앱 대화에는 목록을 싣지 않는다"는 서버 스티커 목록에 한한 말이다.
- 스티커 보내기는 대화로 갈린다. 앱 대화는 앱 목록의 스티커를 `sticker` 프레임으로, 서버 대화는 이 결정대로 그 서버의 스티커를 보낸다. 아껴 쓰기 지침 문구는 둘이 같이 쓴다.
