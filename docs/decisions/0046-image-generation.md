# 0046. 이미지 생성: OpenAI GPT Image 2.5(Flare·Sunburst)로 그림 만들기

- 날짜: 2026-11-19
- 상태: 확정. 하루 예산 기본값($1), 품질 선택지, 사용량이 없을 때 잡는 값($0.25)은 [제안].
- 결정 방식: 사용자 지시를 따랐다.
  - "이미지 생성 기능 구현을 추가해. OpenAI API를 통해 Image 2.5-sunburst와 flare 모델을 상황에 따라 선택하여 사용할 수 있도록 하고."
- 관련 결정: 0005(파일 주고받기), 0013·0022(도구 선언과 찾기), 0025(스크립트 다리), 0045(앱 이모지·스티커)

## 사실 확인(2026-11-19, OpenAI 공식 문서)

읽은 곳: 모델 문서 두 쪽(`developers.openai.com/api/docs/models/gpt-image-2.5-flare`, `…/gpt-image-2.5-sunburst`), 이미지 생성 안내(`…/api/docs/guides/image-generation`), API 참조(`…/api/reference/resources/images/methods/generate`, `…/edit`).

- 모델 ID는 `gpt-image-2.5-flare`와 `gpt-image-2.5-sunburst`다. 날짜가 붙은 판(`-2026-09-08`)도 있다. 접미사 없는 `gpt-image-2.5`가 어디로 가는지는 공식 문서에 없어 쓰지 않는다.
- 차이(문서 문장): Flare는 "fastest model for high-quality, everyday image generation", Sunburst는 "most capable model for image generation and editing"이고 "editing precision matters most"일 때 쓴다. 지연 시간 숫자는 없다.
- 요율은 둘이 같다(100만 토큰당 글 입력 $5, 그림 입력 $8, 출력 $30). 장당 가격표는 없고, 응답의 `usage`로 센다.
- 생성: `POST https://api.openai.com/v1/images/generations`, JSON. 응답은 늘 `data[].b64_json`이다(`response_format`·`style`은 이 모델에서 지원하지 않는다).
- "하나의 프롬프트로 한 장"이면 Image API를 쓰라고 한다(Responses API의 도구가 아니라).
- 복잡한 프롬프트는 2분까지 걸릴 수 있다. 조직 인증이 필요할 수 있다. 안전 검사에 걸리면 `error.code = "moderation_blocked"`다(이 셋은 안내 문서 뒷부분의 요약으로 읽었다. 그래서 오류 처리는 이 값이 없어도 돌게 했다).
- 편집(`/v1/images/edits`): 참조는 JSON(`images[].image_url`)이라 하고 예시는 multipart를 쓴다. 문서가 엇갈리고 확인할 키가 없어 이번에는 만들지 않았다.

## 결정

### 모델을 상황에 따라 고르기

- 고르는 것은 Lucia다. 도구 `image_generate`의 `model` 인자로 요청마다 고른다.
  - `flare`(기본): 가장 빠르고 일상적인 그림.
  - `sunburst`: 가장 정밀. 세밀한 묘사, 그림 속 글자, 정확한 배치처럼 정밀함이 중요하거나 사용자가 가장 좋은 결과를 원할 때.
- 기준은 도구 설명에 문서의 말만 옮겼다. 값 차이가 있다고 하지 않는다(요율이 같다). 캐릭터 파일에는 넣지 않았다.
- 모르는 값(`dall-e`, `max` 등)은 조용히 기본값으로 바꾸지 않고 돌려보낸다. 돈이 드는 선택이기 때문이다.
- 다른 인자: 크기는 정사각형·가로·세로 셋(문서의 고정 값), 품질은 `low`·`medium`(기본)·`high`. `auto`·`xhigh`·`max`는 열지 않았다(비용을 예측하기 어렵다). 투명 배경은 PNG로, 그 밖에는 JPEG(압축 90)로 받는다. 한 번에 한 장.

### 작업으로 돈다

- MCP 요청은 60초쯤에 끊기고 생성은 2분까지 걸릴 수 있다. 그래서 요청은 데몬 작업이 맡고 도구는 45초만 기다린다.
  - 그 안에 끝나면 그림과 파일 ID를 돌려준다. 아니면 작업 ID를 돌려주고, `image_result`로 다시 기다린다.
  - 아무도 기다리지 않아도 결과는 파일과 기록으로 남긴다(돈은 이미 썼다).
  - 시간 초과를 데몬이 스스로 다시 보내지 않는다. Lucia에게도 같은 요청을 되풀이하지 말라고 한다.
  - 한 번에 하나만 만든다. 만드는 중이면 새 요청을 받지 않고 그 작업 ID를 알려 준다.
- 끝난 그림은 주고받는 파일(`files/out`, 결정 0005)에 둔다. 답에 붙이려면 다른 파일처럼 `report_result`의 `attachments`에 ID를 넣는다.
- 도구는 만든 그림을 Lucia에게도 보여 준다. 보지 않은 그림을 설명하지 않게 하려는 것이다.
  - 400 KB까지만 보여 준다 [제안]. 도구 답으로 실제 지나가 본 가장 큰 그림(브라우저 스크린샷 약 408 KB)에 맞춘 값이다. 더 큰 답이 거절되면 돈을 쓴 뒤에 오류로 보여 Lucia가 다시 만들 수 있다.
  - 넘으면 파일만 남기고 "직접 보지 못했다"고 알린다. 실제 생성 결과의 크기를 본 뒤 올린다.
- 데몬이 다시 뜨면 끝을 보지 못한 요청은 실패로 닫는다.

### 돈

- 실제 과금이다. Claude 실행의 하루·주 상한(추정 비용)과 섞지 않고, **이미지 하루 예산**을 따로 둔다. 기본 $1, 관리 페이지에서 바꾼다. 0이면 만들지 않는다.
- 비용은 응답의 `usage`에 문서의 요율을 곱해 요청마다 남긴다(표 `generated_images`, 마이그레이션 0026). 오늘 쓴 돈이 예산에 닿으면 그날은 더 보내지 않는다.
  - 보내기 전에는 한 장의 값을 모른다. 그래서 예산은 한 장만큼 넘을 수 있다(한 번에 하나만 만들므로 그 이상은 아니다).
  - 성공인데 `usage`가 없거나 시간 초과로 결과를 못 받았으면 $0.25를 잡는다. 예산이 뚫리지 않게 하려는 것이다.

### 누가 부르나

- 새 갈래 `Images`를 만들어 **사람이 시작한 대화와 맡긴 작업**에만 열었다. 브리핑·후속 조치·목표 점검·루틴 같은 사람 없는 실행과 스크립트 다리는 부르지 못한다.
  - 이모지·스티커 도구가 있는 "파일" 갈래는 사람 없는 실행에도 열려 있어 쓰지 않았다.
- 도구 설명에 "사용자가 그림을 만들어 달라고 했을 때만"이라고 적었다.
- 두 도구(`image_generate`, `image_result`)는 **늘 바로 보이는 도구**로 두었다.
  - 처음에는 `tool_search` 뒤에 두었다. 실제 모델(개발 설정)에 "노을 지는 바다 그림 한 장 그려줘"라고 하니 도구를 찾지 않고 "이미지는 만들 수 없다"며 SVG 파일을 만들었다.
  - 바로 보이게 올리고 `file_create` 설명에 "그림은 image_generate로"를 더했다. 그 뒤 같은 세션에서 "이번엔 진짜 이미지로, … 그려줘"라고 하니 도구를 불렀다. 앞선 답이 없는 새 대화에서 평범한 부탁만으로 도구에 닿는지는 아직 보지 않았다.

### 키와 밖으로 나가는 것

- OpenAI API 키는 관리 페이지 "연결"의 "이미지 생성"에서 넣는다. systemd-creds로 암호화해 두고(`openai-api-key`) 다시 보이지 않는다. 호스트만 가진다.
- 키가 없으면 도구가 "관리 페이지에 넣어 달라고 하라, 대화로 받지 말라"고 답한다.
- 프롬프트는 OpenAI로 나간다. 보내기 전에 마스킹을 거치고, 도구 설명에 사용자의 비밀·개인 정보를 넣지 말라고 적었다. `user`·`safety_identifier`는 보내지 않는다.
- 실패는 사람에게 전할 말로 바꾼다(키 오류, 조직 인증, 잔액·한도, 안전 검사, 서버 오류). API가 준 글은 200자까지만 덧붙인다.

### 관리 페이지

- "연결" 화면에 "이미지 생성" 패널: 키 넣기·지우기, 하루 예산, 오늘 쓴 돈, 최근 요청 5개(모델, 품질, 크기, 비용, 실패 까닭).
- 기능 보존 기준 목록은 지워진 줄 없이 17줄이 더해졌다.

## 하지 않은 것

- **편집**(사진을 받아 고치기, 참고 그림 넣기). 문서가 엇갈려 확인이 필요하다. Sunburst의 강점이 편집이라, 키가 생기면 다음에 할 만하다.
- **만든 그림을 이모지·스티커로 등록하기.** 생성은 1024px부터인데 이모지는 256px, 스티커는 640px까지다(결정 0045는 그림을 고치지 않는다). 줄이는 기능이 있어야 이어진다.
- 여러 장 한 번에, 임의 해상도, GIF·SVG 출력, 부분 미리보기(스트리밍).
- 키가 맞는지 저장할 때 확인하기. 처음 만들 때 드러난다.

## 확인(2026-11-19)

- **시험**(모델과 OpenAI를 부르지 않는다. 가짜 OpenAI 서버를 띄운다):
  - 고른 모델·크기·품질이 문서의 값 그대로 나가는지, 지원하지 않는 칸을 보내지 않는지, 키가 Bearer로 가는지.
  - 느린 작업: 기다리는 시간 안에 안 끝나면 "아직", 그 사이 새 요청 거절, 다시 기다리면 받기, 요청은 한 번만.
  - 아무도 기다리지 않아도 파일·비용이 남는지. `usage`로 비용 계산.
  - 키 없음, 빈 프롬프트, 예산(다 씀·0·올림), 오류 응답별 안내, 다시 뜬 데몬의 정리.
  - 도구: 대화·작업에서만 열림(사람 없는 실행·스크립트는 닫힘), 모르는 값 거절, 그림과 파일 ID 돌려주기.
  - 관리 페이지: 키 저장·지우기(값이 화면에 나오지 않음), 예산, 최근 요청, CSRF, 기능 보존·접근성.
- **실제 모델**(개발 설정, 키 없음): 도구를 바로 보이게 한 뒤 "이번엔 진짜 이미지로, … 그려줘"에 `image_generate`를 불렀고, 키가 없다는 답을 받아 "관리 페이지 '연결'의 '이미지 생성'에 넣어 달라, 대화로 보내지 말라"고 전했다(SVG로 답한 바로 뒤의 같은 세션이다).
- **주소와 오류 모양**: 실제 주소에 지어낸 키로 한 번 보냈다. 401과 `{"error": {"message", "type", "code": "invalid_api_key"}}`가 왔다. 경로와 오류 읽기는 맞다. 모델 ID와 인자가 받아들여지는지는 이것으로 알 수 없다.
- **보지 못한 것**: 실제 OpenAI 호출. 이 호스트에 키가 없다. 요청 모양·응답 읽기·비용 계산·오류 코드는 문서대로 만들었고, 첫 실제 생성에서 확인해야 한다.

## 후속(2026-11-19): 편집을 넣었다

- 사용자 지시: "편집도 넣어."
- **요청 모양을 정했다.** 공식 안내의 2.5 예시(`-F "model=gpt-image-2.5-sunburst"`, `-F "image[]=@…"`)와 공식 Python SDK(`images.edit`가 늘 `multipart/form-data`로 `/images/edits`에 보낸다)가 같은 모양이다. 참조 문서의 JSON 모양(`images[].image_url`)은 주소나 올려 둔 파일 ID를 가리킬 때의 것이다. 그래서 multipart에 그림을 `image[]`로 싣는다.
- **쓰는 법**: `image_generate`의 `images`에 파일 ID를 넣으면 편집이다(4장까지 [제안], PNG·JPEG·WebP, 한 장 10 MB까지). 사용자가 붙인 그림이나 앞서 만든 그림이다.
- **기본값**: 고르지 않으면 편집은 `sunburst`(편집 API의 기본값이고, 문서가 편집 정밀도에 권하는 모델), 크기는 `auto`(모델이 정한다). 새로 그릴 때의 기본값(flare, 정사각형)은 그대로다.
- `input_fidelity`는 보내지 않는다(2.5 모델에 대한 설명이 없다). 마스크와 마크업은 넣지 않았다.
- 넣은 그림은 그대로 OpenAI로 나간다(사진의 메타데이터도). 도구 설명에 "사용자가 맡긴 그림만"이라고 적었다.
- 비용은 같은 식으로 센다(그림 입력 토큰 $8 / 100만). 기록에 넣은 그림 수를 남긴다(마이그레이션 0027).
- 크기만 줄이거나 형식을 바꾸는 일은 이 도구가 아니라 `code_run`(Pillow)으로 한다(결정 0047). 돈이 들지 않는다.
- **만든 그림을 이모지·스티커로 등록하기**도 결정 0047로 이어졌다(스크립트로 줄인 뒤 등록).
- 확인: 가짜 서버로 칸 이름(`image[]`), 모델 ID, 기본값, 보내지 않는 칸, 비용, 거절(없는 파일, 형식, 장수)을 시험했다. **실제 OpenAI로는 생성도 편집도 아직 보지 못했다**(키가 없다).

## 후속(2026-11-19): Lucia가 보는 그림의 크기를 3.5 MB로 올렸다

- 사용자 질문: "루시아가 생성된 이미지를 여전히 볼 수 없나?"
- 400 KB는 "지나가 본 것만 믿는다"로 잡은 값이었다. 실제로 재 보았다(개발 설정, 실제 모델): 1024×1024 PNG 두 장(2.2 MB, 3.1 MB)을 `image_result`의 답으로 돌려주자 Lucia가 도형과 색을 맞게 말했다.
- 그래서 상한을 올렸다. 처음에는 3.5 MB로 잡았고, 결정 0048에서 실제로 본 크기에 맞춰 3 MB(3 MiB)로 정리했다. base64로 약 4.2 MB라 API의 그림 하나 한도(5 MB) 아래다. 이보다 큰 결과(드물다)는 여전히 파일만 남기고 "직접 보지 못했다"고 알린다.
- 실제 OpenAI가 준 그림으로는 아직 보지 못했다(키가 없다). 형식이 PNG·JPEG인 점은 같다.

## 후속(2026-11-20): 실제 생성을 운영에서 확인했다

- 사용자가 키를 넣은 뒤 운영에서 5장이 만들어졌다(2026-11-19 21:50~22:22, Flare 2장·Sunburst 3장, 모두 medium).
  - 한 장에 16~19초, 비용은 `usage`로 계산해 약 $0.011~0.012(출력 343토큰), 결과는 290~410 KB의 JPEG였다.
  - 요청 모양, 응답 읽기, 비용 계산이 실제로 맞았다. 위의 "실제 OpenAI 호출을 보지 못했다"는 생성에 대해서는 더 이상 맞지 않는다.
- **편집은 아직 실제 호출이 없다**(모든 기록의 넣은 그림 수가 0이다).
