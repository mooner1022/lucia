# 0041. 관리 페이지 전면 개편: 화면 짜임, 접근성, 기능 보존 시험

- 날짜: 2026-11-18
- 상태: 확정. 화면 짜임(메뉴 묶음과 화면 나누기), 루틴·감시 지우기의 확인 단계, 기억 찾기는 사용자가 정하지 않은 설계라 [제안]이다(바꾸려면 알려 달라). **화면 구현과 디자인은 결정 0061로 바뀌었다**(정적 Svelte). 화면 짜임(메뉴 묶음, 화면 나누기)과 기능 보존의 기준 목록은 그대로이고, 아래의 마크업·스타일시트·`view/parity.rs`·`view/a11y.rs` 이야기는 그때의 기록이다(시험은 `web/admin/tests`로 옮겨 갔다).
- 결정 방식: 사용자 지시 "대시보드가 POC 수준에서 기능이 계속 쌓이며 복잡하고 지저분해졌어. 디자인과 사용성, 기능성, 접근성 등을 완전히 개편해." 이어서 "이 때 어느 곳에서도 기존에 있던 기능이 없어져선 안돼. 추가로 기능이 추가되거나 기능성이 개선되는 것은 괜찮으나, 현재 사용 가능한 기능이 없어져선 안돼."
- 바뀌지 않은 것: 라우트와 쓰기 동작(모든 POST), 로그인·CSRF·세션, 보안 헤더. **CSP는 이 결정 때는 그대로였다**(스크립트·인라인 스타일 없음, 결정 0002). 같은 날 사용자 지시로 해제했다(결정 0042). 화면 짜임, 마크업, 스타일시트, 안내 글이 바뀌었다.

## 왜

- 시스템 화면 한 곳에 설정 카드 열 몇 개와 상태 화면이 섞였고(점검, 한도, 신호, 위임, 루틴, 감시, 개발, 브라우저, 백업…), 개요에도 관리 카드(목표·작업·후속 조치)가 쌓였다. 찾기 어렵고, 보는 화면과 고치는 화면이 구분되지 않았다.
- 카드마다 긴 설명 문단이 붙어 화면이 글로 가득했다.
- 입력 일부에 라벨이 없었고, 흐린 글 색이 AA 대비를 못 맞췄고, 건너뛰기 링크·제목 단계·표 머리 칸·초점 표시가 고르지 않았다.

## 화면 짜임(메뉴 묶음)

| 묶음 | 화면(경로) | 담은 것 |
|---|---|---|
| (맨 위) | 홈 `/` | 확인할 것, 상태 타일, 승인 대기, 곧 올 일, 최근 활동, 권한 모드 고르기, 지금 실행, 사용량 |
| 일 | 할 일 `/work` | 목표(지금 점검·완료·포기), 챙기는 마감, 작업(취소), 약속한 후속 조치(취소·브라우저 허용) |
| | 자동화 `/automation` | 반복 루틴(지금 실행·멈추기·켜기·지우기), 페이지 감시(멈추기·켜기·고치기·지우기, 알림 상한) |
| | 활동 `/activity` | 승인 대기, 활동 기록(종류 거르개), 메일 발송 기록, 알림, 최근 신호 |
| Lucia | 기억 `/memory` | 항목 목록·세부·변경 기록·되돌리기·지우기, "기억해 둘 것 말하기", **찾기(`?q=`, 새 기능)** |
| | 스킬 `/skills` | 목록, 본문·개정, 승인·고정·끄기·되살리기 |
| | 캐릭터 `/character` | 파일 편집·변경 기록·되돌리기, 지금 정리해 적용, 메시지 간격 |
| 연결 | 연결 `/connections` | Discord, Discord 서버(부르기·머리말), Google, 앱·기기 토큰 |
| | 브라우저 `/browser` | 상태·화면 넘겨받기(`/browser/handover`), 저장된 로그인, 사이트 위임, 막는 곳 |
| 관리 | 설정 `/settings`(안전과 한도) · `/settings/notify`(알림) · `/settings/work`(작업과 보관) | 권한 모드와 모드별 차이, 출구 검사, 일정 중 조용히, 자동 실행 한도 / 새 메일·일정 알림, 알림 규칙 / 하루 정리 보관, 작업 스레드, 개발 위임 |
| | 시스템 `/system` | 실행 환경 점검, 세션과 기억, 백업, 정기 루틴, 사용량 |

- 옛 주소(`/connections`, `/activity`, `/system`, `/memory`, `/skills`, `/character`, `/browser/handover`, `/site-login/…`)는 그대로 열린다. 옮겨 간 것: 개요의 목표·마감·작업·후속 조치 → `할 일`, 시스템의 루틴·감시 → `자동화`, 시스템의 브라우저·사이트 위임 → `브라우저`, 시스템의 한도·알림·위임 설정 → `설정`, 신호의 "최근 신호" → `활동`.
- 처리 뒤 돌아가는 곳(`Redirect`, `back`)은 그 폼이 있는 화면이다. `back` 값은 `Page::ALL`의 경로만 받는다(결정 0002 그대로).
- 좁은 화면에서는 사이드바가 상단 막대의 "메뉴"(`details`)로 바뀐다. 같은 메뉴를 두 번 그리고 한쪽만 보인다(`display: none`이라 보조 기술에도 한쪽만 나간다).

## 쓰는 방식

- **한 줄 요약은 보이고, 긴 설명은 "자세히"(`details.about`)에 둔다.** 설명 글은 짧게 줄이고 자세한 것은 접어 두었다(일부 문장은 줄였다).
- **되돌리기 어려운 동작**은 `details.confirm`의 두 번 누르기다. 이제 첫 버튼을 다시 누르면 접힌다(예전엔 "취소"가 화면을 다시 불러왔다). 루틴·감시 지우기도 두 번 누르게 했다(예전엔 한 번).
- 입력마다 `label for` + `id`, 도움말은 `aria-describedby`, 상태는 아이콘·글을 함께(점은 장식). 건너뛰기 링크, 이름 있는 메뉴, `aria-current`, 처리 결과 안내(`role=status|alert`), 3px 초점 고리, 터치 화면에서 44px 단추, `prefers-reduced-motion`·`forced-colors`·인쇄.
- 색 토큰은 밝은·어두운 판 모두 WCAG AA(글 4.5:1, 입력 경계·초점 3:1)다. 흐린 글(`--text-3`)을 `#8a8a92`(3.4:1)에서 `#666670`(5.7:1)로 올렸다.
- `<meta http-equiv="refresh">`(화면 넘겨받기)는 이제 `<head>`에 있다. 넘겨받기 이미지는 줄이지 않는다(누른 좌표). 넘겨받기 화면은 원격 화면이 1365px 넓이라 사이드바를 접고 본문을 가득 쓴다.
- 글꼴 목록에 `Pretendard Variable`을 더했다(외부 글꼴은 여전히 받지 않는다).

## 기능 보존 시험(`admin/view/parity.rs`, 이 결정의 핵심 장치)

화면을 다시 고칠 때도 쓸 수 있는 안전망이다.

- **모든 목록이 채워진 시험 데이터**(`full`, 분기를 바꾼 `alt`, 해제 모드)로 모든 화면(하위 화면, 단독 화면 포함)을 그린다. 필드마다 `qz-…` 표지를 심었다.
- 개편 전 화면에서 뽑은 **기준 목록**(`view/parity_baseline.txt`, 542줄)이 지금 화면에 모두 있어야 통과한다: 폼(주소·방식), 입력(이름·종류·`min`/`max`/`maxlength`/`required`/`inputmode`…), 고르기 값, 숨은 값, 링크, 자동 새로 고침, **보이던 데이터 표지 218개**(읽기 정보도 기능이다).
- 라우터(`mod.rs`)의 모든 POST 경로(동사별로 풀어서)가 어떤 화면의 폼으로 닿는지 소스에서 읽어 본다. 라우트를 더하고 화면에 폼을 안 두면 실패한다.
- 기준 목록을 다시 만드는 것은 **의도한 제거일 때만** 한다: `LUCIA_PARITY_OUT=<파일> cargo test -p luciad write_parity_baseline -- --ignored`. 이유를 이 문서에 적는다.
- **지키지 못하는 것**: 문자열 데이터만 본다. 시각·개수·상태 글(예: `time()`의 마우스 올림 시각)과, 폼이 상태마다(예: 승인 대기일 때만 보이는 버튼) 닿는지는 시험 데이터가 그 상태를 그릴 때만 본다.
- 접근성 시험(`view/a11y.rs`): 화면마다 h1·main 하나, 건너뛰기 링크, 이름 있는 nav, 제목 단계, id 유일·참조 해결, 모든 입력의 라벨, 글 있는 단추·링크·summary, 표 `scope`, 점의 `aria-hidden`, 색 토큰 대비(CSS를 읽어 계산).

## 더한 것(기능 개선)

- 기억 찾기(`GET /memory?q=`, 서버에서 거름), 활동의 "최근 신호"와 일일 사용 횟수, 목표의 "왜"·관심 신호, 백업의 저장된 위치 줄, 확인 단계 접기, 화면 안 건너뛰기 링크(구역 수 표시).
- 루틴·감시 지우기에 확인 단계.

## 시험·확인

- 기존 시험은 지우지 않고 새 화면 위치에 맞췄다(할 일·자동화·브라우저·설정으로 옮겨 간 것만 경로를 바꿨다). 새 시험은 위 둘.
- 시각 확인: `LUCIA_PREVIEW_DIR=<디렉터리> cargo test -p luciad write_previews -- --ignored`로 미리보기 HTML을 만들고 헤드리스 Chromium으로 대표 화면을 1280px(밝은·어두운 판)과 390px(밝은 판)에서 봤다. 확인 단계를 펼친 상태, 화면 넘겨받기(실제 크기 이미지 자리), 로그인·사이트 로그인 같은 단독 화면도 봤다. 실제 데몬에 띄워 보지는 않았다.
- 스크립트가 없어서 못 한 것(남긴 한계): 저장 전 변경 경고, 복사 버튼, 모달 닫기(Esc), 수동 테마 바꾸기. CSP를 풀어야 하는 일이라 사용자가 정할 일이었고, 이후 결정 0042에서 CSP를 해제했다(기능은 아직 만들지 않았다).
