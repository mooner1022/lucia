# 0059. VM 안에서 Claude Code의 내장 도구를 쓰고, 되돌릴 수 없는 바깥 동작은 승인을 받는다

- 날짜: 2026-11-20
- 상태: 확정. 값(대화 실행 60분, 승인 카드 30분, 승인 기억 30분, 훅이 기다리는 280초, 작업 공간 경고 5 GiB)은 [제안].
- 결정 방식: 사용자 지시와 답.
  - "지금은 응답에 300초 제한이 있는걸로 보이는데, 이것도 풀어. VM 내에서 Claude Code의 온전한 성능을 발휘할 수 있는 방향으로 가야 해. vm 내의 시스템에서 쉘 스크립트도 실행할 수 있도록 하고, 브라우저도 완전 제어 가능하도록 풀어."
  - "git push, release나 게시글 제출 등 비가역적으로 외부에 영향을 줄 수 있는 행위에 대해선 모델이 내게 승인을 요청하도록 해."
  - 물어서 받은 답: 쉘과 내장 도구는 **상주 VM에서, 인터넷 포함**. 브라우저는 **전부 가능하게, 돈·계정만 카드**(뒤의 지시로 게시·제출도 카드). 권한 모드가 해제여도 **승인을 받는다**.
- 관련 결정: 0001 D7, 0003(내장 도구), 0008(브라우저 동작), 0020(개발 작업의 코드 도구), 0040(권한 모드), 0051(멈추기), 0058(출구 프록시)
- **뒤집는 원칙**: 지금까지는 "모델은 VM 안에서 생각만 하고, 바깥에 닿는 모든 일은 호스트의 데몬이 확인하고 대신 한다"였다(0001 D7, 0003, PoC P2). 이제 사람이 대화 중인 실행에서는 **Lucia가 VM 안에서 직접 한다**(쉘, 파일, 인터넷). 호스트가 지키는 것은 줄었다: VM 격리, 출구 프록시의 주소 검사, 데몬 도구의 권한 검사, 승인 카드. PoC P2의 "VM 안의 통제는 그 실행에만 보장된다"는 그대로 참이고, 그래서 아래 "위험"이 생긴다.

## 결정

### 1. 상주 VM의 내장 도구

- 사람이 대화 중인 실행(`RunProfile::Chat`)에 Claude Code의 **Bash, Read, Write, Edit, Glob, Grep**을 연다(설정 `[sandbox] native_tools`, 기본 켬).
  - 브리핑, 후속 조치, 루틴 깨우기, 작업 세션 같은 사람 없는 실행은 예전대로 웹 검색과 데몬 도구뿐이다.
  - 실행 조합은 그대로 `--restricted --tools … --allowedTools … --permission-prompts none`이다. `--restricted`라 VM 안의 사용자 설정(`~/.claude/settings.json`의 훅 등)은 읽지 않는다. Read·Write·Edit는 작업 디렉터리 안에서만 된다(Bash는 어디든).
  - WebFetch, 하위 에이전트, 할 일 도구는 열지 않았다. WebFetch는 Claude Code 자신의 연결이라 출구 프록시를 타지 않는다(쉘의 curl을 쓴다).
- **훅**(`plugin/hooks/`, 보호 영역, 사용자 지시로 고침): 데몬이 실행마다 환경 변수 `LUCIA_BUILTIN_TOOLS`로 연 도구를 알려 주고, 훅은 그 이름과 데몬 MCP 도구만 통과시킨다. 알려 주지 않으면 예전처럼 WebSearch만이다. `plugin/`은 운영과 개발 VM에 그대로 마운트되어 있어 파일을 바꾸는 순간 적용된다. 그래서 새 훅은 옛 데몬과도 똑같이 움직이게 만들고, 이름을 바꿔치기해 한 번에 넣었다.
- **쉘의 인터넷**: 결정 0058의 출구 프록시를 같이 쓴다. 실행마다 통행증을 내주고 끝나면 거둔다(열린 연결도 끊는다).
  - 통행증은 쉘 명령에만 간다: 데몬이 `LUCIA_PROXY`로 넘기고, 읽기 전용 환경 파일(`plugin/env/bash-env.sh`, `CLAUDE_ENV_FILE`)이 Bash 명령 앞에서 `HTTPS_PROXY`로 옮긴다. Claude Code 자신의 연결(모델 API)은 sbx의 프록시 그대로다.
  - 상주 샌드박스에 허용 규칙 하나(`localhost:<프록시 포트>`)를 더한다. 데몬이 뜰 때 설정에 맞춰 걸거나 치운다. 브라우저 프록시 포트는 여전히 허용하지 않는다.
  - 나가는 글 검사가 "막기"이거나 권한 모드가 엄격이면 통행증을 내주지 않는다(쉘은 열리되 나가지 못한다).
  - 쉘이 나간 호스트는 활동 기록(`shell_net`)에 남는다.
- **파일 잇기**: `file_import(경로)`는 작업 공간의 파일을 파일 id로 만들고(첨부·보기·보관), `file_export(id)`는 파일 id의 내용을 작업 공간에 꺼낸다.
  - 작업 공간은 호스트의 디렉터리다. 호스트가 그 안을 열 때 **VM이 심은 심볼릭 링크를 따라가지 않는다**: 경로를 조각마다 `openat(O_NOFOLLOW)`로 내려간다(`crate::workspace`). 따라가면 VM이 링크 하나로 호스트의 파일을 읽게 하거나 아무 곳에 쓰게 할 수 있다.
- **시간 제한**: 사람이 대화 중인 실행은 60분(`[sandbox] chat_timeout_secs`). 정기 실행은 예전 상한(`timeout_secs`, 운영 300초) 그대로다: 멈춘 브리핑이 줄을 오래 막지 않게. 멈추려면 대화에서 "그만"(결정 0051).
  - 멈추거나 시간을 넘기면 VM 안의 claude와 **그것이 띄운 프로세스까지** 끝낸다(전에는 claude만 끝냈다). 스스로 떨어져 나간 프로세스(`setsid` 등)는 남을 수 있다.
- **안내**: 대화 지침 뒤에 환경 설명(쉘·설치·인터넷·파일 잇기·승인)을 더했다. 내장 도구를 끄면 붙지 않는다.

### 2. 되돌릴 수 없는 바깥 동작의 승인

- 새 승인 종류 `external_action`(`crate::actions`): 무엇을 하려는지와 실제 명령·내용을 카드로 보이고 [승인]/[하지 않기]를 받는다. **데몬은 실행하지 않는다.** 승인은 "해도 된다"는 답이고 실행은 물어본 쪽이 한다.
- 묻는 길 셋:
  1. **쉘 명령**: 훅(`plugin/hooks/gate.py`)이 Bash 명령의 모양을 보고, 바깥에 쓰는 것이면 실행 전에 데몬에 묻는다(`POST /approval`, 실행별 토큰). 답이 올 때까지 280초를 기다리고(명령은 멈춰 있다), 승인되면 통과시키고 아니면 막는다. 데몬에 닿지 못해도 막는다.
     - 잡는 것: `git push`, GitHub·GitLab에 쓰는 명령(`gh`·`glab`의 읽기 아닌 것, 쓰는 `api`), 패키지·이미지 게시(`npm publish`, `cargo publish`, `twine upload`, `docker push` 등), 배포·클라우드 도구(`kubectl`, `terraform`, `aws`, `vercel` 등), 원격 접속·전송(`ssh`, `scp`, `rsync host:`), 메일 보내기, 쓰는 HTTP 요청(`curl -X POST`·`-d`·`-F`·`-T`, `wget --post-*`, httpie).
  2. **도구 `approval_request(what, detail)`**: 훅이 알아볼 수 없는 일(코드 안에서 보내는 요청 등)을 Lucia가 스스로 묻는다. 40초 기다린다.
  3. **브라우저**: 아래 3.
- 늦은 승인: 기다리던 쪽이 떠난 뒤 승인되면 30분 동안 기억해, 같은 동작을 다시 청할 때 한 번 통과시킨다.
- 승인은 카드에 보인 내용 전체에 해당한다. 카드에 다 보이지 않는 긴 내용(1,500자 초과)은 받지 않고, 승인이 필요한 부분만 짧은 명령으로 나누라고 답한다(긴 스크립트 끝의 push를 보지 못한 채 승인하지 않게).
- **권한 모드가 해제여도 묻는다.** 해제가 건너뛰던 것 가운데 메일 발송과 Discord 글·서버 관리를 뺐다(`ONE_SHOT_KINDS`). 해제에 남은 것은 내 캘린더 쓰기, 저장된 로그인으로 다시 로그인하기, 브라우저의 가벼운 확인이다.

### 3. 브라우저: 못 하는 동작을 없애고, 승인으로

- 금지 등급을 없앴다. 등급은 이제 다음과 같다(`browser::tools::Gate`).

| 등급 | 무엇 | 사람이 대화 중 | 사람 없는 실행 |
|---|---|---|---|
| 그냥 | 링크, 펼치기, 입력, GET 폼 | 한다 | 위임 범위 안에서 한다 |
| 가벼운 확인 | 무엇을 하는지 모르는 스크립트 단추, 확인하지 못한 자리 | 기본은 카드, 해제는 그냥 | 카드(위임의 동작 허용이면 그냥) |
| 바깥에 남는 쓰기 | POST 폼 제출, 글 등록·보내기·지우기로 보이는 단추 | **늘 카드**(위임의 동작 허용이면 그냥) | 카드(위임의 동작 허용이면 그냥) |
| 돈·계정 | 결제, 주문, 송금, 탈퇴, 비밀번호 바꾸기(예전 금지) | **늘 카드**(위임도 건너뛰지 못한다) | 하지 않는다 |
| 사람 전용 | 로그아웃, 비밀번호 칸·로그인 폼 입력과 제출(예전 금지) | 그냥 | 하지 않는다 |

- 결제·주문 페이지(주소로 본다)에서는 가벼운 확인도 "돈·계정"으로 올린다: 확인하지 못한 자리나 무엇이 실행될지 모르는 Enter가 결제일 수 있다.
- 새 도구:
  - `browser_eval(script)`: 지금 페이지에서 JavaScript를 돈다(페이지 자신의 실행 공간, 사용자 동작으로). 요청을 보내거나 제출·누르기·이동하는 모양이면, 결제·주문 페이지면, 엄격 모드면 승인 카드를 거친다. 읽기만 하는 스크립트는 바로 돈다.
  - `browser_upload(target, file)`: 파일 고르기 칸에 파일을 넣는다. 늘 승인 카드를 거친다. 넣기만 하고 보내지는 않는다(보내는 제출에서 다시 묻는다).
- 비밀번호 칸에 넣는 글은 활동 기록에 남지 않고, 승인 카드(저장소)로도 가지 않는다(엄격 모드처럼 카드가 필요한 때는 넣지 않는다).
- Chromium을 UTF-8 로캘로 띄운다(한글 이름의 파일을 올리려면 필요했다).
- 사람 없는 실행과 엄격 모드의 규칙은 그대로다.

## 위험과 받아들인 것

- **승인은 모양으로 가려낸다.** 훅은 명령 글자를, 브라우저는 단추의 말·폼·주소를, 스크립트는 글자를 본다. 놓치는 것이 있다: 스크립트 파일 안에서 하는 `git push`, 코드가 보내는 POST, 변수로 조립한 명령, 아이콘뿐인 단추, 낯선 이름의 결제 단추, 돌려 쓴 스크립트. 그런 것은 지침에 따라 Lucia가 스스로 묻는 데 기대고 있다. 웹의 글에 속은 Lucia는 스스로 묻지 않을 수 있다. **카드는 실수를 막는 장치이지, 속은 모델을 막는 벽이 아니다.**
- **바깥 서비스의 자격 증명이 실제 벽이다.** VM에는 GitHub·클라우드 자격 증명이 없다(출구 프록시는 sbx의 자격 증명 주입을 거치지 않는다). 그래서 지금은 `git push`가 승인돼도 인증에서 막힌다. 사용자가 토큰을 주면 그때부터 위의 승인이 실제 문이 된다.
  - 예외 하나(개발 VM에서 확인): **Claude 구독.** 쉘이 sbx의 프록시로 `api.anthropic.com`을 부르면 sbx가 구독 로그인을 끼워 넣어 준다(200). 토큰 자체는 VM에 없지만, 쉘은 사용자의 구독으로 모델을 부를 수 있다. 속은 Lucia가 사용량을 쓸 수 있다는 뜻이다.
- **훅은 Lucia가 끌 수 있다.** 훅 파일은 읽기 전용 마운트지만 훅이 쓰는 `sh`·`python3`은 VM 안의 것이다. sudo를 가진 쉘이 그것을 바꾸면 훅은 그 실행과 그 뒤의 모든 실행에서 힘을 잃는다(도구 이름 검사도 함께). 데몬의 실행 조합(`--tools`·`--allowedTools`)과 데몬 도구의 권한 검사는 호스트에 있어 남는다.
- **읽은 자료가 나갈 수 있다.** 대화 중인 Lucia는 쉘로 무엇이든 https로 보낼 수 있다. 메일·기억을 읽는 도구도 같은 실행에 있다. 프록시에는 호스트 이름만 남는다(결정 0058과 같은 위험이 상주 VM으로 넓어졌다).
- **VM 안의 것은 Lucia가 바꿀 수 있다.** 작업 공간, 홈 디렉터리, 설치한 프로그램, 그리고 세션 기록 파일. 다음 실행의 쉘은 그것을 그대로 쓴다.
  - 사람 없는 실행에는 쉘이 없어 새로 무엇을 실행하지는 못한다. 사용자 설정은 `--restricted`라 읽지 않고, 작업 공간에 둔 `CLAUDE.md`도 실리지 않는다(개발 VM에서 표지 낱말을 심어 확인했다).
  - 그러나 **대화 실행이 띄워 두고 떠난 프로세스는 남을 수 있다**(스스로 떨어져 나간 것). 그런 프로세스는 뒤의 실행의 토큰을 명령줄에서, 뒤의 대화의 통행증을 환경 변수에서 읽을 수 있다. 사람 없는 실행의 권한(그 실행의 데몬 도구)을 빌려 쓸 수 있다는 뜻이다. 속은 한 번의 대화가 뒤의 실행들에 손댈 수 있다.
  - 의심스러우면 상주 샌드박스를 다시 만들어야 하는데, 그러면 세션 기록도 지워진다.
- **호스트가 VM에서 꺼내 오는 것**: 작업 공간의 파일(`file_import`, 링크를 따라가지 않는다)과 하루 한 번의 세션 기록 백업(`sbx cp`가 복사하고, 데몬은 내용을 읽지 않으며 셀 때와 지울 때 링크를 따라가지 않는다. 4 GiB를 넘으면 남기지 않는다).
- **실행별 토큰이 쉘에 보인다.** 훅이 데몬에 묻는 데 쓰는 토큰(MCP 토큰과 같다)이 환경 변수에 있다. 그 실행의 권한 그대로라 넓어지는 것은 없다.
- **긴 실행이 줄을 막는다.** 대화 실행 하나가 60분까지 갈 수 있고, 그동안 다른 메시지와 정기 작업은 기다린다. 승인 카드를 기다리는 동안도 그렇다(훅은 280초). "그만"은 통한다.
- **작업 공간은 호스트 디스크다.** 상한이 없다. 5 GiB를 넘으면 파일 잇기 도구의 답에 정리하라고 붙는다.
- **대화와 정기 실행이 번갈아 돌면 캐시를 다시 쓴다.** 내장 도구 목록이 실행 종류마다 달라서다. 다만 데몬 도구 목록이 이미 달랐고, 운영 기록에서도 정기 실행 뒤의 첫 대화가 맥락 전체를 다시 썼다(11-20 00:07, 7.6만 토큰). 새로 생긴 비용은 아니다.

## 결정 0057의 "더 풀 수 있는 것"과의 관계

1. **시스템 패키지**: 대화 중인 실행은 상주 VM의 쉘에서 `sudo apt-get install`을 쓴다(위에서 확인). 스크립트 샌드박스(`code_run`, 루틴)에는 여전히 PyPI 패키지만 설치된다(`lib_install`). 사람 없이 도는 스크립트가 시스템 프로그램을 쓰게 하려면 `lib_install`에 apt를 더해야 한다. 만들지 않았다.
