# 0006. 브라우저: 로그인 프로필을 유지하는 전용 샌드박스와 데몬이 하는 로그인

- 날짜: 2026-11-16
- 상태: 확정(첫 조각: 읽기와 로그인). **네트워크(허용 사이트만)와 "읽기만"은 결정 0008로 바뀌었다**(차단 목록 방식의 데몬 프록시, 조작 도구와 승인, 아무 https 사이트 로그인). **내려받기는 결정 0057로 바뀌었다**(브라우저는 여전히 받지 않고, 시작하려던 내려받기를 데몬이 대신 받는다). **로그인 정보를 받는 길에 앱의 입력 카드가 더해졌다**(결정 0063: 알림 받을 곳이 앱일 때. 비밀번호는 Discord로 받지 않는다).
- 결정 방식:
  - 4단계 착수(PLAN §7). 첫 사이트는 사용자가 퀘이사존으로 골랐다. 적당한 규모의 국내 사이트이고 사용자 계정이 있다.
  - 사용자 요청: "Muse와 같이 유저가 입력 요청에 입력하면 알아서 로그인 가능한 구조", 자동 재로그인 포함.
  - 사용자 답:
    - 계정은 아이디/비밀번호 방식이다(간편 로그인이 아니다).
    - 정기 작업은 없다. Lucia가 대화 중 필요할 때만 쓴다.

## 실측(PoC P8, 자세한 것은 `poc/RESULTS.md`)

- 버리는 `shell` 샌드박스에서 화면 있는 Chromium이 퀘이사존(Cloudflare 뒤)을 챌린지 없이 열었다.
  - 출구 IP는 호스트와 같다(집 IP).
  - 허용된 호스트는 sbx 프록시가 TLS를 가로채지 않는다(사이트가 Chrome의 TLS를 그대로 본다).
- `sbx exec`가 하나도 없으면 샌드박스는 1분쯤 뒤 스스로 멈추고, Chrome도 같이 끝난다.
- `sbx ports`는 VM 루프백에서만 듣는 서비스(Chrome CDP)에 닿지 않는다.
- `sbx exec -i` 표준 입출력은 바이너리를 그대로 나른다(1 MiB, 모든 바이트값).
- 쿠키는 정상 종료, 샌드박스 정지, 재시작 뒤에도 남는다.
- 퀘이사존 로그인 폼(라라벨):
  - `#login_id`, `#password` 칸.
  - "자동 로그인" 체크 `#login-check`(name `remember`).
  - `#btn-login` 버튼(`loginSubmit()`), 보이는 캡차 없음. 세션 쿠키는 약 5시간이다.

## 결정

### 샌드박스와 연결

- **전용 샌드박스** `lucia-browser`를 둔다(`deploy/create-browser-sandbox.sh`).
  - `shell` 킷, 메모리 2 GiB, 작업 공간 없음.
  - 네트워크는 기본 거부다. 허용 사이트 호스트만 이 샌드박스 범위 규칙으로 연다.
  - Anthropic·Claude 계정 쪽(전역 시크릿 주입 대상)과 GitHub는 명시 거부 규칙으로도 막는다.
  - 패키지 저장소는 설치하는 동안만 허용하고 지운다.
  - Chromium 정책으로 비밀번호 저장, 자동 완성, 동기화, 내려받기를 끈다.
  - 상주 샌드박스와 같은 이름은 설정이 거부한다.
- **CDP는 포트를 열지 않는다.** 데몬이 `sbx exec -i lucia-browser sh -c <시작 스크립트>`를 붙잡아 둔다.
  - VM 안에서 Xvfb와 Chromium(원격 디버깅은 VM 루프백 9222)을 띄우고, 주소를 한 줄 알린 뒤 `socat STDIO TCP:127.0.0.1:9222`로 표준 입출력을 CDP에 잇는다.
  - 호스트에 CDP 포트가 없으므로 이 서버의 다른 프로세스가 로그인된 브라우저를 조종할 수 없다.
  - 웹소켓은 `tokio-tungstenite` 0.30.0을 쓴다(새 의존성, TCP·TLS 기능 없이 핸드셰이크만).
- **쓸 때 열고, 안 쓰면 닫는다.**
  - 처음 쓸 때 띄운다(샌드박스 시작 포함 몇 초).
  - 10분(`browser.idle_minutes`) 쓰지 않으면 `Browser.close`로 정상 종료한다(쿠키를 디스크에 쓴다). 세션이 끝나 샌드박스가 스스로 멈추고 메모리를 돌려준다.
  - 데몬이 멈출 때도 정상 종료한다.
- **한 잠금 아래에서 차례로** 조작한다. 로그인 입력 도중 다른 이동이 끼지 않는다.

### Lucia(모델)가 할 수 있는 것: 읽기만

- MCP `browser_open(url)`이 허용 사이트 페이지를 열어 주소, 제목, 본문 글(20,000자까지), 링크(120개까지)를 돌려준다.
  - 내용은 `<external_data source="browser">`로 감싼다.
  - 입력 칸의 값은 담지 않는다(`innerText`에는 없다).
- MCP `browser_login(site)`은 로그인을 요청한다.
- 두 도구 모두 사람이 시작한 채팅에서만 쓴다. 브리핑에는 주지 않는다(로그인 요청이 사람에게 가므로).
- **주소 검사**: https만 열고, 사용자 정보와 다른 포트는 받지 않는다. 호스트가 사이트 목록에 맞아야 한다.
  - 넘겨주기 뒤 도착한 주소도 다시 본다. 다른 곳이면 빈 페이지로 돌리고 오류를 낸다.
  - 네트워크 정책이 막지 못하는 `file:`·`chrome:`·`javascript:`·`data:`도 여기서 막힌다.
- 클릭, 입력, 글쓰기, 폼 제출은 할 수 없다. 도구 설명과 채팅 지침에 그렇게 적었다(할 수 없는 일을 약속하지 않게).

### 로그인: 데몬의 정해진 코드가 한다

- 사이트 프로필은 코드에 둔다(`browser::sites`). 로그인 주소, 칸 선택자, 로그인 유지 체크, 버튼이 들어 있다.
- **로그인이 필요하다는 판단**: 페이지가 로그인 경로로 튕겼거나 비밀번호 칸이 있으면 데몬이 바로 요청한다.
  - 저장된 로그인이 없으면 **일회용 입력 링크**를 Discord로 보낸다([제안], 아래).
  - 저장된 로그인이 있으면 **재로그인 승인 카드**를 올린다(저장된 로그인을 다시 쓸 때마다, dots 방식).
    - 승인 데스크가 종류(`site_login`)를 보고 카드 모양, 실행, 만료, 재시작 정리를 따로 한다.
    - 승인은 30분 안에 해야 한다.
  - 같은 사이트 요청이 이미 기다리고 있으면 다시 보내지 않는다.
  - 도구 호출은 사람을 기다리지 않고 바로 돌아온다. 결과는 에피소드로 남겨 Lucia가 다음 대화에서 안다.
- **입력**: 칸마다 넣기 직전에 다시 확인한다.
  - 최상위 문서의 출처가 그 사이트여야 한다.
  - 그 칸에 초점이 있어야 하고, 비밀번호는 `type=password` 칸에만 넣는다.
  - 넣은 뒤 글자 수를 확인한다(값은 꺼내지 않는다).
  - 로그인 유지 체크를 켠다.
  - 제출은 한 번만 한다.
  - JavaScript 대화상자(alert 등)는 받자마자 닫고 문구만 남긴다.
- **실패하면**: 칸을 비운다. 입력값이 주소나 본문에 드러났으면 그 페이지를 닫는다.
  - 사이트가 보인 문구(대화상자, 오류 영역)를 이유로 돌려준다(비밀번호는 가린다).
  - 입력 폼에서는 새 토큰으로 바로 다시 넣을 수 있다.
  - 저장된 로그인이 거절되면 새 입력 링크를 보낸다.
- **비밀번호 다루기**:
  - 받는 즉시 마스킹 필터에 등록한다(오류 문구에 섞여도 새지 않게).
  - 모델, 로그, 원장, 메신저, 승인 요청 어디에도 넣지 않는다.
  - CDP 클라이언트는 매개변수를 로그에 남기지 않는다.
- **저장(자동 재로그인)**: 입력 폼의 "저장해 두기"(기본 켬)를 고르면 비밀번호를 `systemd-creds`로 암호화해 `site-<사이트>` 자격 증명으로 둔다.
  - JSON으로 감싸 앞뒤 공백까지 지킨다.
  - 아이디는 설정 `browser.site.<사이트>.username`에 둔다. 아이디는 비밀이 아니고, 가리면 사이트 글의 사용자 이름까지 가려진다.
  - 이미 로그인돼 있어 확인하지 못한 비밀번호는 저장하지 않는다.
  - 관리 페이지 시스템 화면에서 지울 수 있다(두 번 누르기).

### 입력 링크 [제안]

- 관리 페이지에 `/site-login/<토큰>`을 둔다. 로그인 세션 없이 연다. Discord에서 넘어오면 `SameSite=Strict` 쿠키가 실리지 않기 때문이다(Google 콜백과 같은 사정).
- 토큰이 곧 권한이다:
  - 약 244비트, 10분(`browser.login_input_minutes`), 한 번만, 한 사이트에만 쓴다.
  - 데몬 메모리에만 두므로 재시작하면 사라진다.
  - 집 네트워크(밖에서는 WireGuard)에서만 열린다(관리 페이지 바인드).
- 아무것도 미리 채우지 않는다. 응답은 `no-store`, `no-referrer`이고, 토큰·아이디·비밀번호를 로그에 남기지 않는다.
- 링크가 새도 할 수 있는 일은 10분 안에 한 번 "자격 증명을 넣어 보는 것"뿐이다. 읽을 수 있는 것은 없다.

## 하지 않은 것과 미룬 것

- **사용자 결정으로 하지 않음**: 정기 작업, 곧 사이트별 결정적 스크래퍼(명세 4단계 항목)는 두지 않는다.
- **[제안] 미룸**:
  - 클릭·입력과 승인을 받는 폼 제출(접근성 트리와 고수준 동작, 제출류는 Discord 승인).
  - OTP용 Discord modal(퀘이사존에는 2단계 인증이 없다).
  - 캡차·본인인증용 noVNC 넘겨받기. 패키지는 설치하지 않았다. 필요할 때 관리 페이지 로그인 뒤에서만 중계한다.
  - 사이트를 늘릴 때 승인을 받아 네트워크 허용을 더하는 흐름.
- 기존 상주 세션의 웹 페이지 열기(`WebFetch`)는 여전히 닫혀 있다(결정 0003). 브라우저는 허용 사이트로만 나간다.

## 위험

- **외부 글 범위가 넓어졌다.** 게시판 글은 메일함과 달리 누구나 쓸 수 있다.
  - 외부 데이터로 감싸고 크기를 묶지만, PLAN §6의 "알려진 틈"(외부 글이 채팅 실행에 들어가고 그 실행이 핵심 기억을 고칠 수 있다)은 그만큼 넓어진다.
  - 인젝션 검사(3단계 항목)의 우선순위가 올라간다.
- **로그인된 브라우저는 강한 권한이다.** CDP 포트를 열지 않고, Lucia에게는 읽기만 준다. 사이트를 늘릴 때마다 이 판단을 다시 한다.

## 확인

- 시험(모델·네트워크 없음):
  - 주소 검사, CDP 클라이언트(가짜 Chrome: 응답, 오류, 이벤트, 시간 초과, 끊김).
  - 로그인 흐름(입력 링크, 저장, 승인, 거절 뒤 새 링크, 만료, 한 번만).
  - 승인 데스크의 로그인 카드와 실행기, MCP 도구, 관리 페이지 입력 링크와 시스템 화면.
- 실제 샌드박스(`luciad browser-check`):
  - 퀘이사존 첫 페이지 읽기 한 번.
  - VM 루프백의 시험용 로그인 페이지(같은 칸 이름과 `loginSubmit()`)로 확인했다:
    - 빈 아이디(대화상자 자동 닫기)와 틀린 비밀번호(사이트 문구, 입력값 없음).
    - 공백 있는 비밀번호와 로그인 유지 체크, 그리고 이미 로그인된 상태.
    - 브라우저를 닫았다 다시 열어도 로그인이 남는지.
- **확인하지 않은 것**: 실제 퀘이사존 계정 로그인. 첫 로그인은 사용자가 입력 링크로 한다. 그때 "자동 로그인" 쿠키가 얼마나 가는지도 본다.

## 고친 문제(2026-11-17)

- **관리 페이지가 로그인 뒤 멈췄다.**
  - 원인: 화면 데이터를 모으는 `gather`가 저장소 잠금을 쥔 채 `SiteLogins::status`를 불렀고, 그 함수가 같은 저장소를 다시 잠그다 교착됐다.
  - 범위: 브라우저를 켠 뒤(00:23)부터 로그인할 때마다 그 요청이 멈췄다. 멈춘 요청이 저장소 잠금을 계속 쥐어 다른 일도 막혔다.
  - 16:04 UTC에는 Discord 요청 하나(예전 핵심 기억 나누기)가 기억 일은 마쳤지만 답장과 원장 기록을 하지 못했다.
- 고침: 브라우저 상태를 저장소 잠금을 잡기 전에 모은다.
- 회귀 시험: 브라우저가 붙은 상태로 모든 화면을 따로 스레드에서 그려 본다. 교착되면 5초 안에 실패한다.
  - 같은 스레드에서 그리면 막힌 동기 잠금이 시험 런타임까지 멈춰 시간 제한이 듣지 않는다.
