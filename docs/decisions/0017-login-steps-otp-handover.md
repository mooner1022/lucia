# 0017. 단계형 로그인, 인증 코드(OTP) 입력창, 화면 넘겨받기

- 날짜: 2026-11-17
- 상태: 확정. 시간 값은 [제안]. 넘겨받기 방식은 명세와 다르다([제안], 아래 "명세와 다른 점"). **화면 넘겨받기는 결정 0063으로 앱에서도 된다**(아래 "관리 페이지에서만 연다"는 그때까지의 것이다. 범위 `browser_handover`가 있는 앱이 `browser.handover.*`로 한다. 시간·기록·붙잡기는 그대로).
- 결정 방식: 사용자 지시 "1, 3, 4 작업들 모두 순차적으로 진행해"의 4단계 남은 항목(결정 0008의 남은 [제안]). 명세 §브라우저와 웹사이트 로그인(세션 만료 처리 흐름, OTP는 Discord modal, 폼으로 안 되면 noVNC로 넘겨받기)과 §인증과 비밀 관리를 따른다.

## 결정

### 단계형 로그인(아이디 → 다음 → 비밀번호)

- **대상**: 일반 프로필(결정 0008)의 로그인 페이지에 비밀번호 칸이 없을 때만 한다.
- **첫 단계**: 아이디 칸이 하나로 정해질 때만 한다(`autocomplete=username/email` 또는 보이는 글 칸 하나). 여러 개면 하지 않는다. 아이디를 넣고 "다음"(제출 단추나 다음·계속·next 단추, 없으면 Enter)을 누른다.
- **기다리기**: 페이지가 넘어가지 않는 화면도 있어, 같은 사이트에서 비밀번호 칸이 나올 때까지 15초 동안 0.5초마다 본다.
  - 주소는 페이지 스크립트 없이 CDP(`Page.getNavigationHistory`)로 먼저 본다. 넘어가는 도중에는 스크립트 공간이 없어 오래 걸린다.
  - 다른 출처로 넘어가면 그 페이지를 닫고 멈춘다(비밀번호를 넣지 않는다).
  - 비밀번호 칸이 안 나오면 칸을 비우고 멈춘다.
- **둘째 단계**: 비밀번호 칸 하나와 로그인 단추를 찾아 넣는다. 이미 넣은 아이디는 다시 넣지 않는다.
- 단계마다 출처·최상위 창 확인, 한 번만 시도, 실패하면 칸 비우기는 그대로다.

### 인증 코드(OTP)

- **찾기**: 로그인 제출 뒤, 같은 사이트에 인증 코드 칸이 하나로 정해지면 `LoginResult::NeedsCode`로 그 단계에 페이지를 둔다.
  - 코드 칸: `autocomplete=one-time-code`이거나 이름·라벨이 인증 번호·코드·OTP류인 글·숫자 칸이고, 비밀번호 칸이 아니다.
  - 애매하면(여러 개, 비밀번호 칸이 보임) 찾지 않는다. 그런 경우는 넘겨받기로 한다.
  - 일반 프로필은 비밀번호 칸이 없어지면 성공으로 보므로, 성공 판단보다 먼저 본다.
- **요청**: 승인 종류 `login_code`(5분) 카드를 올린다.
  - [코드 입력]은 값을 받는 버튼이다.
  - 카드에는 버튼을 못 쓰는 채널을 위한 일회용 웹 링크(`/site-login/code/…`, 5분, 한 번)도 넣는다.
  - 사용자가 웹 입력 링크로 로그인하던 중이면 그 화면에서 바로 코드 입력 링크로 이어진다.
- **플랫폼 중립 타입**(`lucia-core`):
  - `CardButton.prompt`(입력창 모양).
  - `ButtonPress.input`: `SecretText`, `Debug`·로그에 값이 찍히지 않는다.
  - 능력 `prompts`.
- **Discord**(twilight 0.18 소스 확인):
  - 값을 받는 버튼은 custom_id에 `p|`를 붙인다.
  - 누르면 입력창(modal, interaction 응답 9)을 첫 응답으로 띄운다. 이 누름은 코어로 넘기지 않는다.
  - 입력창 제출(`ModalSubmit`)은 응답(6)한 뒤 값과 함께 코어로 넘긴다.
  - 데몬이 재시작해 입력창 모양을 잃어도 기본 입력창을 띄운다.
- **승인 데스크**:
  - 값을 받는 종류는 값 없이 온 승인을 무시한다.
  - 값은 실행에만 넘기고, 활동·에피소드·승인 기록에는 결과 문구만 남긴다.
  - 받은 코드는 곧바로 마스킹 목록에 넣는다.
- **브라우저 붙잡기**: 코드를 기다리는 동안 상주 대화와 작업은 브라우저를 쓰지 못한다(페이지를 코드 단계에 둔다).
- **넣기**: 코드는 한 번만, 그 사이트에만 넣는다(`SiteLogins::submit_code`).
  - 넣기 전에 같은 사이트·최상위 창·코드 칸을 다시 확인한다.
  - 틀리면 사이트 문구로 알린다(문구에서 코드는 가린다).

### 화면 넘겨받기

- **화면**: 관리 페이지 시스템 화면의 브라우저 카드 → "화면 넘겨받기"(`/browser/handover`). 로그인한 관리 페이지에서만 연다. MCP 도구에는 없다.
- **보기와 조작**: 스크립트 없이 한다(관리 페이지 CSP에 `script-src`가 없다).
  - 화면은 CDP 화면 캡처(JPEG)를 이미지로 보인다.
  - 누르기는 이미지 입력(`input type=image`)이 보내는 좌표로 한다. 이미지를 실제 크기로 두어 좌표가 브라우저 좌표와 같다.
  - 글 넣기, 키(Enter, Tab, ⌫, Esc, ↑, ↓), 스크롤은 폼으로 보낸다. 모두 CSRF를 확인한다.
  - 자동 새로고침(3초)은 사람이 켤 때만 한다.
- **새 창**: 넘겨받는 동안은 새 창(본인인증 팝업 등)을 닫지 않고 탭으로 남긴다. 탭을 골라 그 화면을 보고 다룬다(CDP `Target.attachToTarget`).
  - 넘겨받기를 끝내면 그 탭들을 닫는다. 로그인 쿠키는 남는다.
  - 평소에는 지금처럼 새 창을 바로 닫는다(결정 0008).
- **붙잡기**:
  - 넘겨받는 동안 Lucia의 모든 실행이 브라우저를 쓰지 못한다.
  - 최대 15분이다. 지나면 데몬이 끝낸다(1분마다 확인). "끝내기"로도 끝난다.
- **기록**:
  - 넣은 글과 누른 자리는 남기지 않는다.
  - 시작·끝과 그때의 주소만 활동 기록에 남긴다.
  - 화면 이미지는 저장하지 않는다.
- **나가는 길**: 넘겨받는 동안의 이동도 데몬 프록시와 차단 목록을 거친다(결정 0008). 사설 주소와 차단한 곳에는 닿지 않는다.

## 명세와 다른 점

- 명세는 "캡차나 본인인증처럼 폼으로 안 되는 경우만 noVNC(WireGuard 내부)로 넘겨받는다"이다.
- noVNC 대신 **CDP 화면 중계**로 했다. 까닭:
  - noVNC는 브라우저 샌드박스에 X 서버·VNC·websockify 패키지와 열린 포트가 필요하다.
  - 그 샌드박스는 로그인된 프로필을 지니고, 네트워크가 설치 때만 열린다(결정 0008).
  - CDP 중계는 이미 쓰는 표준 입출력 연결 하나로 되고, 관리 페이지의 로그인·CSRF·LAN 제한을 그대로 받는다.
- **한계**:
  - 화면이 부드럽게 움직이지 않는다(누를 때마다 또는 3초마다 새 화면).
  - 끌기(drag), 오른쪽 클릭, 파일 올리기는 못 한다.
  - 슬라이더를 끄는 캡차처럼 끌기가 필요한 것은 못 넘는다.
- 필요해지면 noVNC를 다시 검토한다.

## 확인(2026-11-17)

- **개발 브라우저 샌드박스**(`lucia-browser-dev`, 프록시 포트 47821)와 `luciad browser-check`. 실제 계정으로는 로그인하지 않는다.
  - 단계형:
    - 한 화면에서 비밀번호 칸이 나중에 나오는 것 → 로그인.
    - 두 페이지로 나뉜 것 → 로그인.
    - 다음 단계가 다른 출처(8001)로 넘어가는 것 → 비밀번호를 넣지 않음.
    - 비밀번호 칸이 안 나오는 것 → 15초 안에 멈추고 칸을 비움.
    - 이미 로그인돼 넘어간 페이지의 입력칸 → 건드리지 않음.
  - 인증 코드:
    - 코드 칸을 찾아 그 단계에 둔다.
    - 틀린 코드는 사이트 문구로 거절한다(문구에 코드 없음).
    - 맞는 코드로 로그인한다.
    - 코드 칸이 없으면 넣지 않는다.
  - 넘겨받기:
    - 화면을 JPEG로 받는다.
    - 누른 자리로 새 창이 열리고 탭으로 남는다. 새 창 화면도 받는다.
    - 끝내면 새 창을 닫는다.
    - 넘겨받지 않은 상태의 입력은 거절한다.
  - 기존 점검(로그인, 동작 등급, 프록시 차단)도 그대로 통과했다.
- **시험**:
  - Discord: 값을 받는 버튼은 입력창을 첫 응답으로 띄우고 넘기지 않는다. 제출 값만 넘기며 `Debug`에 값이 없다.
  - 승인 데스크: 값 없는 승인은 무시하고, 값이 오면 한 번 넣는다. 활동·에피소드·카드에 코드가 없다.
  - 로그인:
    - 코드 단계면 카드와 링크를 주고 브라우저를 붙잡는다.
    - 다른 사이트에는 넣지 않고, 한 번 시도하면 기다림이 끝난다.
    - 웹 링크로 넣은 코드로 로그인하며, 링크는 한 번만 쓴다.
  - 관리 화면: 넘겨받기 페이지는 로그인 필요, 이미지는 로그인해야 받는다, 스크립트 없음, 탭 제목 이스케이프.
- **실제로 아직 안 본 것**:
  - 실제 사이트의 OTP와 Discord 입력창의 실제 모양.
  - 실제 본인인증 팝업 넘겨받기.
  - 운영 브라우저에서의 넘겨받기.
