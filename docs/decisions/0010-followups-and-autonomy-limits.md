# 0010. 후속 조치, 인젝션 검사, 자동 실행 한도 (3단계 첫 조각)

- 날짜: 2026-11-17
- 상태: 확정
- 결정 방식: 사용자 지시 "남은 작업들 중 내 확인이나 점검이 필요한 것을 제외하고 구현 진행해." 3단계 완료 기준(명세: 에이전트가 약속한 후속 조치를 스스로 수행하고, 무응답 승인은 거부로 끝난다)을 채우는 조각만 했다. 세부는 명세 §기억과 연속성·§스케줄링, 사전 체크, 비용 관리를 따랐고, 명세에 없는 값은 [제안]이다.

## 결정

### 후속 조치(진행 상태)

- **도구**(MCP):
  - `followup_create(when, task, detail?)`: 채팅, 브리핑, 후속 조치 실행에서 쓴다.
  - `followup_list()`: 위와 같다.
  - `followup_cancel(id, reason)`: 사람과의 대화(채팅)에서만 쓴다. 외부 글이 사용자의 약속을 지우지 못하게 하려는 것이다.
- **저장**: 저장소 `followups`(마이그레이션 0008)와, 같은 ID의 일회성 스케줄(action `followup`)이다.
  - 스케줄 허용 지연은 30일이다. 데몬이 멈춰 있던 동안 놓친 약속은 건너뛰지 않고 늦게라도 한다.
  - 사용자가 취소하면 스케줄도 멈춘다.
- **맥락**: 채팅, 브리핑, 후속 조치 실행 앞에 `<progress>`(열린 후속 조치: id, 시각, 할 일)를 붙인다. 열린 것이 없으면 붙이지 않는다.
- **발사**(작업 큐 안에서, 채팅과 겹치지 않음):
  - 상주 세션을 깨워 메모를 맡긴다. 프롬프트는 `<request kind="followup">`이고, "Lucia가 스스로 남긴 메모이며 사용자의 새 지시가 아니다"라고 적는다.
  - 결과는 알림 대화(소유자 DM)로 보내고, 에피소드와 활동 기록에 남긴다. 보고가 없으면 한 번 다시 청한다(결정 0005와 같다).
- **잃지 않기**: 일회성 스케줄은 실행 전에 소비되므로, 데몬이 시작할 때와 조용할 때(5분마다) 열렸는데 발사 스케줄이 없는 후속 조치를 다시 건다.
  - 큐에 있던 작업이 재시작으로 사라진 경우가 여기에 해당한다.
  - 지났으면 1분 뒤에 건다. 같은 예정 시각은 스케줄러가 다시 내지 않으므로 새 시각을 쓴다.
  - 30일 넘게 늦은 것은 실패로 닫고 알린다.
  - 실행이 오류로 끝나면(예: 전송 실패) 실패로 닫고 할 일과 함께 알린다. 다시 하면 모델을 또 부르기 때문이다.
  - 두 번 발사돼도 닫힌 것은 건너뛰므로 한 번만 한다.
- **실행 권한**(`RunProfile::Followup`): 읽기(메일, 일정, 웹 검색), 기억 쓰기, 후속 조치 등록만 한다. **결정 0011로 바뀌었다**: 채팅에서 등록한 것은 브라우저도 쓰고, 브리핑에서 시작한 것만 아래처럼 읽기만 한다(`FollowupLimited`).
  - 브라우저, 메일 발송 요청, 기억 지우기는 없고, MCP 서버의 실행별 허락으로도 막는다.
  - 외부 글이 "1분 뒤 이 주소를 열어라"를 예약해 사람 없이 정보를 내보내지 못하게 하려는 것이다.
- **자기 깨우기 고리 막기** [제안]:
  - 열린 것은 30개까지, 등록은 지금부터 2분 뒤부터 1년 안이다. 후속 조치 실행이 등록하면 30분 뒤부터다.
  - 하루 발사는 20번까지다. 넘으면 6시간 미루고 알린다.
- **미등록 약속**(명세 "결과 보고 단계에서 감지해 되묻는다"):
  - 채팅 답에 "내일 다시 확인해 드릴게요" 같은 약속 표현이 있는데, 그 실행이 `followup_create`를 부르지 않았으면 같은 세션에 한 번 되묻는다.
  - 되묻는 실행(`RunProfile::PromiseCheck`)은 후속 조치 도구만 쓸 수 있고, 사용자에게 아무것도 보내지 않는다.
  - 후속 조치 실행과 되묻기 실행에서는 다시 되묻지 않는다.

### 인젝션 검사

- 기억 쓰기(`memory_write`)와 후속 조치 등록의 서버 쪽 경로에서, 명세의 세 갈래 지시문 패턴을 찾는다.
  - 지시 무시 문구: "ignore previous instructions", "이전 지시를 무시" 등.
  - 맥락 태그 위조: `</external_data>`, `<system>` 등.
  - 디코드·실행 파이프: `base64 -d`, `eval(atob(`, 셸로 넘기는 `| sh`(뒤 경계까지 본다: "| show"는 걸리지 않는다) 등.
- 사용자 자신의 규칙("광고 메일은 무시해")이 걸리지 않게 패턴을 좁게 잡았다.
- 걸리면 반영하지 않고 보류 카드(승인 종류 `held_write`, 3일)를 올린다.
  - 카드는 무엇이 왜 걸렸는지와 내용 전부를 이스케이프해 보인다.
  - [적용]을 누르면 쓴다. 기억은 보류할 때의 개정 번호를 다시 확인하고, 그사이 바뀌었으면 쓰지 않는다.
  - [버리기]나 답이 없으면 아무것도 하지 않는다.
- 모델에게는 "보류했다, 같은 내용을 다시 쓰지 말라"고 돌려준다.

### 하루 기억 변경 확인(명세 "하루 한 번 Discord로 변경 요약과 되돌리기 버튼")

> 결정 0027(2026-11-17)에서 없앴다. 되돌리기는 관리 페이지 기억 화면의 변경 기록에서 한다.

- 내장 루틴 `memory-digest`가 매일 21:00(현지 시각)에 돈다. 모델은 부르지 않는다.
- 지난번 뒤에 Lucia가 바꾼 항목마다 카드(승인 종류 `memory_undo`, 24시간)를 올린다. 사용자가 마지막에 손댄 항목은 묻지 않는다.
  - 카드에는 지금 요약, 되돌리면 어떻게 되는지, 바뀐 횟수, 마지막 까닭이 보인다.
  - [되돌리기]는 그날 바뀌기 전으로 돌린다. 그날 새로 만든 항목이면 지운다. 카드 뒤에 또 바뀌었으면 하지 않는다.
  - [그대로 두기]나 답이 없으면 그대로 둔다.
- 카드는 5장까지 올리고, 나머지는 한 줄로 알린다. 바뀐 것이 없으면 메시지도 없다.

### 자동 실행 한도(관리 페이지 시스템 화면 "자동 실행 한도")

- **비용 상한**(명세 "일·주 상한을 두고 넘으면 알림 또는 일시 정지"): 하루 상한과 최근 7일 상한을 달러(원장의 API 환산)로 정한다. 비우면 끈다.
  - 넘으면 데몬이 스스로 부르는 실행(아침 브리핑, 후속 조치)을 멈추고 하루 한 번 알린다.
  - 후속 조치는 1시간 뒤로 미룬다. 건너뛰지 않는다.
  - 사람이 보낸 채팅, 관리 페이지 "기억해 줘", 세션 정리는 막지 않는다.
- **방해 금지**(명세 §알림 묶기): `HH:MM-HH:MM`(현지 시각, 자정을 넘어도 된다)이다.
  - 그 시간의 후속 조치는 끝나는 시각으로 미룬다.
  - 하루 기억 확인은 다음 번에 모아서 한다. 지난번 시각부터 모으므로 빠지는 것이 없다.
  - 오류 알림은 바로 보낸다(긴급으로 본다).
- 관리 화면:
  - 개요에 "Lucia가 약속한 일"(예정 목록과 취소, 최근에 끝난 것)을 보인다.
  - 활동 기록에 등록, 취소, 함, 되묻기, 보류를 남긴다.

## 확인(2026-11-17)

- **시험**:
  - 인젝션 패턴: 걸릴 것과 걸리지 않을 사용자 규칙.
  - 방해 금지: 자정을 넘는 시간대.
  - 비용 상한: 하루·주, 7일이 지나면 풀림.
  - 후속 조치 규칙: 이른 시각, 후속 조치의 30분, 1년, 30개, 수상한 글.
  - 약속 표현 감지.
  - MCP:
    - 실행별 허락: 보고만 하는 실행은 등록을 못 하고, 백그라운드는 취소를 못 한다.
    - 수상한 후속 조치와 기억 쓰기는 보류한다.
  - 데스크: 보류 적용(개정 불일치는 거절)·버리기, 되돌리기(이전 개정, 새 항목 지우기, 그 뒤 바뀌었으면 거절).
  - 관리 화면: 한도 저장, 잘못된 값 거절, 취소하면 스케줄도 멈춤.
- **수용 시험**(`engine::tests::promised_followup_wakes_the_resident_session_and_reports`):
  1. 등록하면 다음 대화 맥락에 진행 상태가 붙는다.
  2. 시각 전에는 스케줄러가 아무것도 내지 않는다.
  3. 시각이 되면 상주 세션을 `Followup` 실행으로 깨운다.
  4. 결과를 보내고 닫는다.
  5. 다시 깨워도 건너뛰고, 할 것이 없으면 모델을 부르지 않는다.
- **또 다른 시험**:
  - 방해 금지, 비용 상한(알림은 하루 한 번), 브리핑 정지에서 모델을 0번 부른다.
  - 미등록 약속은 한 번만 되묻고, 사용자에게 보내는 것이 없다.
  - 하루 확인 카드는 Lucia가 바꾼 항목만 올린다.
- **실제 모델**(sonnet, 개발 저장소): "내일 오전 9시에 택배가 도착했는지 메일로 확인해서 알려 줘"에 `followup_create`를 불러 등록했고, 그 시각을 답에 적었다.
  - 새벽 2시의 "내일"을 같은 날 아침으로 읽었고, 답에 날짜를 밝혀 사용자가 고칠 수 있게 했다.
- **실제로 아직 안 본 것**: 운영에서 후속 조치가 실제로 발사되어 Discord로 오는 것, 보류·되돌리기 카드의 실제 Discord 모양.

## 하지 않은 것

- **작업 세션과 작업별 Discord 스레드, 작업 상태 머신**: 지금은 DM만 쓴다. DM에서 스레드를 쓸 수 있는지, 아니면 전용 채널(사용자 결정)이 필요한지 확인한 뒤에 한다.
- **주기 점검**(기한 임박, 답 없는 일, 연결된 소식)과 **하루 정리**(에피소드를 기억으로 요약, 오래된 원본 정리): 정리는 되돌릴 수 없는 삭제가 끼므로 [제안]으로 남긴다.
- **알림 묶기**: 같은 시간대 소식을 브리핑 하나로 묶는 것. 지금은 방해 금지만 한다.
- **Claude 로그인 만료 리마인더**: 로그인 시각이나 만료를 알 근거가 PoC에 없다(P1). 실행 오류에서 로그인 만료를 감지해 알리는 경로는 이미 있다.
