# 0058. 스크립트의 인터넷: 통행증이 있는 실행만, 데몬 출구 프록시로

- 날짜: 2026-11-20
- 상태: 확정. 연결 수 상한(128)과 실행 하나에 적는 호스트 수(40)는 [제안].
- 결정 방식: 사용자 지시. 결정 0057의 "더 풀 수 있는 것" 셋을 두고 "더 풀 수 있는 것 전부 진행해". 이 문서는 그 3번(스크립트 샌드박스의 네트워크)이다.
- 관련 결정: 0008(브라우저 출구 프록시), 0025(스크립트 샌드박스), 0029(출구 검사), 0040(권한 모드), 0047(패키지 설치)
- 바꾸는 것:
  - 결정 0025의 "네트워크 허용 규칙을 하나도 두지 않는다": 스크립트 샌드박스에 허용 규칙 하나(데몬의 출구 프록시 포트)를 늘 둔다.
  - 결정 0047의 "색인의 이름으로만 설치한다": 사람이 대화 중인 실행의 코드는 `pip`·`git`으로 어디서든 가져올 수 있다(`lib_install`의 규칙은 그대로다).

## 결정

- **길**: 데몬이 HTTP 프록시를 하나 더 연다(`crate::script::net`, 설정 `[scripts] proxy_bind`, 기본 `127.0.0.1:47812`). `CONNECT`(https)와 평문 http 요청을 받는다.
  - sbx 정책으로 바깥을 직접 열지 않는다. sbx는 이름으로 풀린 사설 IP를 막지 못한다(PoC P8b).
  - 검사는 브라우저 출구와 같은 코드다: 80·443만, 차단 목록(관리 페이지의 목록과 내장 목록), 이름을 한 번 풀어 사설·내부 주소를 거르고 그 IPv4 주소로만 연결.
- **통행증**: 요청마다 `Proxy-Authorization`의 통행증을 본다.
  - 실행 하나에 하나를 내주고, 실행이 끝나면 거둔다. **그 통행증으로 열려 있던 연결도 함께 끊는다**(코드가 띄워 두고 간 프로세스가 실행 뒤에도 쓰지 못하게).
  - 통행증은 표준 입력의 첫 줄로 넘긴다(호스트의 프로세스 목록에 남지 않는다). 실행기가 `HTTP_PROXY`·`HTTPS_PROXY`·`ALL_PROXY`에 넣는다. 그래서 `requests`·`urllib`·`curl`·`git`·`pip`가 그대로 된다. 코드는 `lucia.online`으로 나갈 수 있는지 안다.
  - 통행증 없이 온 요청은 407이다. git처럼 407을 받고 같은 연결로 다시 보내는 클라이언트를 받는다(3번까지).
- **누구에게**: 사람이 대화 중인 실행의 `code_run`에만 준다(브라우저를 쓸 수 있는 실행).
  - 사람 없는 실행(브리핑, 후속 조치, 작업, 목표 점검), 반복 루틴, 스킬 스크립트는 받지 못한다. 예전처럼 `lucia.fetch`·`lucia.download`로만 나간다(사람 없는 실행은 위임한 사이트만).
  - 프록시는 TLS 안을 보지 못해 나가는 글 검사(결정 0029)가 걸리지 않는다. 그래서 그 검사가 "막기"이거나 권한 모드가 엄격이면 통행증을 내주지 않는다.
- **샌드박스 규칙**: 스크립트 샌드박스의 허용 규칙은 `localhost:<프록시 포트>` 하나다.
  - 데몬이 뜰 때와 패키지 설치 앞뒤로 허용 규칙을 치우는 일(결정 0047)이 이 규칙은 남기고, 없으면 건다. 설정에서 끄면(`[scripts] net = false`) 치운다.
  - `deploy/create-script-sandbox.sh`도 같은 일을 한다(`LUCIA_SCRIPT_PROXY_PORT`).
  - 상주 샌드박스와 브라우저 샌드박스는 이 포트를 허용하지 않는다(`luciad check`가 본다).
- **기록**: 나간 호스트를 활동 기록의 코드 실행 줄에 남긴다("인터넷: github.com, pypi.org"). 프록시가 막은 연결은 까닭과 함께 코드 결과에 싣는다.
- **끄기**: `[scripts] net = false`.

## 위험과 받아들인 것

- **읽은 자료가 나갈 길이 넓어진다.** 대화 중인 실행의 스크립트는 다리로 메일·일정을 읽을 수 있고, 이제 그것을 아무 https 주소로 보낼 수 있다(전에는 `lucia.fetch`의 GET 주소에 싣는 길뿐이었고, 그 길은 주소마다 기록되고 검사됐다). 웹·메일의 글에 속은 Lucia가 그런 코드를 쓰면 막을 장치가 없다. 호스트 이름만 기록에 남는다. 사용자가 받아들였다(결정 0057의 3번 설명을 보고 진행을 지시).
- **같은 VM의 다른 스크립트가 통행증을 볼 수 있다.** 통행증은 그 프로세스의 환경 변수에 있고, 같은 사용자로 도는 다른 스크립트(같은 때 도는 루틴)가 `/proc`에서 읽을 수 있다. 실행이 끝나면 쓸 수 없다. 나쁜 패키지가 설치된 경우의 위험(결정 0047)에 "대화 중인 스크립트가 도는 동안 바깥으로 나간다"가 더해진다.
- **`lib_install`의 제한이 대화 중인 코드에는 의미가 줄었다.** 코드가 `pip install`을 직접 부를 수 있다(시스템 자리는 `sudo`가 필요하고 그것도 된다). 설치한 것이 뒤의 스크립트와 함께 도는 위험은 결정 0047과 같다. 의심스러우면 샌드박스를 다시 만든다.
- 포트는 80·443뿐이다. ssh로 하는 git, 다른 포트의 API는 되지 않는다.

## 확인(2026-11-20)

- **시험**: 프록시(통행증 없으면 407, 같은 연결로 다시 보내면 통과, 틀린 통행증 407, 차단 목록·사설 주소로 풀리는 이름·사설 주소·다른 포트·내부 이름·Anthropic 쪽 403과 연결하지 않음, 평문 요청에서 통행증과 프록시 헤더를 떼고 원 서버로, 실행이 끝나면 터널이 끊기고 그 통행증으로 다시 못 엶), 실행(사람이 대화 중인 `code_run`만 받고 나간 호스트가 활동 기록에 남음, 사람 없는 실행·브라우저 없는 실행·"막기"·엄격은 못 받음, 루틴은 청하지 않음), 규칙 치우기(프록시 규칙 하나만 남김).
- **개발 스크립트 샌드박스**(`luciad script-check`, 실제 네트워크): 통행증이 있는 실행에서 urllib·curl(https, http)·git(`ls-remote`)·pip가 나갔다. 사설 주소와 데몬 이름은 403, 통행증을 뗀 요청은 407이었다. 통행증을 주지 않은 실행은 프록시에 닿아도 407이었다.
- 실제 모델로는 상주 VM에 도구를 여는 작업(다음 결정)과 함께 본다.
