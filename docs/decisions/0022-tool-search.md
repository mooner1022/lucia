# 0022. 도구 찾기: 대분류 색인, 파라미터까지 주는 검색, 자주 쓰는 도구만 바로 보이기

- 날짜: 2026-11-17
- 상태: 확정. 바로 보일 도구 선정과 문턱 값은 [제안].
- 결정 방식: 사용자 지시. 다음을 따른다.
  - "앞으로 많은 도구가 추가될 예정이고, 이를 모두 컨텍스트에 담고 있는 것은 공간 낭비가 심하지."
  - "메모리 체계를 개선한 것과 같이 도구를 대분류로 나누고, 필요한 것을 검색하여 사용할 수 있도록."
  - "각 대분류는 간략한 설명을 함께 담고 있고, 검색 시 파라미터를 함께 보여주어 한 번의 검색으로 도구 사용이 가능하도록."
  - "자주 사용했거나 자주 사용이 예상되는 도구들은 대분류 밖에 보여주어 검색 수를 줄이고."
  - 결정 0007(기억: 색인에는 이름·제목·요약만, 세부는 읽어서)과 같은 모양이다.

## 문제

- 데몬 MCP 도구 37개의 정의(설명과 파라미터 스키마)가 실행마다 모두 모델의 도구 목록에 들어갔다. 그 실행에서 쓸 수 없는 도구도 들어갔다.
- 도구가 늘수록(외부 기기 명령 등) 컨텍스트를 그만큼 먹는다.

## 결정

### 도구 표에 대분류와 "바로 보임"

- 도구 표(`tools.rs`, 결정 0013)의 도구마다 대분류(`Category`)를 둔다. 대분류에는 id, 이름, 한 줄 설명이 있다.
  - 기억(memory), 메일·일정(google), 브라우저(browser), 작업(tasks), 후속 조치(followups), 스킬(skills), 파일(files), 페이지 감시(watches).
  - 대분류는 찾기 위한 묶음이고, 허락 단위인 갈래(`Group`)와 따로 둔다. 예: 작업 대분류 안에 작업 맡기기·진행 알림·개발 push가 함께 있다.
- **바로 보이는 도구**: 찾지 않고 바로 부르는 도구다.
  - **늘 보임**(`featured`, 자주 쓰일 것으로 보는 것): report_result, memory_read, memory_write, mail_search, calendar_events, followup_create, browser_open, task_start, task_update, skill_read.
  - **사용 기록으로 올림**: 최근 30일에 5번 넘게 쓴 도구 가운데 많이 쓴 5개(`run_tools`와 원장).
    - 하루에 한 번 다시 고른다. 도구 목록이 자주 바뀌면 프롬프트 캐시가 깨진다.
    - 운영 기록에서는 browser_screenshot(7번)이 올라간다.
- 새 도구는 표에 대분류와 함께 더하면 찾기에 바로 나온다. 시험이 표와 서버의 도구가 맞는지 본다.

### 모델이 보는 도구 목록

- 바로 보이는 도구와 `tool_search`, `tool_call`만 있다. 37개 17,982자에서 13개 8,915자로 줄었다(절반). 도구가 늘어도 목록은 거의 그대로다.
- **실행 종류와 상관없이 같은 목록이다**:
  - 상주 세션은 채팅·브리핑·후속 조치·하루 정리가 함께 쓴다. 실행마다 목록이 다르면 바뀔 때마다 프롬프트 캐시가 깨진다.
  - 그래서 실행 범위는 목록이 아니라 찾기와 부르기에서 지킨다.
  - 권한 확인 전용 `request_approval`은 허락이 없는 PoC 실행에만 보인다.

### 찾기: `tool_search(query?, category?)`

- **설명에 대분류 색인이 들어간다**: 대분류마다 id, 이름, 한 줄 설명, 도구 이름. 실행과 상관없이 같다.
- **입력**:
  - `category`: 대분류 id나 이름. 그 대분류의 도구를 모두 준다.
  - `query`: 검색어. 이름 3, 대분류 2, 설명·파라미터 1점으로 점수를 매겨 5개까지 준다.
- **결과**: 도구마다 설명과 파라미터(`- 이름 (형, 필수): 설명`)를 준다.
  - `$ref`, enum, 선택 값, 배열, 안의 객체를 펼쳐 보인다.
  - 한 번 찾고 바로 부를 수 있다.
- 이 실행에서 쓸 수 없는 도구는 찾기에 나오지 않는다. 예: 브리핑에서 메일 발송, 하루 정리에서 브라우저.

### 부르기: `tool_call(name, arguments)`

- 데몬의 MCP `call_tool`이 받아, 실행 범위를 확인한 뒤 그 도구의 처리로 넘긴다.
  - 그 도구 안의 확인(결정 0013)도 그대로 한 번 더 돈다.
  - 결과는 직접 부른 것과 같다.
- **거절하는 경우**: 모르는 도구, 찾기·부르기 자신, 범위 밖, 객체가 아닌 파라미터. `arguments`가 JSON 글이면 풀어서 받는다.
- **실행 기록**: 실행 출력의 `tool_call`은 실제로 부른 도구로 펼쳐 남긴다(`lucia-runner`의 stream-json 해석).
  - 진행 알림("📨 메일 검색: …"), 도구 흔적(결정 0018의 회고·스킬 승인 판단), 사용 횟수가 실제 도구를 본다.
  - `tool_search`는 알리지 않는다.
- **허용 목록**: claude `--allowedTools`에 보고 말고도 쓸 도구가 있는 실행이면 `tool_search`·`tool_call`을 더한다.
- **훅**: 보호 영역인 훅(`only-lucia-tools.sh`)은 `mcp__lucia__*`를 통과시키므로 바꾸지 않았다. 부르기는 데몬 도구로만 넘기므로 "데몬 도구와 정한 내장 도구만"이라는 훅의 경계가 그대로다.

### 지시

- MCP 서버 안내문과 요청마다 붙는 한 줄로 알린다: 목록에 있는 도구는 직접 부르고, 없는 도구는 `tool_call`로 부르며, 파라미터를 모르면 `tool_search`로 찾는다.
- 요청마다 붙이는 줄이 필요했다(아래 실측). 지침과 상주 대화 기록에 도구 이름이 그대로 나와 있어, 모델이 목록에 없는 도구를 직접 부르다 한 번 실패했다.

## 확인(2026-11-17)

- **시험**:
  - 표: 모든 도구에 대분류가 있다. 바로 보이는 것은 3분의 1 이하다. 색인과 대분류 이름이 맞는다.
  - 사용 기록 올림: 문턱, 표 밖·늘 보임은 빼기.
  - 원장: 최근 실행만 센다.
  - 파라미터 표시: 형, 필수, 설명, `$ref`·enum, 필수 먼저.
  - 찾기: 검색어, 대분류(id·이름), 실행 범위 밖은 안 나옴, 모르는 대분류.
  - 부르기:
    - 허락된 도구로 풀린다. `mcp__lucia__` 접두사와 JSON 글 파라미터도 받는다.
    - 찾기·부르기 자신, 모르는 도구, 범위 밖, 이름 없음은 거절한다.
  - 서버:
    - 표와 서버의 도구가 맞는다. 목록은 절반 아래이고 실행 종류와 상관없이 같다.
    - `request_approval`은 PoC에만 보인다. 사용 기록으로 browser_screenshot이 오른다.
  - 실행 기록: `tool_call`을 실제 도구로 펼친다. 이름이 없으면 그대로 둔다.
- **실제 모델**(개발 샌드박스 `lucia-dev`, sonnet):
  - **요청마다 붙는 줄 없이**: "보내는 주소 목록" 요청에서 모델이 먼저 `mcp__lucia__mail_aliases`를 직접 불렀다. Claude Code가 "No such tool available"로 거절했고, 다음 턴에 `tool_call {"name": "mail_aliases"}`로 성공했다. 한 턴을 버렸다.
  - **요청마다 붙는 줄과 함께**:
    - "열린 후속 조치 목록": 첫 호출이 바로 `tool_call {"name": "followup_list"}`였다.
    - "가장 최근 메일": `tool_call`로 파라미터(`query`, `limit`)를 넣어 불렀다.
    - 이때 바로 보이는 mail_search까지 `tool_call`로 불렀다. 동작은 같다. 그 뒤 줄에 "목록에 있는 도구는 직접 부른다"를 더했다.
- **실제로 아직 안 본 것**:
  - 운영 상주 세션에서 캐시가 하루 한 번만 깨지는지(사용 기록 올림이 바뀌는 날).
  - 처음 보는 도구를 `tool_search`로 찾아 파라미터를 채워 부르는 긴 흐름(브라우저 조작 등). 시험에서는 모델이 색인의 이름과 지침만으로 바로 불렀다.

## 하지 않은 것

- **실행마다 다른 목록**: 캐시 때문에 하지 않았다. 범위 밖 도구는 찾기·부르기에서 막는다.
- **모델이 고른 도구를 목록에 더하기**(MCP `tools/list_changed`): 실행 중에 Claude Code가 목록을 다시 읽는지 확인하지 않았고, 캐시도 깨진다. 부르기 도구 하나로 충분하다.
- **Claude Code 내장 도구 찾기**(ToolSearch): 보호 영역인 훅이 내장 도구를 막는다. 대분류 설명도 붙일 수 없다.
