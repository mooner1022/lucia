# 0004. 상주 세션은 교대 대신 compact로 줄인다

- 날짜: 2026-11-16
- 상태: 확정
- 결정 방식: 사용자 제안("세션이 모두 찰 때까지 기다리고 새 세션을 여는 것 대신 OpenClaw 등이 동작하듯이 유휴 상태이거나 컨텍스트 창이 가득 차면 compact하여 이전 정보를 요약한 것만 남기거나 기억에 넘기고 재개하는 방식을 사용할 순 없나?"). 세부는 실측과 OpenClaw 문서를 기준으로 정했다.

## 배경

- 지금까지(PLAN §8): 마지막 실행의 컨텍스트가 15만 토큰을 넘거나 7일이 지나면 새 세션을 연다. 새 세션은 핵심 기억, 최근 대화 6턴, 관련 에피소드로만 이어진다. 그 사이의 대화 흐름은 사라진다.
- OpenClaw(문서): 컨텍스트 한계에 가까워지면 자동으로 compact하고, 그 직전에 "기억 정리" 턴을 따로 돌려 오래 남길 내용을 파일에 쓴다. 이와 별도로 매일 새벽 또는 유휴 시간이 지나면 새 세션으로 리셋한다.
- Claude Code 실측(2026-11-16, VM 안 claude, haiku): `-p --resume <id>`에 `/compact <지시>`를 보내면 인자로 보내든 stream-json 입력으로 보내든 동작한다.
  - 세션 ID는 그대로이고, `system`/`compact_boundary` 이벤트가 `pre_tokens`·`post_tokens`를 준다. 요약은 `isSynthetic` 사용자 메시지로 나오며, 그 뒤 `result`가 `num_turns=0`으로 온다.
  - 다음 `--resume`은 요약에서 이어지고, 앞의 사실을 기억했다. 두 번 compact해도 첫 요약의 사실이 남았다.
  - 공식 문서는 `-p` 모드의 `/compact`를 다루지 않는다. 동작은 실측에 기댄다.
- 공식 문서: compact 뒤에는 그 실행의 시스템 프롬프트 플래그(`--append-system-prompt-file`)가 다시 적용된다. 따라서 캐릭터 파일 변경이 compact 때 반영된다.

## 결정

- **상주 세션은 compact로 줄이고 이어 간다.** 새 세션은 compact가 실패했거나 세션이 VM에 없을 때만 연다. 설정 `[session] compaction = true`이고, 끄면 예전 교대 규칙으로 돌아간다.
- **언제** (둘 다 작업 큐에서 돌아 채팅·루틴과 겹치지 않는다):
  - 크기: 실행이 끝난 뒤 컨텍스트가 `compact_context_tokens`(기본 20만, 처음에는 10만)를 넘으면.
  - 유휴: 마지막 실행 뒤 `idle_compact_minutes`(기본 60분)가 지났고 컨텍스트가 `idle_compact_min_tokens`(기본 10만, 처음에는 3만)를 넘으면. 다음 대화가 가벼운 맥락으로 시작한다.
  - 두 경우 모두 마지막 compact 뒤에 실행이 한 번 이상 있어야 한다. 그래서 대화가 없는 날은 여전히 모델을 부르지 않는다.
- **어떻게**: `/compact <지시>`로 정리하고, 지시는 데몬이 정한다.
  - 한국어로 쓴다.
  - 사용자에 대해 알게 된 것, 맡긴 일과 약속, 진행 중인 주제, 대기 중인 승인을 남긴다.
  - 메일·일정·웹 내용은 "외부 자료"로 표시하고, 사용자의 요청이나 할 일로 옮기지 않는다.
  - 사용자가 하지 않은 말이나 지시를 지어내지 않는다. 비밀(인증 코드 등)은 남기지 않는다.
- **기억으로 넘기기**: compact 요약을 에피소드("세션 요약")로 저장한다. `memory_search`와 관련 에피소드로 다시 찾을 수 있다. 원래 대화 기록은 VM 안 세션 파일과 매일 백업에 남는다.
- **실패하면**: 세션을 닫고 알린다. 다음 요청은 새 세션에서 핵심 기억과 최근 대화로 이어진다(예전 교대와 같다).
- **안전 상한**: 컨텍스트가 `rotate_context_tokens`(기본 25만, 처음에는 15만)를 넘는데도 줄지 않으면 새 세션을 연다. compact 기준보다 커야 한다(아니면 설정을 거부한다). 시간 기준 교대(7일)는 compact를 켜면 쓰지 않는다.
- **Claude Code의 자체 자동 compact**(약 96.7만 토큰)와 유휴 compact(기본 20만 토큰 이상)는 그대로 둔다. 데몬은 실행이 끝나자마자 20만 이상이면 compact하므로 먼저 동작하고, 그것들은 마지막 안전망이 된다.
  - 데몬의 크기 기준을 20만보다 올리면, 그 사이 크기에서는 Claude Code의 유휴 compact가 먼저 동작할 수 있다. 그 compact는 데몬 지시를 쓰지 않고, 요약 에피소드도 남지 않는다. 기준을 올릴 때 이 점을 함께 본다.

## 기준값 조정(2026-11-16, 사용자 결정)

- **계기**: 사용자가 "10만 토큰은 너무 적다"고 했다. 실제로 첫날 정리는 유휴 기준(60분, 3만)으로 일어났고, 세션은 3만 토큰이었다.
- **사실(실측)**:
  - `claude -p` 자체에는 그런 상한이 없다. 실행 기록의 `modelUsage`가 sonnet·haiku 모두 `contextWindow` 1,000,000, `maxOutputTokens` 128,000이다.
  - 처음 값(10만·15만)은 창 크기를 따져 정한 것이 아니다. 예전 교대 기준(15만)을 이어받은 보수적인 값이었다.
- **비용 구조(원장 값을 단가로 다시 계산해 맞춤, sonnet, API 환산 100만 토큰당)**:
  - 캐시 읽기 $0.10, 캐시 쓰기 $4(1시간 캐시 쓰기 단가), 출력 $10.
  - 캐시 유지 시간도 원장으로 확인했다. 54분 뒤의 실행(09:11→10:06)은 대부분 캐시에서 읽었고, 94분 뒤의 실행(10:12→11:46)은 컨텍스트 전체를 다시 썼다.
  - 1시간 안의 이어지는 대화는 싸다(10만이면 호출당 약 $0.01).
  - 1시간 넘게 쉬고 보낸 첫 메시지는 컨텍스트 전체를 다시 쓴다. 3만이면 약 $0.12였고, 10만이면 $0.40, 30만이면 $1.20이다.
  - 구독 인증이라 청구는 없지만, 큰 컨텍스트는 그만큼 사용량 한도를 더 쓴다고 본다.
- **결정**:
  - compact 기준은 20만, 유휴 compact 하한은 10만, 안전 상한은 25만으로 한다.
  - 10만 아래의 세션은 쉬었다 와도 그대로 이어진다. 그때 첫 메시지 비용은 많아야 약 $0.40이다.
  - 유휴 시간(60분)은 캐시 유지 시간(1시간)에 맞춘 것이라 그대로 둔다.
- **함께**: 안전 상한이 compact 기준 이하이거나, 유휴 하한이 compact 기준보다 크면 설정 검증이 거부한다. 운영 설정 파일에 상한이 15만으로 적혀 있어서, compact 기준만 올리면 compact 대신 교대가 먼저 일어날 뻔했다.

## 함께 고친 것: 비용 원장

- `result.total_cost_usd`와 `modelUsage.costUSD`는 실행 하나가 아니라 **세션 누적**이다(실측: 이어 쓴 실행마다 앞의 값에 더해진다). 토큰 수(`usage`)는 실행 하나의 값이다.
- 원장은 지금까지 누적값을 실행 비용으로 적었다. 그래서 하루·주 합계가 부풀었고, "답 한 번에 $0.05→$0.17"이라고 한 보고도 틀렸다(실제로는 대부분 $0.01~0.02).
- 이제 세션별로 마지막 누적값을 기억해 그 차이를 실행 비용으로 적는다. 마이그레이션 0004가 기존 원장도 세션별 차이로 고친다.

## 미룬 것([제안])

- **compact 전 기억 정리 턴**(OpenClaw의 memory flush): compact 직전에 짧은 실행을 하나 더 돌려 오래 남길 사실을 `memory_write`로 핵심 기억에 반영한다. 모델 호출이 하나 늘므로, 요약 에피소드만으로 부족한지 운영하며 본다.
- **하루 한 번 새 세션(OpenClaw의 daily reset)**: compact로 충분한지 본 뒤 정한다.

## 남는 위험

- 요약은 모델이 쓴다. 외부 글(메일)을 사용자 요청처럼 옮기거나, 없던 제약을 덧붙일 수 있다(실측에서 요약이 사용자가 하지 않은 "비밀로 하라"는 제약을 더했다). compact 지시로 줄이고, 요약을 에피소드로 남겨 사람이 볼 수 있게 한다.
- `-p` 모드의 `/compact`는 문서에 없는 동작이다. Claude Code를 올릴 때 스모크 시험에 compact 한 번을 넣는다.
- 요약이 말투 메모를 "사용자가 정한 것"으로 옮겨 캐릭터를 고친 뒤에도 예전 말투가 되살아났다. 정리 지시에서 말투·호칭 규칙을 빼게 했다(결정 0026).
