# 0052. 파일 보관함: 남길 파일은 지워지지 않게 둔다

- 날짜: 2026-11-20
- 상태: 확정. 상한(500개, 합계 2 GiB)은 [제안].
- 결정 방식: 사용자 지시("1, 2, 4, 5 … 개선해")의 4번(오래 보관되는 작업 공간이 없다).
- 관련 결정: 0005(파일, 30일 보관), 0048(file_view)

## 배경

- 주고받은 파일과 만든 그림은 30일 뒤 지워진다(결정 0005). "이건 보관해 둬"를 받을 곳이 없었다.

## 결정

- **보관함**(`kept_files` 표, 마이그레이션 0029): 보관한 파일은 30일 정리에서 빠진다. 찾기 쉬운 이름(60자)과 한 줄 설명(200자)을 붙일 수 있다.
- **넣고 빼기**: Lucia의 도구 `file_keep`(로컬 쓰기). 사용자가 보관해 달라고 하거나 두고두고 쓸 결과물일 때 쓴다. `keep=false`면 뺀다. 뺀 파일은 30일 규칙으로 돌아간다.
- **찾기**: `file_view`를 ID 없이 부르면 보관함이 최근 파일 위에 나온다. `query`로 파일 이름·보관 이름·설명을 찾는다. 보는 도구(읽기)에 쓰기를 넣지 않고 따로 두었다.
- **상한**: 500개, 합계 2 GiB. 디스크가 93%까지 찼던 일이 있어(빌드 디렉터리 때문이었다) 끝없이 쌓이지 않게 했다.
- **관리 페이지**: 설정 "작업과 보관"에 "파일 보관함" 패널(이름, 설명, 종류, 크기, 내려받기, 빼기). 내려받기는 브라우저가 열지 않게 첨부로 준다(파일 내용은 믿지 않는다). 기능 보존 기준 목록은 추가 6줄, 삭제 없음.
- 지침에 한 줄을 더했다: "파일은 30일 뒤 지워진다. 보관해 달라고 하거나 두고두고 쓸 결과물이면 file_keep".

## 하지 않은 것

- 폴더, 버전, 파일 이름 바꾸기. 이름과 설명으로 찾는 납작한 보관함이다.
- 관리 페이지에서 파일 올려 넣기(대화에서 붙이고 보관해 달라고 하면 된다).
- Google Drive 같은 바깥 저장소와 맞추기.
- 이모지·스티커 그림은 따로 보관된다(결정 0045). 여기 넣을 필요가 없다.

## 확인(2026-11-20)

- **시험**: 저장소(보관한 파일은 정리 대상에서 빠지고, 빼면 돌아온다), 도구(넣기, 없는 파일, 목록의 보관함, 찾기, 40일 뒤 정리에서 보관한 것만 남기, 빼기), 관리 페이지(목록, 이스케이프, 내려받기의 로그인·첨부 머리, 빼기), 기능 보존·접근성.
- 실제 모델로는 아직 보지 않았다(다음 배포 뒤 대화에서 "보관해 둬"로 본다).
