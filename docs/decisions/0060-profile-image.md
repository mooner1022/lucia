# 0060. Lucia가 자기 프로필 이미지를 보고 정한다

- 날짜: 2026-11-20
- 상태: 확정. 규칙의 값(한 변 128~2048px, 3 MiB, 예전 그림 20개)은 [제안].
- 결정 방식: 사용자 지시("루시아가 스스로의 프로필 이미지를 확인하고 설정할 수 있도록 해. 디스코드는 가능하다면 넣고, 일단 휴대폰 앱 연동에서 기능하는 것을 우선시해.").
- 이어지는 결정: 0064(소유자도 관리 페이지에서 프로필 그림을 정하고 지운다. 아래 "하지 않은 것"의 첫 항목이 바뀌었다. 같은 규칙·같은 길을 쓰고 `by`가 `owner`로 남는다. 이름도 함께 생겼다)
- 관련 결정: 0043(앱 접속 API), 0045(앱 이모지·스티커: 그림을 검사만 하고 내용 해시 id로 내준다), 0046(이미지 생성), 0048(만든 것을 직접 확인), 0052(보관함), 0059(쉘, 승인)

## 결정

### 보관과 규칙(`crate::profile`)

- 데몬이 프로필 그림 하나를 보관한다. 파일은 `<data_dir>/profile/<id>`에, 지금 쓰는 것은 저장소 설정 `profile.avatar`에 둔다.
  - id는 내용 해시(`a_` + 16진수 24자)다. 그림이 바뀌면 id가 바뀌므로 앱이 id로 영구 캐시한다. 예전 그림은 최근 20개를 남긴다.
- 그림은 고치지 않고 검사만 한다(결정 0045와 같다. 데몬에 이미지 디코더를 두지 않는다).
  - 규칙: 움직이지 않는 PNG·JPEG, 정사각형, 한 변 128~2048px, 3 MiB까지.
  - 3 MiB는 Lucia가 도구 결과로 그림을 직접 볼 수 있는 크기와 같다(자기 프로필을 못 보는 일이 없게). 운영에서 받은 그림은 최대 2.3 MB, 만든 그림은 최대 442 KB였다.
  - 맞지 않으면 **어긴 것을 모두 한 번에** 알려 주고 고치는 법을 말한다(쉘이나 `code_run`에서 pillow로 자르고 줄이기). 휴대폰 사진은 정사각형이 아니고 크므로, 한 번에 다 알려야 여러 번 오가지 않는다.
  - JPEG의 크기는 프레임 머리(SOF)에서 읽는다(결정 0045의 검사에는 JPEG이 없었다).

### 도구 `profile_image`

- 인자 없이 부르면 **지금 프로필 그림을 그림으로 본다.** 정한 것이 없고 Discord가 연결되어 있으면 봇의 지금 아바타를 보여 준다.
- `file`에 파일 id를 주면 그 그림으로 정한다. `clear=true`면 없앤다.
- 늘 바로 보이는 도구다(찾기 뒤에 두면 "할 수 없다"고 답한다, 결정 0046의 경험).
- **승인 카드 없이 한다.** 되돌릴 수 있고, 사용자가 Lucia 스스로 하게 하라고 했다. 대신 정하기와 없애기는 **사람이 대화 중인 실행에서만** 한다(브리핑·루틴이 읽은 글에 속아 바꾸지 않게). 보기는 파일 도구가 있는 실행(대화, 작업, 브리핑, 후속 조치, 목표 점검)이면 된다.
- 정하기와 없애기는 활동 기록(`profile_image`)에 남는다.

### 전용 앱(우선)

- `welcome`과 `GET /v1/me`에 `profile` 필드: `{"avatar": {id, mime, width, height, size, updated_at} 또는 null}`. 필드가 없으면 기능이 없는 데몬, `avatar`가 `null`이면 정한 그림이 없다(이모지·스티커와 같은 약속).
- `GET /v1/profile`(같은 객체), `GET /v1/profile/avatar/{id}`(그림. 토큰이 있어야 하고, `immutable`로 오래 캐시).
- 그림이 바뀌거나 없어지면 연결된 앱에 번호 없는 `profile` 프레임을 보낸다. 꺼져 있던 앱은 다음 `welcome`에서 받는다. 앱은 모르는 `type`을 무시하게 되어 있어(사양서 4장) 고치지 않은 앱도 그대로 동작한다.
- 사양은 `docs/app-api.md`(5.3, 5.5, 8.2, 8.7, 8.8, 12.1, 14)와 `docs/app-api-changes.md`의 맨 위 항목에 적었다.

### Discord(연결되어 있을 때)

- 프로필을 정하면 봇의 아바타도 바꾼다(`PATCH /users/@me`, twilight 0.18의 `update_current_user().avatar()`). 공식 문서의 Image Data는 JPG·GIF·PNG의 데이터 URI다.
- **처음 바꾸기 전에 원래 아바타를 받아 보관함에 넣는다**(사용자가 개발자 포털에서 정해 둔 그림이다. 덮어쓰면 되찾을 길이 없다). 받아 두지 못하면 Discord는 바꾸지 않는다.
- 없앨 때는 원래 아바타로 되돌린다(원래 것이 없었으면 없앤다). 데몬이 바꾼 적이 없는 아바타는 건드리지 않는다.
- **사용자가 그 사이에 개발자 포털에서 아바타를 바꿨으면 그것을 다시 보관한다.** 데몬은 자기가 올린 뒤 Discord가 돌려준 아바타 표식(`seen`)을 기억해 두고, 다음에 바꿀 때 지금 것이 그것과 다르면 사용자가 바꾼 것으로 보아 새 원래 그림으로 보관함에 넣는다(없앨 때 그쪽으로 되돌아간다). 올린 바로 뒤에 표식을 읽지 못했으면 모르는 것으로 두고, 모를 때는 보관해 둔 원래 것을 바꾸지 않는다(Lucia가 올린 그림이 원래 것 자리에 들어가지 않게).
- Discord가 거절하면(자주 바꾸면 한동안 거절한다. 횟수는 공식 문서에 없다) 까닭을 Lucia에게 그대로 돌려주고, 앱 쪽 설정은 그대로 둔다.
- Discord가 연결되어 있지 않으면 앱에만 적용한다.

### 사용자가 직접 정하기(`luciad profile-image`)

- `luciad profile-image [--config <설정>] [<파일>] [--clear]`: 파일 없이 부르면 지금 것을 알려 주고, 파일을 주면 그 그림으로 정한다(규칙은 도구와 같다). 정한 사람은 `user`로 남는다.
- 저장소와 프로필 디렉터리만 고친다. 도는 데몬은 다시 띄워야 알고(연결된 앱에 프레임을 보내는 것은 데몬이다), **Discord 봇의 아바타는 건드리지 않는다.**
- 처음 값은 이 명령으로 넣었다(사용자 지시 "첨부한 이미지가 현재 사용중인 프로필이야. 초기값으로 설정해.", 1254×1254 PNG). 사용자의 말로는 Discord에 이미 걸려 있는 그림이므로(CDN이 내주는 것은 942×942로 다시 인코딩된 것이라 바이트로는 견주지 못한다) Discord 쪽 상태는 "데몬이 바꾼 적 없음"으로 둔다. 그래서 Lucia가 나중에 처음 바꿀 때 Discord의 지금 아바타가 보관함에 들어간다.

## 위험과 받아들인 것

- **Discord 아바타는 다른 사람에게도 보인다**(봇이 들어간 서버의 사람들). 승인 카드 없이 Lucia가 바꾼다. 사람이 대화 중일 때만이고, 원래 아바타는 보관한다. 카드를 원하면 결정 0059의 승인으로 돌릴 수 있다.
- 프로필 그림은 앱 토큰을 가진 쪽 모두가 받는다(앱마다 다른 그림은 없다).
- 그림의 내용은 검사하지 않는다(무엇이 그려졌는지). Lucia가 정한 뒤 직접 보게 했다.

## 하지 않은 것

- 관리 페이지에서 프로필 그림을 보거나 올리기. 지금은 Lucia에게 말해서 바꾼다.
- 푸시 알림에 그림 정보 싣기(앱이 캐시한 그림을 쓰면 된다).
- 이름·소개 같은 다른 프로필 항목. 이름과 말투는 캐릭터 파일의 일이다.
- 움직이는 그림, WebP.

## 확인(2026-11-20)

- **시험**(모델 없음, `luciad` 469개 통과):
  - 그림 읽기(PNG, 손으로 만든 JPEG, 실제 인코더가 만든 점진식·EXIF 포함 JPEG 픽스처), 받지 않는 형식, 어긴 규칙을 모두 알리기.
  - 보관(정하기, 바꾸기, 예전 그림, 없애기, 다시 뜬 데몬).
  - 접속 API: 기능이 붙기 전(필드 없음, `501`), `welcome`·`/v1/me`·`/v1/profile`, 그림 받기(200, 토큰 없으면 401, 없는 id 404, ETag·캐시 머리), 정할 때·바꿀 때·없앨 때의 `profile` 프레임, 나중에 붙은 앱의 `welcome`.
  - Discord(가짜): 연결 없음, 원래 아바타를 못 받으면 덮어쓰지 않음, 처음 바꿀 때 보관, 다시 바꿀 때 또 받지 않음, 사용자가 사이에 바꾼 아바타는 다시 보관, 지금 아바타를 확인하지 못하면 바꾸지 않음, 올린 뒤 확인이 실패했어도 원래 것을 지킴, 거절의 까닭 전달, 없앨 때 되돌리기, 원래 아바타가 없던 봇.
  - 도구의 문: 사람이 대화 중이면 정하고 없앤다(활동 기록). 사람 없는 실행(브리핑)은 보기만 되고 정하기·없애기는 거절되며 그림이 그대로다. 파일 갈래가 없는 실행(하루 정리)은 도구를 쓰지 못한다. 규칙을 어긴 그림은 어긴 것을 모두 듣고 바뀌지 않는다.
- **실제 봇 읽기**(`luciad discord-check`, 쓰지 않음): 봇의 지금 아바타를 CDN에서 받아 읽었다(PNG 942×942, 1.7 MB). 바꾸기 전에 보관하는 길의 읽는 쪽은 실제로 된다.
- **실제 모델**(개발 설정, 두 대화):
  - 가로로 긴 사진(2400×1600 JPEG)을 붙이고 "이 그림을 네 프로필 사진으로 해 줘. 얼굴이 가운데 오게.": `code_run`으로 얼굴이 가운데 오게 800×800 PNG로 자른 뒤 `profile_image`로 정하고, 다시 불러 직접 확인했다. 보관된 그림을 열어 보니 말한 대로였다.
  - 다른 대화에서 "지금 네 프로필 사진을 확인해 줘": 그림을 보고 맞게 설명했다.
- **보지 못한 것**:
  - **앱이 실제로 그리는 것**(여기서는 접속 API의 답까지만 본다).
  - **Discord 봇의 아바타를 실제로 바꾸는 것.** 개발용 실행에는 Discord가 없고, 운영 봇으로는 쓰기를 시험하지 않았다(읽기만 봤다). 쓰는 쪽은 가짜 시험뿐이다. 운영에서 Lucia가 처음 바꿀 때 확인된다(원래 아바타가 보관함에 들어가는지도).
  - Discord가 받는 그림 크기의 상한(공식 문서에 없다). 3 MiB 안에서 거절되면 까닭이 Lucia에게 간다.
