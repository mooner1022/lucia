# 0051. 실행 중인 대화를 "그만"으로 멈춘다

- 날짜: 2026-11-20
- 상태: 확정. 멈춤 말의 목록은 [제안].
- 결정 방식: 사용자 지시("1, 2, 4, 5 … 개선해")의 1번(긴 작업이 대화를 막고, 중간에 멈출 수 없다).
- 관련 결정: 0014(작업 세션), 0050(재시작 복구)

## 잰 것(운영 4일)

- 대화와 정기 작업은 한 줄로 차례대로 돈다(상주 세션 하나에 실행 하나).
- 대화 185건 가운데 25건이 40초를 넘었고, 가장 긴 것은 260초(도구 20번)였다. 그동안 다른 메시지와 정기 작업은 기다렸다.
- 실행 중인 턴을 끊는 길이 없었다. "그만"이라고 보내도 그 말은 큐에서 끝나기를 기다렸다.
- 오래 걸리는 일을 따로 하는 작업 세션은 4일 동안 한 번도 쓰이지 않았다.

## 결정

- **멈춤 말**: 그 대화의 실행이 도는 동안 소유자가 짧은 말 그대로 보내면 멈춘다. `그만`, `그만해(줘)`, `멈춰(줘)`, `중단(해)`, `취소(해)`, `스톱`, `stop`, `/stop`, `/그만`, `/중단`. 끝의 문장부호와 띄어쓰기는 무시한다.
  - 문장 속의 낱말("그만하고 다른 거 하자", "취소 수수료 알려 줘")은 멈춤이 아니다. 보통 메시지로 처리한다.
  - 도는 실행이 없을 때, 다른 대화에서 온 말, 소유자가 아닌 사람의 말도 보통 메시지다.
- **큐 밖의 길**: 받은 메시지를 큐에 넣기 전에 본다. 멈춤이면 큐에 넣지 않고 바로 실행을 끝낸다.
- **끝내는 방법**: VM 안의 그 실행을 실행별 토큰으로 골라 끝낸다(시간 초과 때 쓰던 길). 호스트 쪽은 곧 돌아온다.
- **그 뒤**: 실패 알림 대신 "[알림] 하던 일을 멈췄습니다."를 보낸다. 기록에는 그때까지 보낸 말과 "(사용자가 멈춰서 여기서 끝냄)"이 남는다. 다음 요청에 "직전 요청은 사용자가 도중에 멈췄다. 스스로 이어서 하지 않는다"를 한 번 싣는다.
- 멈출 수 있는 것은 사용자의 대화 실행이다. 브리핑·루틴 같은 정기 작업은 이 말로 멈추지 않는다. 작업 세션은 예전처럼 `task_cancel`이다.
- 앱도 같은 말을 `message`로 보내면 된다(따로 프레임을 만들지 않았다).
- 끝내는 명령이 멈춰도 받은 메시지의 길이 막히지 않게 15초 시간 제한을 두었다(그 길로 모든 메시지가 지나간다).

## 하지 않은 것

- **실행 중에 온 보통 메시지가 실행을 끊게 하기.** 사용자가 정하지 않았다. 지금처럼 차례를 기다린다.
- **긴 일을 자동으로 작업 세션으로 넘기기.** 지침에는 이미 "오래 걸리는 일은 task_start로"가 있다. 도구를 8번 부른 대화의 도구 결과 끝에 "남은 일은 작업으로 맡기라"는 안내를 넣어 보았다. 개발 설정에서 사이트 16곳을 여는 요청에 안내가 실렸는데도 Lucia는 대화 안에서 끝냈다(72초). 효과가 보이지 않아 뺐다.
  - 긴 일이 대화를 막는 문제 자체는 남아 있다. 지금 생긴 것은 멈출 수 있다는 것이다.
- 정기 작업을 대화와 따로 돌리기(같은 상주 세션을 쓰므로 같이 돌 수 없다).

## 확인(2026-11-20)

- **시험**: 받은 메시지의 길 전체(받기 → 큐 밖에서 멈춤 → 작업자)를 지나는 시험: 30초 걸리는 실행 중에 "그만"을 보내면 멈춤 알림이 바로 가고, "그만"은 모델에게 가지 않는다. 멈춤 말 판정. 20초 걸리는 실행을 "그만"으로 바로 끝내고, 멈춤 알림 하나만 가고, 기록이 남고, 다음 요청에 멈춘 사실이 실리는 것. 다른 사람·다른 대화·문장 속 낱말은 멈추지 않는 것.
- **실제**(개발 설정): 웹 검색을 여러 번 하는 요청을 돌리다가 VM 안의 실행을 같은 방법으로 끝냈다. 호스트 쪽은 1초 안에 "결과 이벤트 없이 끝났다"로 돌아왔다. 큐 밖의 길 전체(메시지 → 멈춤)는 운영에서 처음 쓸 때 본다(개발 명령 `ask`는 한 번에 한 메시지라 실행 중에 말을 보낼 수 없다).
