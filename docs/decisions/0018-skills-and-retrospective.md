# 0018. 스킬과 회고(5단계 도구화 루프의 첫 조각)

- 날짜: 2026-11-17
- 상태: 확정. 문턱·기간 값은 [제안]. 스킬을 넣는 길은 명세와 다르다([제안], 아래 "명세와 다른 점").
- 결정 방식: 사용자 지시 "1, 3, 4 작업들 모두 순차적으로 진행해"의 5단계. 명세 §성공한 작업의 도구화(계기, 사다리 1단계 스킬, 생애 주기, 수정, 안전 경계, 사용자 명령)와 완료 기준("사람이 한 번 시켜서 성공한 확인 작업이, 두 번째부터 스킬을 쓰며 더 적은 턴으로 끝난다")을 따른다.

## 결정

### 측정(선행 조건)

- 원장에 실행마다 턴 수(`num_turns`)와 도구 호출 수를 남긴다(마이그레이션 0011).
- 실행별 도구 흔적(`run_tools`)도 남긴다.
  - 도구 이름과 핵심 인자 한 줄(주소, 검색어, 이름)이다. 가린 뒤 200자까지만 둔다.
  - 입력칸에 넣은 글과 메일 내용은 남기지 않는다.
- 완료 기준을 재고, 회고의 계기와 스킬의 승인 판단에 쓴다.

### 스킬 저장과 생애 주기

- **저장소**: `skills`, `skill_revisions`, `skill_uses`(마이그레이션 0012).
  - 고칠 때는 지금 개정 번호를 맞춰야 한다. 모든 개정을 남긴다.
  - 스킬은 100개까지다.
- **파일**: `<data_dir>/skills/<이름>/SKILL.md`(표준 앞머리 name·description)로도 쓰고, 그 디렉터리를 데몬이 git으로 커밋한다(명세 "모든 개정은 git으로").
  - 프로젝트 레포가 아니다. 그 레포는 VM에 마운트된다.
  - 저장소 개정이 원본이고, git이 실패해도 알림만 한다.
- **상태**: 승인 대기 → 시험 중 → 활성 → 오래됨 → 보관.
  - **처음 상태**:
    - 읽기만 하는 절차는 시험 중이다. 사람이 대화에서 만들라고 한 것은 바로 활성이다.
    - 사이트를 열거나 외부에 쓰는 절차는 승인 대기다.
  - **승격**: 그 스킬을 읽은 작업을 사람이 [완료]로 확인할 때만 성공으로 센다(같은 작업은 한 번). 확인된 성공이 2번이면 활성이다. 모델이 스스로 보고한 성공은 세지 않는다.
  - **정리**: 60일 안 쓰면 오래됨, 그 뒤 60일이면 보관이다(하루 정리 때). 고정한 것은 빠진다.
  - **고정**: 고정한 스킬은 Lucia(회고)가 고치지 못하고, 사람만 고친다.

### 쓰기와 읽기(MCP)

- **넣는 길**: 쓸 수 있는 스킬(시험 중, 활성)의 색인 `<skills>`(이름, 제목, 언제)를 채팅·작업·후속 조치 맥락에 넣는다.
  - Lucia는 맞는 것을 `skill_read`로 읽고 따른다.
  - 읽으면 쓴 기록이 그 실행(작업이면 그 작업)에 묶인다.
- **도구**:
  - `skill_save`: 사람과의 대화("이거 스킬로 만들어")와 회고에서만 쓴다.
  - `skill_pin`("이 스킬 고정"), `skill_disable`("그 방식 쓰지 마"): 사람과의 대화에서만 쓴다.
  - 작업 세션·후속 조치·브리핑은 읽기만 한다.
- **안전**:
  - 스킬은 권한을 넓히지 않는다. 실행 범위(`Policy`)는 그대로이고, 외부 쓰기는 그때마다 승인 카드를 거친다. 색인과 본문에 "승인·권한 규칙보다 우선하지 않는다"를 붙인다.
  - **승인이 필요한지**는 모델이 밝힌 것이 아니라 실제로 한 일로 정한다.
    - 원래 작업의 도구 흔적: 브라우저·외부 쓰기 도구, 연 호스트.
    - 본문에 적힌 주소와 도구 이름.
    - 고친 스킬이 새로 사이트·외부 쓰기를 얻으면 다시 승인 대기다.
  - 저장 전에 인젝션 검사(결정 0010)를 한다.

### 사람에게 알리기(승인 종류 `skill_review`, 7일)

- **회고가 새로 만든 읽기 전용 스킬**: 알림 카드다.
  - [고정]은 고정한다. [폐기]는 보관한다.
  - 답이 없으면 시험 중 그대로 둔다.
- **승인 대기 스킬**: 승인 카드다.
  - [승인]이면 쓰기 시작한다. 사람이 만들라고 한 것은 활성, 회고가 만든 것은 시험 중이다.
  - [폐기]나 만료는 보관이다.
- 카드를 올리지 못해 닫힌 것은 사람이 폐기한 것이 아니므로 그대로 둔다. 관리 페이지에서 승인할 수 있다.

### 회고

- **계기**: 사람이 [완료]로 확인한 작업 가운데 하나라도 해당하는 것.
  - 도구를 3번 넘게 불렀다.
  - 턴이 8을 넘었다.
  - 사람이 말을 더했다(교정).
  - 아니면 모델을 부르지 않는다. 작업 하나에 한 번이다.
- **실행**:
  - 작업 줄에서 10분마다 확인한다(채팅을 막지 않게).
  - 그 작업 세션을 회고 모델(`models.retro`, 기본 haiku, 명세 "저렴한 모델")로 이어 `RunProfile::Retro`(스킬 도구만)로 돈다.
  - 작업 세션 컨텍스트가 15만 토큰을 넘으면 하지 않는다.
  - 비용 상한(결정 0010)에 걸리면 미룬다.
- **지침**: "다음번에 단계를 줄이는 것"이 목표다.
  - 실제로 성공한 가장 짧은 경로(바로 열 주소, 읽을 부분, 막혔다 풀린 방법, 교정받은 방식)를 적는다.
  - 헛걸음은 "하지 않는다"로 적는다.
  - 이번에 하지 않은 확인 단계는 더하지 않는다.
  - 비슷한 스킬이 있으면 새로 만들지 않고 읽어서 틀린 부분만 고친다(명세 "부분 수정을 우선").

### 관리 페이지 "스킬"(`/skills`)

- 목록: 상태, 고정, 쓴 횟수, 확인된 성공, 쓰는 것(도구·사이트), 언제.
- 스킬 하나: 본문과 개정 기록.
- 조작: 승인, 고정·풀기, 끄기, 되살리기. 사이트가 든 스킬을 보관에서 되살리면 다시 승인을 거친다.

## 명세와 다른 점

- 명세는 "스킬(SKILL.md) … 관련 작업 때 불러 쓴다"이고, 에이전트가 배운 스킬은 별도 디렉터리에 둔다.
- Claude Code의 기본 스킬 로딩은 쓰지 않고, 데몬이 색인을 넣고 MCP로 본문을 준다. 까닭:
  - 상주 샌드박스의 훅(`plugin/hooks/`, 보호 영역)은 데몬 MCP 도구와 이름을 정한 내장 도구만 통과시킨다. 실행은 `--tools WebSearch`로 돈다. 기본 로딩에는 Skill 도구가 필요하다.
  - 새 디렉터리 마운트는 `sbx`가 샌드박스를 만들 때만 받는다(`sbx --help`). 상주 샌드박스 `lucia`는 다시 만들지 않는다.
- 파일은 표준 `SKILL.md` 모양으로 남겨, 6단계 임시 샌드박스(새로 만든다)에서는 읽기 전용으로 마운트해 기본 방식으로 쓸 수 있게 했다.

## 확인(2026-11-17)

- **시험**:
  - 저장소: 개정·고정·성공 집계(같은 작업 한 번, 2번이면 활성)·노화, 필드 검사, 도구 흔적과 턴 합계(밑줄은 와일드카드가 아님).
  - 흔적: 읽기만 / 사이트 / 외부 쓰기 판단, 본문 주소, git 파일과 커밋 2개, 경로 탈출 거부.
  - MCP:
    - 대화에서 만든 읽기 절차는 활성이다.
    - 본문에 사이트가 있거나, 회고한 작업이 사이트를 열었으면 승인 대기와 카드다.
    - 회고의 읽기 전용은 시험 중과 알림 카드다.
    - 읽으면 작업에 묶인 기록이 남는다. 승인 대기는 읽지 못한다.
    - 작업 세션·브리핑은 만들지 못하고, 고정·끄기는 사람만 한다. 지시문은 거절한다.
  - 엔진: 단계가 많은 확인된 작업만 회고 모델로 그 세션을 이어 스킬 도구만 준다. 한 번만 하고, 적으면 모델 0번이다.
  - 카드: [고정] → 고정, [승인] → 시험 중, [폐기] → 보관. 작업 두 개를 [완료]로 확인하면 활성이다.
  - 관리 화면: 로그인, CSRF, 이스케이프, [승인] 단추.
- **실제 모델**(sonnet 작업, haiku 회고, 개발 샌드박스 `lucia-dev`·`lucia-browser-dev`):
  - **회고**: "Rust·Go·Python 최신 안정 버전·출시일" 작업을 완료로 표시하고 회고했다(haiku 3턴, $0.014).
    - 공식 릴리스 페이지 절차를 스킬로 남겼다.
    - 흔적(브라우저로 세 사이트를 엶)에서 승인 대기로 판단했다.
  - **처음 지침의 결과**: 스킬이 확인 단계를 덧붙여, 다른 언어 세트에서 턴이 줄지 않았다(10·8 → 10·10). 지침을 "가장 짧은 경로, 단계를 더하지 않음"으로 고쳐 다시 회고했다.
  - **두 번째 측정**: 같은 작업을 상주 대화를 거치지 않고, 같은 중립 브리프로 각각 두 번 돌렸다. 결과는 같았다.

    | | 스킬 없이 | 스킬 있이 |
    |---|---|---|
    | 턴 | 9, 8 | 7, 6 |
    | 도구 | 8, 7 | 5, 4 |
    | 시간 | 35, 24초 | 22, 19초 |

    스킬 있이 돌린 첫 번은 보고를 한 번 다시 청해 2턴이 붙었다(7에 포함). **완료 기준을 채웠다.**
  - **알게 된 것**: 같은 요청을 다시 하면 상주 대화가 기억한 결과를 다시 주고 작업을 맡기지 않는다. 그 대화 안에서는 맞는 행동이다. 스킬은 다른 날, 새 대화 맥락에서 같은 일을 할 때 듣는다.
- **실제로 아직 안 본 것**: 운영 Discord의 스킬 카드, 운영에서 회고가 도는 것.

## 하지 않은 것(5단계의 나머지)

- **사다리 2단계(스크립트)**: 스킬 안의 반복 단계를 스크립트로 만들어 샌드박스 안에서만 돌리는 것. 상주 샌드박스에는 코드 실행 도구가 없어 6단계(임시 샌드박스)에서 한다. → 결정 0025에서 했다(스크립트 샌드박스와 `skill_run`).
- **사다리 3단계(사전 체크 승격)**: 결정 0019.
- **비슷한 스킬 합치기 제안**: 하지 않았다. 회고가 비슷한 것을 고치게 한 것으로 대신한다.
