# 0047. 스크립트 샌드박스: Lucia가 패키지를 설치하고, 스크립트가 파일을 읽고 만든다

- 날짜: 2026-11-19
- 상태: 확정. 한도(패키지 8개, 파일 8 MB, 한 실행에 만드는 파일 10개)는 [제안]. **파일 한도는 결정 0057로 바뀌었다**(읽기 100 MB, 만들기 30 MB, 30개).
- 결정 방식: 사용자 지시를 따랐다.
  - "그림을 줄이는 건 스크립트로 가능하지 않나?"
  - "에이전트가 필요한 라이브러리 설치해서 사용할 수 있도록 개선해. 어차피 VM 내에서 돌아가잖아. 이걸 위해 VM을 구축한거고."
- 관련 결정: 0025(스크립트 샌드박스), 0005(파일), 0045(이모지·스티커), 0046(이미지 생성)
- 바꾸는 것: 결정 0025의 "네트워크 허용 규칙을 하나도 두지 않는다"와 "표준 라이브러리만". 평소에는 그대로이고, 설치하는 동안만 다르다.

## 배경

- 만든 그림(1024px부터)이나 사진(JPEG)을 이모지·스티커로 등록하려면 줄이고 형식을 바꿔야 한다. 결정 0045는 데몬에 이미지 디코더를 두지 않아 규격 밖 그림을 거절했다.
- 스크립트 샌드박스에는 Python 3.14와 pip은 있지만 Pillow가 없었다. 그리고 스크립트는 파일에 닿지 못했다(도구 다리는 글과 JSON만 오갔다).
- 처음에는 데몬이 정해 둔 스크립트로 맞춰 주려 했다. 사용자가 방향을 정했다: Lucia가 필요한 라이브러리를 스스로 설치해 쓴다. 코드는 VM 안에서 돈다.

## 결정

### 패키지 설치(`lib_install`, `lib_list`)

- Lucia가 `lib_install`로 PyPI 패키지를 스크립트 샌드박스에 설치한다. 그 뒤 `code_run`과 스킬 스크립트에서 `import`한다.
- **받는 것**: 이름과 버전 조건만(`pillow`, `numpy==2.3.0`, `requests[socks]>=2.31`). 주소, 경로, pip 옵션은 받지 않는다. 그래서 색인 밖에서는 가져오지 않는다. 한 번에 8개까지.
- **네트워크**: 평소에는 그 샌드박스에 허용 규칙이 없다(결정 0025 그대로). 설치하는 동안만 데몬이 `pypi.org`와 `files.pythonhosted.org`를 **그 샌드박스에만** 열고, 끝나면 닫는다.
  - 실패하거나 시간을 넘겨도 닫는다. `sbx` 명령이 멈춰도 닫는 데까지 가도록 호스트에서도 시간을 잰다(규칙 명령 40초, 설치 330초).
  - 데몬이 뜰 때와 설치를 시작할 때마다, 앞서 닫지 못한 허용 규칙을 치운다(`deploy/create-script-sandbox.sh`의 `apply_policy`와 같은 일). 그래서 이 샌드박스에 사람이 손으로 건 허용 규칙도 지워진다(지금은 없다).
  - 열려 있는 동안 함께 도는 다른 스크립트도 그 두 호스트에는 닿을 수 있다. 보통 몇 초에서 몇 분이다.
- **어디에**: 시스템 자리(`sudo python3 -m pip install --break-system-packages`). 스크립트는 `python3 -I`로 돌아 사용자 자리의 패키지를 보지 않기 때문이다.
- **오래 걸리면**: 설치는 데몬 작업으로 돌고 도구는 45초만 기다린다(MCP 요청은 60초쯤에 끊긴다). 그 안에 안 끝나면 "아직"이라고 답하고, Lucia는 `lib_list`로 확인한다. 설치 하나는 5분까지, 한 번에 하나.
- **누가**: **사람이 시작한 대화와 맡긴 작업**만 설치한다(새 갈래 `Packages`). 브리핑·후속 조치·목표 점검·루틴 같은 사람 없는 실행과 스크립트 다리는 설치하지 못한다. 목록 보기(`lib_list`)는 코드를 돌리는 실행이면 된다.
  - 까닭: 설치한 패키지는 시스템 자리에 남아 **뒤의 모든 스크립트와 같은 Python 프로세스에서** 돈다(가져오지 않아도 시작할 때 도는 것이 있을 수 있다). 사람 없는 실행이 설치할 수 있으면, 바깥 글을 읽은 실행이 뒤의 대화 실행(메일 읽기, `lucia.fetch`)을 넓히는 길이 된다. 결정 0028의 "사람 없는 실행은 뒤의 실행을 넓히지 않는다"에 어긋난다.
  - 사용자가 사람 없는 실행에서도 설치하길 원하면 갈래를 그 실행들에 여는 한 줄이다. 설치는 활동 기록에 남는다.
- 패키지는 샌드박스 안에 남는다. 샌드박스를 다시 만들면 사라지고, `import`가 실패하면 결과 글이 "lib_install로 설치한 뒤 다시"라고 알려 준다.
- `lib_install`은 늘 바로 보이는 도구다(결정 0046에서 찾기 뒤에 둔 도구를 실제 모델이 못 찾았다). `lib_list`는 찾기 뒤에 있다.

### 스크립트의 파일 읽기·만들기

- 스크립트 실행기(`lucia` 모듈)에 셋을 더했다.
  - `lucia.read_file(파일 id)` → `bytes`
  - `lucia.file_info(파일 id)` → 이름·형식·종류·크기(내용은 옮기지 않는다)
  - `lucia.save_file(이름, bytes 또는 글)` → 새 파일 id
- 통로는 예전의 표준 입출력 다리 그대로다. 바이트는 base64로 한 줄에 실린다. 샌드박스에 마운트를 더하지 않았다.
- 모델이 직접 부르는 도구로는 만들지 않았다(수 MB의 base64가 대화에 쏟아지지 않게). 스크립트 안에서만 쓴다.
- 한도: 파일 하나 8 MB, 한 실행에 만드는 파일 10개. 만든 파일은 주고받는 파일(`files/out`)에 남고 30일 뒤 지워진다. 글이면 마스킹을 거친다.
- 만든 파일의 id는 결과 글의 `[만든 파일]`에 보인다. `report_result`의 `attachments`나 `expression_add`의 `file`에 쓴다.
- 누가: 파일을 만들 수 있는 실행의 `code_run`과 `skill_run`. 반복 루틴(사람 없이 도는 스크립트)은 파일을 읽거나 만들지 못한다.

### 이모지·스티커 등록과의 이음(결정 0045)

- `expression_add`는 여전히 검사만 한다. 규격 밖 그림은 Lucia가 먼저 `code_run`에서 Pillow로 맞춘다(정사각형으로, 이모지 128px·스티커 320px, PNG). 도구 설명에 그 절차를 적었다.
- 관리 페이지에서 올릴 때는 예전처럼 검사만 한다.

## 위험과 받아들인 것

- 설치한 패키지는 남아서 뒤의 스크립트(루틴 포함)와 **같은 프로세스에서** 돈다. 나쁜 패키지(이름이 비슷한 가짜 등)를 설치하면 그 뒤의 스크립트가 다리로 하는 일을 볼 수 있다: 그 실행의 범위 안에서 메일·일정 읽기, 대화 실행이면 `lucia.fetch`로 바깥에 내보내기까지.
  - 막는 것: 설치는 사람이 시작한 대화와 맡긴 작업에서만, 색인의 이름으로만, 활동 기록에 남는다. 그 VM은 평소 네트워크가 없다. 상주 샌드박스(훅)와 브라우저 샌드박스(쿠키)에는 닿지 않는다.
  - 남는 것: Lucia가 대화에서 잘못된 이름을 설치하는 경우. 사용자의 판단은 "이런 일을 하라고 VM을 두었다"이다. 의심스러우면 샌드박스를 다시 만들면 깨끗해진다(`sbx rm --force lucia-script` 뒤 `deploy/create-script-sandbox.sh`).
- 스크립트가 사용자의 파일을 읽는다. 읽은 내용이 나갈 길은 그 실행의 도구 범위뿐이다(평소 네트워크 없음).

## 확인(2026-11-19)

- **시험**(모델을 부르지 않는다):
  - 패키지: 표기 검사(주소·옵션·경로 거절), 치우기 → 열기 → 설치 → 닫기 순서, 실패해도 닫기, 설치 중 거절, 멈춘 `sbx` 끊기, sbx 출력 읽기.
  - 파일: 실제 Python 실행기로 읽기·고치기·만들기(바이너리 그대로), 허락 없는 스크립트 거절, 큰 파일 거절, 없는 패키지 안내.
  - 도구: 대화·작업만 설치(사람 없는 실행·스크립트 다리 거절), 목록 보기.
- **실제**(개발 설정, 개발용 스크립트 샌드박스, 실제 모델):
  - 1365×812 JPEG를 붙이고 "이 사진을 앱 스티커로 등록해 줘"라고 했다. Lucia는 먼저 등록을 시도해 거절 까닭을 받고, 여백을 채울지 자를지 물었다.
  - "여백을 채워서"라고 하자 `lib_install`(pillow, 9초) → `code_run` 두 번(`read_file`, `save_file`) → `expression_add` 순으로 불렀고, 640×640 PNG(179 KB) 스티커가 등록됐다.
  - 설치 뒤 `sbx policy check`로 `pypi.org`와 `files.pythonhosted.org`가 그 샌드박스에서 다시 막혀 있는 것을 보았다.
- 운영 샌드박스(`lucia-script`)에는 아직 설치된 것이 없다. Lucia가 처음 필요할 때 설치한다.

## 구현하며 있었던 일

- 조사하며 개발 샌드박스(`lucia-script-dev`)에 `deb.debian.org`·`dhi.io`를 잠깐 열어 apt에 Pillow가 있는지 보고 바로 닫았다(있지만 Python 3.13용이라 쓸 수 없었다).
- 그 뒤 내가(이 작업을 한 에이전트) 개발 샌드박스에 직접 PyPI를 열려 한 명령 둘은 권한 검사에 막혀 실행되지 않았다. 그 뒤 사용자가 위 지시를 주었고, 여는 일은 데몬의 `lib_install`이 하게 만들었다.
- 개발 설정의 실제 확인은 설치를 대화로 좁히기 전의 빌드로 했다(대화에서 부른 것이라 결과는 같다).
