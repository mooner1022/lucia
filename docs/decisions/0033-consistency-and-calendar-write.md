# 0033. 교차 정합성 검사와 캘린더 쓰기

- 날짜: 2026-11-18
- 상태: 확정. 값(하루 두 번 12:30·18:30, 앞으로 7일, 이동 30분, 같은 겹침 7일에 한 번, 카드 24시간)은 [제안].
- 결정 방식: 소유자 기능 개선안 C("여러 출처 교차 정합성 검사")를 검토한 적용안(`docs/proposals/functional-brief-review.md` §6)을 따랐다. 소유자 지시: "확인하고 적용해."
  - 캘린더 쓰기는 앞 검토(2026-11-17)에서 "소유자가 정할 기능"으로 남았다. 이번에 물어서 정했다: **참석자 없는 내 일정은 바로 추가·수정, 삭제는 카드.** 참석자가 있는 일정은 카드.
- 명세와 다른 점: 명세는 일정 삭제를 금지 등급으로 둔다. 소유자 결정으로 **지우기는 승인 카드**다("잘못 만든 일정 지워 줘"를 할 수 있게).

## 결정

### 캘린더 쓰기

- 동의 범위 `calendar.events`를 더했다. **예전 연결에는 없다**: 읽기는 그대로 되고, 쓰기는 "관리 페이지에서 Google을 다시 연결" 안내로 실패한다(403). 관리 페이지 개요·연결 화면에 "캘린더 쓰기 권한 없음"이 보인다.
- 도구(갈래 Google):
  - `calendar_create`(로컬 쓰기): 참석자가 없으면 바로 만든다. 참석자를 주면 카드.
  - `calendar_update`(로컬 쓰기): 데몬이 일정을 다시 읽어, 참석자가 있거나(나 말고) 내가 주최하지 않은 일정이면 카드. 모델의 말을 믿지 않는다. 시작만 옮기면 길이를 지킨다.
  - `calendar_delete`(외부 쓰기): 늘 카드.
- 카드(`calendar_write`, 24시간): 연산, 제목, 시각, 장소, 참석자, 지금 일정. 누르면 보인 그대로 데몬이 한다. 카드가 필요한 일은 외부 쓰기까지 열린 실행(대화, 대화 사슬의 후속 조치, 작업)에서만 요청할 수 있다. 브리핑 등급(브리핑, 신호, 정합성 검사, 목표 점검)은 참석자 없는 일정만 바로 하고, 나머지는 사용자에게 알린다.
- 공통: 초대 메일을 보내지 않는다(`sendUpdates=none`). Lucia가 만든 일정에는 표지(`extendedProperties.private.lucia`)를 달아 증분 확인이 돌려준 자기 변화를 신호 처리가 버린다(결정 0031). 고친 일정은 직전 상태와 뒤 상태를 `calendar_edits`(마이그레이션 0020)에 남기고 활동 기록에 적는다. 사람 없는 실행이 바로 한 쓰기는 소식(📅)으로 알린다.

### 교차 정합성 검사(내장 루틴 `consistency-check`)

- 하루 두 번. 관리 페이지 "새 메일·일정 알림" 카드에서 끈다.
- **코드(모델 없음)**
  - 앞으로 7일 일정의 겹침, 다른 장소로 옮기는데 30분이 안 되는 이어진 일정을 소식으로 알린다. 같은 것은 7일에 한 번.
  - 지난 검사 뒤 들어온 메일 신호(결정 0031, 버린 것 빼고) 가운데 제목·미리보기에 날짜·마감·약속 말이 든 것만 후보로 뽑는다(정규식, 넉넉하게).
- **후보가 있을 때만 Lucia**(브리핑 등급 + 캘린더 쓰기): 메일을 읽고, 캘린더에 없는 마감·약속을 넣거나(참석자 없는 내 일정), 메일과 다른 일정을 고치고, 기억과 어긋나면 묻는다. 할 것이 없으면 `-`.
- **같은 제안이 다시 오지 않게**: 메일 하나는 한 번만 본다(검사 시각 뒤에 들어온 것만). 개선안의 "제안 결과(수락·거절·무시) 기록"은 이 방식으로 갈음했다: 같은 메일로 다시 제안할 일이 없다. 카드를 거절한 일정도 그 메일을 다시 보지 않으므로 다시 오지 않는다.
- B의 신호로 바로 하기: 신호 3단계(지금 알릴 것) 지침에 "캘린더에 없는 마감·약속이면 추가"를 더했다. 그래서 관심 메일은 수 분 안에, 나머지는 하루 두 번 검사에서 다룬다(개선안 수용 기준 "같은 날 안에").

- 동의 범위가 아직 없으면(다시 연결 전) 신호 알림·정합성 검사 지침에서 캘린더 추가를 빼고, 넣을 만한 일정은 알림에 적게 한다(`calendar_note`, 배포 뒤 검토로 더함).

## 시험

- 본문 만들기: 표지, 시각(현지 시간대), 하루 종일의 끝 날짜, 끝이 시작보다 앞이면 거절, 참석자 주소 확인. 시작만 옮기면 길이 유지. 참석자(나 말고)나 남이 주최한 일정은 카드.
- Google API(가짜 서버): 만들기·고치기는 `sendUpdates=none`, 없는 일정은 `None`, 403은 권한 없음(다시 연결 안내), 지우기.
- 정합성: 날짜 말 판정, 겹침·빠듯한 이동, 겹침은 코드로 소식, 날짜 말이 든 메일만 Lucia(브리핑 등급, 캘린더 추가는 되고 지우기는 안 됨), 다시 돌려도 같은 메일·겹침은 다시 보지 않음(모델 호출 없음).
- 실제 계정으로는 시험하지 않았다(소유자가 Google을 다시 연결해야 쓰기가 된다). 운영에서 처음 보는 것: 실제 일정 추가, 카드 모양, 하루 두 번 검사의 후보 수.
