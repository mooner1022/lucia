## 결정

### 연결

- 설정 파일 `[gateway] bind`에 주소를 넣으면 `ws://<주소>/v1/ws`(WebSocket)와 `/v1/health`를 연다. 비우면 열지 않는다(기본).
- **주소 제한**:
  - 바인드는 집 LAN·VPN·루프백 주소만 받는다(0.0.0.0·공인 주소는 설정 오류). 관리 페이지·MCP·브라우저 프록시와 다른 포트여야 한다.
  - 바인드와 상관없이, 상대 주소가 루프백·사설·링크 로컬·CGNAT(100.64/10, Tailscale 등)·IPv6 ULA가 아니면 거절한다.
  - 인터넷에 노출하지 않는다. 밖에서 쓰려면 VPN으로 들어온다.
  - 루프백도 받는 주소이므로, 호스트에서 리버스 프록시나 터널(예: 공개 터널 서비스) 뒤에 이 포트를 두면 주소 제한이 무력해진다. 그렇게 두지 않는다. 샌드박스 네트워크 정책에도 이 포트를 열지 않는다(에이전트가 앱인 척할 수 없게).
- **인증**: 첫 프레임 `hello{token}`(10초 안).
  - 브라우저 WebSocket은 머리글을 넣을 수 없어 첫 메시지로 받는다. 쿠키를 쓰지 않으므로 다른 사이트가 연결을 가로챌 수 없다.
  - 한 주소에서 10분 안에 실패가 10번이면 그 주소를 잠시 막는다.
  - 말마다 토큰이 아직 살아 있는지 다시 본다. 취소하면 연결도 바로 끊는다.
- 같은 클라이언트가 다시 연결하면 새 연결이 예전 연결을 대신한다.
- **반쯤 죽은 연결**: 휴대폰이 잠들거나 Wi-Fi를 벗어나면 TCP가 한동안 살아 있는 것처럼 보인다.
  - 데몬이 30초마다 핑을 보내고, 75초 동안 아무것도(퐁 포함) 듣지 못하면 끊는다. 끊긴 앱으로 갈 글은 그때부터 알림 대화로 간다.
  - 받음 확인(ack)이 없으므로, 끊기기 전 그 사이에 보낸 글은 잃을 수 있다(최대 75초 남짓). 결과가 남는 것(작업 결과, 승인 요청, 후속 조치 기록)은 관리 페이지에도 있다.

### 클라이언트와 토큰(마이그레이션 0015 `clients`)

- 관리 페이지 "연결" 화면의 "앱·기기 연결"에서 이름을 붙여 발급한다.
  - 토큰(`lucia_` + 약 244비트)은 발급 직후 안내에 한 번만 보인다. 저장소에는 SHA-256 해시만 남는다.
  - 목록: 역할, ID, 발급·마지막 접속 시각, 연결 여부. [취소]는 두 번 눌러야 한다.
  - 20개까지다.
- **역할**: `app` | `device`.
  - `app`: 소유자가 쓰는 앱. 코어의 허용 규칙(`access_allows`)이 플랫폼 `app`이면 "발급했고 취소하지 않은 app 역할 클라이언트"를 소유자로 본다. Discord 소유자 규칙과 같은 자리다.
  - `device`: 자리만 있다(아래 "기기 연결"). 토큰이 맞아도 `unsupported_role`로 끊고, 허용 규칙도 사람으로 보지 않는다. 관리 페이지는 아직 app만 발급한다.

### 프로토콜(판 1)

- 모든 프레임은 JSON 글 프레임이다(64 KiB까지).
- **클라이언트 → 데몬**:
  - `hello{token}`
  - `message{text}`: 8000자까지. 받으면 `accepted`.
  - `press{ref, action, input?}`: 카드 버튼. `input`은 값을 받는 버튼(인증 코드, 결정 0017)의 값이다(로그에 찍히지 않는 `SecretText`).
    - 게이트웨이는 `ref`가 `app:<자기 ID>:…`인지 본다.
    - 승인 데스크는 앱의 누름을 **그 승인 카드가 실제로 그 참조로 올라갔을 때만** 받는다. 다른 카드의 승인 ID를 넣어 누르지 못한다(Discord 누름은 예전처럼 참조가 달라도 경고만 한다).
  - `ping` → `pong`
- **데몬 → 클라이언트**:
  - `welcome{v, client, name, role, conversation, capabilities}`
  - `text{body}`, `note{body}`: 진행 안내. 8000자 넘으면 나눠 보낸다.
  - `files{body, files[{name, data(base64)}]}`
  - `typing`
  - `card{ref, card}`, `card_closed{ref, card}`: 카드는 머리줄, 제목, 칸, 본문, 꼬리말, 결(tone), 버튼(입력창 정보 포함)이다.
  - `error{code, message}`
- **아직 없는 것**: 앱에서 파일 보내기(`capabilities.attachments = false`), 끊긴 동안 온 카드 다시 받기.

### 채널로서

- 앱의 대화는 `app:<클라이언트>`다. 들어온 말은 Discord와 같은 받은 편지함으로, 버튼은 같은 승인 통로로 간다.
- 코어에 더한 것은 두 갈래뿐이다: 허용 규칙(`access_allows`)의 플랫폼 `app` 갈래, 승인 데스크의 앱 누름 검사. 엔진의 채팅·작업 흐름은 그대로다.
- **`RouterChannel`**: 엔진은 대화 ID로 기본 채널(Discord)과 앱을 가르는 채널을 받는다.
  - 앱 대화로 가는 글·카드·입력 중 표시는 앱으로, 그 밖은 Discord로 간다. 카드 닫기는 카드 참조로 가른다.
  - **앱이 연결되어 있지 않으면** 그 글과 카드는 알림 대화(Discord DM)로 보낸다. 1인 비서라 답·후속 조치·작업 결과가 사라지면 안 된다. 그 카드는 Discord에서 누르고, 닫을 때도 Discord 카드로 닫는다.
  - 능력과 `ready`는 기본 채널의 것이다. 브리핑·알림·작업 스레드는 그대로 Discord로 간다. 앱 대화에는 스레드를 열지 않는다.
- **같은 상주 세션**: 엔진의 상주 세션은 대화 ID와 상관없이 하나다(같은 Lucia, 같은 기억). 다만 새 세션의 첫 요청에 붙이는 "직전 대화"는 그 대화 ID의 것만 붙는다(`recent_in_conversation`). 그래서 세션이 바뀐 직후에는 앱에서 Discord 대화의 직전 턴을 바로 이어 받지 않는다.
- **승인 카드가 가는 곳**: 승인 카드는 예전대로 요청이 정한 대화(작업 스레드), 아니면 소유자 알림 대화(Discord DM)로 간다. 앱에서 한 채팅이 메일 발송을 요청해도 카드는 Discord에 온다.
  - 명세의 "Discord 승인"과 맞추고, 바깥에 영향을 주는 결정을 한 곳에 모으려는 보수적 기본값이다([제안]).
  - 앱으로 카드가 가는 것은 요청이 앱 대화를 정했을 때다(작업 결과 확인 카드에 앱 대화를 넘기는 경우 등). 앱 화면이 생기면 "채팅한 곳으로 카드 보내기"를 설정으로 더한다.

### 기기 연결(자리만, 다음 설계)

Muse Gadgets 같은 외부 기기를 붙일 때의 원칙을 미리 정해 둔다. 지금 코드에는 역할 값, 거절하는 자리, 허용 규칙의 구분만 있다.

- **기기가 보낸 것은 사람의 말이 아니다**. 시작 주체는 `delegated`나 `autonomous`이고(결정 0013), 외부 데이터로 다룬다(인젝션 검사, 지시 따르지 않음).
- **기기 → 데몬**(센서·사건): 사전 체크 소스(`Source`)로 받아, 모델 없이 거른 뒤 바뀐 것만 브리핑·작업으로 간다(결정 0015·0019와 같은 길).
- **데몬 → 기기**(명령): 도구 표(`tools.rs`)에 기기 도구 묶음과 등급을 선언한다. 외부에 영향을 주는 명령은 승인 종류(`ApprovalKind`)를 등록해 카드를 거친다.
- **기기 토큰**은 기기마다 따로 발급하고, 허용 명령의 범위를 클라이언트에 붙인다.
- 같은 접속 API의 다른 프레임(`event`, `command`)으로 넣고 프로토콜 판을 올린다.

## 확인(2026-11-17)

- **시험**:
  - 저장소: 해시로 찾기, 마지막 접속, 취소하면 찾지 못함.
  - 어댑터 공통 계약(긴 글 나누기·빈 글 거절·안내·파일·입력 중)을 통과한다.
  - 라우터: 연결된 앱이면 앱으로(글·카드·닫기). 다른 대화는 Discord로. 끊긴 앱이면 알림 대화로(글·카드). 알림 대화가 없으면 `Closed`. 앱 대화 스레드는 열지 않는다.
  - 승인 데스크와 함께(`app_cards_are_pressed_in_the_app_or_on_discord_when_offline`):
    - 앱 대화로 간 작업 확인 카드를 앱에서 누르면 완료되고 `card_closed`가 앱으로 간다.
    - 다른 클라이언트나 다른 참조로 누르면 무시한다.
    - 앱이 끊겨 있으면 카드가 Discord로 가고, 소유자가 거기서 누르면 완료되고 Discord 카드가 닫힌다(이 시험이 닫을 때의 대화 버그를 찾았다).
  - 반쯤 죽은 연결: 퐁이 없는 연결은 한도 뒤 끊고 다음 글은 알림 대화로 간다. 퐁을 보내는 연결은 그대로다.
  - 실제 WebSocket:
    - hello → welcome. 말 → 받은 편지함(플랫폼 app, 발신자 = 클라이언트, 대화 `app:<ID>`). 허용 규칙이 받아들인다.
    - 답·카드 받기. 버튼과 입력값이 승인 통로로 간다. 남의 카드는 `bad_ref`.
    - 빈 말, 모르는 프레임, 핑.
    - 취소하면 다음 말에서 끊는다. 허용 규칙도 거절한다.
    - hello가 아닌 첫 프레임, 틀린 토큰, 기기 역할은 거절한다. 실패가 쌓이면 맞는 토큰도 막는다.
    - 새 연결이 예전 연결을 대신한다.
  - 관리 페이지: 발급(한 번만 보임, 해시만 저장), 이름 검사, 취소, 로그인·CSRF.
- **실제**(개발 저장소·`lucia-dev`, Discord·Google 자격 증명 없는 별도 디렉터리, 접속 API 127.0.0.1:47830):
  - 시험용 WebSocket 클라이언트로 접속했다. welcome을 받았다.
  - "한 문장으로 짧게 인사해 줘"에 `accepted` → `typing` → 5초 뒤 실제 모델(sonnet)의 답 `text`를 받았다.
- **실제로 아직 안 본 것**:
  - 앱 화면(클라이언트 자체가 아직 없다).
  - 운영에서 LAN의 다른 기기로 접속하는 것(운영 설정의 `[gateway] bind`가 비어 있다).
  - 실제 앱에서 승인 카드를 누르는 흐름, 끊긴 앱의 글이 운영 Discord로 가는 것.
  - 실제 휴대폰이 잠들 때 반쯤 죽은 연결을 찾는 데 걸리는 시간.

## 하지 않은 것

- **HTTP 요청형 API**(한 번 묻고 답 받기): 답이 여러 조각·카드·진행 안내로 나뉘어 와서 WebSocket 하나로 했다. 필요하면 같은 라우터 위에 더한다.
- **앱 푸시 알림**: 앱이 꺼져 있을 때는 Discord로 대신 보낸다. 모바일 푸시는 앱을 만들 때 정한다.
- **TLS**: 집 LAN·VPN 안에서만 열고 토큰은 첫 프레임으로 보낸다. 밖에서 쓰려면 VPN(WireGuard·Tailscale)이 암호화를 맡는다.

## 후속(2026-11-19): 판 2(결정 0043)

- **외부 노출**: "인터넷에 노출하지 않는다", "리버스 프록시·터널 뒤에 두지 않는다"는 결정 0043으로 바뀌었다. 설정 `[public] gateway_url`과 믿는 프록시가 있을 때만 프록시를 거친 외부 연결을 받고, 실패는 `X-Forwarded-For`의 실제 주소로 센다.
- **아직 없던 것 채움**:
  - 끊긴 동안 온 카드 다시 받기: 번호·ack·`hello.resume`.
  - 앱에서 파일 보내기: `POST /v1/files`.
  - 앱 푸시: FCM.
- **승인 카드가 가는 곳**: 관리 페이지에서 "알림 받을 곳"을 앱으로 정할 수 있다.
- **역할 `app`의 범위**: 기본 밖의 권한은 범위(`scopes`)로 준다.
- 프로토콜 전체는 `docs/app-api.md`에 있다.
