# 0037. 로그인 게시판 감시: 세션을 빌려 HTTP로, 브라우저 감시 탭, 방식 고르기

- 날짜: 2026-11-18
- 상태: 확정. 값(다시 로그인 간격, 다시 해 보는 간격, 카드 수)은 [제안]이다.
- 결정 방식: 결정 0036과 같은 사용자 승인이다. 검토 문서는 `docs/proposals/login-board-watch.md`(2·3단계)다. 사용자 덧붙임 "둘 모두 구현하고 상황에 따라 선택하여 사용할 수 있도록 하는 건?"과 "브라우저의 하한" 논의를 따랐다.
  - 15분 하한은 버렸다. 10분 유휴 종료와 15분 간격이면 매번 VM과 Chrome을 처음부터 띄운다. 그래서 브라우저 방식 감시가 있으면 계속 켜 둔다.

## 결정

### 세 방식(`watches.fetcher`, `crate::session::WatchReader`)

| 방식 | 어떻게 | 무게 | 쓰는 곳 |
|---|---|---|---|
| `plain` | 쿠키 없이 HTTP(0019·0036) | 가장 가볍다 | 공개 게시판 |
| `session` | 로그인된 브라우저에서 그 주소로 갈 쿠키만 꺼내 데몬이 HTTP로 | VM은 쿠키를 새로 받을 때만 깬다 | 서버가 목록을 그리는 로그인 게시판 |
| `browser` | 로그인된 브라우저의 감시 탭에서 연다 | 이 감시가 있는 동안 브라우저(약 2 GB)를 계속 켜 둔다 | 자바스크립트로 그리는 게시판, HTTP를 막는 사이트 |

- 감시·제안·루틴 스크립트가 같은 가져오기(`watch::Fetch::fetch_via`)를 쓴다.

### 세션 빌려 읽기

- **쿠키 꺼내기**: CDP `Network.getCookies(urls=[주소])`로 Chrome이 그 주소에 보낼 쿠키만 꺼낸다. 사용자 에이전트는 `Browser.getVersion`으로 그대로 쓴다.
- **보관**: 쿠키는 데몬 메모리에만 둔다. 디스크·로그·저장소에 남기지 않는다.
  - 데몬이 다시 뜨면 비어 처음 쓸 때 다시 꺼낸다.
  - 디버그 출력도 값 대신 개수만 보인다.
- **보내는 곳**(`session::cookie_allowed`):
  - 쿠키는 그 호스트와, 위임이 덮는 호스트로 넘겨질 때만 붙인다.
  - https에서 꺼낸 쿠키를 http로 넘겨질 때는 붙이지 않는다.
  - 출구 검사(차단 목록, 사설 주소 막기, 검사한 주소로만 연결)는 `SafeFetch` 그대로다. GET만 한다.
- **응답 쿠키**: 데몬의 상자만 고치고 브라우저에 되쓰지 않는다. 세션을 돌려 쓰는 사이트면 브라우저 쪽이 풀릴 수 있다. 그때는 아래 "다시 받기"가 덮는다.
- **로그인 풀림 알아보기**:
  - 로그인 주소로 넘겨줌(경로에 login·signin·logon), 또는 401.
  - 볼 것(글·구간)이 없고 비밀번호 칸이 보임.
  - 403은 "막힘"으로 따로 본다. 429(속도 제한)는 막힘이 아니라 물러서기만 한다.
  - **볼 것만 없음**(비밀번호 칸 없이 알림창·스크립트 이동만 주는 로그아웃 화면 등): 기준선이 있고 이어진 실패가 없으면 한 번 다시 받아 해 본다. 그래도 비면 로그인 멈춤이 아니라 일반 실패다(물러서기, 5번이면 알림). 개편과 구별할 수 없고, 실패마다 다시 받으면 브라우저 VM을 계속 깨운다.

### 다시 받기와 멈춤

1. 로그인이 풀렸으면 브라우저에서 쿠키를 다시 꺼낸다. 브라우저 쪽 세션이 더 새것일 수 있다. 달라졌으면 한 번 더 읽는다.
2. 같으면, 위임에 `login`이 있고 저장된 로그인이 있을 때만 위임된 로그인(결정 0028)을 한다.
   - 호스트당 6시간에 한 번까지다. 계정 잠금을 피하려는 것이다.
   - 로그인은 브라우저의 대화용 탭에서 한다(로그인 코드가 그 탭을 쓴다). 그래서 대화 중 Lucia가 보던 화면이 로그인 페이지로 바뀔 수 있다. 6시간에 한 번이라 받아들였다.
   - 활동 기록은 `login_delegated`이고, 에피소드에는 "로그인 위임으로 사람 없이: 페이지 감시"로 남는다(사용자 승인과 구별).
   - 인증 코드가 필요하면 하지 않는다.
3. 그래도 안 되면 감시를 "멈춤(로그인 필요)"으로 두고 한 번 알린다(방해 금지 시간이면 소식).
   - 알림 글: "Lucia에게 'OO 로그인해 줘'라고 하거나 사이트 위임에서 로그인을 허용해 주세요."
4. **스스로 다시 켜기**:
   - 로그인으로 멈춘 감시는 브라우저가 이미 떠 있을 때만 10분마다 다시 해 본다. 사람이 막 로그인했을 수 있고, 다시 해 보려고 VM을 깨우지는 않는다.
   - 글(볼 것)이 실제로 보일 때만 다시 켠다. 본 글 기록은 그대로라 그 사이 올라온 글을 알린다(한꺼번에 30개까지).
   - 관리 페이지 [다시 켜기]도 로그인 멈춤이면 기준선을 다시 잡지 않는다.

### 브라우저 감시 탭

- 대화용 탭과 따로 둔 백그라운드 탭(`Target.createTarget`)에서 연다. 그래서 대화 중인 Lucia가 보던 화면을 옮기지 않는다.
  - 새 창 닫기에서는 이 탭을 뺀다.
  - 사람에게 넘기는 탭 목록에도 넣지 않는다.
  - 이 탭의 대화상자는 닫기만 한다.
- 로드를 기다린 뒤 1.5초 더 기다려 그려진 문서(`outerHTML`)와 도착 주소를 읽는다.
  - 도착 주소도 출구 검사를 한다.
  - 로그인 주소로 넘어갔으면 로그인 문제로 본다.
- 다른 조작이 브라우저를 쥐고 있으면 기다리지 않고 그 회차를 건너뛴다. 실패로 세지 않고 다음 바퀴에 다시 한다.
- **계속 켜 두기**: 켜진 감시 중 브라우저 방식이 하나라도 있으면 유휴 종료를 하지 않는다. 관리 페이지에 "브라우저 상시 켜짐"을 보인다.
  - 간격 하한은 따로 없다(게시판 3분, 같은 사이트 3분).

### 방식 고르기

- **제안할 때(`read_with = auto`, 기본)**: 쿠키 없이 → 로그인 세션 → 브라우저 차례로 해 보고, 패턴에 맞는 글이 보이는 첫 방식으로 정한다.
  - 해 본 것과 까닭(예: "로그인 없이 HTTP: 글 없음 → 로그인 세션으로 HTTP로 글을 찾았다")을 카드에 보인다.
  - Lucia가 사용자 말에 따라 `read_with`로 정할 수도 있다.
  - 셋 다 안 되면 만들지 않는다. "로그인이 필요하면 먼저 browser_login"이라고 돌려준다.
  - 세션 시도에서 글이 없으면 세션을 다시 받아 한 번 더 해 본다. 로그인 전에 한 번 제안해 상자에 낡은 쿠키가 남은 경우, 로그인 뒤 다시 제안해도 브라우저 방식으로 잘못 정해지지 않게 하려는 것이다.
  - 시험 전체는 50초 안에 끝낸다(MCP 요청이 60초에 끊긴다).
  - 사람 없는 실행은 위임한 사이트만 해 본다(결정 0036 그대로).
- **사람이 바꾸기**: 관리 페이지 [고치기]의 "읽는 방식"에서 바꾼다. 본 글 기록(키)은 방식과 상관없으므로 기준선을 다시 잡지 않는다.
- **막혔을 때**:
  - HTTP(쿠키 없이·세션)가 403·429로 막히면 브라우저로 한 번 읽어 본다.
  - 글이 보이면 [브라우저로]/[그대로] 카드(`watch_switch`, 3일)를 올린다. 같은 감시에는 일주일에 한 장이다.
  - 사람 없이 바꾸지 않는다. 브라우저를 계속 켜 두는 비용이 있다.
  - 브라우저에서 HTTP로 내리는 것은 사람이 고를 때만 한다.

### 위임

- `session`·`browser` 감시는 그 사이트의 위임(읽기 이상)이 있어야 돈다. 위임을 거두면 다음 확인부터 실패로 센다(물러서기, 5번이면 알림).
- 감시 카드를 승인하면 위임이 없을 때 읽기 위임을 함께 만든다. 출처는 "로그인 감시 승인"이다. 카드에 그렇게 적었다.
- 로그인 위임은 따로 정한다(관리 페이지나 `site_grant_propose`).
- 카드에는 "계정으로 자주 읽으면 사이트 규칙에 따라 계정이 제한될 수 있다"는 줄을 적었다.

### 루틴 스크립트

- `lucia.fetch(url, session=True)`: 로그인 세션으로 가져온다.
  - 위임한 호스트만 받는다.
  - 루틴·스킬은 `fetch_session`을 선언해야 쓴다. 대화 중 `code_run`은 브라우저를 쓸 수 있는 실행이면 쓴다.
- 로그인 세션으로 가져온 글은 사용자 자료로 친다. 그래서 바깥 `fetch`와 함께 선언하면 루틴 승인 카드를 거친다(결정 0025 규칙).

## 명세·제안과 다른 점

- 제안서는 브라우저 방식에 15분 하한을 두었다. 사용자 지적으로 없앴다(위).
- 로그인이 풀렸을 때 재로그인 카드·입력 링크를 자동으로 보내지 않는다. 알림으로 안내만 한다. 감시가 멈출 때마다 로그인 카드가 쌓이지 않게 하려는 것이다.
- 응답 쿠키를 브라우저에 되쓰지 않는다. 필요해지면 `Network.setCookies`를 더한다.

## 남는 한계

- 로그인 세션 감시에 붙은 `on_change` 루틴이 바깥 `fetch`를 써도 승인 카드 없이 지나간다. 루틴 승인 규칙은 감시 변화를 사용자 자료로 치지 않는다(결정 0025). 제목 정도라 받아들였다.
- 로그인 게시판의 새 글 제목(비공개 글)은 바뀐 것·알림·신호 기록의 기존 보존을 따른다. 따로 짧게 지우는 기간은 두지 않았다.
- 세션·브라우저 감시의 새 글 제목은 출구 검사 대조 자료(결정 0029, 메모리)에 넣는다. 본문은 데몬이 읽지 않으므로 넣을 것이 없다.

## 남는 위험

- 봇 검사가 있는 사이트는 HTTP가 막힐 수 있다. 카드로 브라우저로 바꾼다.
- 세션을 돌려 쓰는 사이트는 브라우저 쪽 세션이 풀릴 수 있다. 위임된 로그인이 덮는다.
- 잦은 확인이 사이트 규칙에 걸릴 수 있다(호스트당 3분, 물러서기, 카드 경고).
- 쿠키가 브라우저 VM 밖(데몬 메모리)으로 나온다. 비밀번호도 이미 호스트(`systemd-creds`)에 있으므로 같은 경계다.

## Advisor 검토에서 반영한 것(배포 전)

- 다시 쓴 HTTP 가져오기를 실제 네트워크로 다시 돌렸고, 쿠키를 붙이는 경로를 계정 없이 실제로 확인했다(httpbin).
- 쿠키 붙이기 규칙을 순수 함수로 빼고 시험했다. 스킴이 내려가면 붙이지 않는다.
- 비밀번호 칸 없는 로그아웃 화면: 한 번 다시 받는다.
- 제안의 낡은 쿠키 상자: 세션 시도 전에 다시 받는다. 제안 시험에 50초 시한을 두었다.
- 다시 켜기는 글이 보일 때만 한다. 위임을 거두면 일반 실패로 센다. 위임된 재로그인 기록을 구별했다. 429는 물러서기만 한다. 남는 한계를 적었다.

## 시험

- **가져오기 계층**:
  - 브라우저 쪽 세션이 새것이면 그것을 쓴다.
  - 같으면 로그인 위임이 없을 때는 거절, 있을 때는 저장된 로그인으로 다시 로그인한다. 6시간 안에는 다시 하지 않는다.
  - 브라우저 읽기: 로그인 주소로 넘어가면 로그인 문제, 바쁘면 건너뛰기, 계속 켜 두기.
- **엔진**:
  - 위임이 없으면 세션으로 읽지 않는다.
  - 로그인 화면이면 다시 받아 한 번 더 읽는다. 안 되면 "멈춤(로그인 필요)"과 알림.
  - 브라우저가 꺼져 있으면 다시 해 보지 않는다. 떠 있으면 다시 켜고, 그 사이 새 글 2건을 알린다. 모델 0번.
  - HTTP가 막히면 브라우저로 읽어 보고 바꾸기 카드를 올린다(한 장).
  - 브라우저가 바쁘면 실패로 세지 않는다. 브라우저 방식 감시가 있으면 계속 켜 둔다.
- **제안 도구**: 쿠키 없이는 로그인 화면이고 세션으로는 글이 보이면 `session`으로 정한다. 까닭과 "위임 없음"이 카드에 간다.
- **카드**: 세션 감시를 승인하면 읽기 위임(출처 watch)을 만든다. 쿠키 없이 읽는 감시는 만들지 않는다.
- **루틴**: `fetch_session` 선언 가능, `fetch_session` + `fetch`는 승인.
- **쿠키 붙이기 규칙**: 같은 호스트, 위임이 덮는 하위 도메인, 비슷한 이름 거절, 위임 없으면 같은 호스트만, https 쿠키를 http로 보내지 않음.
- **빈 화면**: 알림창만 주는 로그아웃 화면은 다시 받아 읽는다. 다시 받지 못하면 일반 실패(로그인 멈춤 아님). 위임을 거두면 실패로 센다.
- **제안의 낡은 상자**: 처음에는 로그인 화면이고 다시 받으면 글이 보이면 세션 방식으로 정한다(브라우저까지 가지 않는다).
- **실제 네트워크**: 다시 쓴 HTTP 가져오기로 공개 페이지·사설 주소 막기·넘겨주기·Hacker News 게시판(`real_fetch_goes_through_the_checks`).
- **실제 세션 빌려 읽기**(`LUCIA_BROWSER_CHECK_ONLY=session luciad browser-check`, 계정 없음):
  - 브라우저로 httpbin `/cookies/set`에 가짜 쿠키를 심었다. 세션 방식으로 `/cookies`를 읽으면 `{"lucia_check":"ok"}`, 쿠키 없이 읽으면 `{}`였다.
  - 감시 탭으로도 같은 값을 읽었다.
- **실제 브라우저**(`luciad browser-check`, 개발 샌드박스, VM 안 시험 페이지):
  - 로그인된 세션 쿠키 꺼내기(쿠키 1개, 사용자 에이전트).
  - 감시 탭에서 읽기(대화용 탭 주소 그대로).
  - 감시 탭도 로그인된 세션(같은 탭을 다시 씀).
  - 넘겨받기 탭 목록에 감시 탭이 없음. 새 창 닫기는 그대로. 나머지 점검도 모두 통과.
- **아직 못 본 것**: 실제 계정의 로그인 게시판(개발에서는 실제 계정으로 로그인하지 않는다), 실제 사이트의 세션 돌려 쓰기·봇 검사, 운영에서 브라우저를 계속 켜 둘 때의 메모리.
