# 0025. 스크립트와 반복 루틴: 코드 실행, 단축키, 에이전트가 만드는 반복 실행

- 날짜: 2026-11-17
- 상태: 확정. 한도·간격 값은 [제안]. 명세의 도구화 사다리 2단계를 넓혔다([제안], 아래 "명세와 다른 점").
- 결정 방식: 사용자 지시를 따랐다.
  - 요청: "현재 주기적 실행은 무조건 고정된 시간에만 실행되어야 하고, 에이전트가 사용 가능한 건 단건 후속 조치 뿐이야. 코드를 작성하여 기계적으로 처리하거나 필터링하는 등의 작업이 가능한 분야에도 에이전트가 직접 모든 내용을 확인하고 실행해야 하는 구조고. 스킬 또한 … 실행 가능한 코드 등으로 일종의 단축키 같은 것을 만들어 놓으면 숙달된 작업은 빠르게 자동화가 가능할 것으로 보여."
  - 보안: "보안 모델은 너무 빡빡하게 잡지 말고, 정말 크리티컬한 부분에 가드를 세우는 등의 조치만 취해."
  - Advisor의 설계 검토를 받아 반영했다(아래 "Advisor 검토에서 반영한 것").

## 결정

### 스크립트 샌드박스와 도구 다리

- **어디서 도나**: 전용 샌드박스 `lucia-script`에서 돈다(`deploy/create-script-sandbox.sh`, shell 킷, 1 GB).
  - 마운트가 없고 네트워크 허용 규칙도 없다(전역 `default-deny-all`).
  - 상주 샌드박스 `lucia`와 따로 둔다. 코드가 VM 안 Claude 설정(훅의 이중 방어)을 바꿔 다음 실행의 권한을 넓히지 못하게 하려는 것이다.
  - 브라우저 샌드박스와도 따로 둔다. 로그인 쿠키에 닿지 않게 하려는 것이다.
- **통로**: `sbx exec -i`의 표준 입출력 하나다.
  - 데몬이 실행기([`harness.py`])를 `python3 -I -u -c`로 띄운다.
  - 첫 줄로 코드·입력·상태를 넣는다.
  - 코드가 도구를 부르면 한 줄로 묻고 한 줄로 답한다.
  - 코드의 `print`와 자식 프로세스 출력이 이 통로를 더럽히지 않게 fd 1을 stderr로 돌린다. print는 따로 모은다.
- **도구 다리**: 코드가 부르는 도구는 데몬이 자기 MCP 서버에 실행별 토큰으로 다시 부른다(rmcp 클라이언트).
  - 그래서 실행 범위 확인, 승인 카드, 인젝션 보류, 활동 기록이 모델이 부를 때와 같다.
  - 활동 기록에는 부른 실행 ID에 `-code`·`-skill`·`-routine`을 붙인 ID로 남는다. 작업에 묶이는 것도 그대로다.
- **범위**(`Policy::for_script`): 부른 실행의 범위에서 다음을 뺀 것이다. 넓어지는 것은 없다.
  - 사람 없음으로 한다.
  - 보고, 코드, 루틴, 작업, 후속 조치, 감시, 스킬 쓰기, push 갈래를 뺀다. 스스로를 부르거나 새 자동 실행을 거는 길이다.
  - 같은 목록을 이름으로도 한 번 더 막는다.
- **JSON 결과**: 스크립트가 부르면 자주 거르는 읽기 도구 넷은 글 대신 JSON을 준다. `mail_search`, `mail_read`, `calendar_events`, `discord_messages`다.
  - 보안 메일의 미리보기·본문 가림은 글과 같다.
  - 나머지 도구는 외부 데이터 표지를 벗긴 글을 준다.
- **공개 페이지 가져오기**(`lucia.fetch`): 감시와 같은 검사(`watch::SafeFetch`: 차단 목록, 사설 주소 막기, 2 MB)를 거친다. JSON 응답도 받는다.
  - 대화 중 코드는 브라우저를 쓸 수 있는 실행에서만 쓴다. 브리핑 등은 쓰지 못한다.
  - 루틴과 스킬 스크립트는 `fetch`를 선언해야 쓴다.
- **한도** [제안]:
  - 대화 중 실행은 45초다(MCP 요청이 60초에 끊긴다). 루틴은 120초다. 둘 다 설정 `[scripts]`에서 바꾼다.
  - 도구 호출은 200번까지다. print는 16,000자, 돌려줄 값은 64 KB, 상태는 256 KB까지다.
  - 동시 실행은 2개다.
- **끝내기**: 호스트에서 `sbx exec`를 끊어도 VM 안 프로세스는 남는다(실측). 그래서 VM 안에서 `timeout -s KILL`로 감싸고, 시간을 넘기면 실행 표지(`lucia-run-…`)로 찾아 한 번 더 끝낸다.

### 코드 실행(`code_run`, 늘 보이는 도구)

- Lucia가 Python 코드로 도구를 불러 많은 자료를 기계적으로 거르고·세고·계산해 결과만 받는다.
- 돌려주는 글은 8 KB까지다. 외부 데이터로 감싼다.
- 채팅, 작업, 후속 조치, 브리핑, 루틴이 깨운 실행에서 쓴다.
- 루틴 효과(`notify`·`wake`·`next_run`·`finish`)는 실제로 하지 않는다. 무엇을 할지만 보인다. 루틴 스크립트를 시험하는 데 쓴다.

### 단축키(스킬 스크립트, 도구화 사다리 2단계)

- `skill_save`에 `script`(Python)와 `script_tools`(부를 도구 목록, `fetch` 포함)를 붙인다.
  - 개정마다 코드가 남는다(`skill_revisions.script`).
  - 파일은 `<data_dir>/skills/<이름>/run.py`로도 쓰고 git으로 남긴다.
  - 고칠 때 빼면 지난 개정 것을 그대로 두고, 빈 글이면 뗀다.
- `skills` 색인에 ▶가 붙는다. `skill_run(name, input)` 한 번으로 돈다.
  - 쓴 기록은 `skill_read`와 같이 남아 시험 → 활성 승격에 센다.
  - 상태는 `skill:<이름>`으로 이어진다.
- **승인 판단**은 스킬의 기존 규칙(결정 0018)에 스크립트를 더해 한다. 다음이 있으면 승인 대기다.
  - 선언한 도구 중 브라우저·외부 쓰기.
  - 사용자 자료 읽기와 `fetch`의 조합.
  - 코드에 적힌 주소.
- 승인이 필요한 스킬은 쓰는 것이 늘거나 스크립트(코드·도구)가 바뀌면 다시 승인 대기다. 고정되지 않은 스킬은 회고가 고칠 수 있기 때문이다.
- **회고**는 작업에서 `code_run`으로 성공한 코드가 있으면 그대로 단축키로 남긴다(지침).

### 반복 루틴

- **만들기**: 사람과의 대화에서만 쓴다(`routine_create`·`routine_update`·`routine_delete`는 사람만, `routine_list`는 읽기).
  - 외부 글이 사람 없는 실행에서 반복 실행을 심지 못하게 하려는 것이다.
- **언제**(셋 중 하나):
  - `cron`: 사용자 시간대.
  - `every_minutes`: 지난 실행에서 몇 분 뒤, `between`으로 시간대 안에서만.
  - `on_change`: 사전 체크가 `gmail`·`calendar`·`watch`·`watch:<id>`에서 새 변화를 찾을 때. 한 시간마다 확인한다. 스크립트는 변화 목록을 `lucia.input["changes"]`로 받는다.
  - **간격 하한** [제안]: 스크립트가 있으면 5분, 없으면(매번 모델) 60분이다.
- **스크립트가 먼저**: 스크립트가 있으면 모델 없이 그것부터 돈다.
  - `lucia.notify(글, batch=False)`: 바로 알린다(사용자가 맡긴 일의 결과, 결정 0015). `batch=True`이거나 방해 금지 시간이면 모아 보는 소식으로 간다.
  - `lucia.wake(무엇을, 자료)`: Lucia를 깨운다.
  - `lucia.next_run(분)`: 다음 실행을 한 번 당기거나 미룬다.
  - `lucia.finish(까닭)`: 루틴을 끝낸다(예: "택배가 오면 알리고 끝").
  - `lucia.state`(dict): 다음 실행에 넘어간다. 알림을 넘긴 뒤에만 남긴다.
  - 할 일이 없으면 토큰 없이 끝난다. 스크립트가 없으면 매번 Lucia를 깨운다.
- **만들 때 시험**: 스크립트를 한 번 돌린다(대화 중이므로 대화 상한 45초로).
  - 실패하면 만들지 않는다.
  - 성공하면 그 상태를 기준선으로 남긴다(지금 있는 메일을 첫 실행에 한꺼번에 알리지 않게).
  - 시험의 효과는 하지 않고 보이기만 한다.
- **루틴은 코드를 고정한다**: 만들 때의 코드를 루틴이 가진다. 회고가 스킬을 고쳐도 사람 없이 도는 코드는 바뀌지 않는다. 고치려면 사람이 대화에서 `routine_update`로 고친다(다시 시험한다).
- **사람 없는 스크립트의 범위**: 만든 사람(채팅)의 범위가 아니라 발사할 때 정한 읽기 범위다(기억·메일·일정·Discord 읽기). 만들 때 선언한 도구로 더 좁힌다.
  - 쓰기 도구와 브라우저는 선언할 수 없다. 쓰기가 필요하면 `wake`로 Lucia를 깨운다. 그 실행은 후속 조치와 같은 범위이고, 바깥 쓰기는 승인 카드를 거친다.
- **승인 카드**(`routine_review`, 3일): 하나뿐인 승인이다. 사용자 자료를 읽으면서 `fetch`로 바깥 페이지를 가져가는 스크립트일 때만 올린다(자료가 주소에 실려 나갈 수 있다).
  - 새 메일·일정 변화로 도는 루틴은 변화 목록이 사용자 자료이므로 읽기로 친다(`fetch`만 있어도 승인).
  - 승인 대기 루틴은 카드나 관리 페이지에서만 켠다. `routine_update`로 고치거나 `resume`해도 승인 대기 그대로다. 켜진 것도 코드·도구·언제가 바뀌면 다시 승인을 받는다.
  - 카드에는 이름, 언제, 도구, 할 일, 코드 앞부분이 보인다.
  - [켜기]면 켠다. [지우기]나 만료면 지운다.
  - 나머지 루틴은 바로 켠다. 사용자는 대화의 답과 관리 화면에서 본다.
- **걸기**: 후속 조치처럼 루틴 ID와 같은 일회성 스케줄 하나를 둔다. 실행마다 다음 것을 건다.
  - 설정의 cron 루틴 동기화(`disable_cron_schedules_except`)가 끄지 않게 하려는 것이다.
  - 잃은 스케줄은 시작할 때와 조용할 때(5분마다) 다시 건다. 기한(`until`)이 지난 것은 끝낸다.
- **어디서 도나**:
  - 스크립트는 작업 큐 밖(별도 태스크)에서 돈다. 오래 걸려도 채팅을 막지 않는다. 같은 루틴은 겹쳐 돌지 않는다(지금 실행·다시 걸기가 겹쳐도 상태를 덮어쓰지 않게).
  - Lucia를 깨울 일만 큐로 들어와 상주 세션을 깨운다(채팅과 겹치지 않는다).
- **깨우기의 문**(후속 조치와 같다): 방해 금지 시간은 끝날 때로 미룬다. 비용 상한이면 건너뛴다.
  - 하루 깨우기 상한 [제안]은 기본 24번이고, 관리 페이지 "자동 실행 한도"에서 바꾼다.
  - 메신저가 없으면 15분 뒤로 미룬다.
- **깨운 실행**:
  - 요청(`<request>`)에는 사람이 만든 할 일만 넣는다. 스크립트가 본 것(`lucia.wake`의 첫 인자)과 자료는 메일 글이 섞일 수 있으므로 외부 데이터로 감싸 요청 뒤에 붙인다.
  - 알릴 것이 없으면 빈 보고로 아무것도 보내지 않는다.
- **실패**: 세 번 이어 실패하면 멈추고 알린다 [제안]. 대화나 관리 화면에서 고쳐 다시 켠다.
- **한도** [제안]: 루틴은 30개까지다. 이름은 60자, 할 일은 1,000자, 스크립트는 32 KB, 한 번에 보내는 알림은 5건까지다.
- **맥락**: 채팅 맥락에 `<routines>`(id·이름·언제·상태)를 넣어 같은 루틴을 또 만들지 않게 한다.

### 관리 페이지와 점검

- **시스템 화면 "반복 루틴"**: 상태, 언제, 다음 실행, 실행·깨운 횟수, 이어진 실패, 할 일, 스크립트(코드·도구), 최근 기록 5개를 보인다.
  - [지금 실행], [멈추기], [다시 켜기], [켜기(승인)], [지우기].
- **"자동 실행 한도"**: 루틴이 하루에 Lucia를 깨우는 횟수.
- **`luciad check`**: 스크립트 샌드박스가 있는지, 바깥·Anthropic·데몬·브라우저 프록시·관리 페이지가 모두 막혔는지.
- **`luciad script-check`**: 모델도 데몬도 없이 실제 샌드박스를 점검한다.
  - 코드와 도구 다리가 오가는지.
  - 공인 주소·데몬 포트에서 응답이 오지 않는지. sbx는 TCP 연결을 받아 두고 끊으므로 응답으로 본다(실측).
  - 시간을 넘긴 코드가 끝나고 VM 안에 남지 않는지.
- **개발용**: `luciad routine --config <개발 설정> routine:<id>`로 루틴 하나를 지금 돌린다.

## 명세와 다른 점

- 명세의 사다리 2단계는 "스킬 안의 반복 단계를 실행 가능한 스크립트로, 샌드박스 안에서만"이다. 여기서는 세 가지로 넓혔다. 모두 샌드박스 안에서 돈다.
  - 같은 실행기를 대화 중 일회성 코드(`code_run`)에도 쓴다.
  - 사람이 만든 반복 루틴에도 쓴다.
- 명세의 스케줄러는 "cron 식 루틴과 일회성 리마인더"다. 에이전트가 사람의 요청으로 반복 실행을 만드는 것은 명세에 없는 [제안]이다. 사람이 대화 중일 때만 만들 수 있게 해서 "외부 글이 일을 예약하지 못한다"는 원칙(결정 0010)을 지킨다.
- 사전 체크 승격(사다리 3단계)은 결정 0019의 선언형 감시와 함께, 이제 스크립트 루틴(`on_change`, `every_minutes`)으로도 된다.
  - 데몬 코드가 아니라 사람이 대화에서 본 코드(관리 화면에서도 보인다)를 샌드박스에서 돌린다.
  - PR 리뷰 대신 이 방식을 쓰는 까닭은 결정 0019와 같다.

## Advisor 검토에서 반영한 것

- **스케줄 잃음**: 루틴을 cron 스케줄로 두면 설정 동기화가 재시작 때마다 꺼 버린다. 그래서 일회성 스케줄과 다시 걸기로 했다.
- **끝내기**: VM 안 프로세스가 남는 것을 실측했고, VM 안 `timeout`과 표지로 끝낸다.
- **통로 분리**: fd 1과 print를 나눴다.
- **큐**: 스크립트는 큐 밖에서 돈다. 사람 없는 스크립트에는 브라우저가 없다.
- **다리**: 도구 부르기 경로와 범위 계산을 다시 쓴다. 발사할 때 범위를 정한다.
- **외부 데이터**: 스크립트 결과는 외부 데이터로 감싸고, 사용자에게 바로 갈 때는 가린다.
- **코드 고정·선언**: 루틴은 코드를 고정하고, 선언한 도구만 부른다.
- **승인**: 자료를 바깥으로 가져가는 조합만 승인을 받는다.
- **JSON**: 거를 읽기 도구 넷만 JSON으로 준다. 가림은 유지한다.
- **아이디어**: 상태, 만들 때 시험, 효과 계약, 변화 트리거, 결과 8 KB, 연속 실패 멈춤, 관리 화면, `script-check`.
- **완료 뒤 두 번째 검토**에서 고친 것:
  - 승인 대기 루틴이 `routine_update`로 켜지던 구멍.
  - 새 메일 변화 + `fetch`가 승인을 건너뛰던 것.
  - 스크립트가 본 것이 사람의 할 일 자리에 들어가던 것.
  - 만들 때 시험이 MCP 요청보다 길 수 있던 것.
  - 알림이 기본으로 30분 묶음으로 늦던 것. 처음엔 묶음을 기본으로 했다가, 결정 0015의 "맡긴 일의 결과는 바로"에 맞게 바로 보내기를 기본으로 바꿨다.

## 하지 않은 것

- **사람 없는 루틴의 브라우저**: 로그인 사이트 확인을 정기적으로 하려면 Lucia를 깨워서 한다(그 실행은 브라우저를 쓴다). 스크립트에서 브라우저를 직접 몰지 않는다.
- **스크립트에서 쓰기**: 메일 발송·글 올리기는 스크립트에서 바로 하지 않는다. Lucia를 깨워 승인 카드로 한다.

- **비슷한 루틴 합치기 제안**: 맥락에 있는 루틴 목록으로 같은 것을 또 만들지 않게만 했다.
