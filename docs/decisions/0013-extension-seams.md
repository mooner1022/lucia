# 0013. 외부 기기 연결에 대비한 구조: 도구 등급 선언, 등록식 승인, 시작 주체

- 날짜: 2026-11-17
- 상태: 확정(구조). 기기 연결 자체는 [제안]으로 미룬다.
- 결정 방식: 사용자 지시 "추후 Muse Gadgets와 같이 외부 기기를 api를 통해 연결하여 사용하는 기능을 추가할 계획이 있으니 수정 시 이런 부분에 대한 확장성을 고려해." 같은 조각에서 남은 작업 3의 두 항목(후속 조치의 메일 발송 요청, 항목별 브라우저 허용)도 했다.

## 배경: Muse Gadgets의 모양(2026-11-17 조사)

- 출처: gadgets.muse.ai, GitHub `facebookincubator/muse-gadget-sdk`(README, `protocols/DEVICE.md`, `linux/README.md`). 보조 출처는 2026년 10월 기사들이다.
- **기기가 바깥으로 접속한다**:
  - 기기에는 듣는 포트가 없다. Muse 쪽 WebSocket(`wss://…/v1/noise`)에 붙어 Noise 핸드셰이크를 하고 긴 연결을 유지한다.
  - 짝짓기는 휴대폰 앱(BLE)과 SDK 토큰으로 한다.
- **명령 선언과 호출**:
  - 기기는 `link.register`로 명령 목록(`commands_v2`)을 올린다. 명령마다 설명, 인자 스키마(타입별 required·optional), 시간 제한이 있다.
  - 사용법 안내(`device.guide`)는 마크다운이다.
  - 호출은 `link.invoke`, 결과는 `link.result`다.
- **기기가 먼저 보내는 것**: 별도 요청(`/chat/stream`)으로 보낸다. 일반 센서 이벤트 형식은 문서에 없다.
- **권한 모델이 없다**:
  - 명령별 확인, 민감 동작 등급, 속도 제한이 없다. 짝짓기 확인 하나뿐이다.
  - Linux 명령은 설치한 계정 권한으로 돈다("sudo를 쓸 수 있으면 Muse도 쓴다").
- **Lucia에 주는 뜻**:
  - 기기는 "실행 중에 명령을 선언하는 도구 공급자"이고, 들어오는 연결의 클라이언트다.
  - 명세는 모든 행동에 등급과 승인을 요구한다. 그래서 기기 명령도 Lucia 쪽에서 등급을 매겨 같은 권한 계산과 승인 경로를 타야 한다.

## 결정

### 1. 등급과 시작 주체는 플랫폼 중립 타입이다(`lucia-core`)

- **`Grade`**: `Read`, `LocalWrite`, `ExternalWrite`, `Forbidden`. 명세 §권한 등급 표 그대로이고 순서가 있다.
- **`Initiator`**: 일을 시작한 주체다. 작업 레코드(다음 조각)에 남긴다.
  - `Human`: 사람이 지금 대화 중이다.
  - `Delegated`: 사람이 맡긴 일을 나중에 한다.
  - `Autonomous`: 루틴, 사전 체크, 나중의 기기 이벤트다.
  - 모르는 값은 `Autonomous`로 읽는다.

### 2. 도구는 등급을 선언하고, 실행 종류는 범위만 정한다(`crates/luciad/src/tools.rs`)

- **선언**: 도구마다 갈래(보고, 기억, Google, 파일, 후속 조치, 브라우저), 등급, 사람이 대화 중이어야 하는지를 표 하나(`TOOLS`)에 적는다.
- **실행 종류의 범위**: `Policy` = 열린 갈래 + 최대 등급 + 사람 있음. 허용은 선언과 범위로 계산한다.
  - claude 허용 목록과 MCP 서버의 확인이 같은 계산을 쓴다. 모든 도구(읽기 도구 포함)를 서버가 다시 확인한다.
- 전에는 기능마다 허락 칸(`memory_write`, `send_requests`, `browser`, `human` …)이 늘었다. 이제 새 기능은 표에 한 줄을 더한다.
- **기기 명령의 자리**: 표에 없는 동작도 `Policy::allows_grade(등급, 사람 필요)`로 판단한다. 나중에 실행 중 선언된 기기 명령을 같은 규칙으로 연다.
  - 기기는 갈래 하나와 `device_list`·`device_call` 같은 고정 도구 두 개로 연다. 명령별 등급은 호출 때 서버가 본다. 기기마다 MCP 도구 이름을 새로 만들지 않는다(허용 목록이 실행 시작 때 정해지므로).
- **실행 종류별 범위**:

| 실행 종류 | 갈래 | 최대 등급 | 사람 |
|---|---|---|---|
| 채팅 | 모두 | 외부 쓰기(승인) | 있음 |
| 채팅에서 맡긴 후속 조치 | 모두 | 외부 쓰기(승인) | 없음 |
| 브리핑, 브리핑에서 시작한 후속 조치 | 브라우저 빼고 | 로컬 쓰기 | 없음 |
| 기억해 줘(관리 페이지) | 보고, 기억 | 로컬 쓰기 | 있음 |
| 보고 다시 청하기 | 보고 | 읽기 | 없음 |
| 약속 되묻기 | 후속 조치 | 로컬 쓰기 | 없음 |

- "사람이 대화 중이어야 하는 것"(`human_only`): 기억 지우기, 후속 조치 취소, 사이트 로그인 요청.

### 3. 승인 종류는 등록한다(`approvals/kinds.rs`)

- 승인 종류마다 이름, "하지 않았다" 문구, 카드, 실행, 닫힘 알림, 재시작 정리를 `ApprovalKind` 하나에 둔다.
- 데스크는 종류를 모르고 등록된 것에 맡긴다. 결과 기록, 마스킹, 카드 닫기는 데스크가 한다.
- 지금 종류: 메일 발송, 사이트 로그인, 브라우저 동작, 보류한 쓰기, 기억 되돌리기.
- 등록되지 않은 종류(그 기능이 꺼진 채 남은 요청)는 실행하지 않는다.
  - 전에는 모르는 종류를 메일 카드로 그렸다. 이제는 "처리할 수 없는 승인 요청" 카드로 닫는다.
- 다음 종류(작업 완료 확인, 스킬 고정·폐기, git push, 기기 동작)는 구현해 등록만 한다.

### 4. 남은 작업 3의 두 항목

- **후속 조치의 메일 발송 요청**: 채팅에서 맡긴 후속 조치는 `mail_send`를 쓴다. 승인 카드(24시간)를 거친다. 지침에 "메모에 사용자가 보내라고 한 것만, 보냈다고 말하지 않는다"를 적었다.
- **항목별 브라우저 허용**:
  - 관리 페이지 개요의 "Lucia가 약속한 일"에서, 브리핑이 등록해 읽기만 하는 항목에 [브라우저 허용]을 둔다.
  - 누르면 출처가 `user`가 되고, 그 실행은 채팅에서 맡긴 것과 같은 범위로 돈다.
  - 사용자가 메모를 보고 그 하나만 허용하므로, 브리핑 사슬의 위험(결정 0011)은 그대로 막힌다.

### 5. 기기 연결 때 지킬 것 [제안, 아직 만들지 않음]

- **접속**: 기기는 데몬의 접속 API(7단계의 WebSocket/HTTP)에 바깥에서 붙는다.
  - 토큰은 관리 페이지가 발급하고 언제든 취소할 수 있다. 기본은 거부다.
  - 토큰에는 역할(앱 채널 / 기기)이 있다.
  - LAN·WireGuard에서만 연다.
- **명령 등급**: 기기가 올린 명령 선언에 Lucia 쪽 등급을 붙인다. 기본은 외부 쓰기(승인)이고, 사용자가 관리 페이지에서 명령별로 내린다. 기기가 스스로 매긴 등급을 믿지 않는다.
- **기기가 보내는 이벤트**:
  - 사전 체크의 "바뀐 것"(`lucia_precheck::Change`)과 알림 묶기의 입력으로 넣는다.
  - 기기 이벤트로 시작한 실행은 `Autonomous`다.
  - 기기 결과·이벤트 글은 외부 데이터로 감싼다.
- **나가는 길**: 기기의 로컬 HTTP API(사설 IP)는 데몬이 호스트에서 중계한다. sbx·브라우저 출구를 넓히지 않는다(결정 0008).

## 확인(2026-11-17)

- **시험**:
  - 도구 표: 이름이 겹치지 않는다. 갈래·등급·사람 조합이 맞다. 금지 등급은 늘 닫힌다.
  - 허용 목록:
    - 채팅에서 맡긴 후속 조치에 `mail_send`와 브라우저가 열린다.
    - 로그인 요청·지우기·취소는 닫힌다.
    - 브리핑과 그 사슬에는 브라우저가 없다.
  - MCP 서버가 열리지 않은 도구를 거절한다(읽기 도구 포함).
  - 승인 데스크:
    - 새 종류를 등록하면 카드·실행·기록이 돈다.
    - 모르는 종류는 실행하지 않고 메일로 보내지 않는다.
    - 기존 시험이 그대로 통과한다.
  - 관리 화면: [브라우저 허용] → 출처 `user` → 브라우저를 쓰는 실행.
- **실제로 아직 안 본 것**: 운영에서 후속 조치가 메일 발송 카드를 올리는 것, 허용한 항목이 브라우저로 페이지를 여는 것.
