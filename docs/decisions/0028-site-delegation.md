# 0028. 사이트 위임: 한 번 허용한 사이트는 사람 없는 실행이 다시 묻지 않는다

- 날짜: 2026-11-18
- 상태: 확정. 값(만료·상한·카드 수명)은 [제안].
- 결정 방식: 사용자 지시를 따랐다.
  - 소유자 개선안("위임 기반 자율성과 출구 검사")을 검토한 적용안(`docs/proposals/delegation-and-egress-review.md`)을 사용자가 승인했다: "이대로 진행해봐."
  - 덧붙인 지시: "브라우저 관련은 한 번 이후 작업을 모두 명시적으로 허용한 상황에 대해선 다시 묻지 않고 수행할 수 있도록 하고, 여기에 로그인을 포함해."
  - Advisor 설계 검토를 받아 반영했다(아래).
- 함께 넣은 작은 묶음(같은 결정): 범위를 줄이는 동작은 사람 없이, 링크 미리보기로 새는 길 막기, 기억 변경 출처, 카드 위험 줄.

## 배경

- 권한을 "실행하는 순간 사람이 있는가"로 정해서, 맡긴 일일수록 권한이 줄었다.
- 실제 사례: 11/17 07:30 아침 브리핑이 등록한 "암호학 과제 제출 여부" 후속 조치는 브리핑 사슬이라 브라우저가 없었다. 메모에 "브라우저는 못 쓰니 사용자에게 확인 요청"이라고 적혔다.

## 결정

### 사이트 위임(저장소 `site_grants`, 마이그레이션 0017)

- 위임 하나 = 호스트 하나(그 하위 도메인 포함) + 할 수 있는 것.
  - 늘: 사람 없이 열고 읽기.
  - `login`: 세션이 끊기면 저장된 로그인으로 **묻지 않고** 다시 로그인.
  - `actions`: 폼 제출처럼 승인이 필요한 브라우저 동작도 **묻지 않고** 하기.
  - 금지 동작(결제·주문·송금·탈퇴·비밀번호 바꾸기·로그아웃·파일 올리기·로그인 폼 직접 입력)은 위임해도 하지 않는다(I3).
- 호스트 덮기: 같은 호스트와 하위 도메인만(`a.example.com`은 `example.com`이 덮는다. `evil-example.com`과 `example.com.evil.com`은 아니다).
  - 공개 접미사 목록 없이 사람이 고른 호스트 그대로 쓴다. 대신 2단 공용 접미사(`ac.kr`, `co.kr` 등)와 최상위 도메인 하나, IP 주소는 받지 않는다(그 아래 모든 사이트가 열린다).
  - 로그인이 다른 호스트(통합 인증)에서 이뤄지면 둘을 덮는 상위 호스트를 위임한다.
- 만료: 기한 없는 위임은 90일 [제안] 쓰지 않으면 쓰지 않는다(관리 페이지에서 보인다). "이번만"은 12시간.
- 같은 호스트에 위임이 있으면 새 줄을 만들지 않고 넓히기만 한다. 50개까지 [제안].

### 만들기와 넓히기(I1: 사람만)

세 길뿐이다. 모델·스크립트·사람 없는 실행은 만들거나 넓히지 못한다.

1. **대화에서 제안 → 카드**: 새 도구 `site_grant_propose(host, purpose, login, actions)`. 사람 필요 도구(대화 중에만)이고, 스크립트에서는 이름으로도 막는다. 카드(`site_grant`, 3일)에 범위를 문장으로 보이고, [위임하기]를 누르면 보인 그대로 위임한다.
2. **사람 없는 실행의 카드에서 [이 사이트 계속 허용]**(결정 0029): 읽기 위임만 만든다. 로그인·동작은 이 단추로 생기지 않는다(카드가 그 범위를 말하지 않으므로).
3. **관리 페이지** 시스템 화면 "사이트 위임": 직접 추가(로그인·동작 체크), 목록(범위·출처·쓴 횟수·마지막 사용), [거두기].
- 앞서 검토 문서는 "사람 없는 실행이 카드로 위임을 요청하는 길은 두지 않는다"고 했다. 사용자의 "한 번 이후 다시 묻지 않게"에 따라 2번 길을 열었다. 단추를 누르는 것은 사람이고(카드에 실행 종류·주소·까닭을 보인다), 하루 카드 수와 같은 호스트 한 장 제한을 둔다(결정 0029).

### 쓰기

- 브라우저 도구가 호출자를 보고(아래 "누가 부르나") 위임을 확인한다.
- 위임이 덮는 사이트에서는 **누가 불렀든**(대화 중이어도, 위임 전 후속 조치여도) 다시 묻지 않는다: 로그인 페이지로 튕기면(내장 사이트) `login`이 있고 저장된 로그인이 있으면 카드 없이 로그인하고, `actions`가 있으면 승인 카드가 필요한 동작을 그냥 한다(활동 기록 `browser_delegated`, `login_delegated`).
- 사람 없는 실행의 `browser_login`은 로그인을 위임한 사이트만 받는다. 그 확인을 지나기 전에는 저장된 로그인 주소도 바꾸지 않는다.
- 위임 범위로 **묶는 것**(위임 밖은 열지 않음)은 사람 없는 실행만이다(결정 0029).
- 쓸 때마다 위임의 사용 횟수·마지막 사용을 적는다.
- **브리핑 사슬**(브리핑, 브리핑이 등록한 후속 조치, 사람 없이 시작한 작업)도 위임한 사이트를 브라우저로 **읽는다**(사용자 지시). 이 실행들은 로컬 쓰기 등급이라 누르기·입력은 여전히 없다(주소로 열어 읽기, 스크롤, 화면 찍기, 위임된 로그인).
  - 사슬을 가르는 기준을 "브라우저 갈래가 있는가"에서 "외부 쓰기까지 열린 실행인가(`browser_click` 허용)"로 바꿨다. 브리핑 사슬이 브라우저 갈래를 얻어도 대화 사슬로 올라가지 않는다(시험이 잡았다).

### 누가 부르나

- MCP가 브라우저 도구를 부르는 동안 `tokio::task_local`로 호출자(실행 ID, 사람 있음)를 싣는다. 없으면 데몬 자신의 동작(승인된 동작 실행, 로그인)이다.
- 코드 다리로 부른 브라우저도 사람 없음으로 본다(스크립트 범위가 그렇다). 그래서 대화 중 `code_run`이 부른 브라우저도 위임한 사이트만 연다.

### 맥락과 지침

- 채팅·후속 조치·브리핑·루틴·작업 맥락에 `<site_grants>`(호스트, 할 수 있는 것, 쓰는 곳)를 붙인다. 없으면 "없음: 사람 없는 실행이 사이트를 열려 하면 카드로 묻는다"고 적는다("열지 못한다"고 적으면 11/17처럼 모델이 시도조차 하지 않는다).
- 11/17 실패의 원인이었던 "브라우저·메일 발송·기억 지우기를 할 수 없다" 지침을 "site_grants의 사이트만 주소로 열어 읽는다"로 고쳤다.
- 채팅 지침: 사람 없이 도는 일이 로그인 사이트나 처음 보는 사이트를 쓰면 등록할 때 `site_grant_propose`로 위임을 제안한다.

### 위임 전에 만든 후속 조치

- 마이그레이션이 `delegation.since`를 적는다. 그 전에 만든 후속 조치는 예전처럼 어디든 연다(배포 전 약속을 깨지 않게). 운영에는 대화에서 만든 한양 러닝 확인이 두 건 열려 있다.

## 같은 결정의 작은 묶음

- **줄이는 동작은 사람 없이**(개선안 I2): 사람 없는 실행은 지금 발사한 후속 조치와 같은 실행이 등록한 것만 취소한다(사람이 맡긴 약속은 못 지운다). 자기를 깨운 루틴은 멈추기·간격 늘리기만 한다.
- **링크 미리보기로 새는 길**: 글 메시지의 주소를 `<주소>`로 감싸고(코드 블록 빼고, `[글](주소)`도), 미리보기 끄기 플래그를 단다. 카드 임베드에는 플래그를 쓰지 않고(카드가 숨겨진다) 머리줄 주소만 감싼다. 플래그가 Discord의 가져오기 자체를 막는지는 실측하지 못했다. `<>` 감싸기는 미리보기를 만들지 않는 Discord 표기다.
- **기억 변경 출처**: 관리 페이지 기억 변경 기록에 바꾼 실행(대화 중 / 후속 조치(사람 없음) / 하루 정리 등)을 보인다.
- **카드 위험 줄**: 메일·Discord 글·브라우저 동작 카드 맨 위에 "⚠ 처음 보내는 주소 · 전화번호" 같은 줄. 요청 때 계산해 카드 내용에 고정한다(보이는 것 = 실행하는 것).

## Advisor 검토에서 반영한 것

- [계속 허용]은 읽기만(로그인·동작은 대화 카드나 관리 페이지). 호스트당 대기 카드 한 장, 하루 카드 수 상한.
- 호스트 단위 덮기(라벨 개수로 eTLD+1을 추정하지 않음), 공용 접미사 거절. 도착 주소(넘겨주기)와 누를 링크의 `href`를 모두 검사.
- 맥락에 위임 목록, 낡은 지침 문구 정정.
- 기존 운영 후속 조치는 시각 기준으로 예외.
- 로그인 없이 카드만 생기는 위임 단추 금지, 실제 계정 대신 가짜 브라우저로 시험.

## 시험

- 저장소: 하위 도메인 덮기와 비슷한 이름 거절, 넓히기만, 이번만 만료, 오래 안 씀, 거두기, 공용 접미사 거절.
- 브라우저 도구(가짜 브라우저): 위임 밖은 열지 않고 카드, 위임 안은 묻지 않음, 동작 위임이면 POST도 묻지 않음, 금지 동작은 그대로 못 함(I3), 위임 밖 링크·넘겨주기 도착 막기, 거두면 다음 호출부터 막힘, 사람이 대화 중이면 그대로. 로그인 위임이면 저장된 로그인으로 카드 없이 로그인, 아니면 길게 사는 재로그인 카드.
- MCP: 사람 없는 실행 네 종류의 `site_grant_propose` 거절(I1), 대화에서는 카드만(누르기 전에는 위임 없음), 이미 위임된 것은 다시 묻지 않음. 사슬 출처가 올라가지 않음.
- 실제 모델(개발): "모레 9시 LMS 과제 확인, 세션 끊기면 저장된 로그인으로"에 Lucia가 `site_grant_propose(login=true, actions=false)`와 후속 조치를 함께 걸었다(CLI 채널이라 카드는 올라가지 못했다).
- 실제 계정으로는 시험하지 않았다. 운영에서 처음 보는 것: 사이트 위임 카드 모양, 위임된 로그인의 실제 사이트 동작.
- 첫 배포 뒤 Advisor 검토로 고친 것(같은 날 다시 배포): 사람 없는 실행의 승인 카드를 만들 때 저장소 잠금을 한 식 안에서 두 번 잡아 멈출 수 있던 것(시험 추가), 위임의 혜택이 사람 없는 실행에만 걸리던 것, 위임이 없을 때 맥락 문구, 로그인 주소를 확인 전에 바꾸던 것, "이번만"을 계속 허용으로 넓혀도 출처가 남던 것.
