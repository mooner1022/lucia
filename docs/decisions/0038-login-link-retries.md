# 0038. 로그인 입력 링크 다시 쓰기와 일반 사이트 로그인 고침

- 날짜: 2026-11-18
- 상태: 확정. 시도 수(3번)는 [제안]이다. **알림 받을 곳이 앱이면 앱의 입력 카드로 받는다**(결정 0063: 링크는 카드 본문에 남고, 카드와 링크가 같은 요청이라 토큰과 시도 수를 나눠 쓴다. 알림 받을 곳이 Discord이면 그대로).
- 결정 방식: 사용자 지시 "지금 로그인 요청이 계속 실패하고 있는데, 에러 메세지가 `로그인하지 못했습니다: 비밀번호를 입력하세요.`야. 로그인에 실패하고 다시 입력하면 이 입력창이 바로 유효하지 않게 되어 버리는 문제도 있었어. 전반적으로 점검해봐."

## 무엇이 잘못됐나(운영 2026-11-18 15:23~15:25, 일반 프로필 사이트)

### 1. 넣은 비밀번호를 지운 채 제출했다

- 그 사이트의 로그인 단추는 `<input type="image">`이고, 폼은 제출할 때 스크립트로 빈 칸을 검사한다(`비밀번호를 입력하세요.`).
- 일반 프로필의 칸 찾기는 단추를 `form.elements`에서 찾는다. 그런데 이미지 단추는 `form.elements`에 들어가지 않는다(HTML 명세). 그래서 단추가 없다고 보고 "비밀번호 칸에서 Enter" 경로로 갔다.
- 그 경로는 Enter 전에 칸에 초점을 다시 주는 함수(`login_focus`)를 불렀다. 이 함수는 넣기 전에 칸을 비우도록 만든 것이라, 방금 넣은 비밀번호를 지웠다.
- 그래서 사이트가 빈 비밀번호로 보고 대화상자를 띄웠고, 데몬은 그 문구를 거절 까닭으로 돌려줬다.

### 2. 실패한 뒤 다시 넣으면 링크가 무효가 됐다

- 입력 링크의 토큰을 제출하는 순간 지웠는데, 로그인은 페이지 로드를 기다리느라 수십 초 걸린다.
- 그 사이 제출을 다시 누르거나 브라우저가 다시 보내면, 같은 토큰이 이미 지워져 "쓸 수 없는 링크"가 됐다.
- 실패한 뒤에는 실패 화면에만 새 토큰이 있었다. 그래서 Discord의 처음 링크를 다시 열면 무효였다.
- 하는 중에는 대기 중인 입력도 없어서, Lucia에게 다시 부탁하면 새 링크가 또 갔다. 운영 기록에서 실패 → 43초 뒤 새 링크 → 18초 뒤 앞선 시도의 실패 순서가 이것이다.

## 결정

- **단추 찾기**: 폼 조작 요소에 이미지 단추(`input[type=image]`)를 더한다. 처음 로그인, 단계형 두 단계, 인증 코드 단계 모두다.
- **초점 주기**: 칸을 비우는 것은 넣을 때만 한다. 제출하려고 초점만 줄 때는 비우지 않는다.
- **제출 직전 확인**: 아이디·비밀번호 칸의 글자 수를 한 번 더 본다. 사이트 스크립트가 지웠으면 제출하지 않고 그 까닭을 돌려준다.
- **입력 링크**:
  - 성공하면 닫힌다.
  - 실패하면 같은 링크로 3번까지 다시 넣는다. 실패할 때마다 10분을 다시 준다. 빈 칸처럼 시도하지 않은 실패는 세지 않는다.
  - 하는 중에 같은 링크가 또 오면 "이미 로그인하고 있다, 1분쯤"이라는 화면을 보인다.
  - 하는 중에도 링크는 살아 있어, Lucia가 다시 요청해도 새 링크를 보내지 않는다.
  - 실패는 Discord로도 알린다(제출 화면의 응답을 놓쳐도 결과를 안다). 3번 실패하면 닫고 Lucia에게 다시 요청하라고 알린다.
- 입력 폼과 Discord 메시지의 안내도 "한 번만"에서 위에 맞게 고쳤다.

## 고친 뒤 다시 본 문제(같은 날 15:44, 사용자 보고)

- 제출하면 "이미 이 링크로 로그인하고 있습니다"만 보였고, 3분을 기다려도 그대로였다. 로그인도 되지 않았다.
- 원인: 로그인을 수십 초 걸리는 HTTP 요청 안에서 했다. 그 사이 제출을 다시 누르면 브라우저가 첫 요청을 취소한다. 서버(axum/hyper)는 연결이 끊긴 요청의 처리를 중간에 버린다. 그래서 로그인 자체가 버려졌고, "하는 중" 표시만 남아 다음 제출이 모두 "이미 하는 중"이 됐다(결과 기록이 하나도 없었다). 앞의 "링크가 바로 무효"도 같은 원인이었다.
- 결정:
  - 제출을 받으면 로그인은 **요청과 떨어진 작업**(`SiteLogins::spawn_submit`)으로 돌리고 바로 결과 화면으로 보낸다(POST → 303 → GET).
  - 결과 화면은 링크의 상태를 보인다: 하는 중(`Refresh: 3` 머리로 스스로 새로 고침, 스크립트 없음), 성공, 인증 코드 필요, 실패(같은 링크로 다시 넣는 폼과 까닭), 시도 상한.
  - 끝난 링크로 또 넣어도 다시 로그인하지 않고 결과만 보인다.
  - 로그인 하나에는 150초를 준다. 넘으면 실패로 세고 알린다. "하는 중"이 남지 않는다.
  - 인증 코드 입력도 떨어진 작업으로 돌린다(요청이 버려져도 코드 입력은 끝까지).
  - 닫힌(시도 상한) 링크는 기다리는 요청으로 치지 않는다. Lucia가 다시 요청하면 새 링크를 보낸다.

## 시험

- **떨어진 작업**: 요청을 기다리지 않아도 로그인이 끝나 결과(실패 까닭)가 링크에 남는다. 없는 링크는 시작하지 않는다.
- **관리 페이지**: 제출은 303으로 결과 화면, 하는 중이면 `Refresh` 머리, 끝나면 "로그인했습니다". 끝난 링크로 또 넣어도 다시 로그인하지 않는다.
- **로그인 흐름**: 실패해도 같은 링크(Discord 알림 포함), 링크가 살아 있으면 새 링크를 보내지 않음, 빈 칸은 세지 않음, 세 번째 실패면 닫고 그 뒤에는 무효, 하는 중에 또 오면 기다리라고 함. 저장은 실패하면 하지 않음.
- **실제 브라우저**(`luciad browser-check`, 개발 샌드박스, VM 안 시험 페이지):
  - 운영에서 실패한 사이트와 같은 모양(이미지 로그인 단추 + 제출 검사 스크립트)의 로그인 성공.
  - 단추 없이 Enter로 제출하는 폼(넣은 비밀번호를 지우지 않음)의 로그인 성공.
  - 기존 점검 53개가 모두 통과했다.
- **아직 못 본 것**: 운영의 그 사이트에서 실제 계정으로 다시 로그인하는 것. 사용자가 다시 시도할 때 본다.

## 사람 확인 단계(같은 날 17:51, 네이버)

- **문제**:
  - 네이버 로그인이 두 번 다 "로그인함"으로 기록됐다. 그런데 브라우저 프로필에 로그인 세션 쿠키(`NID_AUT`, `NID_SES`)가 없었고, naver.com은 로그아웃 상태였다.
  - 개발 샌드박스에서 가짜 아이디로 넣어 봤다(`LUCIA_BROWSER_CHECK_ONLY=probe LUCIA_PROBE_URL=…`). 네이버는 같은 주소에 "추가 보안 확인"(영수증 문제 캡차)을 띄웠다. 그 화면에는 비밀번호 칸이 없어서, 일반 프로필의 "비밀번호 칸이 사라지면 성공" 판정이 성공으로 봤다.
- **결정**:
  - 제출 뒤 화면을 사람 확인 단계로 알아본다. 근거는 문구(캡차, security verification, 자동입력 방지, 추가 보안, 새로운 기기·환경, 2단계 인증 등)와, 캡차 iframe·요소다.
    - 이런 화면이면 성공이 아니라 새 결과 `NeedsHuman`이다.
    - 페이지는 그 단계에 그대로 둔다(칸을 비우지 않는다).
    - 결과 화면·Discord에 "관리 페이지 브라우저 넘겨받기에서 10분 안에 직접 풀어 달라"는 안내와 링크를 보인다.
    - 활동 기록은 `login_challenge`이고, "로그인함"으로 남기지 않는다.
  - 저장을 골랐으면 넣은 로그인을 저장한다. 맞는지는 아직 모른다. 틀렸으면 다음 재로그인이 거절되고 입력 링크가 다시 간다.
  - 로그인 칸은 한 글자씩 실제 키 입력(`Input.dispatchKeyEvent`, 글자 사이 40~110ms)으로 친다. 자판에 없는 글자만 그대로 넣는다.
    - 네이버의 보안 확인은 이것으로도 떴다. 새 환경의 자동화된 브라우저에 대한 사람 확인이라 데몬이 우회하지 않는다.
    - 키 입력 기록을 보는 다른 사이트에는 도움이 될 수 있어 남겼다.
- **시험**:
  - 비밀번호 뒤 캡차 화면 시험 페이지에서 `NeedsHuman`.
  - 네이버 로그인 페이지에 가짜 값을 넣으면 `NeedsHuman { "security verification" }`.
  - 사람 확인이면 결과가 넘겨받기 링크와 Discord 알림이고, "로그인함" 기록이 없다.
  - 브라우저 점검 54개가 모두 통과했다(한 글자씩 치는 방식으로 바꾼 뒤에도).
- **아직 못 본 것**: 실제 계정으로 네이버 보안 확인을 넘겨받아 푼 뒤 로그인이 이어지는지.
