# 0012. 데몬을 systemd 사용자 서비스로 돌린다

- 날짜: 2026-11-17
- 상태: 확정
- 결정 방식: 사용자 지시 "1, 3, 4 작업들 모두 순차적으로 진행해"(1 = 운영: 커밋, systemd, 재부팅 시험). 명세 §운영 "데몬은 … systemd 서비스로 돌리고, 조용히 멈추는 일이 없게 한다". 경로와 유닛 나누기는 [제안]이다.

## 결정

- **사용자 유닛 두 개**(`~/.config/systemd/user/`):
  - `luciad.service`: `Type=notify`, `WatchdogSec=180s`, `Restart=on-failure`(1시간에 5번까지).
    - 스케줄러 루프가 60초마다 watchdog 신호를 보낸다. 모델 실행은 작업 큐에서 돌아 이 루프를 막지 않는다.
  - `lucia-sbx.service`: sbx 데몬(`sg kvm -c 'sbx daemon start'`).
    - sbx 데몬은 처음 부른 sbx CLI가 띄우고 그 cgroup을 물려받는다. luciad 유닛이 띄우면 luciad를 재시작할 때 systemd가 cgroup째 정리해 VM(상주 세션, 로그인된 브라우저 프로필)이 멈춘다. 그래서 따로 둔다.
    - 이미 살아 있는 sbx 데몬이 있으면(소켓에 연결된다) `ExecCondition`으로 건너뛴다. 지금은 앞서 셸에서 띄운 데몬이 돌고 있어 건너뛰었다. 다음 부팅부터 이 유닛이 띄운다.
- **바이너리 고정 경로**: `~/.local/lib/lucia/luciad`.
  - 레포의 `target/`에서 돌리면 개발 중 릴리스 빌드가 운영 바이너리를 바꾼다. 그 상태로 데몬이 재시작하면 시험하지 않은 빌드가 운영 저장소를 마이그레이션한다.
- **배포**: `deploy/install.sh` 하나로 한다.
  1. 릴리스 빌드.
  2. 운영 저장소 백업(`sqlite3 .backup`, `<data_dir>/backup/`, 최근 20개).
  3. 바이너리 설치, 유닛 설치.
  4. 시작 횟수 카운터를 비우고(`reset-failed`) 재시작한다. 유닛의 시작 제한(1시간 5번)은 충돌을 막으려는 것이라 배포 재시작은 세지 않는다. 2026-11-17 하루에 여러 번 배포하다 제한에 걸려 서비스가 9초 멈췄다.
- **linger**를 켰다(`loginctl enable-linger`, sudo 없이 됐다). 로그인하지 않아도 부팅 때 뜬다.
- **로그**는 journal로 간다(`journalctl --user -u luciad`). 예전 `luciad.log`는 더 쓰지 않는다.
- **개발과 겹치는 것**: 서비스가 MCP 포트(47810)와 브라우저 프록시 포트(47811)를 쥔다. 개발용 `ask`·`briefing`·`browser-check`를 운영 설정으로 돌리지 않는다.
  - 상주 샌드박스의 네트워크 정책은 운영 MCP 포트 하나만 연다. 그래서 포트만 바꾼 개발 설정은 VM에서 닿지 않는다.
  - 개발용 상주 샌드박스 `lucia-dev`(MCP 포트 47820만 허용)와 `~/.config/lucia/lucia-dev.toml`(저장소·포트·샌드박스 분리, 브라우저 끔)을 만들었다.
  - 2026-11-17 이것으로 실제 모델 채팅과 작업 맡기기를 확인했다(결정 0014).

## 확인(2026-11-17)

- 서비스로 시작했다: Discord 게이트웨이 연결, 관리 페이지, 브라우저 프록시.
- 같은 환경(`systemd-run --user`, 같은 PATH)에서 `luciad check`가 모두 통과했다: sbx 데몬 kvm 권한, 샌드박스, 네트워크 규칙, 캐릭터, 브라우저.
- `lucia-sbx.service`는 살아 있는 데몬을 보고 건너뛰었다.

## 하지 않은 것

- **재부팅 복구 시험(P3)**: 호스트를 재부팅하지 않는다. 사용자가 유지보수로 재부팅할 때 `poc/p3/after_reboot.sh`와 함께 확인한다.
  - 확인할 것: `lucia-sbx`가 sbx 데몬을 kvm 그룹으로 띄우는지, luciad가 뜨는지, 상주 세션이 이어지는지.
- **전용 시스템 사용자**(명세 "전용 사용자와 systemd 샌드박싱"): sbx 로그인, Claude 로그인, 자격 증명이 지금 사용자에게 묶여 있어 옮기지 않았다.
