# 0027. 하루 기억 변경 확인을 없앤다

- 날짜: 2026-11-17
- 상태: 확정. 명세와 다르다([제안], 아래 "명세와 다른 점").
- 결정 방식: 사용자 지시를 따랐다.
  - 계기: 21:00 확인 카드 다섯 장과 "그 밖에 22개" 알림이 한꺼번에 왔다. "그대로 두기"를 누르자 "🚫 거절했습니다. 그대로 두었습니다."가 떠서 뜻을 알기 어려웠다.
  - 사용자 의견: "기억은 모델이 관리하는 나에 대한 정보들이고, 대화에서 가져온 것이니 수정이 필요하다면 그 때 변경하는 게 낫지 않나?"
  - 범위를 좁히는 안(사용자가 없을 때 바뀐 것만 한 통으로 알리기)도 제안했지만, 사용자가 골랐다: "하루 확인을 아예 없애."

## 그날 일어난 일(2026-11-17 21:00, 운영)

- 하루 동안 Lucia가 27개 항목을 45번 고쳤다. 대부분 15시대에 시드 문서를 기억으로 옮기고(17번) 오래된 기억을 정리한(6번) 것이다.
- 카드는 5장까지만 올리고 나머지는 한 줄로 알렸다. 사용자는 다섯 장 모두 "그대로 두기"를 눌렀다. 바뀐 기억은 없다.
- 카드 문제
  - 승인 카드의 틀을 그대로 써서, 닫힐 때 "거절"이라는 말이 붙었다.
  - 기억을 지우는 "되돌리기"가 초록색 주 단추였다.

## 결정

- 내장 루틴 `memory-digest`(매일 21:00)를 없앴다.
  - 설정에서 사라진 내장 루틴은 `sync_routines`가 스케줄을 끈다.
  - 저장소의 `memory.digest_at` 설정과 예전 카드 기록은 그대로 둔다(해가 없다).
- 승인 종류 `memory_undo`(카드, 되돌리기 실행)와 엔진의 `memory_digest`, 작업자 동작 `memory_digest`를 지웠다.
  - 예전 카드 기록은 모두 닫혀 있다(운영 5건 모두 처리됨). 관리 페이지에서는 이름 모르는 종류("승인 요청")로 보인다.
- 기억을 고치는 길
  - **대화에서**: Lucia가 기억을 저장하면 DM에 "🗂 기억 저장: …" 알림이 그 자리에서 뜬다. 틀렸으면 그때 고쳐 달라고 한다. 명세의 "사용자 교정이 우선이다"는 그대로다.
  - **관리 페이지 기억 화면**: 항목의 변경 기록마다 "이 내용으로 되돌리기"를 더했다.
    - 지금 개정 말고, 내용이 있는 예전 개정만 고를 수 있다.
    - 되돌리면 사용자 변경으로 남고, 활동 기록에 "기억 되돌림"이 찍힌다.
    - 다른 항목의 개정 번호로는 되돌리지 않는다.
    - 변경 기록에 개정마다의 요약도 보인다.
  - 지우기는 예전처럼 같은 화면에서 한다.
- 남는 보호
  - 지시처럼 보이는 글을 기억에 넣으려 하면 보류 카드로 묻는다(인젝션 검사, 결정 0010). 이것은 그대로다.
  - 모든 변경은 기록된다.

## 명세와 다른 점

- 명세 §쓰기 정책: "핵심 기억은 에이전트가 직접 고치되, 모든 변경을 기록하고 하루 한 번 Discord로 변경 요약과 되돌리기 버튼을 보낸다."
- **지키는 것**: 모든 변경 기록, 되돌리기(관리 페이지).
- **없앤 것**: 하루 한 번 Discord로 보내는 요약과 버튼.
- **남는 위험**
  - 사용자가 보지 않는 사이(20:30 하루 정리, 후속 조치·루틴·작업 실행)에 Lucia가 바꾼 기억은 이제 알림 없이 들어간다.
  - 그럴듯하지만 틀린 사실(인젝션 검사에 걸리지 않는 것)은 나중에 엉뚱한 판단으로 드러날 때까지 모를 수 있다.
  - 그때는 관리 페이지 기억 화면의 변경 기록에서 찾아 되돌린다.
