# 0062. 관리 화면의 디자인 언어: 캐릭터 시트에서 가져온다

- 날짜: 2026-11-21
- 상태: 확정. 시트의 무엇을 화면의 무엇으로 옮길지(색, 꼴, 문양, 글꼴)는 사용자가 세부를 정하지 않은 설계라 [제안]이다.
- 결정 방식: 사용자 지시(캐릭터 디자인 시트 그림 첨부).
  - "디자인적으로 바뀐 게 크게 없는 것 같아. 루시아의 캐릭터성을 잘 살리는 디자인을 원해. 캐릭터 디자인 시트를 첨부했으니 이에 기반하여 디자인 언어를 정한 뒤 이를 페이지에 적용해. 약간의 감성을 첨가해서."
  - (첫 적용을 본 뒤) "카드 내의 약한 그라데이션은 빼고, 배경의 바람 무늬 대신 연하고 반투명한 꽃잎이 흩날리는 애니메이션을 추가해. 추가로 레이아웃이나 계층 면에서 어색한 부분을 찾아 개선해."
  - "지금 좌측 탭 상단의 꽃잎 로고가 중앙이 맞지 않는 문제도 있어."
  - "권한 모드 선택창에서 이모지를 빼고 아이콘으로 대체해."
- 관련 결정: 0061(정적 Svelte 화면과 디자인 토큰·부품), 0041(기능 보존)
- 바꾸는 것: 결정 0061의 "디자인 [제안]" 가운데 **색·모서리·그림자·글꼴·틀의 모습**. 화면의 짜임(부품만으로 짠다), 데이터, 기능, 시험 장치는 그대로다.

## 왜

- 0061의 디자인은 흰 카드에 남색 강조색을 쓴 무난한 관리 화면이었다. 구조는 전부 바뀌었지만 사용자가 보기에 "바뀐 게 크게 없었다". 누구의 화면인지 드러나지 않았다.
- 사용자가 Lucia의 캐릭터 디자인 시트를 주고, 그것에 기반한 디자인 언어를 정해 화면에 적용하라고 했다.
- 시트의 색은 0061의 색(흰색, 남색)과 가깝다. 그래서 색만 바꾸면 또 달라 보이지 않는다. 달라져야 하는 것은 **꼴과 자리**다: 쪽빛이 어디에 어떤 모양으로 놓이는가, 제목이 어떤 글씨인가, 화면의 가장자리에 무엇이 있는가.

## 결정

디자인 언어는 `web/admin/docs/design.md`에 적는다(시트의 요소 → 화면의 자리, 색 토큰의 뜻, 꼴, 글꼴, 문양, 부품별 모습, 지킬 것). 요지는 이렇다.

### 시트에서 가져온 것 [제안]

- **비율**: 흰 옷감이 대부분, 푸른 번짐이 조금, 쪽빛은 띠에만, 금색은 가는 선에만. 화면도 같다.
- **쪽빛 띠**: 시트의 이름표(쪽빛 바탕, 흰 글, 겹선)와 허리띠를 화면의 **구역 제목**(카드의 왼쪽 가장자리에서 나온 띠. 처음에는 위 테두리에 걸쳤다가 아래 "둘째 손질"에서 바꿨다), **지금 화면 표시**, **탭의 지금 칸**, **주된 단추**, 좁은 화면의 **위 막대**로 옮긴다. 띠 안쪽에는 금선을 한 줄 두른다.
- **치마**: 위는 희고 단으로 갈수록 푸르며 흰 꽃무늬가 놓인다. **사이드바와 펼침 메뉴, 로그인 화면의 바탕**이 이 꼴이다.
- **하늘과 꽃잎**: 본문 위쪽에 하늘빛이 번지고, 카드 뒤의 바탕에 연한 꽃잎이 흩날린다(처음에는 오른쪽 위에 구름 문양을 뒀다가 사용자 지시로 바꿨다). 어두운 판에서는 오른쪽 위에 달빛이 번진다.
- **꽃**: 이름 표식(쪽빛 원 안의 흰 꽃, 파비콘도 같다), 화면 제목 아래 맺음 줄, 소제목 앞, 본문 맺음.
- **명조 글씨**: 시트의 이름 글씨를 따라 화면 제목·이름·로그인·맺음 글귀만 고운바탕으로 쓴다. 본문은 Pretendard다.
- **꼴**: 모서리를 더 둥글게(카드 20px), 단추·배지·탭·띠는 알약 꼴, 테두리는 옅은 푸른 실선, 그림자는 푸른빛이 도는 옅은 것.
- **어두운 판은 달밤**: 밝은 판을 뒤집지 않고 따로 정했다. 바탕은 짙은 쪽빛, 글은 옅은 푸른 흰색.
- **결의 색**도 시트의 빛깔에 맞췄다: 비취(정상), 호박(주의), 연지(문제), 하늘(안내).

### 감성 [제안]

"약간의 감성"은 화면의 가장자리에만 둔다. 일하는 자리(표, 폼, 목록)에는 장식을 넣지 않는다.

- 로그인 화면: 하늘에서 치맛단까지 이어지는 바탕, 흩날리는 꽃잎, 치맛단의 흰 꽃. 카드 머리에 이름 표식과 이름, 그리고 시트의 머리말 글귀.
- 본문 맺음: 꽃 한 송이와 같은 글귀 한 줄.
- 글귀는 시트에 적힌 것을 그대로 옮겼다("구름처럼, 조용히 흐르고 달빛처럼, 은은히 비추며…"). 화면에 새로 더한 글은 이것 하나다. `character/`는 건드리지 않았다.
- 움직이는 장식은 처음에는 두지 않았다가, 사용자 지시로 **바탕에 흩날리는 꽃잎** 하나를 뒀다(아래 "둘째 손질"). 카드와 글 뒤에만 그리고, 움직임 줄이기를 켠 기기에서는 그리지 않는다.

### 넣지 않은 것

- **시트의 이름**: 화면의 이름은 "Lucia"다. 시트의 이름은 쓰지 않는다.
- **캐릭터 그림**: 화면에 넣지 않았다. 그림 파일을 레포와 바이너리에 넣는 것은 사용자가 정할 일이고, 디자인 언어는 그림 없이도 서야 한다.
- **뿔, 깃털, 술**: 작게 그리면 알아볼 수 없어 뺐다.

### 만든 방식

- **문양은 색 없는 SVG 모양**이다(`src/ui/motif/`, 만드는 스크립트 `tools/gen-motifs.mjs`). 부품이 `mask`로 걸고 색은 토큰으로 칠한다. 밝은·어두운 판을 따르고, CSP(`style-src 'self'`)에 걸리지 않는다. 장식은 `::before`/`::after`나 보조 기술에 숨긴 요소(흩날리는 꽃잎)로만 그려 글·조작과 겹치지 않고, 강제 색 모드와 인쇄에서는 지운다.
- **글꼴을 빌드에 넣었다**(Pretendard Variable, 고운바탕 400·700. 둘 다 SIL OFL 1.1, 허가서는 `public/licenses/`). 지금까지는 기기에 깔린 글꼴에 기대어 기기마다 모습이 달랐다. 낱자 조각(unicode-range)으로 나뉘어 있어 브라우저는 화면에 나온 글자의 조각만 받는다. 바이너리는 그만큼 커진다(아래 "검증"의 크기).
- **바꾼 것은 토큰과 부품(`src/ui`)뿐이다.** 화면 코드(`src/pages`, `src/standalone`)와 데몬은 손대지 않았다. 0061이 "화면은 부품만으로 짠다"를 시험으로 막아 둔 덕에, 모습을 통째로 바꾸는 일이 부품 안에서 끝났다. 틀의 마크업은 세 곳만 바꿨다: `Shell`(이름 표식의 아이콘, 사이드바의 안쪽 상자, 맺음), `Section`(제목 묶음을 띠로), `Page`(맺음 줄), `Solo`(이름·글귀).
- **색 대비 시험에 새 면의 짝을 더했다**(`tests/a11y.test.ts`의 `PAIRS`): 띠 위의 글·곁글·금선, 하늘·번짐·치맛단 위의 글과 초점 고리.
- **개발 서버로 모습을 바로 본다**: `LUCIA_UI_DEV_PROXY`를 주면 Vite 개발 서버가 데이터·폼만 시험 데이터 서버로 넘긴다(`vite.config.ts`). 모습을 고칠 때마다 데몬을 다시 빌드하지 않아도 된다.
- 설계(디자인 언어, 토큰, 문양, 틀·구역·화면 머리·로그인·단추)는 직접 하고, 나머지 부품의 모습은 빠른 모델의 하위 에이전트 둘에 나눠 맡긴 뒤 스크린샷과 시험으로 검수했다.

## 둘째 손질: 꽃잎, 평평한 카드, 배치와 계층

첫 적용을 본 사용자의 지시(위 "결정 방식"의 둘째~넷째)로 바꾼 것이다.

### 바탕

- **카드 안의 번짐을 뺐다.** 숫자 타일(`Stat`)의 아래쪽 푸른 번짐을 없애 카드 안은 모두 흰 면이다.
- **구름 문양을 빼고 흩날리는 꽃잎을 뒀다**(`src/ui/Petals.svelte`). 연하고 반투명한 꽃잎 열여덟 장이 위에서 아래로 천천히 떨어지며 흔들린다.
  - **카드와 글 뒤에만 그린다.** 화면 머리, 카드 사이, 본문 양옆, 로그인 바탕에서 보인다. 글 위로 지나가게 하지 않은 것은 읽는 데 방해가 되어서다. 그래서 휴대폰 너비에서는 화면 머리 말고는 거의 보이지 않는다.
  - 화면 높이만큼의 층이 스크롤을 따라 붙어 있어 문서의 길이를 바꾸지 않는다(켠 것과 끈 것의 문서 크기를 견줘 확인했다). 누를 수 없고 보조 기술에 숨긴다.
  - **움직임 줄이기를 켠 기기, 강제 색 모드, 인쇄에서는 그리지 않는다.**
  - 순수 CSS 애니메이션이다(스크립트로 움직이지 않는다). 꽃잎마다 다른 값은 스타일에 `:nth-child`로 적는다(CSP 때문에 인라인 스타일을 쓰지 않는다).
  - 배치 검사는 움직임 줄이기로 잰다(`e2e/check.mjs`, 켠 채로 재려면 `--motion`).
- **이름 표식의 꽃을 가운데로 맞췄다.** 다섯 꽃잎의 하나가 위를 향해 꽃의 위아래가 고르지 않았다(위 11.1, 아래 9). 꽃 모양 자체를 0.8만큼 내려 그렸다(아이콘, 문양, 파비콘). 사이드바 표식의 꽃도 조금 키웠다.
- **권한 모드의 이모지를 아이콘으로 바꿨다.** 데몬이 화면에 주던 이모지(`consts.security.modes[].icon`)를 아이콘 이름(`lock`·`shield`·`unlock`)으로 바꾸고, 화면은 목록 줄의 앞 아이콘 자리에 그린다(지금 모드는 색으로도 드러난다). 이모지는 기기마다 모양이 다르고 글꼴이 없으면 빈 네모다. Discord에서 쓰는 이모지(`Mode::icon`)는 그대로다.

### 배치와 계층 [제안]

전 화면을 1280px·360px에서 찍어 따로 훑게 한 뒤(하위 에이전트의 감사), 찾은 것을 눈으로 확인하고 고쳤다. 규칙은 `web/admin/docs/design.md` 8장에 적었다.

- **구역 머리를 한 줄로**: 띠가 카드 위 테두리에 걸쳐 있어, 그 구역의 배지·링크·단추가 띠 아래 줄에 따로 떠 있었다. 띠를 카드 안으로 들여 왼쪽 가장자리에서 나오게 하고 오른쪽 것과 한 줄에 놓았다. 두 단 배치에서 카드의 위쪽 선도 맞는다. 곁글이 길면 아이콘 아래가 아니라 제목 아래로 내려간다. (`Section.svelte` 한 파일의 변경이다.)
- **두 단의 균형**: 한 구역이 유난히 길어 옆 단이 크게 비던 화면의 구역 순서를 바꾸거나 긴 구역을 전체 너비로 꺼냈다. 시험 데이터 기준 두 단의 끝 차이: 브라우저 1,507px → 1px, 알림 설정 869px → 없음(한 단), 연결 739px → 50px, 설정 506px → 79px, 이모지·스티커 441px → 132px. 순서는 상태·목록이 먼저, 폼이 뒤다.
  - **운영 저장소의 사본으로 다시 쟀다**(자격 증명이 없는 서버라 Discord·Google·브라우저는 꺼진 모습이다). 연결 2px, 설정 133px, 시스템 125px, 홈 53px. 할 일은 시험 데이터에서는 맞았지만(4px) 실제로는 후속 조치 구역 하나가 1,611px, 나머지 셋이 200px 안팎이라 1,438px이 비었다: 약속의 글이 길고 끝난 것까지 쌓인다. 그래서 후속 조치를 두 단 밖에 전체 너비로 꺼내고 나머지 셋(목표, 작업, 챙기는 마감)만 두 단에 뒀다.
- **작은 표가 카드로 쌓이지 않게**: 표는 놓인 자리가 30rem보다 좁으면 줄마다 카드로 바뀌는데, 두 단 배치의 카드 안은 늘 그보다 좁아 칸 셋짜리 숫자 표도 데스크톱에서 카드로 쌓였다. 칸이 셋 이하인 표는 18rem 아래에서만 바뀐다. 시스템의 사용량 구역이 793px에서 466px(360px에서는 1,048px에서 471px)이 됐고, 숫자를 오른쪽에 맞췄다.
- **목록 줄**: 휴대폰 너비에서 시각이나 단추 하나가 제목 아래 줄로 혼자 내려가던 것을 제목 옆에 남게 했다. 줄 아래 덧붙임(펼침)을 제목의 왼쪽 선에 맞췄다. 그림은 제목 안이 아니라 앞자리에 둔다(`Item`의 `media`).
- **이름–값**: 휴대폰 너비에서 짧은 값도 이름 아래 줄로 내려가던 것을 이름 옆에 남게 했다.
- **소제목**: 목록 줄의 제목과 같은 크기·굵기라 구별되지 않았다. 한 단 작고 흐린 이름표로 바꾸고, 앞 묶음과 선으로 나눴다.
- **탭 줄**: 휴대폰 너비에서 글자 중간에 잘려 더 있는지 알 수 없었다. 가려진 쪽 끝을 흐리게 하고, 지금 칸이 가려져 있으면 보이는 자리로 민다.
- **화면의 동작 단추**: 휴대폰 너비에서 설명과 맺음 줄 사이에 끼던 것을 맺음 줄 아래 오른쪽으로 내렸다.
- **그 밖**: 두 단 아래의 간격이 첫 단이 길 때 24px 더 벌어지던 것, 잇달아 놓인 접힌 펼침의 간격이 자리마다 달랐던 것.

### 남긴 것

- 브라우저 화면의 사이트 위임 줄마다 같은 범위 안내 글이 반복된다(짧은 배지로 줄이려면 데몬이 주는 글과 글 보존 기준을 함께 바꿔야 한다).
- 브라우저 화면의 설명 글은 예전 구역 순서로 적혀 있다(글을 바꾸지 않았다).
- 기억 화면은 갈래마다 구역이 하나씩이라 항목이 하나뿐인 갈래가 카드 하나를 차지한다.
- 휴대폰의 메뉴 단추가 위 막대와 아래 막대에 둘 다 있다(하나를 빼는 것은 기능 제거라 묻지 않고 하지 않았다).
