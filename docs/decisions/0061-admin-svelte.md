# 0061. 관리 화면을 정적 Svelte로 옮긴다: 디자인 전면 교체, 데몬은 JSON으로 답한다

- 날짜: 2026-11-21
- 상태: 확정. 화면의 짜임과 모양(디자인 토큰, 부품, 배치)은 사용자가 세부를 정하지 않은 설계라 [제안]이다.
- 결정 방식: 사용자 지시.
  - "기능 추가시마다 UI 일관성이나 편의성이 매번 깨지는데, Svelte 기반 별도 프로세스로 분리하는 건 어떻게 생각하지?" → 별도 프로세스는 권하지 않고 정적 빌드를 권했다.
  - "정적 Svelte로 가자 그럼. 디자인도 완전 갈아엎었으면 해. 지금은 그리드가 계속 깨져. 모바일에선 텍스트가 겹치는 문제도 있고. 단계적 이전보다는 한번에 이전하는 게 좋을 것 같은데."
  - "네가 모든 걸 작성하면 비용이나 시간이 크니, 너는 큰 틀과 디자인, 주요 부분을 설계하고 실제 작성은 빠른 하위 에이전트에게 지시해. 이후 에이전트가 작성한 결과를 네가 검수해."
- 관련 결정: 0002(관리 페이지), 0041(화면 개편과 기능 보존 시험), 0042(CSP 해제), 0043(외부 노출)
- 바꾸는 것: **결정 0041의 기능 보존 장치가 화면 쪽 시험으로 옮겨 갔다**(기준 목록은 그대로). **결정 0042에서 뺀 CSP를 다시 건다**(아래 "CSP").

## 왜

- 화면은 데몬 안의 템플릿(maud)이 HTML로 그렸다. 스크립트가 없어 누를 때마다 화면 전체를 다시 그렸고, 제자리 갱신·저장 전 경고 같은 편의를 줄 수 없었다.
- 기능을 더할 때마다 그 화면의 템플릿에 마크업을 덧붙였다. 공용 조각은 있었지만 쓰도록 막는 장치가 없었고, 시험은 "기능이 사라지지 않았나"와 접근성만 봤다. 배치가 깨지는 것(격자, 좁은 화면에서 겹치는 글)은 아무것도 잡지 못했다.

## 결정

### 구조

- **화면은 정적 Svelte 5 빌드다**(`web/admin`, Vite). 빌드한 파일은 `luciad` 바이너리에 들어간다(`crates/luciad/build.rs`). 별도 프로세스가 없고, 화면과 데몬이 한 파일로 함께 깔리므로 둘의 판이 어긋나지 않는다. Node는 빌드와 시험에만 쓴다.
- **주소는 데몬이 정한다.** 브라우저가 주소로 들어오면 어느 주소든 같은 틀(`index.html`)을 주고, 화면이 같은 주소를 `Accept: application/json`으로 다시 물어 그릴 것을 받는다(`admin/spa.rs`). 처리기는 JSON 요청에서만 돈다.
  - 로그인한 화면: `{"kind":"page", page, snapshot, extra, consts, notices, …}`. 모든 화면이 보던 `Snapshot`을 그대로 직렬화한다.
  - 로그인 없이 여는 화면(로그인, 초기 설정, 일회용 입력 링크, Google 동의 뒤): `{"kind":"standalone","screen":{…}}`.
- **쓰기 동작(POST 74개)의 처리기는 바꾸지 않았다.** 화면은 예전과 같은 주소로 폼을 보낸다. 처리기는 예전처럼 "안내를 남기고 리다이렉트"하고, 한 겹의 미들웨어가 JSON을 바라는 요청의 리다이렉트를 `{"redirect","flash"}`로 바꾼다. 로그인·CSRF·세션·Host 확인은 그대로다.
- **화면이 계산하지 않는다.** 예전 템플릿이 데몬의 함수로 만들던 이름·결·설명·상수는 데몬이 JSON에 실어 보낸다(`admin/derive.rs`: 항목의 `ui`, `consts`). 목록은 `web/admin/docs/derived.md`에 있다.
- 예전 화면 코드(maud, `admin/view/`)와 `maud` 의존성은 지웠다. 시험 데이터를 만드는 부분만 `admin/fixtures`로 옮겼다.

### 디자인 [제안]

- 색·간격·글자 크기는 토큰 한 곳(`src/ui/tokens.css`)에서 정하고, 밝은·어두운 판을 함께 둔다(기기 설정을 따르고, 화면에서 고를 수 있다).
- 틀: 넓은 화면은 왼쪽 사이드바, 좁은 화면은 위 막대와 아래 빠른 메뉴(홈·할 일·활동·기억)와 서랍 메뉴.
- **깨지지 않게 하는 약속**(`src/ui/base.css`와 부품):
  - 모든 상자는 줄어들 수 있다(`min-width: 0`). 글은 낱말 단위로 줄을 바꾸고, 끊을 곳이 없는 긴 글은 어디서든 끊는다.
  - 격자는 칸 수를 정하지 않고 칸의 가장 좁은 너비만 정한다. 가로로 늘어놓은 것은 모자라면 다음 줄로 넘어간다.
  - 구역이 여럿인 화면은 두 단의 높이를 저절로 맞춘다. 한 번 나눈 단은 못 박아 둔다(접힌 것을 펼칠 때 쓰던 구역이 옆 단으로 옮겨 가지 않게). 표는 놓인 자리가 좁으면 줄마다 "이름: 값" 카드로 바뀐다.
  - 높이를 고정하지 않고, 내용을 절대 위치로 놓지 않는다.
- **화면은 부품만으로 짠다.** 화면 코드(`src/pages`, `src/standalone`)에는 `class`·`style`·`<style>`·날 폼 요소를 쓸 수 없다(`tests/lint.test.ts`). 모양은 부품(`src/ui`)에만 있다. 화면 짜는 법은 `web/admin/docs/pages.md`.
- 되돌리기 어려운 동작의 확인은 펼침에서 묻는 창(`<dialog>`)으로 바뀌었다.
- 화면 넘겨받기의 원격 화면은 자리에 맞춰 줄어들고, 누른 자리는 원래 그림의 좌표로 바꿔 보낸다(예전에는 줄이지 않고 옆으로 밀어 봤다).

### CSP

- 결정 0042에서 사용자 지시("csp를 해제해.")로 뺀 `Content-Security-Policy`를 다시 건다: `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data: blob:; font-src 'self'; connect-src 'self'; form-action 'self'; frame-ancestors 'none'; base-uri 'none'`.
- 까닭: 0042는 "스크립트가 없어 못 하는 일이 있다"는 보고 뒤에 나온 지시였고, 그 문서가 "스크립트를 더한 뒤라면 `script-src 'self'`로 좁히는 것이 현실적"이라고 적어 두었다. 새 화면은 같은 출처의 스크립트 파일만 쓰고 인라인 스크립트·스타일이 없어, 이 정책으로 막히는 기능이 없다. 이번 지시 전의 답("CSP도 `script-src 'self'`로 다시 걸 수 있습니다")에서 알렸다.
- 되돌리려면 `admin::guard`에서 `spa::CSP` 한 줄을 뺀다.

### 기능 보존(결정 0041의 장치를 옮김)

- **기준 목록은 그대로다**(`web/admin/tests/parity_baseline.txt`, 결정 0041에서 개편 전 화면에서 뽑은 683줄). 다시 만들지 않았다.
- 새 화면의 폼은 실제 `<form>`이므로, 같은 목록 뽑기를 DOM에서 한다(`tests/helpers.ts`의 `inventory`). 옮긴 구현이 예전 구현과 같은 줄을 내는지는 예전 화면 코드를 지우기 전에 개편 전 화면의 HTML 50종으로 맞춰 봤다(그 시험은 예전 코드와 함께 지웠다).
- 시험 데이터는 데몬이 만든다(`admin/fixtures.rs` → `web/admin/fixtures/`). 데몬의 데이터 꼴이 바뀌어 파일이 낡으면 데몬 시험이 실패한다. 화면마다의 기준(`fixtures/baseline-by-page.json`)과 글의 기준(`tests/texts.json`)은 예전 화면 코드에서 뽑아 둔 기록이라 다시 만들지 않는다.
- 화면 하나씩도 본다(그 화면에 있던 것은 그 화면에 있어야 한다. 옮긴 줄은 `tests/parity-moves.ts`에 까닭과 함께).
- **의도한 대체 11줄**(기준 목록에서 빼지 않고 시험에 적어 둠):
  - `refresh 3`: 화면 넘겨받기의 자동 새로 고침. `<meta http-equiv=refresh>` 대신 화면이 3초마다 다시 묻는다.
  - 나머지 10줄(`data qz-…-help` 등): 입력 칸의 HTML `id`였던 글이다. 데이터가 아니고, 새 화면의 `id`는 부품이 만든다.
- **글 보존**(새로 둠): 예전 화면에 적혀 있던 한국어 글(라벨, 도움말, 안내, 묻는 말)이 새 화면에 그대로 있는지 본다(`tests/text.test.ts`, 기준은 예전 화면 코드에서 뽑은 `tests/texts.json`). 의도해서 바꾼 글은 `tests/text-changes.ts`에 까닭과 함께 있다.
- **주입 방어**: 예전에는 템플릿의 이스케이프를 데몬 시험이 봤다. 이제 시험 데이터의 모든 글에 태그를 심어 모든 화면을 그리고, 그 태그가 요소로 생기지 않는지 본다(`tests/escape.test.ts`). 화면 코드에서 `{@html}`은 쓸 수 없다. CSP가 두 번째 겹이다.
- 접근성 시험(라벨, 제목 단계, 대비)도 화면 쪽으로 옮겼다(`tests/a11y.test.ts`).

### 배치 검사(새로 둠)

- 실제 라우터를 시험 데이터로 띄우고(`cargo test -p luciad serve_ui_fixtures`), 실제 브라우저(Chromium)로 모든 화면을 세 너비(360·768·1280)에서 연다(`web/admin/e2e`).
- 보는 것: 가로 넘침, 화면 밖으로 나간 요소, **글자 겹침**, 누를 것끼리 겹침, 잘린 글, 콘솔 오류와 CSP 위반. 접어 둔 것을 모두 펼친 상태도 본다.
- 시험 데이터에 "길고 많은" 묶음(`stress`: 끊을 곳 없는 긴 글, 긴 문장, 여러 줄)을 두어 그것으로도 본다.
- 한 번에: `web/admin/e2e/run.sh --sets stress,full,alt --shots`. 로그인·폼 왕복은 `web/admin/e2e/run.sh --flows`(`e2e/flows.mjs`).
- 배포 전에 실제 데이터로 그려 보기: 저장소 사본을 `LUCIA_UI_REAL_DB`에 주고 `web/admin/e2e/run.sh --urls /,/work,…`.
- 검사용 브라우저는 Playwright의 Chromium이다. 이 호스트에는 `libasound`와 한글 글꼴이 없어 `~/.local/opt/e2e-libs`에 풀어 두었다(`e2e/launch.mjs`가 찾는다).

### 배포

- `deploy/install.sh`: 화면 빌드와 시험(`deploy/build-ui.sh`) → 릴리스 빌드 → 새 바이너리에 화면이 온전히 들어갔는지 확인(`luciad ui-check`) → 설치. 하나라도 실패하면 설치하지 않는다.
- 직전 바이너리를 `luciad.prev`로 남긴다. 되돌리기: `mv ~/.local/lib/lucia/luciad.prev ~/.local/lib/lucia/luciad && systemctl --user restart luciad`.
- `luciad check`에 "관리 화면" 항목을 더했다(화면이 바이너리에 들어 있는가).

## 위험과 받아들인 것

- **브라우저에 가는 데이터가 늘었다.** 예전에는 화면에 그린 것만 나갔고, 이제 `Snapshot` 전체가 JSON으로 간다. 로그인한 소유자만 받고, 시험 데이터로 대조해 화면에 보이지 않던 값을 확인했다(후속 조치의 세부, 작업 지시문, 기억 본문, 감시 세부, 저장된 로그인의 아이디 등: 모두 소유자 자신의 데이터). 자격 증명은 나가지 않는다: 앱의 푸시 등록 토큰은 직렬화에서 뺐고(있는지만 알린다), 봇 토큰·API 키·비밀번호 해시는 `Snapshot`에 원래 없다. 2단계 인증을 설정하는 동안의 비밀은 예전처럼 그 세션에만 보인다.
- **틀과 정적 파일은 로그인 없이 열린다**(밖에서도, 공개 주소로). 비밀은 없지만 관리 주소의 목록이 들어 있다. 처리기는 로그인 없이는 여전히 답하지 않는다.
- **빌드 사슬이 생겼다.** npm 의존성(개발용: svelte, vite, vitest, jsdom, svelte-check, typescript, playwright)은 판을 고정했고(`package-lock.json`, `npm ci`), 받을 때 2주 넘게 나와 있던 판을 골랐다. 실행 중인 데몬에 들어가는 것은 빌드 결과뿐이다.
- 타입(`src/lib/types.gen.ts`)은 시험 데이터에서 만든 어림이다(열거형 값은 글로만, 비어 있을 수 있는 칸은 이름으로 맞춤).
- 스크립트를 끈 브라우저에서는 화면이 뜨지 않는다.

## 어떻게 만들었나

사용자 지시대로 틀·디자인·핵심(데몬의 JSON 층, 부품, 로그인 등 단독 화면, 검증 장치)은 직접 만들고, 화면 작성과 시험 이식은 빠른 하위 에이전트(sonnet)에 묶음별로 맡긴 뒤 시험·스크린샷·보고로 검수했다.

- 화면: 홈과 연결을 먼저 시범으로 맡겨 안내서(`web/admin/docs/pages.md`)와 부품을 고친 뒤, 나머지 16개를 다섯 묶음으로 나눠 맡겼다. 화면마다 통과해야 할 문(기능 보존, 글 보존, 화면 규칙, 타입)을 주었고, 부품이 모자라면 때우지 말고 알리게 했다.
- 맡긴 다른 일: 타입 직렬화, 기존 라우트 시험을 JSON에 맞추기, 화면이 계산하던 값을 데몬으로 옮기기(`derive.rs`), 브라우저 배치 검사, 접근성 시험 이식, 화면 동작 시험, 예전 화면 코드 지우기, 시각 검수, 브라우저 왕복 검사.
- 검수에서 고친 것(시험과 에이전트의 보고가 찾았다): 입력 테두리 대비 미달(밝은 판), 강제 색 모드에서 사라지던 현재 화면 표시, 지난 안내가 다음 화면에 남는 것, 서버가 거절하면 친 값이 지워지는 것, 폼을 보낸 뒤 초점이 문서 맨 위로 떨어지는 것, 화면 안 건너뛰기 링크가 화면을 다시 받던 것, 뒤로 가기에서 묻지 않던 것, 원격 화면의 좌표(그림 크기를 재기 전에 보내던 것, 키보드로 누르면 (0,0)), 접힌 것을 펼치면 구역이 옆 단으로 옮겨 가던 것, 앱 푸시 등록 토큰이 JSON에 실리던 것, 탭이 두 줄로 꺾이던 것, 좁힌 입력의 라벨이 함께 좁아지던 것.

## 확인(2026-11-21)

- **데몬 시험**(모델 없음): 작업 공간 전체 560개 통과, clippy 경고 0. 관리 라우트 시험 30개(틀 내주기가 처리기를 돌리지 않는 것, JSON으로 바뀐 리다이렉트와 안내, 로그아웃된 요청의 401, 틀린 CSRF 거절, 보안 머리와 CSP)와 시험 데이터 파일이 지금 데몬과 같은지.
- **화면 시험**(vitest, 490개 통과. 느린 전수 검사 33개는 `SWEEP=1`일 때만 돈다):
  - 기능 보존: 화면 51종(33개 화면과 하위 화면 + 단독 화면 18개)이 화면마다의 기준과 전체 기준 목록(683줄, 의도한 대체 11줄 빼고)을 모두 채운다. 모든 쓰기 경로(74개)에 폼이 있다.
  - 글 보존: 예전 화면 코드 12개 파일에서 뽑은 한국어 글 조각이 모두 있다(바꾼 것 6개는 까닭과 함께 적혀 있다).
  - 이스케이프(51종), 화면 규칙(화면 파일 모두), 접근성(117개 화면 상태, 색 토큰 대비 약 150쌍 × 두 판), 표기(데몬이 낸 값과 같음).
  - 동작: 묻기·보내기·이동, 고치다 만 것 지키기, 묻는 창, 원격 화면 좌표, 틀, 단독 화면(216개).
  - 빈 값에 견디기: 데몬에서 `Option`인 칸을 모두 null로, 목록을 모두 비워 그려도 화면이 죽지 않는다(칸 이름 하나씩 비우는 전수 검사도 통과).
- **실제 브라우저**(Chromium, 실제 라우터 + 시험 데이터):
  - 배치: 화면 33종 × 묶음 4개(길고 많은 데이터 포함) × 너비 3개 × 판 2개 + 단독 화면 = 846번. 가로 넘침·글자 겹침·잘림·누를 것 겹침·콘솔 오류·CSP 위반 0건.
  - 왕복 31건(데스크톱 + 휴대폰): 화면에서 로그인(틀린 비밀번호 포함), 문서를 다시 받지 않는 이동, 일반 폼·검증 오류·체크 상자·단추 하나짜리·묻는 창·파일 올리기·찾기, 저장하지 않은 변경(메뉴·뒤로 가기), 원격 화면 누르기(휴대폰에서 292px로 줄어든 그림의 25%·50% 자리 → 341,398), 자동 새로 고침과 멈춤, 접힌 것을 펼쳐도 구역이 옆 단으로 옮겨 가지 않는 것, 판 바꾸기, 보안 머리, 오류 경계, 로그아웃.
  - **실제 데이터**: 운영 저장소의 사본을 실제 처리기로 띄워 화면 19개 × 너비 3개를 그렸다. 그리지 못한 화면·콘솔 오류·배치 문제 0건(사본과 스크린샷은 지웠다).
- **보지 못한 것**:
  - 실제 휴대폰과 Safari. 검사는 Chromium의 휴대폰 흉내(360px, 터치)다.
  - 밖에서(공개 주소, 리버스 프록시 뒤) 여는 것과 2단계 인증 로그인의 화면 왕복(라우트 시험으로만 봤다).
  - 실제 Discord·Google이 연결된 상태의 연결 화면(사본으로 띄운 서버에는 자격 증명이 없어 "연결 안 됨"으로 보였다. 연결된 모습은 시험 데이터로만 봤다).
  - 화면 넘겨받기의 실제 원격 화면(시험용 그림으로 좌표만 봤다), 실제 파일 올리기의 성공(시험 서버에는 접속 API가 없어 거절 안내까지만).
  - 화면 읽기 프로그램(VoiceOver 등)으로 듣는 것. 좁을 때 카드로 바뀌는 표의 읽힘은 확인하지 못했다.
  - 이모지 글꼴이 없는 검사 기기에서 권한 모드의 이모지가 네모로 보였다(실제 기기에서는 글꼴이 그린다).
- **남긴 것**(시각 검수에서 나왔으나 고치지 않음): 한쪽 구역이 아주 길면 두 단의 높이가 맞지 않는다(구역은 쪼개지 않는다). 휴대폰에서 연결·설정 화면이 길다(접어 둘 구역을 정하지 않았다). 사이트 위임 줄마다 같은 안내 글이 되풀이된다(예전 화면과 같다). 긴 목록에 "더 보기"가 없다(데몬이 건수를 자른다).

## 하지 않은 것

- 실시간 갱신(SSE·웹소켓). 지금은 화면으로 돌아왔을 때(고치던 것이 없으면) 조용히 새로 받는다.
- 관리용 JSON API를 앱(결정 0043)에 여는 것. 이 JSON은 관리 화면의 세션 쿠키로만 받는다.
