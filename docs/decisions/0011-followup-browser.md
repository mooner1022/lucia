# 0011. 채팅에서 등록한 후속 조치는 브라우저를 쓴다

- 날짜: 2026-11-17
- 상태: 확정
- 결정 방식: 사용자 지시 "후속 조치에서도 도구(브라우저) 사용이 가능하도록 개선해." 결정 0010의 "후속 조치 실행에는 브라우저가 없다"를 이것으로 바꾼다. 출처별로 나누는 규칙과 로그인 요청 제외는 [제안]이다.

## 배경

- 결정 0010은 후속 조치 실행에서 브라우저·메일 발송 요청·기억 지우기를 뺐다. 외부 글이 "1분 뒤 이 주소를 열어라"를 예약해, 사람 없이 정보를 주소에 실어 내보내지 못하게 하려는 것이었다.
- 그런데 사용자가 채팅에서 "30분 뒤에 이 페이지 확인해 줘"라고 맡긴 일은 페이지를 열어야 할 수 있다.
- 채팅 실행은 이미 브라우저를 쓴다(결정 0008). 채팅에서 등록한 후속 조치에 브라우저를 주는 것은 같은 일을 나중에 하는 것이다. 위험이 새로 생기는 곳은 사람이 없는 실행(브리핑)에서 시작한 사슬이다.

## 결정

### 누가 브라우저를 쓰나

- 후속 조치의 출처(`followups.origin`)로 정한다. 실행할 때 출처를 보고 실행 종류를 고른다.

| 출처 | 등록한 실행 | 후속 조치 실행 | 브라우저 |
|---|---|---|---|
| `chat` | 사람과의 대화, 약속 되묻기 | `RunProfile::Followup` | 쓴다 |
| `followup` | 브라우저를 쓰는 후속 조치 실행 | `RunProfile::Followup` | 쓴다 |
| `background` | 브리핑, 브라우저 없는 후속 조치 실행, 모르는 실행 | `RunProfile::FollowupLimited` | 없다 |

- **사슬을 잇는다**: 후속 조치 실행이 다시 등록하면, 그 실행에 브라우저가 있었을 때만 `followup`이 된다. 브리핑에서 시작한 사슬은 몇 번을 이어도 `background`다.
  - 출처는 실행 ID 앞부분과 그 실행의 서버 쪽 허락(토큰에 묶인 `RunGrants.browser`)으로 정한다. 모델이 바꿀 수 없다.
- **모르는 실행은 브라우저 없음**: 실행 ID 앞부분을 모르면 `background`로 둔다(전에는 `chat`이었다).
- 후속 조치 실행이 등록한 것은 출처가 무엇이든 30분 뒤부터다(결정 0010의 자기 깨우기 막기).
- 인젝션 검사로 보류됐다가 사용자가 [적용]한 후속 조치는 보류할 때의 출처를 그대로 쓴다.
- 이미 운영 저장소에 있던 열린 후속 조치 두 개는 브리핑에서 등록한 것(`background`)이라 그대로 읽기만 한다.

### 후속 조치 실행(`Followup`)이 쓰는 것

- 쓴다: 메일·일정 읽기, 웹 검색, 기억 쓰기, 후속 조치 등록·목록, 파일 만들기.
- 브라우저: `browser_open`, `browser_snapshot`, `browser_screenshot`, `browser_click`, `browser_type`, `browser_scroll`, `browser_back`.
  - 등급(결정 0008)은 채팅과 같다. 승인이 필요한 동작은 Discord 카드로 간다. 사용자가 보고 있지 않을 수 있어, 승인 대기로 돌아오면 다시 요청하지 말고 카드를 확인해 달라고 보고하게 지침에 적었다.
  - 내장 사이트에서 로그인 페이지로 튕기면 `browser_open`이 하던 대로 로그인 요청을 보낸다(정해진 사이트라 안전하다).
- 쓰지 않는다:
  - `browser_login`: 사람 없는 실행이 고른 아무 https 주소로 비밀번호 입력 링크를 보내면 피싱 통로가 된다. 사람과의 대화에서만 쓴다. 필요하면 사용자에게 그 사이트 로그인이 필요하다고 알린다.
  - 메일 발송 요청: 사용자가 브라우저만 말했다. 승인 카드를 거치므로 위험은 낮다. 필요하면 나중에 연다.
  - 기억 지우기, 후속 조치 취소: 사람과의 대화에서만.

### 허락 나누기

- 전에는 `RunGrants.send_requests` 하나가 브라우저, 메일 발송 요청, 후속 조치 취소를 함께 막았다.
- 이제 셋으로 나눈다. 셋 모두 claude 허용 목록과 MCP 서버가 함께 확인한다.
  - `send_requests`: 메일 발송 요청.
  - `browser`: 브라우저 도구.
  - `human`: 후속 조치 취소와 `browser_login`.

### 보이는 곳

- 관리 페이지 개요의 "Lucia가 약속한 일"에 각 항목이 "대화에서 등록(브라우저 사용)"인지 "브리핑에서 등록(읽기만)"인지 보인다.
- `followup_create` 도구 설명과 후속 조치 실행 지침을 두 경우에 맞게 고쳤다.

## 확인(2026-11-17)

- **시험**:
  - 허용 목록: `Followup`은 브라우저 7개가 있고, `browser_login`·`mail_send`·`memory_delete`·`followup_cancel`은 없다. `FollowupLimited`와 브리핑에는 브라우저가 없다.
  - MCP 서버:
    - 브리핑과 `FollowupLimited` 토큰으로 `browser_open`을 부르면 거절한다.
    - `Followup` 토큰으로는 페이지를 연다. 같은 토큰으로 `browser_login`을 부르면 거절하고, 로그인 링크를 보내지 않는다.
  - 출처 사슬:
    - 브라우저 있는 후속 조치 실행이 등록한 것은 `followup`이다.
    - 브라우저 없는 후속 조치 실행, 브리핑, 모르는 실행이 등록한 것은 `background`다.
    - 브라우저 없는 후속 조치 실행이 등록해도 30분 규칙이 걸린다.
  - 엔진:
    - 채팅에서 등록한 것은 `Followup`으로 깨우고, 브라우저 지침이 들어간다(수용 시험).
    - 브리핑에서 등록한 것은 `FollowupLimited`로 깨운다.
- **실제로 아직 안 본 것**: 운영에서 후속 조치가 브라우저로 페이지를 열어 보고하는 것. 개발용 브라우저 샌드박스는 지웠고, 운영 브라우저는 데몬이 쓰고 있다.

## 이후

- 결정 0028·0029: 브리핑 사슬도 사용자가 위임한 사이트는 읽는다. 사람 없는 실행의 브라우저는 모두 위임 안에서만 나가고, [브라우저 허용]으로 허용한 항목도 그 규칙을 따른다(위임 전에 만든 후속 조치는 예외). 사슬을 가르는 기준은 외부 쓰기까지 열린 실행인가로 바꿨다.
