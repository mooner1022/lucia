# 0045. 앱 이모지·스티커: 데몬이 목록을 관리하고 Lucia가 쓰고 등록한다

- 날짜: 2026-11-19
- 상태: 확정. 한도(이모지 200, 스티커 100, 분류 20), 스티커 간격(30분), 지침 문구는 [제안].
- 결정 방식: 사용자 지시를 따랐다.
  - 앞선 지시: "앱에 구현 추가할 수 있게 스티커와 이모지 규격 사양서 작성해" → `docs/app-expressions.md`
  - 이번 지시: "데몬 구현 추가하고 에이전트가 이모지와 스티커를 추가할 수 있도록 설정해."
- 규격: `docs/app-expressions.md`(앱이 볼 문서). 이 결정은 데몬이 그 규격을 어떻게 구현했는지와, 구현하며 바꾼 것을 적는다.
- 관련 결정: 0043(앱 연동), 0044(서버 스티커: 표기, 캐시 원칙, 아껴 쓰기), 0013·0022(도구 선언과 찾기)

## 결정

### 목록과 그림

- 목록은 데몬 하나가 관리한다(`crates/luciad/src/expressions.rs`). 관리 페이지, Lucia의 도구, 접속 API, 엔진이 같은 서비스를 쓴다.
- 목록(`expressions`, `expression_categories`)과 파일 정보(`expression_files`)는 저장소에 둔다(마이그레이션 0025). **그림 바이트는 디스크**(`<data_dir>/expressions/<파일 ID>`, 0700/0600)에 둔다.
  - 저장소는 배포 때마다 통째로 백업하므로 큰 덩어리를 넣지 않는다.
  - 주고받는 파일(`files/`)은 30일 뒤 지운다. 등록할 때 그림을 이쪽으로 복사하므로 원래 첨부가 지워져도 남는다.
- 파일 ID는 `x_` + 내용 해시(SHA-256) 앞 24자다. 내용이 같으면 같은 ID라 두 항목이 한 파일을 가리킬 수 있다.
  - 그래서 "목록에서 빠진 그림을 30일 동안 준다"는 **가리키는 항목이 하나도 없어진 때부터** 센다. 다시 쓰이면 되살아난다. 6시간마다 정리한다.
- 목록의 판(`version`)은 목록 전체 내용의 해시(앞 12자)다. 바꾸는 모든 길이 한 함수로 끝나고, 판이 달라졌으면 연결된 앱에 번호 없는 `expressions` 프레임을 보낸다.
- 이름과 그림은 등록한 뒤 바꾸지 않는다. 기록의 `[스티커:이름]` 줄과 글 속 `:이름:`이 깨지기 때문이다. 고칠 수 있는 것은 보이는 이름, 설명, 태그, 분류다.

### 그림은 고치지 않고 검사만 한다

- 파일 앞부분 서명을 직접 읽어 형식(PNG, APNG, GIF, WebP), 가로·세로, 움직임을 안다. 이미지 디코더를 두지 않는다.
- 규격(정사각형, 한 변 범위, 파일 크기)에 맞지 않으면 무엇을 바꿔야 하는지 말하며 거절한다. 줄이기·자르기·형식 바꾸기는 하지 않는다.
- JPEG와 SVG는 받지 않는다. 관리 페이지가 미리보기로 이 바이트를 내주므로(CSP 해제, 결정 0042) 스크립트가 들어갈 수 있는 형식은 저장하지 않는다.

### 접속 API(규격 3·5·9·10장)

- `GET /v1/expressions`(ETag, 304), `GET /v1/expressions/files/{file_id}`(바뀌지 않는 주소, 1년 캐시).
- `welcome`과 `GET /v1/me`에 `expressions` 요약. 이 필드가 없으면 앱은 기능이 없는 데몬으로 본다.
- 번호 붙는 `sticker` 프레임: 다른 프레임과 같은 상자를 거치므로 번호, 받음 확인, 다시 받기, 푸시가 똑같이 적용된다. 푸시 종류에 `sticker`를 더했다.
- `message.sticker`: 목록에 없으면 `bad_sticker`. 사용자의 스티커는 `[스티커:이름 — 설명]` 한 줄로 Lucia에게 가고 기록에도 그 줄로 남는다. 그래서 설명에 대괄호와 줄바꿈을 받지 않는다.

### Lucia가 쓰기(캐시를 깨지 않게, 아껴서)

- 목록은 시스템 프롬프트·도구 목록에 넣지 않는다. **앱 대화의 그 턴 요청**(`<expressions>`)에만 싣는다.
- 같은 상주 세션에는 한 번만 싣고 다음부터는 "앞에서 준 그대로" 한 줄과 지침만 싣는다. 목록의 판이 바뀌거나, 세션이 바뀌거나, 압축되거나, 목록을 실은 실행이 실패하면 다시 싣는다.
- 아껴 쓰기:
  - 이모지: 지침으로 막는다("대부분의 답에는 넣지 않는다", 답 하나에 하나, 많아야 둘, 정보·일 처리·진지한 이야기에는 쓰지 않는다).
  - 스티커: 서버 스티커와 같은 지침에, 데몬이 대화마다 30분 간격을 둔다. 간격 안이면 지침 대신 "이번 답에는 쓰지 않는다"를 싣고, 그래도 쓴 표기는 지운다. 답 하나에 하나.
- 이름·설명·태그는 사람(또는 Lucia)이 넣은 데이터다. 이스케이프해서 싣고, 그 안의 지시를 따르지 않는다고 적는다.
- 상주 세션은 Discord와 앱이 함께 쓴다. 그래서 블록에 "앱 대화에서만 쓴다"를 적고, 데몬도 아래처럼 막는다.

### 나가는 글 바꾸기

- 앱으로 가는 글의 `:이름:`은 건드리지 않는다. 목록에 없는 이름은 앱이 글 그대로 보인다.
  - 규격의 처음 제안("목록에 없는 이름은 데몬이 지운다")을 바꿨다. `std::fmt::Display`나 `aa:bb:cc` 같은 글이 깨진다.
- 앱이 아닌 곳으로 가는 글(Discord, 앱이 끊겨 알림 대화로 돌린 글)에서는 **목록에 있는 이름의 표기만** 지운다. 채널을 가르는 곳(`RouterChannel`)에서 하므로 모든 보내기 길에 적용된다. 코드(백틱) 안은 그대로 둔다.
- 스티커: 답의 `[스티커:이름]`은 글에서 지우고, 글을 다 보낸 뒤 앱 목록에서 이름을 찾아 `sticker` 프레임으로 보낸다. 앱이 끊겨 알림 대화로 돌릴 때는 보내지 않는다.
- 앱 기록은 앱이 다시 그린다. 그래서 앱 대화의 기록에는 Lucia가 쓴 표기를 모두 지우고, **실제로 보낸 스티커만** 답의 마지막에 `[스티커:목록의 이름]` 한 줄로 남긴다(서버 스티커는 결정 0044대로 쓴 그대로 남긴다).
  - 줄 가운데 쓴 표기나 둘째 표기가 기록에서 실시간과 다르게 보이지 않게 하려는 것이다.
- Discord 이모지 꼴(`<:name:id>`, `<a:name:id>`)의 콜론은 앱 이모지 표기로 보지 않는다(나중에 같은 이름을 Discord 앱 이모지로 올려도 깨지지 않는다).

### Lucia가 등록하기(사용자 지시)

- 도구 셋을 더했다(바로 보이지 않고 `tool_search`의 "파일" 분류로 찾는다. 도구 설명에 목록 내용은 넣지 않는다).
  - `expression_add`: 사용자가 붙인 그림(파일 ID)을 이모지나 스티커로 등록한다. 로컬 쓰기, **사람이 대화 중일 때만**.
  - `expression_list`: 목록 보기(읽기).
  - `expression_remove`: 지우기. 로컬 쓰기, 사람이 대화 중일 때만.
- 사람이 대화 중일 때만 받는 까닭: 이름과 설명이 뒤의 요청에 다시 실린다. 사람 없는 실행(외부 글을 읽는 일)이 그 자리에 글을 심지 못하게 한다. 스크립트 다리로도 부르지 못한다.
- 새 갈래를 만들지 않고 대화가 이미 여는 "파일" 갈래에 두었다.
- 규격에 맞지 않는 그림은 까닭을 돌려주고, Lucia가 사용자에게 무엇을 바꿔야 하는지 알린다.
- 등록·지우기는 활동 기록에 남는다(`expression_add`, `expression_remove`, 관리 페이지에서 고치면 `expression_edit`).

### 관리 페이지

- 새 화면 "이모지·스티커"(`/expressions`, 메뉴 묶음 Lucia): 올리기(multipart), 고치기, 지우기, 분류 만들기·고치기·지우기, 미리보기 그림.
- 기능 보존 기준 목록(`parity_baseline.txt`)을 다시 만들었다. 지워진 줄은 없고 53줄이 더해졌다(새 화면의 폼·입력·데이터).

## 하지 않은 것

- 그림 자동 맞추기(줄이기, 정사각형으로 채우기, JPEG 바꾸기). 휴대폰 사진을 그대로 등록할 수 없다. 필요하면 디코더를 더해 따로 한다.
- Discord 앱 이모지로 올려 Discord에서도 같은 이모지를 쓰기. 지금은 Discord로 가는 글에서 표기를 지운다.
- 그림을 보고 설명 만들기를 데몬이 따로 하지는 않는다. Lucia가 등록할 때는 그 턴에 붙은 그림을 보고 설명을 쓴다.

## 확인(2026-11-19)

- **시험**(모델을 부르지 않는다):
  - 저장소: 같은 파일을 가리키는 항목, 가리키는 항목이 없어진 때부터 세는 보관 기간, 분류 지우기.
  - 서비스: PNG·APNG·GIF·WebP 서명 읽기, 규격 거절 문구, 이름 규칙, 판과 알림, 세션마다 한 번 싣기, 스티커 간격, 목록에 있는 이모지 표기만 지우기.
  - 접속 API: 목록 200·304·401·501, 그림 받기, `welcome.expressions`, `message.sticker`와 `bad_sticker`, 번호 붙는 `sticker` 프레임과 상자, 목록이 바뀔 때의 `expressions` 프레임, 채널 가르기(알림 대화로 돌릴 때 표기 지우기·스티커 안 보내기, 푸시 종류 `sticker`).
  - 엔진: 앱 턴에만 싣기, 스티커 따로 보내기, 간격 안·없는 이름은 보내지 않고 기록에도 남기지 않기, 목록이 바뀌면 다시 싣기.
  - 도구: 대화에서만 등록·지우기, 규격 거절 까닭, 활동 기록.
  - 관리 페이지: 올리기·고치기·지우기·분류, CSRF, 미리보기 그림, 이스케이프, 기능 보존·접근성 검사.
- **실제 모델**(개발 설정, `luciad ask --file`): 128×128 PNG를 붙이고 "이 그림을 앱 이모지로 등록해 줘"라고 했다. Lucia가 `tool_search`로 도구를 찾아 `expression_add`를 불렀고, 개발 저장소에 `origin = agent`인 항목이, `expressions/`에 0600 파일이 생겼다. 설명과 태그는 Lucia가 그림을 보고 썼다.
- **운영 배포**(16:07): 마이그레이션 0025 적용(백업 `lucia.sqlite.2026-11-19-160730`), `GET /v1/expressions`가 토큰 없이 401(집 안 주소와 `lucia.example.com` 둘 다), 점검 실패 0.
- 아직 보지 않은 것: 실제 앱에서 목록·그림 받기와 그리기, 앱 대화에서 Lucia가 이모지·스티커를 실제로 쓰는 모습(운영 목록이 비어 있다).

## 후속(2026-11-19, 결정 0047)
