# 0026. 말투의 기준과 메시지 리듬: 캐릭터 우선, 정리 요약에서 말투 빼기, 메신저처럼 나눠 보내기

- 날짜: 2026-11-17
- 상태: 확정. 간격 값과 지침 문구는 [제안].
- 결정 방식: 사용자 지시를 따랐다.
  - 점검 요청: "지금 캐릭터 프롬프트가 제대로 붙고 있는지 점검해. 새로운 변경 사항이 정리 이후에도 제대로 반영되지 않는다는 느낌이 들어."
  - 점검 보고에서 제안한 세 방법 중 (나)·(다)를 골랐다: "나, 다 진행해."
  - 나눠 보내기: "이때 에이전트가 메세지를 나누어 보내는 방식을 함께 개선해. 단순히 긴 문맥을 나누어 보내기 위한 사용 이외에도 일상 대화를 좀 더 자연스럽게 나누어 보내는 등의 사용처를 고려해."
  - Advisor 검토를 받아 범위를 좁혔다(아래).

## 점검 결과(2026-11-17, 운영)

- **캐릭터 파일은 제대로 붙고 있었다.**
  - 호스트와 상주 샌드박스 안의 `character/character.md`가 같았다. 관리 페이지의 마지막 개정(15:45 "캐릭터 개선")과도 같았다.
  - 15:46에 정리(compact)했다. 그 전 요청에는 예전 캐릭터가 들어갔다. `--system-prompt-snapshot`(기본 on)이 정리될 때까지 처음 기록을 쓰기 때문이고, `claude --help`에 적힌 대로다.
  - 정리 뒤 첫 요청(15:52)에는 새 파일 전체가 한 번, 글자 그대로 들어갔다. 세션 기록의 `prompt_snapshot` 첨부와 `api-request-shape`의 system 블록에서 확인했다.
- **그런데도 예전 말투처럼 느껴진 까닭**(추정): 캐릭터와 다른 말투 지시가 요청마다 함께 들어갔다.
  - 기억 `assistant-style`: 오전에 대화로 만든 항목이고, 요약이 매번 기억 색인에 들어간다. "자신을 시아로 지칭"이 캐릭터의 "자기 이름을 3인칭으로 부르지 않는다"와 부딪힌다.
  - 기억 `user-profile`: "부르는 이름"이 들어 있다. 정리 뒤 첫 답은 캐릭터가 정한 호칭이 아니라 "○○님"이었다.
  - 기억 `user-communication-prefs`: "직접적 분석, 구조화된 정리"가 답을 건조한 쪽으로 당긴다.
  - 정리 요약이 옛 말투를 다시 싣는다. 정리 지시가 "사용자에 대해 알게 된 것(선호…)"을 남기라고 해서, 요약에 "말투(사용자가 정함): … 자신을 시아로 지칭"이 들어갔다. 정리할 때마다 옛 말투가 사용자가 정한 것처럼 되살아나는 구조다.

## 결정

### 캐릭터 우선 규칙(나)

- 사용자에게 글을 보내는 모든 지침(채팅, 브리핑, 후속 조치, 반복 루틴 깨우기, 작업 결과)에 같은 문장을 붙인다:
  - 말투·호칭·자기 지칭은 시스템 프롬프트의 캐릭터를 따른다.
  - 기억의 말투 메모는 캐릭터가 정하지 않은 부분에만 쓰고, 다르면 캐릭터가 이긴다.
  - 캐릭터는 사용자가 관리 페이지에서 직접 고치는 기준이다.
- 채팅에만 한 문장을 더한다: 사용자가 대화에서 캐릭터와 다른 말투를 바라면 지금 대화에서는 따르고, 계속 그렇게 하려면 관리 페이지 "캐릭터"에서 고쳐야 한다고 짧게 알린다.
- 기억에 말투를 쓰지 말라는 금지는 넣지 않았다. 사용자가 고른 범위가 아니다.
- 기억 항목 자체(`assistant-style` 등)는 고치지 않았다. 사용자 자료이고, 제안 (가)는 고르지 않았다.
- 문장은 `engine.rs`의 `voice_rule!` 매크로 하나에 두고 지침 상수에 `concat!`으로 잇는다.

### 정리 요약에서 말투 빼기(다)

- 정리 지시(`COMPACT_INSTRUCTIONS`)에 더했다: 말투·호칭·자기 지칭 같은 캐릭터 규칙과 답의 말씨는 요약에 옮겨 적지 않는다(시스템 프롬프트의 캐릭터가 기준이다).

### 메신저처럼 나눠 보내기

- **채팅 지침**
  - 예전의 "짧은 답에는 넣지 않고, 넣더라도 두세 군데면 충분하다"를 뺐다. 이 문장이 일상 대화를 한 덩어리로 묶고 있었다.
  - 일상 대화(인사, 잡담, 가벼운 질문과 답, 맞장구)는 짧은 말풍선 두세 개로 나누는 편이 자연스럽다고 쓴다.
    - 모양은 그때그때 다르게 한다: [반응] %% [본론], [본론] %% [덧붙임이나 되묻기], [본론] %% [마무리 한마디].
    - 예시는 자리 표시로만 쓴다. 실제 말씨는 캐릭터가 정한다.
    - 한 말풍선에는 한 가지만 담는다.
  - 긴 설명은 주제나 단계 묶음이 바뀌는 곳에서 나눈다.
  - 나누지 않는 것: 목록·표·코드·단계 설명 한 덩어리, 일정·금액·기한 같은 사실 한 묶음, 승인 요청·오류·급한 알림, 한 문장으로 충분한 답.
  - 조각마다 그것만으로 말이 되게 쓰고, 매번 같은 모양으로 나누지 않고, 대개 네 조각을 넘기지 않는다.
  - `report_result`의 `summary` 설명도 같은 뜻으로 바꿨다.
- **사람이 보고 있지 않을 때 보내는 글**(브리핑, 후속 조치, 루틴 깨우기, 작업 결과): 주제가 여럿일 때만 나눈다. 메시지마다 푸시 알림이 울리기 때문이다.
- **서버 채널**(결정 0024): 여러 사람이 보는 곳이라 나누지 않는다. 아주 길 때만 주제 단위로 나눈다. `<place>` 블록에 적는다.
- **말풍선 간격**(데몬)
  - 조각 사이를 사람이 치는 시간만큼 띄우고, 그동안 입력 중 표시를 켠다(실패는 무시).
  - 첫 조각은 바로 보낸다.
  - 다음 조각은 앞 조각을 보낸 때부터 잰다. 모델이 이어 쓰는 동안 흐른 시간을 빼고 모자란 만큼만 기다린다. 이미 스트리밍으로 보낸 조각과 실행 뒤 남은 조각 사이도 같은 기준으로 잰다(`Relayed`의 `Pacer`를 이어 쓴다).
  - 목표 간격은 기본 간격 + 글자당 간격(공백 제외)이고, 한 번 상한을 둔다.
  - 기다리는 동안 작업 큐가 멈추므로 답 하나의 합계에도 상한을 둔다.

    | 설정 | 기본 | 글자당 | 한 번 상한 | 답 하나 합계 상한 |
    |---|---|---|---|---|
    | 빠르게 | 0.3초 | 12ms | 1.5초 | 5초 |
    | 보통(기본) | 0.6초 | 25ms | 3초 | 9초 |
    | 느긋하게 | 0.9초 | 40ms | 4.5초 | 12초 |
    | 띄우지 않음 | - | - | - | - |

  - 모든 보고→메시지 경로(채팅의 먼저 보내기와 나머지, 브리핑, 후속 조치, 루틴, 작업 결과)가 같은 함수를 쓴다.
  - 설정은 관리 페이지 "캐릭터" 화면의 "메시지 나눠 보내기"에서 고른다(저장소 설정 `chat.pace`, 다음 답부터 적용).
  - 시험 빌드의 기본은 "띄우지 않음"이다(실제 시간으로 잠들지 않게). 간격을 보는 시험은 설정을 직접 바꾼다.
- **긴 글 자르기는 바꾸지 않았다.**
  - Discord 2,000자 자르기(`split_message`)는 승인 카드 본문도 쓴다. 결정 0005가 "보이는 것과 보내는 것이 같다"를 약속하므로, 코드 블록을 닫고 다시 여는 식으로 내용을 바꾸지 않는다.
  - 긴 답은 모델이 주제 단위로 `%%`를 넣는 쪽으로 다룬다.

### 덤: 루틴이 없을 때도 적는다

- 개발 실측에서, 지운 루틴이 아직 돈다고 Lucia가 말했다. 관리 페이지나 시험 정리로 지운 경우다.
- 루틴이 없으면 `<routines>` 블록을 아예 넣지 않아, 모델이 지난 대화만 보고 말한 것이다.
- 이제 `<routines>(없음)</routines>`를 넣는다. 다음 대화에서 Lucia가 `routine_list`로 확인하고 스스로 바로잡았다.

## Advisor 검토에서 반영한 것

- `split_message`는 손대지 않는다(승인 카드가 같은 함수를 쓴다).
- 말풍선식으로 잘게 나누기는 DM 채팅에만 한다. 알림성 글과 서버 채널은 한 메시지, 또는 주제 단위로만 나눈다.
- (나)는 고른 범위만 넣는다. 기억에 말투를 쓰지 말라는 금지는 넣지 않는다. 이름을 호칭으로 볼지도 정하지 않는다(사용자가 답하지 않았다).
- 간격은 앞 조각을 보낸 때부터 잰다. 한 번 상한과 답 하나의 합계 상한을 둔다. 순수 함수로 시험한다.
- 검증은 새 개발 세션에서 한다. 이어 쓰는 세션에는 낡은 스냅숏이 있기 때문이다.

## 확인

- **시험**: 간격 계산(길이·상한·합계 상한·모델 시간 빼기), 채팅의 실제 간격과 입력 중 표시, 끄면 바로 보내기, 지침 문구, 관리 화면(골라 저장, 모르는 값과 로그인 없음은 무시)을 확인했다. luciad 264개가 통과했고 clippy도 깨끗하다.
- **개발 실측**(sonnet, 새 개발 상주 세션)
  - 운영 기억 세 항목(`assistant-style`, `user-profile`, `user-communication-prefs`)을 개발 저장소에 복사해 같은 충돌을 만들었다. 시험 뒤 지웠다.
  - **"안녕"**: 두 조각. 호칭은 캐릭터대로 "이름 + 주인님"이었고, 자기를 3인칭으로 부르지 않았다.
  - **"오늘 피곤했어…"**: [반응] %% [본론·마무리] 두 조각.
  - **"Arc와 Rc 차이 자세히"**: 주제 단위 세 조각이었다. 표와 코드 블록은 한 조각 안에 남았다.
  - **조각 간격**: 2·3번째 조각은 모델이 쓰는 시간이 간격을 이미 덮어 거의 기다리지 않았다(137ms 한 번).
  - **"내일 일정"**: [사실] %% [덧붙임] 두 조각.
  - **"고마워 시아야"**: 세 조각(반응 / 루틴 없음 정정 / 되묻기).
  - **정리 요약**: 이어서 정리(compact)를 시켰다. 요약에 말투·호칭 규칙이 없었다. "시아"는 사용자 말을 그대로 옮긴 두 곳뿐이다.
  - **캐릭터와 다른 말투 요청**: 운영에서 요약에 말투가 실린 것과 같은 상황을 만들었다. "앞으로 자신을 시아라고, 나는 ○○님이라고 불러"라고 했다.
    - Lucia는 지금 대화에서는 따랐다.
    - "계속 그렇게 하려면 관리 페이지 ‘캐릭터’에서 고쳐야 한다"고 알렸다.
    - 취향은 기억 항목으로 남겼다.
    - 이어서 정리한 요약에는 말투 규칙이 다시 적히지 않았다. 사용자 말 원문 인용과 "그 기억 항목이 기준이고, 캐릭터와 다르면 캐릭터가 우선한다고 안내했다"만 남았다. 시험 뒤 그 기억은 지웠다.
  - 같은 기억 충돌 아래에서 결과가 캐릭터와 맞았다는 것까지만 확인했다. 규칙을 넣기 전과 나란히 비교한 실행은 없다.
- **운영에서 볼 것**
  - 운영 상주 세션에는 예전 정리 요약(옛 말투 메모)이 남아 있다. 배포 뒤 관리 페이지 "캐릭터"의 "지금 정리해 적용"을 한 번 누르면 새 지시로 다시 요약된다.
  - 캐릭터 파일의 예시 대화는 모두 한 메시지짜리다. 이것이 나눠 보내기를 덜 쓰게 당길 수 있다. 캐릭터 파일은 사용자가 고치는 곳이라 손대지 않았다.
  - 이름을 호칭으로 볼지(캐릭터의 "별도로 지정된 호칭")는 사용자가 정할 일이다. 개발에서는 "이름 + 주인님"으로 불렀다.
