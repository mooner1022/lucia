# 0023. 브라우저 좌표 동작과 iframe: 화면 좌표로 누르기, 초점에 글 넣기, 키, iframe 읽기

- 날짜: 2026-11-17
- 상태: 확정. "누를 수 있는 요소가 아닌 곳" 규칙과 키 목록·한도 값은 [제안].
- 결정 방식: 사용자 지시 "브라우저 사용의 기능성을 강화해. 현재는 특정 요소를 지정해서 클릭하는 방식이라 iframe 안의 요소는 확인이나 클릭이 불가한 등의 문제가 있어. 이를 화면 내 위치를 지정하여 클릭할 수 있도록 하는 등의 기능성 개선으로 해결해."
  - 결정 0008의 등급 원칙은 그대로다: 등급은 모델의 말이 아니라 데몬이 동작 직전에 직접 읽은 요소로 정하고, 정하지 못하면 승인을 받는다.

## 문제

- 화면 읽기와 요소 누르기가 최상위 문서에서만 돌았다(`document.querySelectorAll`). iframe 안의 글과 요소는 보이지 않았고, 참조도 없었다.
- 요소 목록에 없는 곳(리스너만 단 그림·지도·캔버스)도 누를 수 없었다.

## 실측(2026-11-17, `lucia-browser-dev`의 Chromium, 일회용 시험 페이지)

- **좌표계**: 화면 1365×812, devicePixelRatio 1. 화면 스크린샷 JPEG도 1365×812다.
  - `Input.dispatchMouseEvent` 좌표 = 스크린샷 픽셀 = CSS 픽셀(1:1).
  - 스크롤바가 생기면 너비가 바뀐다(1350). 그래서 화면 크기를 결과에 늘 적는다.
- **좌표 클릭**: 페이지 세션의 좌표 클릭은 다음에 모두 정확히 닿았다.
  - 같은 사이트 iframe, 다른 사이트 iframe(별도 프로세스).
  - `pointer-events:none` 덮개 아래 단추, shadow DOM 단추, 리스너만 단 div.
- **입력 전달**: 다른 사이트 iframe의 입력칸을 누른 뒤 페이지 세션의 `Input.insertText`가 그 칸에 들어갔다.
- **히트 테스트**: `DOM.getNodeForLocation`
  - `DOM.enable` 없이 된다.
  - 같은 프로세스 iframe 안의 요소까지 내려가고(`frameId`가 그 프레임), `pointer-events:none`을 건너뛰고, shadow DOM 안 단추를 준다.
  - **문서 좌표(화면 + 스크롤)를 받고 화면 안만 맞힌다**. 스크롤 50px에서 화면 좌표를 넣으면 빗나갔다.
  - 다른 사이트 iframe에서는 iframe 요소에서 멈춘다.
- **다른 사이트 iframe**: 별도 타깃(`iframe`)이다.
  - 페이지 세션에서 `Target.setAutoAttach{flatten}`를 켜면 그 세션이 붙는다.
  - 그 세션에서 지역 좌표 히트 테스트, 격리된 실행 공간, `document.hasFocus()`가 된다. 타깃 정보에 `parentFrameId`가 있다.
  - 포트만 다른 출처(127.0.0.1:8000과 8001)는 같은 사이트라 같은 프로세스다. 다른 사이트 시험에는 `localhost`를 쓴다.
- **iframe 위치**: `DOM.getFrameOwner` → `DOM.getBoxModel`의 content quad는 화면 좌표이고, 스크롤에 따라 움직인다. 브라우저가 계산한 값이라 페이지 스크립트가 꾸밀 수 없다.

## 결정

### 새 도구(대분류 browser)

- **`browser_click_at(x, y)`**: 지금 보이는 화면의 좌표(스크린샷 픽셀)를 누른다. iframe 안, 목록에 없는 곳, 그림·지도에 쓴다.
- **`browser_type_text(text, submit?)`**: 초점이 있는 칸(iframe 안도)의 커서 자리에 글을 넣는다.
  - 기존 값은 지우지 않는다. 바꾸려면 먼저 `browser_key(select_all)`.
  - 줄바꿈은 글 안에 쓴다.
- **`browser_key(key)`**: 정해진 키만 받는다.
  - enter, space, tab, shift+tab, escape, backspace, delete, 화살표, home, end, pageup, pagedown, select_all.
  - 글자 키는 받지 않는다. 편집 칸 밖에서는 웹앱 단축키가 된다.
- **`browser_scroll`에 x·y**: 그 점 아래의 스크롤 영역(iframe, 목록 상자)을 휠로 굴린다.
- **바로 보이는 도구**(결정 0022): `browser_screenshot`과 `browser_click_at`을 더했다. 좌표 작업의 기본 둘이다.
  - 실측에서 모델이 목록에 없던 `browser_screenshot`을 직접 부르다 한 턴을 버렸다.
- 스크린샷 결과에 화면 크기와 "이 픽셀 좌표를 그대로 쓴다"를 적는다. 전체 페이지 스크린샷은 좌표용이 아니라고 적는다.

### 등급(결정 0008의 규칙을 그 점·초점의 요소에)

- **좌표 클릭**: 데몬이 그 점을 히트 테스트해 읽은 요소로 정한다.
  - 문서 좌표로 바꿔 `DOM.getNodeForLocation`을 쓴다. 다른 사이트 iframe이면 그 세션에서 지역 좌표로 다시 한다(3단까지).
  - 노드는 그 프레임의 격리된 실행 공간에서 읽는다.
  - 다른 사이트 iframe이 CSS로 늘이거나 줄여 그려졌으면(요소 크기와 그 문서 화면 크기가 다르면) 지역 좌표가 어긋나므로 확인하지 못한 것(승인)으로 둔다.
  - 누를 수 있는 가장 가까운 조상이 있으면 참조 클릭과 같은 `classify`를 쓴다. iframe 안이면 그 프레임 주소로 결제·폼 판단을 한다.
  - **label**: 누르면 연결된 컨트롤이 눌린다. 그래서 label 안의 링크·단추를 누른 것이 아니면 연결된 컨트롤로 판정한다. POST 제출 단추의 label은 승인, 파일 칸의 label은 못 함이다.
  - **누를 수 있는 요소가 아닌 곳**(글, 빈 곳): 그냥 누른다. 단 손가락 커서(`cursor:pointer`)가 뜨는 곳은 스크립트가 받는 곳으로 보고 스크립트 단추와 같이 다룬다(안전한 이름이 아니면 승인) [제안].
  - **확인하지 못한 곳**(붙지 못한 iframe 등)은 승인이다. 카드에 그 까닭과 "넘겨받기로 볼 수 있다"를 적는다.
- **초점에 글 넣기**: 초점 요소로 참조 입력(`Act::Type`)과 같은 규칙을 쓴다.
  - 비밀번호 칸·로그인 폼은 못 한다. Enter 제출은 폼 판단을 따른다.
  - 초점이 없으면 못 하고("먼저 누른다"), 모르면 승인이다.
  - 초점은 프레임마다 그 문서의 `activeElement`(shadow DOM 안까지)를 읽어 정한다. 여럿이면 `hasFocus()`인 문서의 것, 그래도 하나로 안 정해지면 모른다.
- **키**:
  - **enter**: 입력칸에서는 제출(폼 판단). 단추·링크에서는 누름으로 판단한다(Tab으로 초점을 옮긴 뒤 Enter도 같다). 여러 줄 칸·편집 칸에서는 보내기일 수 있어 승인이다.
    - **폼 안의 체크 칸·선택 단추·선택 상자의 Enter도 폼 판단이다**. Chrome은 체크 칸에서 Enter로 폼을 제출한다(실측: GET 폼이 /search로 넘어갔다).
  - **space**: 단추·링크에서 누름이다.
  - **그 밖의 키**: 편집·이동이라 그냥 한다.
- **잠금 안 재확인**: 실행 직전(그냥 하는 동작도, 승인된 동작도) 같은 주소인지 보고, 그 점을 다시 히트 테스트하거나 초점을 다시 읽어 같은 대상(`same_target`, 프레임 주소 포함)인지 본다.
  - 승인된 동작은 폼 값도 같은지 본다.
  - 승인을 기다리는 사이 바뀌었으면 하지 않는다.
- 저장된 승인 동작의 JSON은 예전 모양도 읽힌다(`Scroll`의 `at`은 기본값). 요소의 프레임 주소는 빈 값이면 쓰지 않는다.

### iframe 읽기

- 화면 읽기(`browser_open`·`browser_snapshot`·동작 결과)가 보이는 iframe을 덧붙인다(10개까지 살펴 6개까지 보인다).
  - 대상: 같은 프로세스 iframe(최상위 세션의 프레임 트리)과 붙은 다른 사이트 iframe(그 세션의 프레임 트리).
  - 내용: 프레임마다 주소, 화면 영역, 글, 지금 보이는 요소의 가운데 점(화면 좌표)과 등급 표시.
  - **한도**:
    - 글은 본문과 함께 한 예산(15,000자)을 쓴다. 큰 iframe부터 남은 만큼 받고, 본문이 길어도 iframe 몫 3,000자는 남긴다. 본문이 껍데기이고 내용이 iframe에 있는 페이지(블로그 등)를 위한 것이다.
    - 요소는 iframe 하나에 40줄, 모두 합쳐 60줄까지다.
  - iframe 요소에는 참조를 달지 않는다. 누르기는 `browser_click_at` 한 길로만 보내 강제 지점을 하나로 둔다.
  - 작은 iframe(2,500px² 미만, 추적 픽셀·광고 조각)과 화면 밖의 것은 넘긴다.
- **이동 기다리기**:
  - 최상위 문서의 이동을 먼저 본다(예전과 같다).
  - iframe 이동은 그 동작이 닿은 iframe(히트 테스트·초점이 읽은 프레임)의 것만, 8초까지 기다린다. 스스로 다시 뜨는 광고 iframe이 본 페이지 이동 기다리기를 가로채지 않게 하려는 것이다.
  - 다른 사이트 iframe 세션에도 `Page.enable`을 켠다.
- **대화상자**: 다른 사이트 iframe의 확인(confirm) 대화상자도 같은 규칙으로 처리한다(승인된 동작 중에만 수락).
- 다른 사이트 iframe은 별도 프로세스 그대로 둔다. 사이트 격리를 끄면(`--disable-site-isolation`) 붙지 않아도 되지만, 로그인 쿠키가 든 프로필에서 페이지 사이의 격리를 버리게 되어 하지 않았다.

## 확인(2026-11-17)

- **시험**:
  - 좌표 클릭 등급: 링크, iframe 입력칸, 글, 손가락 커서 빈 곳(안전한 이름은 그냥), iframe POST·스크립트 단추는 승인. 로그인 폼·결제·로그아웃은 못 함. 모르는 곳은 승인.
  - 초점 등급:
    - iframe 입력칸은 그냥. 비밀번호·로그인 폼은 못 함. 초점 없음은 못 함, 모름은 승인.
    - POST 칸의 제출·Enter는 승인. 단추의 Enter·Space는 누름으로, 편집 칸 Enter는 승인. 그 밖의 키는 그냥.
  - 흐름(가짜 브라우저):
    - 화면 밖 좌표는 거절한다. 그냥 누르는 곳은 재확인 기대값(프레임 주소 포함)과 함께 실행한다.
    - 모르는 곳은 승인 카드다(좌표·까닭). 누르기 전에는 하지 않는다.
    - 비밀번호 칸에는 넣지 않는다. 예전 모양의 저장된 스크롤 동작을 읽는다.
  - 화면 글: 화면 크기, iframe 영역·글·요소 좌표와 등급 표시. 스크롤 뒤에는 글 없이 보인다.
- **실제 브라우저**(`luciad browser-check`, 개발 브라우저 샌드박스). 기존 점검이 모두 그대로 통과하고, 새로 더한 것도 통과했다(두 번 이어 돌림).
  - 같은 사이트·다른 사이트 iframe의 글과 요소 좌표.
  - 다른 사이트 iframe 입력칸을 좌표로 누름(그 안의 요소로 판정). 초점 칸에 글 넣기(값 "안녕" 확인).
  - iframe 안 POST 폼의 Enter, Tab으로 제출 단추에 초점 뒤 Enter·Space는 승인.
  - 두 iframe의 POST 제출·스크립트 단추는 승인.
  - iframe 안 아이디 칸을 누르고 Tab 뒤 비밀번호 칸에 글 넣기는 못 함.
  - 투명 제출 단추, `pointer-events:none` 미끼(그 아래 POST 단추), 리스너만 단 손가락 커서 div는 모두 그 아래 실제 요소로 승인 판정했다.
  - 승인을 기다리는 사이 이름이 바뀐 단추는 누르지 않았다(`Stale`).
  - iframe 안 휠 스크롤.
  - label: POST 단추의 label은 승인, 파일 칸의 label은 못 함.
  - POST 폼 안의 체크 칸·선택 상자에서 Enter는 승인. 참고로 Chrome은 체크 칸 Enter로 폼을 제출했다(GET 폼으로 확인). 처음 규칙(그냥 함)이었으면 승인 없이 POST가 나갈 뻔했다.
  - 300ms마다 스스로 다시 뜨는 iframe이 있는 페이지에서 참조 링크 클릭이 둘째 쪽까지 기다렸다(0.8초).
  - **이 동안 승인 없이 나간 POST 0건**(서버 쪽 수).
  - 실제 사이트(퀘이사존 첫 화면, 프록시 경유):
    - 본문 19,736자, 요소 762개, 광고 iframe 1개(criteo, 요소 2개)였다.
    - 모델에게 가는 화면 글은 29,678자이고 iframe 몫은 626자다. 나머지는 예전과 같은 본문 상한과 요소 150줄이다.
    - 점검 전체는 2분쯤 걸린다.
  - 점검 서버를 여러 연결을 받는 서버로 바꿨다. 한 연결씩 받는 서버는 Chrome이 미리 열어 둔 빈 연결에 막혀 iframe이 뜨지 않았다.
- **실제 모델**(`lucia-dev`, sonnet, 공개 페이지 w3schools Tryit의 결과 iframe):
  - "결과 화면(iframe)의 First name 칸에 '루시아'를 넣고 제출하지 말라"를 요청했다.
  - 모델이 `browser_open` 결과의 iframe 요소 좌표로 `browser_click_at(747, 136)`을 불렀다. 이어 `browser_key(select_all)`, `browser_type_text("루시아")`, `browser_screenshot` 순으로 했다.

  - 이때 `browser_screenshot`을 직접 부르다 한 번 실패했다. 그래서 바로 보이는 도구로 올렸다.
- **실제로 아직 안 본 것**:
  - 운영 Discord의 좌표 동작 승인 카드.
  - 실제 사이트의 다른 사이트 iframe(결제 위젯, 댓글 위젯 등)에서의 동작.
  - 스크린샷만 보고 고른 좌표의 정확도(실측은 화면 글의 좌표를 썼다).
  - 중첩된 다른 사이트 iframe 안의 iframe 위치(한 단까지만 시험했다).
  - 다른 사이트 iframe 안의 확인(confirm) 대화상자 처리(코드만 있고 시험 페이지에 없다).

## 하지 않은 것

- **iframe 요소에 참조 달기**: 참조 동작 전부(`inspect`·`point`·`focus`·`select`·재확인)에 프레임을 싣게 된다. 좌표 한 길로 충분해 하지 않았다.
- **수정 키 조합**(Ctrl+Enter 등)과 글자 키: 받지 않는다.
- **끌기(드래그)·두 번 누르기·오른쪽 누르기**: 아직 없다. 필요하면 같은 히트 테스트 판정 위에 더한다.
