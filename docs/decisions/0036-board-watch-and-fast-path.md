# 0036. 게시판 감시와 빠른 경로(로그인 게시판 감시 1단계)

- 날짜: 2026-11-18
- 상태: 확정. 값(간격 하한, 사이트 간격, 상한, 물러서기)은 [제안]이다. 2·3단계(로그인 세션으로 읽기, 브라우저 읽기와 방식 고르기)는 같은 제안서의 다음 결정에서 한다.
- 결정 방식: 사용자 지시를 따랐다.
  - 요청: "지금은 사이트 변경 감지 등을 사용하려면 해당 사이트가 공개 페이지여야 하는데, 로그인이 필요한 커뮤니티 게시판 등은 여기에 적용이 불가해서 빠른 폴링과 알림이 불가한 문제가 있어. 개선안을 고안해."
  - 검토 문서: `docs/proposals/login-board-watch.md`.
  - 사용자 덧붙임 두 가지를 넣었다.
    - "둘 모두 구현하고 상황에 따라 선택하여 사용할 수 있도록 하는 건?"(2·3단계)
    - "스크립트로 값을 전처리한 후 유의미한 데이터가 존재할 때에만 모델에게 알리는 방식"(아래 "스크립트로 거르기").
  - 승인: "이렇게 진행해." 추천안 그대로 정했다.
    - 키워드에 맞는 새 글은 모델 없이 바로 알린다.
    - 게시판 감시 간격은 3분 하한, 10분 기본이다.
    - 브라우저 모드 감시가 있으면 브라우저를 계속 켜 둔다(3단계).
    - HTTP가 막혔을 때 브라우저로 바꾸는 것은 카드로 묻는다(3단계).

## 배경

- 구간 감시(결정 0019)를 게시판에 쓰기 어려웠다.
  - 글이 올라올 때마다 "바뀜"이라 세 번 만에 잡음으로 멈춘다.
  - 무엇이 새로 올라왔는지 말하지 못한다(구간 앞 600자).
- 감시 변화는 브리핑과 묶음 소식으로만 갔다. 간격 하한도 30분이었다.
- 매시 사전 체크(지금은 5분 증분 확인) 안에서 작업 큐를 타고 돌았다.

## 결정

### 게시판 감시(`mode = items`, `crate::board`)

- **글 링크 패턴**: 글 주소의 모양으로 글을 찾는다. 예: `/bbs/board.php?bo_table=free&wr_id=*`, `/article/*`.
  - `*`는 경로 한 마디 전체나 쿼리 값 전체다.
  - 패턴에 적힌 쿼리만 보고 나머지(`page` 등)는 무시한다.
  - `*`가 잡은 값들이 글의 키다. 제목 뒤 댓글 수가 바뀌어도 키가 같아 새 글이 아니다.
  - 같은 글의 링크가 여럿이면 가장 긴 글을 제목으로 한다.
  - CSS 선택자는 두지 않았다. 패턴은 사이트 개편에 덜 깨지고 카드에서 읽기 쉽다.
- **새 글**:
  - 본 글 키의 해시를 500개까지 커서에 남긴다.
  - 첫 확인은 기준선이다.
  - 목록 밖으로 밀려났다 다시 보이는 글은 새 글이 아니다.
  - 한 번에 30개 넘게 새로 보이면 목록이 통째로 바뀐 것으로 본다. 알리지 않고 기준선을 다시 잡고 소식으로 알린다.
  - 글이 하나도 안 보이면 변화가 아니라 오류다(로그아웃·개편).
- **키워드**: 제목에 들어가야 할 말 / 빼야 할 말. 각 20개, 40자까지.
- **알림 방식**(감시마다):
  - `now`(게시판 기본): 키워드에 맞는 새 글을 모델 없이 바로 보낸다. 예: "📌 중고 게시판 새 글: 제목 + 주소".
    - 방해 금지 시간(고정·일정 기반)이거나 메신저가 없으면 소식으로 보낸다.
    - 감시 하나가 하루 20건까지 보낸다(관리 페이지). 넘으면 소식으로 모은다.
  - `classify`: 신호 처리(결정 0031)에 넣는다. 작은 모델이 지금/소식/버림으로 나눈다. 보낸 곳 키는 `watch:<id>`라 반응 카드·규칙(결정 0034)도 감시 단위로 따른다.
  - `digest`: 소식으로만.
  - 바로 보낸 글은 브리핑의 바뀐 것에 "(이미 알림 보냄)"으로 남는다.
  - 신호 처리가 꺼져 있으면 `classify`는 소식으로 떨어진다(사라지지 않게).
- **브리핑**: 게시판 새 글은 감시마다 한 줄로 묶는다("새 글 N건(이미 알림 보냄 K건): 제목 5개 외 M건"). 바쁜 게시판이 브리핑 예산을 차지해 메일을 다음 날로 밀어내지 않게 하려는 것이다.

### 스크립트로 거르기(사용자 제안)

싼 단계가 비싼 단계의 문을 지킨다.

| 단계 | 하는 것 | 비용 |
|---|---|---|
| ① | 데몬 코드로 새 글 찾기 | 0 |
| ② | 키워드 | 0 |
| ③ | 루틴 스크립트(스크립트 샌드박스) | 토큰 0 |
| ④ | 작은 모델 | 적음 |
| ⑤ | Lucia | 큼 |

- 이미 있는 반복 루틴(결정 0025)의 `on_change: watch:<id>`를 쓴다. 감시가 변화를 남기면 바로 돈다.
- 게시판 감시의 변화는 새 글 하나당 하나다(`payload`: `title`, `url`, `key`, `what`). 스크립트는 `lucia.input["changes"]`로 받는다.
- 이 감시로 도는 루틴이 있으면 감시는 알리지 않는다. 루틴의 스크립트가 `notify`(모델 없이)나 `wake`(Lucia)를 정한다. 같은 글을 두 번 알리지 않게 하려는 것이다.
- 스크립트는 ②를 지난 새 글이 있을 때만 돈다. 스크립트 샌드박스도 microVM이라 확인마다 돌리면 늘 깨어 있거나 매번 띄우게 된다.

### 빠른 경로

- **전용 타이머**: 감시는 사전 체크와 작업 큐에서 빠져 작업자의 전용 타이머(1분)로 돈다.
  - 한 바퀴가 패닉해도 타이머는 다음 바퀴를 돈다(처음 한 번 알린다).
  - 모델이 없어 대화를 막지 않는다.
  - 새 변화가 있으면 작업자에게 알려 루틴 발사와 신호 분류를 바로 잇는다.
- **간격**: 게시판 3~1440분(기본 10), 구간 10~1440분(30에서 내림).
  - 감시마다 다른 ±10% 흔들림을 준다.
- **사이트 예의**:
  - 같은 호스트는 3분에 한 번까지 가져온다. 한 사이트의 감시들은 이 간격을 나눠 쓴다(가장 오래 확인 안 한 것부터 돌아 하나가 굶지 않는다).
  - 실패하면 간격을 두 배씩 늘려 60분(간격이 더 길면 간격)까지 물러선다.
  - 다섯 번 이어 실패하면 소식으로 한 번 알린다.
  - 조건부 요청(`If-None-Match`)은 넣지 않았다. 게시판 목록은 대개 매번 새로 그려 효과가 작다.

### 문자 집합

- 응답을 헤더의 `charset`, 없으면 문서 앞쪽 `<meta charset>`대로 푼다(없으면 UTF-8). EUC-KR 게시판의 제목이 깨지면 키워드가 조용히 하나도 맞지 않는다.

### 제안과 승인

- `watch_propose`에 `item_pattern`, `include`, `exclude`, `notify`를 더했다. `interval_minutes`는 선택이 됐다(방식별 기본).
- **게시판 감시는 제안할 때 한 번 가져와 본다.**
  - 패턴에 맞는 글이 없으면 만들지 않는다. 대신 페이지의 링크 예(모양마다 하나, 외부 데이터로 감쌈)를 돌려줘 Lucia가 패턴을 고친다.
  - 찾으면 글 수, 키워드에 맞는 수, 앞 글 5개를 카드와 Lucia에게 보인다.
  - 사람 없는 실행(목표 점검)이 제안하면 위임한 사이트만 미리 가져온다(결정 0029의 출구 제한). 아니면 시험 없이 카드에 "미리 가져와 보지 않았다"고 적는다.
- 카드(`watch_review`): 글 링크 모양, 넣을·뺄 말, 알림 방식, 간격, 찾은 글을 보인다. 승인은 지금처럼 사람이 카드에서 한다.

### 관리 페이지("페이지 감시")

- 방식, 패턴, 키워드, 알림 방식, 이어진 실패, 멈춘 까닭(계속 바뀜 / 로그인 필요)을 보인다.
- [고치기]: 간격, 넣을·뺄 말, 알림 방식.
- 전체 설정: 감시 하나의 하루 바로 알림 상한.

### 저장(마이그레이션 0022)

- `watches`에 열을 더했다: `mode`, `item_pattern`, `include_words`, `exclude_words`, `notify`, `fetcher`(2·3단계 자리, 지금은 `plain`), `failures`, `paused_reason`, `sent_day`, `sent_count`.
- 상태 CHECK는 그대로 두고, 멈춘 까닭은 `paused_reason`에 둔다. 표를 다시 만들지 않으려는 것이다.

## 알려진 한계

- 제목 링크가 바깥으로 가는 게시판(Hacker News 등)은 글 링크의 글이 "1 minute ago" 같은 것이 된다. 카드의 앞 글에서 드러나므로 Lucia가 다른 패턴이나 루틴 스크립트로 바꾼다.
- 자바스크립트로 목록을 그리는 게시판과 로그인 게시판은 아직 안 된다(2·3단계).
- 작성자는 뽑지 않는다(게시판마다 자리가 달라 패턴만으로 정할 수 없다).

## Advisor 검토에서 반영한 것(배포 전)

- 문자 참조 풀기가 한글 글자 중간에서 잘라 패닉할 수 있던 것: 바이트로 `;`를 찾는다. 한글 시험을 넣었다. 타이머는 패닉해도 산다.
- 같은 사이트의 감시가 만든 순서로 돌아 뒤쪽이 굶던 것: 오래 확인 안 한 것부터.
- 목표 점검의 제안이 위임 밖 주소를 미리 가져오던 것: 위임한 사이트만.
- EUC-KR, 신호 꺼짐 때의 `classify`, 브리핑 부피.

## 시험

- **패턴**: 쿼리 패턴(다른 쿼리 무시, 같은 글의 여러 링크 합치기, 문자 참조 풀기), 경로 패턴, 잘못된 패턴.
- **새 글 비교**: 기준선, 새 글, 밀려났다 다시 보이는 글, 한꺼번에 30개 넘게(기준선 다시), 구간 커서에서 바꾸기.
- **키워드**: 넣을 말·뺄 말.
- **엔진**:
  - 구간 감시: 기준선 → 그대로 → 바뀜(변화와 소식) → 세 번 이어 바뀌면 "멈춤(계속 바뀜)". 모델 0번.
  - 게시판 감시 `now`: 기준선은 알리지 않음, 키워드에 맞는 새 글만 바로, 하루 상한을 넘은 것은 소식, 브리핑에 "(이미 알림 보냄)", 목록이 비면 오류와 실패 수.
  - 루틴이 붙은 감시는 알리지 않고, 루틴이 새 글 하나당 하나인 변화를 받는다.
  - `classify`는 신호(`watch:<id>`)로 들어간다.
  - 타이머 한 바퀴: 같은 사이트는 3분 사이를 두고, 때가 안 된 감시는 건너뛴다.
- **제안 도구**: 패턴이 안 맞으면 링크 예(외부 데이터), 게시판 하한 3분, 찾은 글 수·키워드 수·앞 글이 카드에, 게시판 기본은 바로 알림.
- **문자 집합**: 헤더 EUC-KR, `<meta>` EUC-KR, UTF-8.
- **브리핑**: 게시판 새 글은 감시마다 한 줄, 모든 변화 ID를 소비.
- **실제 네트워크**(`real_fetch_goes_through_the_checks`, 수동): Hacker News 최신 목록에서 `/item?id=*`로 글 20개 넘게 찾음.
- **실제 모델**(개발, `lucia-dev`): "클리앙 회원중고장터에 그래픽카드 판매글이 올라오면 바로 알려 줘. 사는 글은 빼고."
  - Lucia가 브라우저로 목록을 보고 `item_pattern=/service/board/sold/*`, 넣을 말(그래픽카드·RTX·모델 번호 등), 뺄 말(삽니다·구입 등), 바로 알림, 5분으로 제안했다.
  - 데몬은 글 30개를 찾았고, 키워드에 맞는 것은 2개였다.
  - CLI 채널이라 카드는 올라가지 못했다.
- **아직 운영에서 못 본 것**: 실제 Discord 카드, 승인 뒤 운영 타이머의 첫 새 글 알림, 루틴이 붙은 게시판 감시, `classify` 감시의 실제 분류.
