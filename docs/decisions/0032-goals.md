# 0032. 목표: 하위 항목을 묶고, 사람 없이 점검해 다음 할 일을 정한다

- 날짜: 2026-11-18
- 상태: 확정. 값(점검 주기 기본 24시간, 하루 점검 6번, 신호 뒤 10분, 열린 목표 10개, 완료 확인 카드 7일)은 [제안].
- 결정 방식: 소유자 기능 개선안 A("목표")를 검토한 적용안(`docs/proposals/functional-brief-review.md` §5)을 따랐다. 소유자 지시: "확인하고 적용해."
  - 개선안 §6의 권한 질문은 물어서 정했다: 목표 점검이 하위 루틴을 사람 없이 **만들기까지 허용**한다. 단, 만든 루틴은 점검보다 넓은 범위로 돌지 않는다.

## 개선안과 다르게 한 것

- **위임서(mandate)는 없다.** 앞 개선안의 위임서는 사이트 위임(결정 0028, 전역·호스트 단위)으로 들어갔다. 그래서 "목표 하나에 위임서 하나"는 두지 않았다.
  - 목표가 쓰는 사이트는 지금처럼 `site_grant_propose` 카드로 위임받는다.
  - 목표를 닫아도 위임은 거두지 않는다(다른 일이 같이 쓴다). 관리 페이지에서 따로 거둔다.
- **대화에서 만들 때 카드가 없다.** 개선안은 `goal_propose` + 카드였다. 사람이 대화에서 맡긴 일이고, 루틴·후속 조치도 대화에서 카드 없이 만들므로(소유자가 줄이자고 한 카드 마찰), 필요한 사이트 위임 카드 하나가 개선안의 "한 번의 승인"이다.
- **작업(task)은 하위 항목으로 잇지 않는다.** 작업은 사람의 말로 이어지는 따로 세션이다(결정 0014). 후속 조치·루틴·감시만 잇는다.

## 결정

### 데이터(마이그레이션 0019)

- `goals`: 제목, 목적, 끝났다고 볼 조건, 마감(선택), 상태(진행 중 / 사람 차례 / 완료 / 포기), 관심사(줄마다), 점검 주기, 다음 점검, 결과를 보낼 대화.
- `goal_log`: 진행 기록(점검, 메모, 상태, 하위 항목, 신호).
- `goal_children`: 하위 항목(후속 조치·루틴·감시)과 **점검이 만든 것인가**(`by_review`). 한 항목은 한 목표에만.

### 도구(갈래 `Goals`)

- `goal_create`(사람 필요): 대화에서 만든다. 만들면 첫 점검을 주기 뒤로 건다.
- `goal_list`(읽기).
- `goal_update`: 진행 기록(note), 상태, 마감·관심사·점검 주기·다음 점검, 하위 항목 잇기(link, 대화에서만).
  - **사람 없는 실행은 실행 맥락(`runctx`)이 정한 목표만** 고친다. 모델이 준 목표 ID를 믿지 않는다.
  - 점검이 아닌 하위 실행(하위 후속 조치·루틴이 깨운 실행)은 진행 기록만 남긴다.
  - 제목·끝 조건 바꾸기와 포기는 대화에서만. 점검이 "끝났다"고 하면 바로 닫지 않고 [완료]/[아직] 카드(`goal_done`, 7일)를 올린다(작업 완료 확인과 같다).
- 글은 인젝션 검사를 거친다.

### 목표 점검(실행 종류 `GoalReview`, 사람 없음)

- 언제: 점검 주기마다(기본 하루 1번), 그리고 하위 후속 조치가 끝나거나 하위 루틴이 깨우거나 목표 관심사와 맞는 새 메일·일정 신호(결정 0031 1단계)가 오면 10분 뒤. 한 목표 하루 6번까지(신호 → 점검 → 새 하위 항목 → 신호 고리를 막는다). 방해 금지면 끝난 뒤, 비용 상한이면 다음 주기.
- 범위: 브리핑 등급(읽기, 로컬 쓰기, 위임 사이트 읽기) + 목표 도구 + 루틴 갈래 + 감시 제안(카드). 메일 발송·폼 제출·사이트 위임 제안은 없다.
- 맥락: 목표(조건, 마감과 남은 날, 관심사), 하위 항목의 상태와 지난 실행, 진행 기록 12줄(신호 포함), 위임 사이트, 기억 색인.
- 하는 일(지침): 진행 판단 → `goal_update(note)` 한 줄 → 하위 루틴·후속 조치 조정, 다음 점검 → 사람 차례면 `waiting`과 알림 → 끝났으면 확인 카드. 알릴 것이 없으면 `-`(보내지 않음). 점검이 기록을 남기지 않으면 데몬이 보고 한 줄을 남긴다.

### 넓어지지 않게(소유자 조건)

- 사람 없는 실행의 `routine_create`는 **목표 점검만**, 그 목표의 하위 루틴으로 만든다(`by_review`). 다른 사람 없는 실행(후속 조치, 루틴 깨우기, 브리핑, 신호)은 거절한다.
- **점검이 만든 루틴은 깨울 때 `FollowupLimited`(브리핑 등급)로 돈다.** 대화에서 만든 루틴은 예전처럼 `Followup`이다. 이 둘을 가르는 것은 `goal_children.by_review`다.
- 점검이 등록한 후속 조치는 사슬 출처가 `background`(브라우저 동작 없음)이고 그 목표의 하위 항목이 된다.
- 점검은 자기 목표의 하위 루틴 가운데 **점검이 만든 것만** 고칠 수 있고, 대화에서 만든 하위 루틴은 예전 규칙대로 줄이기만 한다. 지우기는 자기 목표의 하위 루틴만.
- 하위 후속 조치 취소도 자기 목표의 것만.
- 루틴 승인 카드 규칙(사용자 자료 + 외부 가져오기, 결정 0025)과 하루 깨우기 상한은 그대로 걸린다.
- **점검이 만든 루틴의 스크립트**(배포 뒤 검토로 더함): 선언할 수 있는 도구는 점검 자신이 쓸 수 있는 것만(예: Discord 읽기 없음), `fetch`는 사이트 위임한 호스트만(만들 때의 시험, 고칠 때의 시험, 발사 모두). 결정 0025의 "만들 때 사람이 정한 가져오기"라는 전제가 점검이 만든 루틴에는 맞지 않기 때문이다.
- 점검이 기록을 남기지 않았을 때 데몬이 남기는 줄과 실패 줄은 하루 점검 수에 세지 않는다. 열린 완료 확인 카드가 있으면 또 올리지 않는다.

### 닫기

- 완료·포기: 하위 후속 조치 취소, 하위 루틴 끝내기, 하위 감시 지우기, 점검 스케줄 끄기. 사이트 위임은 그대로.

### 다른 곳

- 채팅·브리핑·신호·후속 조치·루틴 맥락에 `<goals>`(열린 목표 한 줄씩) 블록. 아침 브리핑은 진행 중인 목표를 한 줄씩 짚는다.
- 채팅 지침: 마감이 있거나 여러 날 걸리는 일을 맡기면 `goal_create` → 하위 항목 만들기 → `goal_update(link)`.
- 관리 페이지 개요 "맡은 목표": 상태, 끝 조건, 마감, 다음 점검, 하위 항목, 진행 기록, [지금 점검]·[완료]·[포기].

## 시험

- 저장소: 만들기·상한·잇기(한 목표에만)·닫힌 목표는 다시 열지 않음·하루 점검 수.
- 규칙: 사람 없는 실행은 자기 목표만, 하위 실행은 기록만, 점검은 포기·잇기·제목 못 바꿈, 끝은 카드, 닫으면 하위 항목이 끝나고 점검이 꺼짐, 신호 점검은 하루 상한.
- 엔진: 점검 실행은 `GoalReview`(사람 없음, 위임 제안·메일 발송·누르기 없음), 다음 주기를 다시 건다, 방해 금지·하루 상한이면 모델 없이 미룸. 점검이 만든 루틴은 `FollowupLimited`, 대화에서 만든 루틴은 `Followup`, 하위 항목이 돌면 곧 점검.
- MCP: `goal_create`는 대화에서만, 사람 없는 `routine_create`는 점검만, 남의 루틴 지우기 거절, 점검이 등록한 후속 조치는 `background` 출처와 하위 항목, 하위 실행의 기록.
- 관리 페이지: 개요에 보이고 [포기]가 하위 항목·점검을 끝낸다.
- 실제 모델(개발): "12월 5일 오후 6시까지 대학원 원서 접수, 입학처 메일 알려 주고 사흘 전 확인"에 Lucia가 `goal_create`(관심사: 입학처·대학원·원서·접수, 마감) → `followup_create`(12/2 09:00) → `goal_update(link, note)`. 점검을 돌리자 메일을 확인하고 "새 메일 없음, 지원 학교 모름, 다음은 12/2"를 기록한 뒤 `-`로 끝냈다.
