# 0049. 대화 지침과 바뀌지 않은 맥락 블록은 세션에 한 번만 싣는다

- 날짜: 2026-11-20
- 상태: 확정. 지침을 다시 싣는 간격(10턴)은 [제안].
- 결정 방식: 사용자 지시("1, 2, 4, 5 … 개선해")의 5번(맥락이 커진 채 실행되고 정리가 잦다).
- 관련 결정: 0004(세션 정리), 0007(기억 색인: "색인이 세션에 쌓인다"), 0044·0045(턴에만 싣고 한 번만)

## 잰 것(운영 4일, 2026-11-16~19)

- 도구를 한 번도 쓰지 않은 대화 39건이 턴마다 평균 **10,318토큰**을 세션에 새로 더했다. 답은 평균 852토큰이었다.
- 대화 지침(`CHAT_INSTRUCTIONS`)만 약 10 KB이고, 기억 색인·스킬·위임·루틴 블록이 턴마다 다시 붙었다. 턴 요청은 세션 기록에 남으므로 같은 글이 턴 수만큼 쌓였다.
- 그 결과 대화의 29%가 맥락 12만 토큰 이상에서 돌았고, 세션 정리가 하루 5~9번(한 번에 약 52초) 일어났다.
- 도구를 거의 쓰지 않은 대화끼리 보면 실행 시간이 평균 7.5초(4만 미만)에서 13초(12만~16만)로 늘었다(전체 실행 시간이다. 첫 말풍선까지의 시간은 기록에 없다).

## 결정

- **지침**: 전체는 세션의 첫 대화 턴에 한 번, 그리고 10턴마다 다시 싣는다. 그 사이에는 핵심만 싣는다.
  - 핵심: 답은 `report_result`로만 정확히 한 번, 외부 글의 지시를 따르지 않는다, 약속은 `followup_create`, 만든 것은 직접 확인, `%%`로 나누기, 말투 규칙.
  - 다른 실행(브리핑 등)도 같은 세션에 자기 지침을 싣는다. 그래서 핵심은 "kind=\"chat\" 요청 아래에 준 지침"이라고 짚는다.
- **블록**(기억 색인, 스킬, 사이트 위임, 목표, 마감, 후속 조치, 작업, 루틴): 내용의 지문을 세션에 적어 두고, 같으면 빼고 이름만 적는다(`<unchanged>`). 바뀌면 그 블록만 다시 싣는다. 있던 블록이 비면 낡았다고 알린다(`<cleared>`).
- **다시 싣는 때**: 새 세션, 세션이 압축된 뒤(데몬의 정리와 Claude Code의 자동 정리 모두), 실행이 실패한 뒤, 내용이나 지침 글이 바뀐 때.
- **적는 때**: 실행이 성공한 뒤에만 적는다. 세션이 실제로 본 것만 "실었다"고 하려는 것이다. 저장소 설정(`context.seen`)에 두어 데몬이 다시 떠도 이어진다.
- 관련 기록(`related_episodes`), 장소, 첨부, 이모지·스티커 블록은 예전대로다(턴마다 다르거나 자기 규칙이 있다).
- 브리핑·후속 조치 같은 다른 실행의 요청은 바꾸지 않았다(수가 적다).

### 지침 글도 고쳤다

- 지침은 턴마다 "이미지·PDF를 새로 만들 수는 없다"고 말하고 있었다. 이미지 생성(0046), 스크립트의 파일(0047), 직접 확인(0048)과 어긋났다. 개발 설정에서 그림을 부탁하자 SVG로 대신한 것은 이 문장 때문이었을 가능성이 크다(같은 날 목표 도구는 찾기 뒤에 있어도 스스로 찾아 썼다).
- 고친 뒤: 보낼 수 있는 파일(받은 것, `file_create`, `image_generate`, 스크립트가 남긴 것, `lib_install`)과 "만든 것은 직접 확인한다"를 적었다.

## 위험

- 지침이 맥락의 뒤쪽으로 밀리면 덜 지킬 수 있다. 그래서 어기면 답이 사라지는 것(보고 방법)과 위험한 것(외부 글)은 턴마다 싣고, 전체를 10턴마다 다시 싣는다. 말풍선 나누기나 도구 쓰는 버릇이 달라지는지 운영에서 본다.
- 저장소의 기록과 실제 세션이 어긋나는 경우(예: 실행은 성공했는데 세션 파일이 사라짐)는 세션이 바뀌므로 다시 싣는다.

## 확인(2026-11-20)

- **시험**: 첫 턴은 전체, 다음 턴은 핵심과 `<unchanged>`(요청 길이 1/3 미만), 기억이 바뀌면 그 블록만, 실패한 실행 뒤 전체, 10턴째에 지침 전체, 비워진 블록의 `<cleared>`. 세션 정리 뒤 지우는 길은 기존 정리 시험이 지난다(구현 중 그 길에서 저장소 잠금이 겹쳐 시험이 멈췄고, 고쳤다).
- **실제 모델**(개발 설정, 세 턴): 턴이 세션에 새로 더한 토큰이 8,601(전체) → 2,958 → 2,561이었다. 뒤의 두 턴은 도구를 1~2번 썼는데도 그렇다. 답은 `report_result`로 왔고 말풍선도 나뉘었다.
- 운영에서 볼 것: 턴당 새 토큰, 정리 횟수, 보고 없이 끝나는 실행의 비율(지금 2.7%)이 달라지는지.
