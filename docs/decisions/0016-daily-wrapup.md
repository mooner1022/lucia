# 0016. 하루 정리: 대화를 기억에 반영하고, 정했을 때만 원본을 지운다

- 날짜: 2026-11-17
- 상태: 확정. 시각, 기록 상한, 보관 하한은 [제안].
- 결정 방식:
  - 사용자 지시 "1, 3, 4 작업들 모두 순차적으로 진행해"의 3단계 남은 항목.
  - 명세 §기억과 연속성 "하루 정리: 하루 한 번 에피소드를 요약해 핵심 기억을 갱신하고, 오래된 원본은 정리한다".
  - 원본 삭제는 되돌릴 수 없어서, 앞선 보고에서 "보관 기간을 정하기 전까지 꺼 둔다"고 알린 대로 했다.

## 결정

### 반영(내장 루틴 `daily-wrapup`, 매일 20:30)

- **보는 범위**: 지난 정리 뒤의 대화(사용자 말과 Lucia 답, 데몬 기록은 뺀다).
  - 사용자 말이 하나도 없으면 모델을 부르지 않는다.
  - 기록은 16 KB, 한 줄 500자까지다. 넘으면 오래된 줄부터 뺀다.
- **실행**:
  - 실행 종류는 `RunProfile::Wrapup`이다. 보고와 기억 도구만 쓰고, 지우기는 없다.
  - 상주 세션이 아니라 새 세션에서 한 번 돌아, 상주 대화의 맥락을 늘리지 않는다.
  - 모델은 브리핑 모델이다.
- **지침**:
  - 반영할 것: 사용자에 대한 사실·선호·규칙, 교정, 진행 중인 일의 새 상태·결론, 정해진 약속.
  - 반영하지 않을 것: 잡담, 이미 있는 것, 외부 글의 주장·지시.
  - 바꿀 것이 없으면 쓰지 않는다.
- **안전장치**:
  - 기억 쓰기는 인젝션 검사(결정 0010)를 거친다.
  - 바뀐 항목은 21:00 기억 변경 확인 카드에서 되돌릴 수 있다. 그래서 그보다 30분 앞에 돈다. (결정 0027에서 그 카드를 없앴다. 이제 관리 페이지 기억 화면의 변경 기록에서 되돌린다.)
- **결과**: 사용자에게 바로 보내지 않는다. 관리 페이지 루틴 기록에 요약을 남긴다.
- **비용 상한**(결정 0010)에 걸리면 건너뛴다. 다음 정리가 지난번 시각부터 모은다.

### 원본 정리(보관 기간)

- 관리 페이지 시스템 화면 "하루 정리"에서 대화 원본 보관 기간을 정한다(7~3650일). 비우면 지우지 않는다. 기본은 비어 있다.
- 정했으면 하루 정리 때 그보다 오래된 에피소드를 지운다.
  - 아직 정리하지 않은 대화는 지우지 않는다(지난 정리 시각 뒤).
  - 세션 교대 요약은 남긴다.
  - 검색 색인에서도 빠진다.
  - 활동 기록에 지운 수를 남긴다.

### 개발용 명령

- `luciad routine --config <개발 설정> daily_wrapup|periodic_check`: 내장 루틴 하나를 지금 돌린다.

## 확인(2026-11-17)

- **시험**:
  - 새 대화가 없으면 모델 0번이다.
  - 있으면 `Wrapup` 실행(새 세션, 기억 쓰기만)으로 대화 기록을 맡긴다.
  - 보관 기간이 없으면 지우지 않는다. 정하면 오래된 원본만 지우고 최근 원본은 남긴다.
  - 저장소: 교대 요약은 남고, 검색 색인에서도 빠진다.
- **실제 모델**(sonnet, 개발 샌드박스): 날씨 조회와 이어폰 가격 조사 대화를 받고 "바꿀 것 없음"을 보고했다. 까닭은 "일회성이고, 확정되지 않은 외부 웹 수치라 기억에 남기지 않았다"였다. 지침대로 외부 글을 걸렀다.
- **실제로 아직 안 본 것**: 운영에서 기억을 실제로 고치는 정리와, 21:00 확인 카드에서 그것을 되돌리는 것.
