# 0009. 캐릭터 파일을 관리 페이지에서 고친다

- 날짜: 2026-11-17
- 상태: 확정
- 결정 방식: 사용자 요청. "(캐릭터 파일 19행을) 지금 기억 구조에 맞게 고쳐. 이를 대시보드에서 수정할 수 있도록 해."

## 배경

- 캐릭터 본체 `character/character.md`는 보호 영역이다(명세 §캐릭터).
  - 에이전트와 학습 루프는 고칠 수 없다.
  - "본체 수정은 사람이 한다."
- 지금까지 사람이 고치는 길은 레포 파일을 직접 고치는 것뿐이었다. 결정 D5(PLAN §1)는 이름·말투·관계를 사용자가 정해 채운다고 했다.
- 19행은 "말투를 바꿔 달라는 요청은 … 핵심 기억에 취향으로 남긴다"였다. 결정 0007로 기억이 항목(나·주제·영역)으로 바뀌어 낱말이 맞지 않았다.

## 결정

### 19행

- 새 문구: "말투를 바꿔 달라는 요청은 이 파일을 바꾸는 것이 아니라, 기억의 ‘나’ 갈래 항목에 말투 취향으로 남긴다(memory_write). 이 파일은 사용자가 관리 페이지의 캐릭터 화면에서만 고친다."
- `memory_write` 설명에 있던 연결 문구("지침의 ‘핵심 기억’은 이 기억 항목을 말한다", 결정 0007)는 지웠다.

### 관리 페이지 "캐릭터" 화면(`/character`)

- 지금 파일 내용을 편집창에 보이고 저장한다. 바꾼 까닭(선택)을 함께 남긴다.
- **변경 기록**:
  - 저장할 때마다 전체 내용을 저장소(`character_revisions`, 마이그레이션 0007)에 남긴다.
  - 고치기 전 내용이 기록에 없으면 먼저 남긴다. 처음 고칠 때나 레포에서 직접 고쳤을 때가 그렇다.
  - 개정 화면에서 내용을 보고 되돌린다. 되돌리기도 새 개정으로 남는다.
  - 활동 기록에는 `character_edit`로 남는다.
- **저장 규칙**:
  - 줄바꿈을 LF로 맞추고 줄 끝 공백을 지운다. 끝에는 줄바꿈 하나를 둔다.
  - 빈 파일은 받지 않는다.
  - 16 KB까지 받는다. 매 실행 시스템 프롬프트에 통째로 들어가서다.
  - 비밀(마스킹 목록에 든 토큰·비밀번호)이 들어 있으면 받지 않는다.
  - 화면을 연 뒤 파일이 바뀌었으면 덮어쓰지 않는다(내용 지문 비교).
  - "캐릭터보다 우선하는 것" 절이 없으면 저장은 하되 경고한다. 판단·정확성·승인 규칙이 말투보다 우선한다는 절이다.
  - 같은 디렉터리의 임시 파일에 쓰고 이름을 바꾼다. 파일 권한은 지킨다. VM은 디렉터리를 마운트하므로 바뀐 파일을 바로 본다(확인).
- **파일 위치**:
  - 설정에 따로 적지 않는다. `sbx ls --json`의 상주 샌드박스 마운트 가운데 VM 안 경로(`sandbox.character_file`)를 품은 것에서 호스트 경로를 찾는다. 지금은 레포의 `character/character.md`다.
  - `luciad check`가 "캐릭터 파일"(찾음, 크기)과 "캐릭터 읽기 전용"(VM에서 쓸 수 없음)을 본다.
- **보호는 그대로다**:
  - VM 마운트는 읽기 전용이다.
  - Lucia에게 이 파일을 고치는 도구는 없다.
  - 고치는 길은 로그인한 관리 페이지뿐이다. 관리 페이지는 LAN·WireGuard에만 열리고, CSRF 검사를 거친다.
- 레포 파일을 고치므로 git 작업 트리에 변경으로 보인다. 명세 §캐릭터 "버전 관리"대로 사용자가 원할 때 커밋한다.

### 적용 시점

- Claude Code는 대화의 첫 요청에서 만든 시스템 프롬프트를 기록해 두고, 이어 쓰는 동안(`--resume`) 압축될 때까지 그 기록을 그대로 보낸다. `--system-prompt-snapshot`의 기본값 on이 그렇게 한다(`claude --help`, 2.1.325).
- 그래서 고친 캐릭터는 상주 대화의 **다음 세션 정리(압축)나 새 세션**부터 적용된다. 명세 §캐릭터의 "캐릭터 변경은 세션 교대 때 적용된다"와 같다.
- 바로 적용하려면 캐릭터 화면의 "지금 정리해 적용"을 누른다. 세션 정리와 같고, 모델을 한 번 부른다.
- `--system-prompt-snapshot off`는 쓰지 않는다. 명세가 운영 중에는 캐시 효율 때문에 끄라고 했다.

## 확인(2026-11-17)

- 시험:
  - 마운트에서 경로 찾기(가장 깊은 마운트, 경로 조각 단위 비교).
  - 다듬기·상한·비밀 거절·경고.
  - 저장 전후 기록, 낡은 화면 거절, 바깥에서 고친 내용 기록, 되돌리기, 권한 유지.
  - 관리 화면 흐름: 로그인·CSRF, 이스케이프, 알림, 개정 화면, 되돌리기.
- 실제:
  - `luciad check`가 호스트 경로와 VM 읽기 전용을 확인했다.
  - 호스트에서 이름을 바꿔 넣은 파일을 VM이 바로 읽었다.
  - VM에서 새 19행이 보인다.
- 고친 곳: 화면이 세션을 확인할 때 알림을 미리 꺼내 버려, 저장 뒤 알림이 보이지 않았다. 알림을 꺼내지 않는 로그인 확인으로 바꿨다. 같은 모양이던 기억 항목 화면도 고쳤다.

## 이후

- 기억의 말투 메모가 캐릭터와 다를 때 캐릭터가 이긴다는 규칙을 지침에 넣었다(결정 0026). 점검 결과 캐릭터 파일은 정리 뒤 제대로 붙고 있었다.
