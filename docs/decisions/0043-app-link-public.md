# 0043. 전용 앱 연동: 외부 노출, 접속 API 판 2, FCM 푸시, 넓히는 자리

- 날짜: 2026-11-19
- 상태: 확정. 한도 값과 범위 이름은 [제안].
- 결정 방식: 사용자 지시 "대시보드와 엔드포인트를 외부망에 노출하고 fcm 푸시도 연동할 계획이야. 대시보드도 외부망에서 접속할 수 있도록 할거고. 이 점을 염두하여 전용 앱 연동에 필요한 여러 변경 사항을 적용해. 앱에서만 가능한 여러 연동을 계획중이니 확장성을 고려해."
  - 사용자 답:
    - 관리 페이지 2단계 인증은 "외부에서만 필수"다.
    - 다른 세션이 남긴 관리 화면 개편(0041·0042)은 "먼저 따로 커밋"한다(`c34f20c`).
  - Advisor 설계 검토를 반영했다:
    - 프록시 뒤의 상대 주소
    - 노출 자체는 하지 않기
    - 0040과의 충돌
    - 실패 기록 상한
    - 푸시 내용 기본값
- 대체:
  - 결정 0002의 "인터넷에 노출하지 않고, Traefik에도 올리지 않는다"
  - 결정 0021의 "인터넷에 노출하지 않는다"와 "리버스 프록시·터널 뒤에 두지 않는다"
  - 이제는 아래 조건(믿는 프록시, 공개 주소, 2단계 인증)을 지키면 열 수 있다. 설정이 비어 있으면 예전과 똑같다.

## 결정

### 1. 외부 노출(`crate::public`, 설정 `[public]`)

- 데몬은 노출을 스스로 하지 않는다. 리버스 프록시(이 서버에서는 이미 도는 Traefik + Let's Encrypt)가 TLS를 맡고, 데몬의 LAN 바인드로 넘긴다. 연결은 `deploy/traefik/docker-compose.yml`(라벨 컨테이너)이다(아래 후속).
- 설정:
  - `admin_url`, `gateway_url`: `https://<호스트>`. 경로는 쓸 수 없다.
  - `trusted_proxies`: 프록시 주소. IP나 CIDR이고, 이 호스트의 루프백·사설 주소만 된다.
  - 공개 주소를 쓰려면 프록시가 있어야 한다. `gateway_url`은 `gateway.bind`가 있어야 한다.
- **누가 보냈나**: 소켓 상대가 믿는 프록시일 때만 `X-Forwarded-For`를 읽는다.
  - 오른쪽부터 믿는 프록시가 아닌 첫 주소가 실제 상대다. 왼쪽 값은 클라이언트가 지어낼 수 있다.
  - 그 요청은 **외부**다. 집 안 주소가 공개 주소로 들어와도 외부로 본다.
  - 믿는 프록시가 머리를 주지 않으면 거절한다. 모든 외부 요청을 프록시 주소 하나로 뭉치면 잠금이 쓸모없어지거나, 남이 소유자를 잠글 수 있기 때문이다.
  - **믿지 않는 상대가 전달 머리(`X-Forwarded-For`·`Forwarded`)를 실었으면 거절한다.** 프록시 주소를 잘못 적었거나 Traefik 주소가 바뀌었을 때, 밖의 요청이 집 안 대접을 받지 않게 하려는 것이다(닫힌 쪽으로 실패). 관리 페이지는 Host 확인으로도 막히지만, 접속 API는 Host를 보지 않아 이것이 없으면 열려 버린다.
  - 프록시가 아닌 상대는 예전처럼 집 안이다(바인드가 LAN·루프백뿐이다).
- Traefik 컨테이너의 주소는 다시 만들면 바뀔 수 있다. 같은 Docker 망의 다른 컨테이너도 그 대역에서 머리를 지어낼 수 있으므로, 대역보다 Traefik의 주소를 믿고 바뀌면 고친다(compose 파일 머리에 적었다).

### 2. 관리 페이지를 밖에서 열 때

- 외부 요청은 공개 Host 하나만 받는다. 공개 주소를 정하지 않았으면 외부 요청을 받지 않는다.
- 외부 응답에는 HSTS를 보낸다. 외부 로그인 쿠키에는 `Secure`를 붙인다. 집 안은 평문 HTTP라 붙이지 않는다(결정 0002의 절충 그대로).
- **2단계 인증(TOTP, `crate::totp`)**: RFC 6238, HMAC-SHA1, 30초, 6자리다.
  - 비밀은 자격 증명 `admin-totp`(systemd-creds)에 둔다.
  - 앞뒤 한 칸(±30초)까지 받는다. 한 번 받은 칸과 그 앞의 칸은 다시 받지 않는다.
  - **외부 로그인에만 필수다**(사용자 답). 집 안은 비밀번호만 받는다.
  - 켜지 않았으면 외부 로그인을 아예 받지 않는다. 비밀번호도 확인하지 않아, 맞는지 드러나지 않는다.
  - 켜고 끄기와 다시 설정하기는 **집 안에서 로그인한 세션만** 할 수 있다. 가로챈 외부 세션으로 끄지 못하게 하려는 것이다.
  - 끄면 외부 세션을 모두 끝낸다.
  - 설정은 설정 화면 "외부 접속과 2단계 인증"에서 한다. 키(base32)와 `otpauth://` 링크를 보이고, 코드를 맞히면 저장한다. QR 그림은 없다(새 의존성을 피했다).
- **실패 한도**:
  - 주소별로 5번 틀리면 5분 잠근다(예전 그대로, 실제 상대 주소로 센다). 기록은 4096개까지 둔다.
  - 밖의 실패가 한 시간에 20번이면 외부 로그인을 한 시간 막는다 [제안]. 집 안 로그인은 막지 않는다.
- 외부 로그인 성공, 한도 넘김, 2단계 인증 켜기·끄기는 활동 기록에 남기고 알림 받을 곳으로 알린다.
- 세션은 외부·집 안을 구분한다. 한쪽에서 만든 세션을 다른 쪽에서 쓰면 쿠키를 지우고 로그인으로 보낸다. 쿠키가 호스트마다 따로라 보통은 일어나지 않는다.
- 초기 설정 링크(`/setup`)는 밖에서 열리지 않는다.
- 일회용 입력 링크(사이트 로그인, 인증 코드)는 공개 주소로 만든다(`browser.form_base_url`이 없을 때). 밖에서도 열리도록 하려는 것이다.
  - 토큰은 약 244비트다. 사이트 로그인은 10분, 3번까지 쓸 수 있다.
  - 화면 넘겨받기는 로그인이 있어야 한다.
- **남은 위험**: CSP는 결정 0042에서 해제된 채다. 인터넷에서는 이스케이프에 구멍이 하나 생겨도 그대로 스크립트가 돈다. 이번 결정은 되돌리지 않았다. 앞으로 스크립트를 쓸 거라면 `script-src 'self'`로 다시 좁히기를 권한다.

### 3. 접속 API 판 2(`crate::gateway`, `PROTOCOL_VERSION = 2`)

발급한 토큰이 없고 판 1 앱도 없어서, 호환 장치 없이 올렸다. 앱 개발자용 설명은 `docs/app-api.md`에 있다.

- **잃지 않게**:
  - 앱으로 가는 글·안내·파일·카드·카드 닫힘은 클라이언트마다 번호(`seq`)를 붙인다. 상자(`app_outbox`, 마이그레이션 0024)에 넣은 뒤 보낸다.
  - 앱은 `ack{seq}`(누적)로 어디까지 받았는지 알린다. 다시 연결할 때 `hello.resume`을 주면 그 뒤를 다시 받고, 끝에 `resumed{truncated}`가 온다.
  - 번호는 클라이언트의 `out_seq`로 매긴다. 지워져도 되돌리지 않는다.
  - 상자 보관은 받은 것 7일, 받지 않은 것 30일이다 [제안]. 한 시간마다 정리한다.
  - 입력 중 표시와 답(`result`)은 넣지 않는다.
- **오프라인 정책 하나**: 앱 대화(또는 앱으로 돌린 알림 대화)로 갈 것은 이렇게 보낸다.
  1. 연결돼 있으면 앱으로 보낸다. 앱이 `presence{background}`라고 알렸으면 푸시도 한다.
  2. 끊겨 있고 푸시를 쓸 수 있으면(자격 증명 + 그 앱의 토큰) 상자에 쌓고 푸시로 깨운다. 카드 참조는 앱의 것이라 앱에서 누른다.
  3. 둘 다 아니면 예전처럼 Discord DM으로 보내고, 상자에는 넣지 않는다. 한 카드가 두 곳에 열려 하나가 남는 일이 없게 하려는 것이다.
- **HTTP**(`Authorization: Bearer`, app 역할만, 출처 확인·실패 막기는 WebSocket과 같다):
  - `GET /v1/me`
  - `GET /v1/history`
  - `POST /v1/files?name=`: 본문이 파일이고, 30 MB까지다. 토큰을 확인한 뒤에야 본문을 읽는다.
  - `GET /v1/files/{id}`: 그 앱 대화로 오간 파일만 준다.
  - `PUT|DELETE /v1/push`
- **파일**:
  - 앱이 올린 파일은 `files/in`에 두고, 말의 `files`로 붙인다. 엔진에는 `lucia-file:<ID>` 첨부로 들어가고, 같은 대화로 올린 것만 받는다.
  - 데몬이 보내는 파일은 `files/out`에 두고 프레임에는 ID만 싣는다. 보관 30일은 결정 0005 그대로다.
- **알림 받을 곳**(설정 `app.notify_client`, 연결 화면): Discord DM이나 앱 하나를 고른다.
  - 앱을 고르면 소유자에게 알릴 곳을 읽는 곳(엔진의 브리핑·알림, 승인 카드, 로그인 안내, 목표 등, `NotifyTarget`)이 그 앱 대화를 쓴다. 대화 ID가 아니라 **용도로** 가른다. 소유자가 Discord DM에서 직접 한 대화의 답은 DM으로 간다.
  - 앱이 끊겨 있고 푸시도 없으면 라우터가 Discord DM으로 돌린다.
  - 예외: 제안 받기(`reports.rs`)는 Discord 소유자의 말로 넣으므로 Discord DM을 쓴다. 앱에서 권한 모드를 바꾼 기록은 앱 밖(Discord DM)에 남긴다.
  - 작업 스레드는 Discord에만 있다.
  - 결정 0021의 "승인 카드는 Discord로"는 이 설정으로 바꿀 수 있게 됐다. 기본은 예전 그대로 Discord다.
- **명령**: 앱은 `call command {name: "권한", option?}`으로 Discord `/권한`과 같은 처리기를 부른다.
  - 보기는 누구나 된다.
  - **바꾸기는 `security_mode` 범위가 있는 토큰만 된다.** 범위는 관리 페이지에서 발급할 때나 나중에 고르고, 기본은 없다.
  - 결정 0040의 "앱 게이트웨이는 흉내 낼 수 없다"를 범위로 좁혀 연 것이다. 인터넷에 열린 토큰이 새도 해제 모드로 바꾸지 못하게 하려는 것이다.
  - 앱에서 바꾸면 알림 대화에도 남는다.

### 4. FCM 푸시(`crate::push`, `crate::apppush`)

- 자격 증명:
  - 관리 페이지에 Firebase 서비스 계정 JSON을 붙여 넣으면 확인한 뒤 `fcm-service-account`(systemd-creds)로 저장한다. 화면에는 프로젝트 ID만 보인다.
  - RS256 JWT는 `ring`으로 서명하고(새 크레이트 없음), OAuth 토큰으로 바꿔 HTTP v1(`messages:send`)로 보낸다.
  - 엔드포인트와 오류 코드는 공식 문서로 확인했다(`push.rs` 머리 주석에 주소가 있다).
- **내용**: 기본은 고정 문구만 보낸다("새 메시지가 있습니다", "확인할 카드가 있습니다", "파일이 왔습니다"). 푸시는 Google을 거치기 때문이다.
  - 연결 화면에서 "푸시에 글 앞부분 싣기"를 켜면 120자까지 싣는다. 마스킹을 거친다.
  - 데이터 `{type: wake, kind, seq, client}`가 함께 가서, 앱은 열리면 상자에서 받는다.
- **우선순위와 간격**:
  - 카드는 높은 우선순위로 늘 보내고, 따로 보인다.
  - 글·파일은 한 알림으로 바꿔 끼운다(`collapse`). 한 앱에 10초에 한 번까지 보낸다 [제안].
- **오류 처리**:
  - UNREGISTERED이면 토큰을 지운다.
  - 일시 오류이면 한 번 다시 보낸다(최대 60초 기다림).
  - 그 밖의 오류는 `push_failed` 활동으로 남긴다. 인증 오류(설정 문제)이면 푸시를 쓸 수 없는 것으로 보고, 그 뒤의 글·카드는 Discord DM으로 간다. 자격 증명을 다시 넣으면 되살아난다.
  - **빈틈**: 푸시가 "보내졌는데" 휴대폰이 꺼져 있거나, 인증 아닌 오류로 실패한 그 한 건은 앱 상자에만 남는다. 앱을 열 때까지 소유자가 모를 수 있다. 카드는 만료 시간이 지나면 거부로 닫힌다.
- 연결 화면에 앱마다 "시험 푸시" 버튼이 있다.

### 5. 넓히는 자리(앱에서만 되는 연동)

- **앱 → 데몬 메서드**: 등록표 `AppMethod`(`name`, `scope`, `call`)다. 새 연동은 모듈이 `Gateway::register`로 더한다. 범위가 필요한 메서드는 그 범위가 없는 토큰의 `welcome.methods`에 보이지 않고, 부르지도 못한다.
  - 기본 메서드: `history`, `commands`, `command`, `push.register`, `push.unregister`.
- **데몬 → 앱 부탁**:
  - 앱이 `hello.features`로 할 수 있는 일(예: `location`)을 알린다. 데몬은 `Gateway::invoke(client, "location.get", params, timeout)`으로 부탁하고 `result`를 기다린다.
  - 알리지 않은 기능은 부르지 않는다. 다른 앱이 보낸 답은 받지 않는다. 끊기면 `offline`으로 끝난다.
  - 모델 도구로 내는 것은 기능마다 따로 설계한다. 도구 등급과 승인 종류를 정하는 일로, 결정 0013의 원칙을 따른다.
- **앱 이벤트**: 앱도 `event{key, text}`를 보낼 수 있다. 휴대폰 알림 같은 것을 염두에 둔 자리다.
  - 소유자의 앱이어도 글은 외부 데이터다. 신호 처리로 가고, 사람의 말로 들어가지 않는다.
  - 연결마다 한 시간에 60개까지 받는다.
- **범위**(`gateway::scopes`): 기본 밖의 권한을 하나씩 더하는 자리다. 지금은 `security_mode` 하나다.

## 남은 위험(알고 받아들인 것)

- **외부 로그인 막기는 누구나 걸 수 있다**: 밖의 실패 한도(한 시간 20번)는 남이 일부러 넘겨 외부 로그인을 한 시간씩 막아 둘 수 있다. 집 안 로그인은 그대로다.
- **알림 받을 곳이 앱이면 앱 토큰이 곧 승인 권한이다**: 토큰이 새면 그 토큰으로 승인 카드를 받아 누를 수 있다. `security_mode` 범위는 이것을 막지 못한다. 토큰을 잃으면 바로 취소한다.
- **CSP 해제(결정 0042)인 채로 인터넷에 연다**: 위 2절.

## 하지 않은 것

- Traefik 설정과 운영 설정 `[public]`은 바꾸지 않았다. 사용자가 노출할 때 한다.
- 앱 화면 자체, iOS의 APNs 별도 설정, 웹 푸시(VAPID)는 하지 않았다. FCM이 Android와 iOS(APNs 키를 Firebase에 등록했을 때)를 맡는다.
- 모델이 앱 기능을 부르는 도구(`invoke`를 쓰는 도구)는 만들지 않았다.
- 패스키(WebAuthn)·앱 승인 로그인은 하지 않았다. 앱이 생기면 "앱에서 관리 페이지 로그인 승인"을 메서드로 더할 수 있다.
- 2단계 인증의 복구 코드는 없다. 잃어버리면 집 안에서 끄고 다시 켠다.

## 확인(2026-11-19)

- **시험**:
  - 프록시 판별:
    - 지어낸 머리는 무시한다. 오른쪽부터 읽는다. 머리가 없으면 거절한다.
    - `public_host`는 https만 받는다.

  - 설정:
    - 공개 주소에는 https와 프록시가 있어야 한다. 공인 주소는 프록시로 믿지 않는다.
    - 입력 링크는 공개 주소로 만든다.
  - 관리 페이지:
    - 공개 주소가 없으면 외부 요청을 거절한다. LAN Host로 온 외부 요청도 거절한다.
    - 2단계 인증 없이는 외부 로그인이 안 된다. 외부 요청에는 HSTS를 보낸다. `/setup`은 밖에서 404다.
    - 세션은 외부와 집 안을 넘나들지 못한다. 밖에서는 2단계 인증을 켜지 못한다. 실패 한도를 넘으면 429다.
    - 실제 systemd-creds로 TOTP를 켜고 밖에서 로그인했다: `Secure`가 붙고, 쓴 코드는 다시 받지 않고, 활동 기록에 남는다. 집 안에서 끄면 외부 세션이 끝난다.
  - 저장소: 상자 번호, 다시 받기, 정리, 범위, 푸시 토큰, 취소하면 상자와 토큰을 버린다. 여러 대화의 기록을 거꾸로 넘긴다.
  - 접속 API(실제 WebSocket·HTTP):
    - 번호·ack·다시 받기(글·카드·닫힘 순서)와 정리 뒤 `truncated`.
    - `history`(app·owner, 서버 대화 제외), 모르는 메서드.
    - 범위 없는 모드 바꾸기는 처리기로 보내지 않는다. 범위가 있으면 보낸다.
    - 푸시 토큰 형식, 앱 이벤트, 말 ID.
    - `invoke`: 알린 기능만 부른다. 남의 답은 받지 않는다. 끊기면 offline이다.
    - 파일: 올리기 → 말에 붙이기 → 첨부. 남의 파일은 404다. 보낸 파일은 ID로 받는다.
    - `/v1/me`·`/v1/history`·`/v1/push`.
    - 프록시: 공개 주소가 없으면 403, 머리가 없으면 400이다. 믿지 않는 상대가 전달 머리를 실으면 400이다. 실패는 실제 주소로 센다.
  - 파일 저장소: `lucia-file:` 첨부는 같은 대화로 올린 것만 받고, 보낸 파일은 받은 파일로 쓰지 않는다.

      - 뒤로 가 있으면 푸시하고, 안내는 깨우지 않는다. 끊겼어도 푸시가 있으면 카드를 앱으로 보내고 DM과 겹치지 않는다.

## 후속(2026-11-19): lucia.example.com 연결

- (2026-11-21 덧붙임) 공개 준비로 이 기록의 도메인과 주소를 예시 값으로 바꿨다. `deploy/traefik/docker-compose.yml`은 값을 같은 디렉터리의 `.env`(레포에 올리지 않는다, 예시 `env.example`)에서 읽는다.

- 사용자 지시 "lucia.example.com로 도메인 연결했어. traefik 설정해."와 "traefik 파일을 수정하는 게 아니라 docker-compose에 연결하는 방식으로."를 따랐다.
- **연결 방식**: Traefik 설정 파일은 바꾸지 않는다. `deploy/traefik/docker-compose.yml`의 라벨 컨테이너(`lucia-route`)를 쓴다.
  - 이 컨테이너는 잠만 자고 라벨만 들고 있다. 이미지는 `alpine`이고, 읽기 전용에 권한을 모두 뺐다.
  - 라벨 `loadbalancer.server.url`이 호스트의 데몬을 가리킨다. Traefik v3 Docker 라벨이 이 값을 받는다는 것은 공식 문서로 확인했다.
  - 한 호스트를 둘로 나눈다. `Host(lucia.example.com) && PathPrefix(/v1)`은 접속 API(8790)로, 나머지는 관리 페이지(8780)로 간다.
- **Cloudflare 뒤의 실제 주소**: DNS가 Cloudflare 프록시를 거친다. whoami로 실측했다.
  - 미들웨어가 없으면 `X-Forwarded-For`에 엣지 주소 하나만 온다.
  - `cloudflarewarp@file` 미들웨어를 걸면 `X-Forwarded-For: <실제>, <엣지>`, `X-Real-Ip: <실제>`, `X-Is-Trusted: yes`가 온다.
  - 그래서 오른쪽부터 읽으면 엣지 주소가 나온다. 설정 `[public] real_ip_header`를 더해, 믿는 프록시에서 온 요청은 그 머리(`X-Real-Ip`) 하나를 실제 주소로 읽게 했다.
  - 머리가 없거나 둘이거나 깨졌으면 거절한다.
  - `X-Real-Ip`는 Traefik이 늘 다시 쓰고, 플러그인은 Cloudflare 주소에서 온 요청에만 바꾼다. 그래서 클라이언트가 지어내지 못한다.
- **인증서**: Cloudflare가 TLS를 끝내므로 Let's Encrypt TLS 챌린지가 실패한다(Traefik 로그). 그래서 라벨에 certresolver를 걸지 않는다.
  - Traefik 기본 인증서와 Cloudflare SSL 모드 Full로 잇는다. 실측으로 https 접속이 된다.
  - Cloudflare 엣지와 Traefik 사이의 인증서는 검증되지 않는다(Full이지 Full (strict)가 아니다). 엄격하게 하려면 Cloudflare Origin 인증서를 Traefik에 넣어야 하는데, 이는 Traefik 설정 파일을 바꾸는 일이라 하지 않았다.
- **운영 설정**:
  - `[gateway] bind = ["192.168.0.10:8790"]`
  - `[public] admin_url = gateway_url = "https://lucia.example.com"`
  - `trusted_proxies = ["172.18.0.3", "172.18.0.11"]`: Traefik 컨테이너의 monitoring·proxy 망 주소다. 데몬에는 monitoring 망 주소로 붙는다.
  - `real_ip_header = "X-Real-Ip"`
  - 설정 파일 백업은 `~/.config/lucia/lucia.toml.bak-2026-11-19`다.
