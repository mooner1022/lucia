### 2.2 `claude -p` 플래그 대조 (2.1.325 `--help` 기준)

이 대조는 **호스트에 설치된** Claude Code 2.1.325로 했다. 데몬이 실제로 실행하는 것은 sbx 샌드박스 안의 Claude Code이고 그 버전은 아직 모른다. PoC P7에서 VM 안 설치본으로 같은 대조를 다시 한다.

명세 §실행 계층에 나온 플래그:

| 플래그 | 상태 | 비고 |
|---|---|---|
| `-p`, `--input-format`/`--output-format stream-json` | 확인 | `--replay-user-messages`, `--include-hook-events`도 있음 |
| `--session-id <uuid>`, `-r/--resume` | 확인 | `--fork-session`도 있음(세션 교대·분기에 쓸 수 있음) |
| `--plugin-dir`, `--mcp-config` | 확인 | |
| `--append-system-prompt-file`, `--system-prompt-file` | 확인(간접) | 별도 항목은 없고 `--bare` 설명에 `--append-system-prompt[-file]`로 나온다 |
| `--permission-prompt-tool` | 확인(간접) | `--permission-prompts host` 설명 안에서만 언급된다. 동작은 PoC에서 확인 |
| `--max-turns` | **도움말에 없음 → P7에서 동작 확인** | 숨은 플래그다. `error_max_turns`로 끝난다(`poc/RESULTS.md` P7) |
| `--system-prompt-snapshot on\|off` | 확인 | 명세 §캐릭터의 설명과 일치 |

명세에 없지만 쓸 만한 플래그(도움말로 확인):

| 플래그 | 용도 [제안] |
|---|---|
| `--json-schema` | 구조화된 출력 검증. 결과 보고의 1차 수단은 MCP `report_result`이고, 이 플래그는 보고가 빠졌을 때 쓰는 2차 수단으로 검토한다 |
| `--max-budget-usd` | 실행당 비용 상한(명세 §작업 모델의 실행 한도). 구독 인증에서도 의미가 있는지는 미확인 |
| `--permission-prompts none` | 프롬프트가 필요한 행동을 자동으로 거부한다. 백그라운드 읽기 전용 프로필에 맞는다 |
| `--restricted` | 코드 실행 도구를 빼고 파일 도구를 작업 디렉터리로 제한하며 bypassPermissions를 거부한다. 루틴 실행 프로필 후보지만, sbx가 기본으로 붙이는 bypass와 충돌할 수 있다(미확인) |
| `--strict-mcp-config`, `--setting-sources`, `--settings`, `--tools` | VM 안 설정이 섞여 들지 않게 막아 실행 조합을 결정적으로 만든다 |

**`--bare`는 쓰지 않는다.** 도움말에 따르면 `--bare`는 settings와 plugin에 정의된 훅을 건너뛰고, 인증은 `ANTHROPIC_API_KEY`나 apiKeyHelper만 쓴다(OAuth 미사용). 그래서 안전 훅이 꺼지고 구독 백엔드도 쓸 수 없다. 실행을 결정적으로 만드는 일은 위 플래그 조합으로 대신한다.

### 2.3 쓰기 경로별 강제 지점 [제안]

원칙 4(규칙은 코드로 강제)와 원칙 5(백그라운드는 읽기 전용)를 어디서 강제하는지는 쓰기 경로마다 다르다.

| 쓰기 경로 | 예 | 강제 지점 | sbx 기본 bypass의 영향 |
|---|---|---|---|
| 데몬이 실행하는 MCP 도구(D7) | 메일 발송, 캘린더 수정 | **데몬 코드**: 그 행동에 대한 승인 레코드가 없으면 실행하지 않는다 | 없음(데몬은 Claude 권한 모드와 무관) |
| VM 안의 네트워크 쓰기 | 허용 도메인으로 보내는 `curl -X POST`, 프록시가 비밀을 주입한 API 직접 호출 | 네트워크 허용 목록, PreToolUse 훅, 도구 허용 목록 | **크다**: bypass 상태에서는 permission-prompt-tool이 호출되지 않을 수 있다(미확인) |
| VM 안의 git push | 개발 위임 | 네트워크 기본 차단과 훅. VM 안에는 GitHub 자격 증명이 없으므로 push는 데몬 MCP 도구로 옮긴다 | 위와 같음 |
| 브라우저 조작 | 폼 제출 버튼 클릭 | 브라우저 도구 계층(고수준 동작만 허용)에서 제출류 동작에 승인을 요구한다 | 위와 같음 |
| 로컬 쓰기 | 작업 공간 안 파일, 초안 | 자동 허용(명세 등급표) | 해당 없음 |

메신저로 직접 보내는 도구는 명세대로 어느 경로에도 두지 않는다. 전송은 데몬이 결과 보고를 받아서 한다.

정리:
- 외부 쓰기는 가능한 한 데몬 MCP 도구로 만들고 승인은 데몬 코드가 강제한다(D7, 명세 변경). 인증 정보가 호스트에만 있으므로(원칙 1) 대부분의 외부 쓰기는 자연히 이 경로를 지난다.
- VM 안 행동은 훅, 도구 허용 목록, 네트워크 정책이 1차 강제 지점이다. PoC에서 확인하기 전까지 permission-prompt-tool은 보조 수단으로 다룬다.
- PoC에서 확인할 것: bypass 상태에서도 PreToolUse 훅의 deny가 지켜지는지, permission-prompt-tool이 호출되는지, sbx 기본값 대신 `--permission-mode`를 지정할 수 있는지.
- **P2 결과(2026-11-16)**: bypass 상태에서도 훅의 거부는 지켜지고, 데몬은 `sbx exec`로 bypass를 피할 수 있다. 하지만 VM 사용자는 비밀번호 없는 sudo가 있어 VM 안 통제는 그 실행 하나에만 보장된다. 작업 공간에 심은 프로젝트 설정의 훅은 Bash 없는 실행에서도 돈다(`--restricted`로 막힘). 실행 조합과 통제 위치 표는 `poc/RESULTS.md` P2, D7 재검토는 `docs/decisions/0001`.

### 2.4 그 밖에 짚을 점 [제안]

- **상주 세션 동시성**: 같은 session-id에 `claude -p -r`이 동시에 둘 붙으면 기록이 꼬일 수 있다(미확인). 세션 하나는 액터 하나가 소유하고 요청을 직렬화한다. 브리핑 중에 채팅이 오면 큐에서 기다리게 하거나 별도 루틴 실행으로 처리한다.
- **데몬 전용 사용자와 sbx 로그인**: 데몬을 전용 시스템 사용자로 돌리면 sbx 호스트 측 로그인과 kvm 권한도 그 사용자 기준이어야 할 수 있다. PoC P1에서 함께 확인한다.
- **"바뀐 것"의 정의**: MVP 완료 기준은 "전날 대화 반영"과 "변화 없는 날 토큰 0"을 함께 요구한다. 그래서 변화에는 사전 체크 결과뿐 아니라 전날 이후 **사용자가 시작한** 에피소드(대화, 채팅 요청)와 기한이 된 후속 조치도 포함한다. 셋 다 없으면 모델을 부르지 않고 템플릿 문구(예: "새 소식 없음, 오늘 일정 n건")만 보낸다. 데몬이 보낸 브리핑도 에피소드로 남지만 변화로 세지 않는다. 세면 브리핑이 다음 날 브리핑을 부르게 되어 토큰 0인 날이 생기지 않는다.
- **토큰 0을 측정할 수 있어야 한다**: 비용 원장에는 모델 없이 끝난 실행도 기록한다.
- **결과 보고 누락**: 에이전트가 `report_result`를 부르지 않고 끝날 수 있다. 이때 자유 텍스트를 메신저로 흘리지 않고(명세 §출력 계약) "보고 없음"으로 표시한 뒤 한 번만 다시 요청한다.
- **한국어 전문 검색**(2026-11-16 시험으로 확정): trigram은 두 글자 질의("과제")를 MATCH로 못 찾지만 LIKE로는 합성어("기말과제")까지 찾는다. unicode61 + 접두사(`과제*`)는 조사가 붙은 말은 찾지만 합성어를 놓친다. **trigram FTS5를 쓰고, 세 글자 이상은 MATCH, 두 글자 이하는 LIKE로 찾는다**(`crates/lucia-store/tests/fts_korean.rs`).

## 5. 1단계 — PoC: 실행 계층 검증

**완료 기준(명세)**: 데몬이 같은 세션에 두 번 이어 보낸 요청에서 첫 요청의 맥락이 유지되고, 구조화된 결과 보고를 받는다.

실험은 명세 §미결정 사항의 순서("위부터 차례로 닫는다")를 따르고, 그 뒤에 로드맵의 나머지 PoC 항목을 붙였다.

| # | 실험 | 통과 기준 | 실패 시 |
|---|---|---|---|
| P1 | sbx 호스트 측 Claude 로그인: 공식 문서상 샌드박스 안 `/login`으로 로그인하고 토큰은 호스트에 남는다. 헤드리스 서버에서 되는지, 샌드박스 사이에 공유되는지, 데몬 전용 사용자로도 되는지를 확인한다. 첫 `sbx run`이 네트워크 프리셋을 물으므로 `sbx policy init`으로 먼저 정한다. 같이 확인할 것: `sbx login` 없이도 로컬 샌드박스가 도는지, Docker 로그인이 만료되면 어떻게 실패하는지(감시 대상에 넣는다), 텔레메트리 끄기 | 샌드박스 두 곳에서 따로 로그인하지 않고 `claude -p`가 응답하고, VM 안에서 토큰 파일이나 환경 변수가 보이지 않는다 | `claude setup-token`과 프록시 주입(명세의 대안)을 쓴다. 그래도 안 되면 D2 |
| P2 | `sbx run claude -- -p` 일회성 실행과 stream-json 왕복. 기본 `--dangerously-skip-permissions`가 permission-prompt-tool, PreToolUse 훅, `--permission-mode`, `--restricted`와 어떻게 맞물리는지 | 데몬 쪽에서 stream-json 이벤트를 파싱하고, bypass 상태에서도 훅의 deny가 도구 호출을 막는다 | 공식 문서가 설명하는 방법으로 실행 명령을 바꾼다(환경 파일이나 Dockerfile). 명세가 말한 shell 샌드박스는 문서에 없으므로 `sbx --help`로 있는지 확인한다 |
| P3 | 샌드박스를 백그라운드로 유지하는 방법과 재부팅 후 복구 | 재부팅 뒤 같은 샌드박스에서 이전 세션을 재개한다. 이 기준은 P5(세션 재개)가 통과해야 확인할 수 있고, 호스트 재부팅이 필요하므로 시각을 사용자와 맞춘다. **→ 재부팅 시험은 건너뜀(2026-11-16)** | systemd 유닛으로 샌드박스 기동을 관리하고, 세션 기록은 백업에서 복원한다 |
| P4 | VM에서 호스트 데몬 MCP(Streamable HTTP)에 접근하는 방법과 네트워크 정책. rmcp의 `allowed_hosts`를 넓히는 대신 실행마다 발급하는 토큰을 MCP URL이나 헤더에 넣어, 보고를 실행과 짝짓고 인증도 겸하게 한다 [제안] | VM 안 Claude가 `report_result`를 호출하고, 토큰이 없거나 틀린 요청은 거부되며, 허용 목록 밖 도메인은 막힌다 | sbx 문서에 나온 접근 경로(호스트 주소, 포트 노출)를 차례로 시험한다 |
| P5 | 세션 재개: `--session-id`로 첫 요청을 보내고 `-r`로 두 번째 요청을 보낸다 | 두 번째 응답이 첫 요청 내용을 정확히 가리킨다 | 세션 파일 위치와 영속성을 확인한다(P3와 연결) |
| P6 | 권한 승인 도구 왕복: permission-prompt-tool → MCP `request_approval` → 응답(PoC에서는 터미널) | 허용, 거부, 무응답 타임아웃 거부가 모두 기대대로 끝난다 | P2 결과에 맞춰 승인 흐름을 훅과 MCP 중심으로 다시 설계한다 |
| P7 | **VM 안** Claude Code의 버전 확인과 §2.2 대조 재실행. 이어서 `--max-turns`(숨은 플래그인지), `--append-system-prompt-file`, `--json-schema`, `--max-budget-usd`(구독 인증일 때), `--system-prompt-snapshot`, 백엔드 전환(D6)을 시험한다. Claude Code의 auto-memory(작업 디렉터리별 기억 저장소)는 데몬 기억 밖의 두 번째 저장소이므로, 공식 문서에서 끄는 방법을 찾아 적용한다 | VM 안 버전과 플래그별 실제 동작을 기록하고, auto-memory가 꺼진 것을 확인한다 | 다른 플래그나 데몬 쪽 한도로 대신한다 |

## 6. 2단계 — MVP: 기억하는 브리핑

**완료 기준(명세)**: 아침 브리핑에 전날 대화에서 말한 내용이 반영되고, 바뀐 게 없는 날에는 토큰을 쓰지 않는다.

대략 아래 순서로 진행한다.

1. **저장소**: SQLite 스키마와 마이그레이션, 비용 원장(모델, 토큰, 소요 시간, 출처를 기록하고 모델 없이 끝난 실행도 남긴다)
2. **비밀과 로그**: systemd-creds 로딩(`LoadCredential=`), 로그·원장·메신저가 함께 쓰는 마스킹 필터, tracing 구조화 로그
3. **스케줄러**: cron 루틴과 일회성 리마인더, 재시작 뒤에도 유지, 허용 지연 안의 놓친 실행 처리
4. **사전 체크**: 트레이트와 Google Calendar·Gmail 모듈. 데몬이 API를 직접 부르고 증분 동기화 토큰(Calendar syncToken, Gmail historyId)으로 변화를 감지한다. refresh 실패는 알린다

이번 조각에서 정한 것:
- 상주 세션 교대는 MVP에서 모델 요약 없이 한다. 새 세션의 연속성은 다음이 맡고, 둘 다 시험으로 확인했다:
  - 브리핑: 매 요청에 붙는 핵심 기억, 지난 브리핑 이후 사용자 말(`recent_user_messages`), 관련 에피소드(수용 시험).

- 설정에서 지운 루틴은 꺼진다. 소스 기준점이 무효가 되면 다시 잡고, 그 사이 변화를 놓쳤을 수 있다고 알린다.
- 결과 보고가 없거나 여럿이면 실패로 알리고, 브리핑의 소스 변화는 소비하지 않아 다음 브리핑에서 다시 다룬다.
- 인증 오류처럼 세션이 만들어지기 전에 실패한 실행은 세션을 "시작됨"으로 표시하지 않는다(없는 세션 재개를 막는다).
- 외부 토큰은 채팅으로 받지 않는다. 사용자가 `systemd-creds encrypt --user`로 직접 암호화 파일을 만들고, 데몬은 실행 중에만 푼다(sudo 없이 동작 확인).
- 사용자 systemd 관리자(11월 9일 시작)에는 kvm 그룹이 없다. `luciad`를 사용자 서비스로 돌리면 sbx 데몬 함정에 빠지므로 배포 때 `sg kvm`으로 띄우거나 관리자를 다시 시작한다.

## 9. 공통 원칙(모든 단계)

- **테스트**: 실행 계층은 `fake-claude`가 기록된 stream-json을 재생해 테스트한다. 채널 어댑터는 공통 계약 테스트를 통과해야 한다. 상태 머신은 허용되지 않은 전이를 거부하는지 단위 테스트로 확인한다.
- **버전 고정**: 샌드박스 안에 설치된 Claude Code(P7에서 버전 확인)와 sbx 버전을 고정하고 수동으로 올린다. 호스트의 2.1.325는 대화형 개발용이라 고정 대상과 별개다. 올린 뒤에는 스모크 테스트 작업을 돌린다.
- **보안 위생**: 마스킹 필터를 거치지 않고 저장하거나 전송하는 경로가 없어야 한다. 백업에서 인증 정보를 뺀다.
- **결정 기록** [제안]: PoC 결과와 D1~D7 같은 결정은 `docs/decisions/`에 짧게 남긴다.
