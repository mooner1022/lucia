# Lucia 앱 커스텀 이모지·스티커 사양서

- 대상: Lucia 전용 앱 개발자, 그리고 이 사양을 구현할 데몬 쪽 작업
- 바탕: 앱 접속 API 판 2(`docs/app-api.md`)에 더하는 확장이다. 이 문서에 없는 규칙(인증, 프레임 번호, 다시 받기, 푸시, 오류 모양)은 `app-api.md`를 따른다.
- 상태: **데몬 구현됨**(결정 0045, 2026-11-19). 앱은 이 규격에 맞춰 만든다. 한도와 간격은 [제안]이다.
- 관련 결정: 0045(이 사양의 데몬 구현), 0043(앱 연동), 0044(Discord 서버 스티커: 표기 `[스티커:이름]`, 캐시 원칙, 아껴 쓰기)

---

## 1. 개요

| 구분 | 이모지(emoji) | 스티커(sticker) |
|---|---|---|
| 모양 | 글 안에 섞이는 작은 그림 | 메시지 하나를 차지하는 큰 그림 |
| 글 속 표기 | `:이름:`(예: `:lucia_smile:`) | 글에 섞지 않는다. 따로 보낸다. 기록에는 `[스티커:이름]` 줄로 남는다. |
| 데몬 → 앱 | `text`·`note`·`files`의 `body` 안 | 새 프레임 `sticker` |
| 앱 → 데몬 | `message.text` 안 | `message.sticker`(스티커 ID) |
| 그림 받기 | `GET /v1/expressions/files/{file_id}` | 같음 |

- **목록은 데몬이 하나로 관리한다.** 앱은 목록과 그림을 내려받아 그린다. 목록에 더하는 길은 둘이다.
  - 사용자가 관리 페이지 "이모지·스티커"에서 그림을 올리고 이름, 설명, 태그, 분류를 정한다.
  - 대화에서 Lucia에게 그림을 붙이며 등록을 부탁한다(Lucia의 도구 `expression_add`). 그림 규격은 같다.
  - 데몬이 관리하는 까닭은 둘이다. Lucia가 같은 목록을 보고 골라야 하고, 나중에 Discord 같은 다른 플랫폼과 맞출 때도 이 목록 하나에서 시작해야 하기 때문이다.
- 앱에서만 되는 것과 Discord에서도 되는 것은 다르다. 이 사양은 **앱**을 다룬다. Discord 쪽 바꾸기 규칙은 11장에 참고로만 적는다.

## 2. 목록 모델

### 2.1 이모지

```json
{
  "id": "e_3f9a0c12de4b",
  "name": "lucia_smile",
  "label": "루시아 웃음",
  "description": "기분 좋게 웃는 얼굴",
  "tags": ["웃음", "좋아", "기쁨"],
  "category": "lucia",
  "animated": false,
  "file": {"id": "x_9b2e…", "mime": "image/webp", "width": 128, "height": 128, "size": 18342}
}
```

| 필드 | 형식 | 규칙 |
|---|---|---|
| `id` | 문자열 | `e_` + 16진수 12자. 바뀌지 않는다. 이름과 그림도 등록한 뒤에는 바뀌지 않는다(지우고 다시 등록한다). |
| `name` | 문자열 | `[a-z0-9_]`, 2~32자. 글자(a-z)가 하나 이상 있어야 한다. 이모지끼리 겹치지 않는다. 글 속 표기 `:name:`에 쓴다. |
| `label` | 문자열 | 사람에게 보일 이름(한국어 가능, 32자까지, 빈 글일 수 있다). 고르기 화면에 쓴다. 이모지에만 있다. |
| `description` | 문자열 | 100자까지(빈 글일 수 있다). 대괄호(`[ ]`)는 없다. Lucia가 고를 때 쓰는 설명이다. 앱은 접근성 라벨로 쓴다. |
| `tags` | 문자열 배열 | 10개까지, 각 20자까지. 찾기와 자동 완성에 쓴다. |
| `category` | 문자열 | 고르기 화면의 묶음 ID(2.3). 빈 글이면 분류 없음이다. |
| `animated` | 불 | 움직이는 그림인가 |
| `file` | 객체 | 2.4 |

> `name`을 ASCII로 제한하는 까닭: 나중에 Discord 앱 이모지로 올릴 때 이름이 그대로 맞아야 한다. 한국어 이름은 `label`에 둔다.

### 2.2 스티커

```json
{
  "id": "s_7a1c0e9b3f52",
  "name": "축하",
  "description": "꽃가루가 날리는 축하",
  "tags": ["축하", "합격", "🎉"],
  "category": "lucia",
  "animated": true,
  "file": {"id": "x_51c0…", "mime": "image/webp", "width": 320, "height": 320, "size": 201733}
}
```

| 필드 | 규칙 |
|---|---|
| `id` | `s_` + 16진수 12자. 바뀌지 않는다. |
| `name` | 2~30자(한국어 가능). 앞뒤 공백, 줄바꿈, `[` `]` `:` `—`(기록 줄의 구분자)는 쓸 수 없다. 스티커끼리 겹치지 않는다(대소문자 무시). Lucia의 표기 `[스티커:이름]`에 쓴다. |
| `description`, `tags`, `category`, `animated`, `file` | 이모지와 같다 |

### 2.3 분류

```json
{"id": "lucia", "label": "루시아", "order": 0, "icon": "e_3f9a0c12de4b"}
```

- `id`는 영문 소문자·숫자·`_`로 24자까지다. `order`로 정렬한다(작은 것이 앞).
- 항목의 `category`는 이 목록에 있는 `id`이거나 빈 글(분류 없음)이다. 분류 없음을 어디에 보일지는 앱이 정한다.
- `icon`은 탭 아이콘으로 쓸 이모지나 스티커의 ID다(없을 수 있다).

### 2.4 그림 파일

| | 이모지 | 스티커 |
|---|---|---|
| 형식 | PNG, WebP(정지·움직임), GIF | PNG, APNG, WebP(정지·움직임), GIF |
| 크기(가로×세로) | 정사각형. 128×128 권장, 32~256 | 정사각형. 320×320 권장, 160~640 |
| 파일 크기 | 256 KiB까지 | 512 KiB까지 |
| 배경 | 투명 권장 | 투명 권장 |
| 움직임 | 반복. 3초 안쪽 권장 | 반복. 5초 안쪽 권장 |

- 데몬은 등록할 때 파일 서명으로 형식을 확인하고, 크기와 비율을 검사해 맞지 않으면 거절한다. **등록 단계는 그림을 고치지 않는다**(줄이기, 자르기, 형식 바꾸기 없음). JPEG와 SVG는 받지 않는다.
  - 대화에서 Lucia에게 부탁하면 Lucia가 등록 전에 스크립트로 규격에 맞춘다(결정 0047). 그래서 목록에 들어온 그림은 늘 이 표의 규격 안이다.
- `mime`은 `image/png`, `image/apng`(움직이는 PNG), `image/webp`, `image/gif` 가운데 하나다.
- 앱은 `mime`을 믿지 말고 디코더가 받는지로 판단한다. 그리지 못하면 대체 표시(5.3)를 쓴다.
- `file.id`는 `x_` + 16진수 24자이고 내용 해시에서 만든다. 내용이 같으면 같은 ID다(두 항목이 같은 `file.id`를 가질 수 있다). 그래서 앱은 `file.id`를 키로 **영구 캐시**해도 된다.
- 이모지 256 KiB는 Discord 앱 이모지 한도(공식 문서)와 같게 맞췄다. 스티커 한도는 앱 기준이다.

## 3. 목록 받기

### 3.1 `GET /v1/expressions`

인증은 `app-api.md` 8장과 같다(`Authorization: Bearer`).

```json
{
  "version": "c41d9e07a2b8",
  "categories": [ {…} ],
  "emoji": [ {…} ],
  "stickers": [ {…} ]
}
```

- 응답 머리:
  - `ETag: "<version>"`
  - `Cache-Control: private, no-cache`(쓰기 전에 확인)
- 앱이 `If-None-Match: "<version>"`을 보내고 목록이 그대로면 `304`가 온다(본문 없음).
- `version`은 목록 전체 내용의 해시다. 무엇이든 바뀌면 바뀐다.
- 목록이 비어 있어도 `200`이다(빈 배열).

### 3.2 `GET /v1/expressions/files/{file_id}`

- `200`이면 본문이 그림이다. 머리:
  - `Content-Type: <mime>`
  - `Cache-Control: private, max-age=31536000, immutable`
  - `ETag: "<file_id>"`
- `404 not_found`: 없는 파일, 또는 목록에서 빠진 지 30일이 지난 파일이다.
  - 목록에서 빠진 파일도 **30일은 계속 준다.** 예전 메시지와 기록이 깨지지 않게 하려는 것이다. 30일은 그 파일을 가리키는 항목이 하나도 없어진 때부터 센다.
- 다른 머리: `X-Content-Type-Options: nosniff`

### 3.3 언제 다시 받나

- `welcome`(5.3)과 `GET /v1/me`에 `expressions` 필드가 더해진다.

```json
"expressions": {"version": "c41d9e07a2b8", "emoji": 24, "stickers": 12}
```

- 연결 중에 목록이 바뀌면 번호 없는 프레임이 온다. `{"type": "expressions", "version": "…"}`
- 앱이 저장한 `version`과 다르면 `GET /v1/expressions`로 새로 받는다. 그림은 새 `file.id`만 받는다.

## 4. 글 속 이모지 표기 `:name:`

### 4.1 문법

- 토큰: `:` + 이름 + `:`. 이름은 2.1의 규칙(`[a-z0-9_]{2,32}`, 글자 하나 이상)을 따른다.
- 대소문자를 구분한다. 목록의 이름은 늘 소문자다.
- **목록에 있는 이름일 때만** 그림으로 바꾼다. 없으면 글 그대로 둔다(예: `10:30:00`, `:not_ours:`).
- 다음 안에서는 바꾸지 않는다.
  - 인라인 코드와 코드 블록
  - 링크 주소
  - `\:name:`처럼 앞에 역슬래시가 있을 때. 역슬래시를 지우고 글로 보인다.
- 오른쪽 `:`를 다음 토큰과 나눠 쓰지 않는다. `:a_b::c_d:`는 두 토큰이다. 왼쪽부터 가장 짧게 맞춘다.
- 정규식 예: `(?<!\\):([a-z0-9_]*[a-z][a-z0-9_]*):`. 맞춘 뒤 목록에 있는지 본다.

### 4.2 어디에 나타나나

| 곳 | 나타나는가 |
|---|---|
| `text.body`, `note.body`, `files.body` | 그렇다 |
| 카드의 `body`, `fields[].value` | 그렇다(Lucia가 쓴 글이 실릴 때) |
| 카드의 `headline`, `title`, 버튼 글 | 쓰지 않는다(데몬이 정한 고정 문구) |
| `history` 항목의 `body` | 그렇다 |
| 앱 → 데몬 `message.text` | 그렇다(사용자가 고른 이모지) |
| 푸시 본문 | 미리보기를 켰으면 그렇다. 알림에는 그림이 없으므로 `label`로 바꾸거나 그대로 보인다(앱이 정한다). |

### 4.3 그리기

- 줄 안에서는 글자 높이에 맞춘다(줄 높이의 약 1.2배 권장).
- **이모지만 있는 메시지**는 크게 그린다. 공백 말고 다른 글이 없고 이모지 토큰이 1~3개일 때, 40~48pt 권장.
- 접근성: 그림의 대체 글은 `label`(없으면 `name`)이다. 화면 읽기에는 "이모지: {label}"로 읽힌다.
- 움직이는 그림:
  - 화면에 보일 때만 돌린다.
  - 기기의 "동작 줄이기" 설정이 켜져 있으면 첫 장면만 보인다.

## 5. 스티커

### 5.1 데몬 → 앱: `sticker` 프레임(번호 붙음)

```json
{"type": "sticker", "seq": 64, "sticker": {"id": "s_7a1c0e9b3f52", "name": "축하"}}
```

- `app-api.md` 5.4의 **번호 붙는 프레임**에 하나가 더해진다. 상자에 남고, `ack`와 다시 받기, 중복 거르기가 똑같이 적용된다.
- 보통 Lucia의 글(`text`) 바로 뒤에 온다. 같은 답의 일부로 이어 붙여 보여도 된다.
- 앱 목록에 그 `id`가 없으면(목록이 늦게 받아졌다) 목록을 새로 받아 본다. 그래도 없으면 대체 표시를 쓴다(5.3).

### 5.2 앱 → 데몬: 스티커 보내기

`message`에 `sticker` 필드가 더해진다.

```json
{"type": "message", "sticker": "s_7a1c0e9b3f52", "id": "m-1700000000002"}
{"type": "message", "text": "나 합격했어!", "sticker": "s_7a1c0e9b3f52", "id": "m-…"}
```

| 필드 | 규칙 |
|---|---|
| `sticker` | 목록에 있는 스티커 ID 하나. 글·파일과 함께 보낼 수 있다. |
| `text`, `files` | 기존과 같다. 셋 중 하나는 있어야 한다. |

- 성공하면 `accepted`가 온다(기존과 같다).
- 목록에 없는 ID이면 오류 `bad_sticker`가 온다(연결은 유지).
- 데몬은 사용자의 말을 `<글>\n[스티커:이름 — 설명]`으로 Lucia에게 넘긴다(설명이 없으면 `[스티커:이름]`). Lucia는 그림을 보지 않고 이름과 설명으로 이해한다.
- 글 없이 스티커만 보내면 그 줄 하나가 말이 된다. `sticker`가 빈 글이면 없는 것으로 본다.

### 5.3 대체 표시

그림을 그릴 수 없을 때(파일 404, 디코드 실패, 목록에 없음):
- 이모지: 토큰 글 그대로(`:lucia_smile:`)
- 스티커: 작은 상자에 `[스티커: {name}]`

### 5.4 그리기

- 말풍선 없이 크게 보인다. 160~200pt 권장, 정사각형.
- 눌렀을 때 이름과 설명을 보여 주는 것은 선택이다.
- 움직임 규칙은 4.3과 같다.

## 6. 기록(`history`)에서

- 기록은 글이라 스티커가 **줄 하나로** 남는다. `[스티커:이름]` 또는 `[스티커:이름 — 설명]`이다(사용자가 보낸 것).
- Lucia의 답에는 **실제로 보낸 스티커만** 남는다. 답의 마지막 줄에 `[스티커:이름]`(목록의 이름 그대로) 한 줄이다. 간격에 걸렸거나 목록에 없어 보내지 않은 것은 기록에도 없다.
- 앱은 `history.items[].body`에서 다음 줄을 찾아 스티커로 그린다.
  - 정규식: `^\[스티커:\s*([^\]\n—]+?)\s*(?:—[^\]\n]*)?\]$`
  - 이름으로 목록에서 찾는다(대소문자·앞뒤 공백 무시).
  - 없으면 그 줄을 대체 표시로 바꾼다.
- 이모지 토큰은 4장 그대로다.
- 실시간 프레임(`text` + `sticker`)과 기록의 모양이 다르므로, 기록으로 다시 그릴 때 위 규칙이 필요하다.

## 7. 고르기와 입력(앱 UX 권장)

- **고르기 화면**: 분류 탭과 "최근 쓴 것"(기기에 저장, 20개)을 둔다. 이모지 탭과 스티커 탭을 나눈다.
- **찾기**: `label`, `name`, `tags`에서 찾는다. 한글 초성 검색은 선택이다.
- **자동 완성**: 글을 쓰다 `:` 다음에 두 글자를 넣으면 이모지 후보를 띄운다. 고르면 `:name:`을 넣는다. 입력창 안에서는 그림으로 보여도 되지만, **보낼 때는 반드시 `:name:` 글로 바꿔 보낸다.**
- **스티커 보내기**: 누르면 바로 `message{sticker}`로 보낸다. 입력창에 쓰던 글이 있으면 같이 보낼지 앱이 정한다(같이 보내도 된다).
- 보낼 수 있는 이모지·스티커는 목록에 있는 것뿐이다. 기기의 유니코드 이모지는 그대로 글로 보내면 된다(이 사양과 상관없다).

| WebSocket `error` | `bad_sticker` | `message.sticker`가 목록에 없다 |
| HTTP | `304` | `If-None-Match`의 버전이 그대로다(오류 아님) |
| HTTP | `404 not_found` | 없는 그림 파일 |
| HTTP | `501 unsupported` | 이모지·스티커를 다루지 않는 데몬(이 사양을 구현하기 전의 판) |

앱은 `welcome.expressions`가 **없으면** 이 기능이 없는 데몬으로 보고, 고르기 화면을 숨긴다.

---

## 10. 푸시

- `sticker` 프레임도 깨운다. `data.kind`는 `"sticker"`다.
  - 기본 본문: "스티커를 보냈어요"
  - 우선순위: 보통. 접기: `lucia-messages`(`text`와 같다).
- 같은 답의 `text` 바로 뒤에 오므로, 글 알림 간격(한 앱 10초) 안이면 따로 울리지 않는다.

---

## 11. 데몬 쪽 동작(참고: 앱이 할 일은 없다)

앱이 받는 것을 이해하는 데 필요한 만큼만 적는다.

- **Lucia가 고르는 방법**(캐시 유지, 결정 0044와 같은 원칙):
  - 이모지·스티커 목록은 시스템 프롬프트·도구 목록(캐시되는 앞부분)에 넣지 않는다. **앱 대화의 그 턴 요청**에만 싣는다.
  - 같은 상주 세션에는 한 번만 싣고, 다음 턴부터는 가리키기만 한다. 목록 `version`이 바뀌거나 세션이 압축되면 다시 싣는다.
  - Lucia는 아껴 쓴다. 지침(대부분의 답에는 쓰지 않는다)과 데몬의 간격으로 막는다.
- **Lucia의 출력을 바꾸기**:
  - 앱 대화에서 Lucia가 쓴 `:name:`은 그대로 `text`에 실린다. **데몬은 앱으로 가는 `:name:`을 건드리지 않는다.** 목록에 없는 이름은 앱이 글 그대로 보인다(4.1).
    - 처음 제안은 "목록에 없는 이름은 데몬이 지운다"였다. `std::fmt::Display`나 `aa:bb:cc` 같은 글이 깨지므로 바꿨다.
  - `[스티커:이름]` 줄은 글에서 지우고 `sticker` 프레임으로 보낸다. 목록에 없거나 간격 안이면 버리고 기록에도 남기지 않는다.
- **다른 플랫폼**:
  - 앱이 아닌 곳(Discord, 그리고 앱이 끊겨 알림 대화로 돌린 글)으로 가는 글에서는 **목록에 있는 이름의 `:name:`만** 지운다. 코드(백틱) 안과 목록에 없는 이름은 그대로 둔다. Discord 앱 이모지로 바꾸는 것은 아직 하지 않는다.
  - 앱 스티커는 Discord에 없으므로 Discord에서는 쓰지 않는다. Discord 서버에서는 결정 0044대로 그 서버의 스티커만 쓴다.
  - 앱이 끊겨 알림 대화로 돌릴 때는 스티커를 보내지 않는다.
- **관리**: 관리 페이지 "이모지·스티커"에서 그림 올리기, 보이는 이름·설명·태그·분류 고치기, 지우기, 분류 만들기를 한다. Lucia도 대화에서 등록(`expression_add`), 목록 보기(`expression_list`), 지우기(`expression_remove`)를 한다. 등록과 지우기는 사람이 대화 중일 때만 된다. 무엇이든 바뀌면 `version`이 바뀌고, 연결된 앱에 `expressions` 프레임이 간다.

---

## 12. 구현 순서

데몬 쪽 1~3은 끝났다(결정 0045). 남은 것은 4(앱)다.

1. 데몬:
   - 목록 저장(마이그레이션)과 관리 페이지
   - `GET /v1/expressions`·`files`
   - `welcome.expressions`와 `expressions` 프레임
2. 데몬: `sticker` 프레임과 `message.sticker`, 기록 줄, 푸시 `sticker`
3. 데몬: Lucia에게 목록 싣기(앱 턴, 세션마다 한 번)와 출력 바꾸기, 아껴 쓰기 지침
4. 앱:
   - 목록·그림 캐시
   - `:name:` 그리기(4장), `sticker` 프레임과 기록 줄 그리기(5·6장)
   - 고르기와 자동 완성(7장)

앱은 1번이 끝나면 목록과 그리기부터 만들 수 있다. `welcome.expressions`가 없으면 숨기므로, 데몬보다 먼저 배포해도 된다.
